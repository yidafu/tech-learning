## 必须遵守的约定

- **大纲文件保持精简**：只放阶段列表、进度复选框和笔记链接；详细学习内容一律写入各阶段笔记文件，不要写入大纲。
- **每阶段一个 `0N-第N阶段/` 目录**：`NN-` 前缀 = 阶段序（文件系统排序 + 站点侧边栏顺序，Docusaurus 会剥离前缀，URL 段即“第N阶段”）。历史目录名 `章节N/` 已于 2026-11-10 全部改名为 `01-第一阶段/` ~ `06-第六阶段/`。
- **阶段内文章排序：文件名加两位数字前缀 `NN-名称.md`**。`01-` 固定为该阶段**导览页**，文件名 `01-<主题>.md`（如 `01-架构思维与设计基础.md`，H1 与文件名同名、不带阶段号——阶段号由侧边栏类别承担）；内容分册从 `02-` 起按学习顺序编号；`99-` 固定为自测答案档案。**示例项目场景/ 目录特例**：`01-~14-` 已是场景编号，导览页用 `00-导览.md`。**示例目录**命名形如 `NNa-示例-名`（NNa = 所属分册号 + 字母次级序），排在所属分册之后、下一分册之前（如 `01-第一阶段/07a-示例-patterns`、`02-第二阶段/04a-示例-es-cqrs`、`02-第二阶段/04b-示例-event-driven`）。第一阶段现状：`01-架构思维与设计基础` → `02-认识软件架构` → `03-代码级设计能力` → `04-架构质量属性` → `05-康威定律-补充` → `06-常用设计模式-补充` → `07-设计模式使用场景` → `99-自测答案与点评`；其余各阶段均已按同规则拆分（各阶段分册清单见其导览页）。阅读站点（Docusaurus）原生把 `NN-` 前缀解析为侧边栏顺序，并从 URL/标题中剥离前缀；因此笔记**不要写 frontmatter `title`**（会覆盖取自首个 `#` 标题的页面标题与侧边栏标签）。插入新文件时按学习顺序编入；任何改名都必须同步更新全工作区引用该文件的链接。
- **标题命名规范**（2026-11-10 统一）：内容分册文件名 = `NN-主题[-副题].md`（短，供 URL），H1 = `主题[: 副题]`（副题可选，文件名可省），H1 不带文件名主题词之外的前缀/尾巴（如“进阶选修：”“速查”“（工具清单）”）。**文内标题**：原节分册的小节直接用 H2（原节号 X.Y / X.Y.Z 保留，**节号数字一律不改**——140+ 处“见 N.M”文字引用依赖）；新增分册与档案用本地编号 `N.`（0 可作总纲）或“第X部分：”形；自测标题统一 `## 【本节自测】`，导览页阶段自测 `## 第N阶段自测`；标题不带 ✅ 等进度标记（进度以大纲复选框为准）。**术语**：全书统一用“第N阶段”指六个学习阶段（目录名、侧边栏、导航、链接文字一致），不用“章/章节N”指阶段；分册内部小节称“N 节 / §N”。
- **补充内容默认写进对应分册笔记的小节**（2026-11-04 拆分后每阶段由多个分册组成，“主笔记”即对应主题的分册）；仅当用户明确要求单独成文件时才拆出（如 `01-第一阶段/05-康威定律-补充.md`），并在分册原位置留一句话摘要 + 链接。
- **复选框进度**：`[x]` 已学、`[ ]` 未学；只有讲完/学完一节才勾选对应条目。
- **【本节自测】批改流程**：用户作答自测题后，逐题按固定四段回复：① 判定结论（正确 / 部分正确 / 不正确）；② 对在哪里；③ 错在哪里；④ 参考正确答案（开放题给要点式达标线，不是唯一答案）。每次批改同步两件事：把逐题记录追加写入该阶段的答案文档 `0N-第N阶段/99-自测答案与点评.md`（随首次批改按需创建，遵守两位数字前缀与无 frontmatter `title` 规则），并更新下方“当前进度”。
- **自测与勾选联动**：讲解新节以该节自测收尾；该节自测全部达标才勾选复选框，未达标先补讲薄弱点、重测通过再勾（替代“讲完即勾”）。
- **双向链接**：大纲中链接指向 `0N-第N阶段/xxx.md`；每份笔记开头的返回链接用 `../软件架构学习大纲.md`。
- **内容语言**：简体中文。教学风格：概念 + 反例/修正（贯穿例子常用订单系统，并优先结合下方“示例项目场景”），每节末尾附自测题。
- **代码示例语言**：统一使用 Kotlin 编写代码示例（含反例与修正版）。
- 用户说“继续”= 讲解大纲中的下一节；每阶段讲完，把该阶段笔记整理写入对应 `0N-第N阶段/` 文档。

## 示例项目场景

讲解示例除通用“订单系统”外，按主题优先从下列场景取材；速览与大纲映射见 [示例项目场景/00-导览.md](示例项目场景/00-导览.md)，各场景的业务画像、核心模块逐一展开、架构挑战与取材指引见 [示例项目场景/](示例项目场景/) 下对应详情文档（01~12 对应原节一~十二，13、14 为新增场景）。

用户熟悉的真实项目：

- **工单中心**：工单创建、分派、流转、SLA 时限与关单——适合讲状态机、流程/规则引擎、模块划分。
- **桶装水商城**：商品、下单、周期购订阅、配送排线、水桶押金与回收——适合讲分层架构、领域建模、幂等与事务。
- **MES（Manufacturing Execution System，制造执行系统）**：生产工单、工序排程、报工采集、物料追溯、设备联网与工控（PLC/SCADA）集成——适合讲事件驱动、系统集成、实时性分层与工控安全。

经典演示场景（对应大纲第六阶段“典型场景拆解”）：

- **秒杀/限时抢购**：瞬时高并发、库存扣减与防超卖——适合讲缓存架构、限流熔断降级、削峰填谷。
- **即时通讯（IM）**：长连接接入、消息收发、离线同步与已读回执——适合讲接入层/网关设计、推拉模型、消息顺序与可达性。
- **支付与清结算**：收款、分账、对账与差错处理——适合讲分布式事务、幂等、最终一致性。
- **Feed 流内容社区**：发布、关注关系、时间线聚合、热搜——适合讲读写分离、缓存体系、分库分表。
- **物联网平台（数据上报采集）**：海量设备接入、高频上报、指令下发——适合讲消息队列削峰、时序数据存储、背压与流控。
- **低代码开发平台（搭建系统）**：表单/流程/页面拖拽搭建、元数据驱动运行——适合讲元数据建模、解释器模式、动态字段存储与配置版本化。
- **API 网关**：统一入口的路由、认证卸载、限流配额、插件链与灰度分流——适合讲网关层职责边界（该做什么/不该做什么）、责任链模式落地、限流位置选择与认证授权。
- **多租户 SaaS 控制平面**：租户生命周期、套餐订阅与计费、用量计量与配额、操作审计——适合讲多租户隔离、控制面/数据面分离、配额限流与计费最终一致性。
- **Git 托管平台（GitHub、GitLab、Gitea）**：仓库存储（Git 对象内容寻址、按仓库分片）、PR/MR 评审状态机、CI/CD Runner 调度、Webhook 事件外发——适合讲不可变数据设计、协作状态机、任务队列与消费语义、API 限流；三家形态对照讲“架构形态跟着规模走”。
- **研发 Ops 平台**：应用与开发/预发/生产三环境模型（一次构建多环境晋升）、容器管理与漂移治理、发布编排（灰度分批放量与健康门禁、蓝绿秒级切流、滚动）、研发需求管理与全链路追溯、审批与封网管控——适合讲发布单状态机、不可变制品与环境配置收敛、回滚两种语义（切流/版本）、变更审计。
