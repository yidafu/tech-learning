# 数据系统内核专题

> 所属学习计划：[软件架构学习大纲](../软件架构学习大纲.md)（专题，接在第三阶段之后阅读最顺）
> 示例取材：[示例项目场景](../示例项目场景/00-导览.md)——物联网水表上报贯穿存储引擎；工单中心/桶装水商城贯穿并发控制；多租户计量事件流、支付日终对账贯穿批与流。
> 可运行示例目录：`02a-示例-storage-engines/`（LSM 引擎 + B+ 树页分裂对照）、`03a-示例-mvcc-snapshot/`（MVCC 与快照隔离）、`04a-示例-streaming/`（事件时间窗口与水位线）。

## 专题定位

大纲推荐书目里的《数据密集型应用系统设计》（DDIA，Martin Kleppmann）是全大纲最重的一本“硬书”，但六阶段笔记里只有第三阶段真正吸收了它的分布式部分（CAP、复制、共识、分区）。它另外两大块——**存储与索引的机械**、**事务与并发控制**，以及批处理与流处理两章——在站内几乎是空白：存储引擎只在选型表里按名字出现，事务隔离、MVCC、快照隔离、写偏斜全站提过一两处，批与流没有专册。本专题把这三块补齐，作为第三阶段的向下延伸。

一句话定位分工：**第三阶段讲“数据在多台机器上怎么摆”（复制、分区、共识、分布式事务），本专题讲“单台机器上数据到底怎么存、事务到底怎么并发”**。两层互为表里：

- 第三阶段的“B+ 树索引对雪花 ID 友好”，机械原因在本专题第 2 册（页分裂与顺序插入）；
- 第三阶段 Saga“没有隔离性”，隔离性本来是什么、单机数据库买到了哪一档，在本专题第 3 册；
- 第三阶段消息队列档案讲“顺序写日志、消费者位移”，位移之上的窗口、状态、恰好一次语义，在本专题第 4 册；
- 第三阶段 Raft 日志、2PC 的 prepare/commit 记录，本质是把本专题第 2 册的 WAL 思想推广到多节点。

读完本专题再回看第三阶段，会看到同一组原理（追加日志、版本、快照、幂等）在单机内核与分布式两个层面的重复出现——这正是资深架构师该有的视角：**新系统不是新原理，是旧原理换了载体**。

## 阅读路线

- **主干**：02（存储）→ 03（事务）→ 04（批流）。02 与 03 是“单机内核”的左右两半——一个讲数据怎么摆放，一个讲并发怎么协调，先后皆可；04 依赖前两册的概念（LSM、快照、幂等），放最后。
- **与六阶段的穿插**：02 册可与第三阶段[数据架构分册](../03-第三阶段/04-数据架构-缓存分库与选型.md)对读（它讲选型表，本册讲表背后的机械）；03 册前半可与第三阶段[分布式事务分册](../03-第三阶段/05-分布式事务-从2PC到最终一致.md)开头对读（它假设“本地事务可靠”，本册解释这份可靠从哪来）。
- **动手**：每册配一个可运行 Kotlin 示例（见上方示例目录链接），单文件、无第三方依赖，`kotlinc xx.kt -include-runtime -d xx.jar && java -jar xx.jar` 即可跑。02 册的 MiniLsm 会把写放大、读放大、空间放大用引擎自己实测的字节算给你看。

## 专题综合自测

1. 物联网平台的水表上报峰值 5 万条/秒，同一个键每小时覆盖一次，偶发点查；MES 报工每秒几百条、按工单号/工序查询、要求读到即最新。两者分别选 B+ 树还是 LSM 主存储？用两大放大（写/读）与崩溃恢复成本推导，不要只报产品名。
2. 桶装水商城同一 SKU 并发扣库存出现“两个事务都读到余 1、各扣 1、超卖”。指出这是哪类异常（丢失更新还是写偏斜？），分别给出乐观锁与 `SELECT ... FOR UPDATE` 两种修法，并说明两种修法各自把隔离级别要求提到了哪一档。
3. “MySQL 的可重复读防幻读，PostgreSQL 的可重复读不防”——这句话哪里对、哪里不准确？用两库各自的实现机械（ReadView 建立时机 vs 快照读与 next-key 锁）解释同名不同义。
4. 水表断网两天后补传数据，实时大屏与日报口径不一致。用事件时间/处理时间、水位线与迟到数据三层策略解释为什么统计必须事件时间，并说明补传数据进入哪个通道。
5. 支付平台日终对账为什么至今仍是批处理而不是流处理？给出至少两条结构性理由（可重复性/全量核对/幂等），并说明流处理在同一条链路上承担什么角色。
