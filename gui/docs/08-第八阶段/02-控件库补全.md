## 1. 概念坐标：TextField = 光标几何 + 键盘编辑 + 焦点

```text
第三阶段（文本）：layoutText / offsetToX / xToOffset —— 量与映射，当时承诺「第五阶段输入框直接用」
第五阶段（事件）：FocusManager / dispatchKey —— 键盘路由
第八阶段（本册）：RenderTextField —— 把两者焊在一起：
    键码 → 编辑动作 → 文本/光标变更 → markNeedsLayout/Paint
    点击 → xToOffset（中点吸附）→ 光标落位
```

字段表（逐字要点）：`text`（内容）、`caret`（0..len）、`textLayout2`（第三阶段 TextLayout，paintSelf 与 xToOffset 共用——**私有字段命名 `textLayout2` 避开与基类 `layout` 方法撞名**，ScriptC 命名冲突的实测规避）、`focused`（基类 RenderObject 的标志，第八册 §4 讲它差点失灵）。

## 2. 键码表：raylib 数值的平台无关封装

```ts
  static readonly KEY_BACKSPACE = 259;
  static readonly KEY_DELETE = 261;
  static readonly KEY_RIGHT = 262;
  static readonly KEY_LEFT = 263;
  static readonly KEY_HOME = 268;
  static readonly KEY_END = 269;
  static readonly KEY_ENTER = 257;
  static readonly KEY_KP_ENTER = 335;
```

键码常量收在类上（对照第五阶段散在 focus.ts 的同款数值）：编辑键的语义归属控件，不该由路由层知道。可打印区 `code >= 32 && code <= 126`（ASCII）——**CJK 走 IME，教学版明确不接**（第 6 节的边界账）。

## 3. 编辑操作全表：光标与文本的状态机

`onKey` 的完整分支（逐字语义，手算用例直接代）：

| 键码 | 动作 | 光标变化 | 文本变化 | 失效通道 |
|---|---|---|---|---|
| Backspace(259) | 删光标前字符 | caret-1（若>0） | 移除 [caret-1, caret) | layout（→级联 paint） |
| Delete(261) | 删光标后字符 | 不动 | 移除 [caret, caret+1) | layout |
| ←(263) | 左移 | max(0, caret-1) | — | paint only |
| →(262) | 右移 | min(len, caret+1) | — | paint only |
| Home(268) | 行首 | 0 | — | paint only |
| End(269) | 行尾 | len | — | paint only |
| Enter(257/335) | 提交 | — | 触发 onSubmit | — |
| 32..126 | 插入字符 | caret+1 | 前插 ch | layout |

三条失效纪律在表里可见：**移动光标只标 paint**（几何没变，只是光标画在哪）；**改文本标 layout**（宽度可能变 → 父排列可能变）；**onChanged 回调只在真正改文本时发**（`afterEdit` 统一出口）。手算用例（widgets.test 逐条）：`"abc"` 光标 0 → End → ← → Delete 得 `"ab"` → Backspace 得 `"a"`——三条通道（layout/paint/回调）在四个动作里各出现一次。

**光标初始在 0 不是在尾**——demo08 集成时测试第一版就栽在这里（按 H 得到 "Hedit me" 而非 "edit meH"）。约定写死：程序化聚焦不动光标，用户点击/方向键才移动；要尾插先按 End。

## 4. 焦点标志：demo08 实抓的内核缺陷

onKey 第一行守卫（逐字）：`if (!this.focused) return false;`——`focused` 是**节点上的标志**。demo08 集成时发现：`FocusManager.focusNode(field)` 只更新了**管理器侧**的 `this.focused` 引用，**节点侧的 `focused` 标志从没被点亮**——键全被守卫吞掉，文本纹丝不动。第五阶段的焦点测试能过是因为测试手工设了 `tf.focused = true`（绕过了缺陷）。

修复（focus.ts，逐字）：

```ts
    // 管理器侧引用 + 节点侧标志必须同步点亮/熄灭——
    // 之前只记管理器侧，控件自身的 focused 守卫永远不亮（demo08 集成实测抓到）
    const prev = this.focused;
    if (prev !== null && prev !== node) prev.focused = false;
    if (node !== null) node.focused = true;
```

配套的内核改动：`focused = false` 从 TextField 上移到 **RenderObject 基类**（与 canFocus 配对——焦点是节点级概念，任何可聚焦控件都要这个标志，不该每控件自declare）。这个 bug 的教学价值：**单元测试全绿 ≠ 集成可用**——第五阶段的焦点单测、第八阶段的 TextField 单测各自通过（各自手工设标志），拼起来才发现路由层没人点灯。「无头全绿 + 窗口必验」的纪律（第六册 §2）第三次兑现。

## 5. 点击定位与 paintSelf

点击（逐字语义）：命中点的窗口 x 减去**沿父链累加的自身偏移**得局部 x → `xToOffset(textLayout2, 0, localX, measurer)` 中点吸附 → caret。与绘制共享同一套坐标合同（paint 局部坐标 = 窗口 − Σ偏移）——命中与绘制对齐的又一次兑现（第五阶段修过的「命中对绘制错」在这里的正面应用）。

paintSelf 四层（逐行）：边框（聚焦 accent / 失焦 border）→ 底色（聚焦时 lerp 微亮）→ 文本（12,10 起，fontSize）→ 光标（聚焦时 `12 + offsetToX(layout, 0, caret)` 处 2×(h-16) accent 竖条）。第三阶段的两个几何函数在 paint 与 hit 各用一次——**「测量=绘制」铁律**保证两个函数拿到同一个 layout。

## 6. 明确不做的边界（IME 与选区）

| 不做 | 为什么 | 工程化路径 |
|---|---|---|
| IME 合成中态 | ScriptC/raylib 无输入法事件面（拿不到 preedit/preedit-cursor） | 平台层补 ime 事件 → 控件加 preedit 槽 |
| 选区拖拽 | 需要 shift+点击/拖拽手势 + 选区绘制（第三阶段 span 着色可复用） | 手势层加 drag-select → anchor/focus 两光标 |
| 剪贴板 | raylib 有 GetClipboardText/SetClipboardText，教学版未接 | Ctrl+C/V/X 三键 + 系统剪贴板直通 |
| 多行 | 单行布局（textLayout2 单行）；多行 = 每行一个 TextLayout + 行游标 | 第三阶段断行器的直接复用 |

「明确不做」不是偷懒清单，是**边界声明**：毕业项目的文本编辑器选型（07 册）会用这张表倒推工作量。

## 8. 本册小结

- TextField = 第三阶段光标几何 + 第五阶段焦点路由的焊接点；`textLayout2` 命名规避与基类 layout 撞名
- 键码表收控件、编辑操作四通道失效纪律（移动→paint、改文→layout、提交→回调、插入→layout+onChanged）

- IME/选区/剪贴板/多行四项明确不做，各留工程化路径——边界声明是选型依据

## 附录 A：RenderTextField 全量源码走读（分段）

**构造与字段**（逐字）：

```ts
export class RenderTextField extends RenderObject {
  private text = "";
  private caret = 0;                    // 光标 offset（0..len）
  private fontSize: number;
  private measurer: TextMeasurer;
  private textLayout2: TextLayout | null = null;   // ← 命名避开与基类 layout 方法撞名
  focused = false;                      // （第八册 §4 后改由基类声明）

  constructor(fontSize: number, measurer: TextMeasurer) {
    super();
    this.fontSize = fontSize;
    this.measurer = measurer;
    this.canFocus = true;               // 可聚焦：FocusManager 的收集条件
  }
```

五个字段、一个构造三行——控件的「状态面」就这么小。`canFocus = true` 是焦点系统的注册方式（focus.ts 的 collectFocusables 按 it 收集）。

**setText 与光标钳制**（逐字）：

```ts
  setText(t: string): void {
    this.text = t;
    this.caret = clamp(this.caret, 0, t.length);   // 程序化改文不动光标语义，只钳合法性
    this.markNeedsLayout();
    this.markNeedsPaint();
  }
```

**onKey 全分支**（逐字，第 3 节状态机的源文本）：

```ts
  onKey(ev: KeyEvent): boolean {
    if (!this.focused) return false;               // 守卫：非聚焦不消费（集成缺陷的案发现场）
    const code = ev.code;
    if (code === RenderTextField.KEY_BACKSPACE) {
      if (this.caret > 0) {
        const head = this.text.slice(0, this.caret - 1);
        this.text = head + this.text.slice(this.caret);
        this.caret -= 1;
        this.afterEdit();                          // 统一出口：标脏 + onChanged
      }
      return true;                                 // 消费（不冒泡）
    }
    if (code === RenderTextField.KEY_DELETE) {
      if (this.caret < this.text.length) {
        this.text = this.text.slice(0, this.caret) + this.text.slice(this.caret + 1);
        this.afterEdit();
      }
      return true;
    }
    if (code === RenderTextField.KEY_LEFT)  { this.caret = Math.max(0, this.caret - 1); this.markNeedsPaint(); return true; }
    if (code === RenderTextField.KEY_RIGHT) { this.caret = Math.min(this.text.length, this.caret + 1); this.markNeedsPaint(); return true; }
    if (code === RenderTextField.KEY_HOME)  { this.caret = 0; this.markNeedsPaint(); return true; }
    if (code === RenderTextField.KEY_END)   { this.caret = this.text.length; this.markNeedsPaint(); return true; }
    if (code === RenderTextField.KEY_ENTER || code === RenderTextField.KEY_KP_ENTER) {
      const cb = this.onSubmit;
      if (cb !== null) cb(this.text);
      return true;
    }
    if (code >= 32 && code <= 126) {               // 可打印 ASCII（IME 边界见 §6）
      const ch = String.fromCharCode(code);
      this.text = this.text.slice(0, this.caret) + ch + this.text.slice(this.caret);
      this.caret += 1;
      this.afterEdit();
      return true;
    }
    return false;                                  // 未消费：冒泡给父（快捷键等）
  }

  private afterEdit(): void {
    this.markNeedsLayout();
    const cb = this.onChanged;
    if (cb !== null) cb(this.text);
  }
```

读法四点：①「消费/不消费」的返回值语义——未识别键 return false 让父链继续（快捷键系统的挂点）；②Backspace 与 Delete 的字符串切片互为镜像（caret-1 前删 / caret 后删）；③onChanged 只在文本真变时发（光标移动不发）；④ScriptC 的字符串拼接没有复合赋值——`head + this.text.slice(...)` 是全量重建（O(n) 每键，万字符文本每键 O(n)——工程化加 rope/span 缓冲，教学版明账）。

**点击定位与绘制**（逐字）：

```ts
  onPointerDown(ev: PointerEvent): void {
    if (this.textLayout2 === null) return;
    let wx = 0;                                    // 沿父链累加自身偏移（与绘制同一坐标合同）
    let node: RenderObject | null = this;
    while (node !== null) { wx += node.x; node = node.parent; }
    this.caret = xToOffset(this.textLayout2, 0, ev.x - wx, this.measurer);
    this.markNeedsPaint();
  }

  protected paintSelf(p: Painter): void {
    const border: Color = this.focused ? PALETTE.accent : PALETTE.border;
    const bg: Color = this.focused ? lerpColor(PALETTE.surface, PALETTE.accent, 0.06) : PALETTE.surface;
    p.fillRect({ x: 0, y: 0, width: this.width, height: this.height }, border);
    p.fillRect({ x: 1, y: 1, width: this.width - 2, height: this.height - 2 }, bg);
    p.text(this.text, 12, 10, this.fontSize, PALETTE.text);
    if (this.focused && this.textLayout2 !== null) {
      const cx = 12 + offsetToX(this.textLayout2, 0, this.caret, this.measurer);
      p.fillRect({ x: cx, y: 8, width: 2, height: this.height - 16 }, PALETTE.accent);  // 光标
    }
  }
```

绘制四层与聚焦态两档（边框色 + 底色微亮 lerp 0.06）——「聚焦态可见性」是无障碍的最低配：键盘用户靠它知道输入去哪了。光标 x = 左内边距 12 + 第三阶段 offsetToX——**承诺兑现的一行**（第三册注释「第五阶段输入框直接用」）。

## 附录 F：光标状态机的三组纸上推演（自测 1 的完整答案）

练习一（删改混合，widgets.test 序列的推广）——`"abc"` 光标 2 起：

| 步 | 按键 | text | caret | 失效通道 |
|---|---|---|---|---|
| 0 | — | `abc` | 2 | — |
| 1 | Delete | `ab` | 2 | layout + onChanged |
| 2 | End | `ab` | 2（len=2，已在尾） | paint only |
| 3 | Backspace | `a` | 1 | layout + onChanged |
| 4 | 输入 X | `aX` | 2 | layout + onChanged |

注意第 2 步：End 在已行尾时 caret 不变，但 onKey 分支**仍然 markNeedsPaint**——光标移动没有做「同值短路」（每按一次多一条光标命令的重画）。这是明账优化点：先比较 caret 是否真的变了再标脏，可省稳态连按的重画（对照第七阶段 setText 的同值短路——同一条纪律在控件层的缺席处）。

练习二（边界对撞）：空文本 `""` 光标 0——Backspace（`caret > 0` 不成立）、Delete（`caret < len` 不成立）、←/→（钳制后原值）**四个键全部消费且全部无效**（返回 true 保持吞键不冒泡）。黄金用例的边界行从这里出（第五册纪律三：空容器行从不缺席）。

练习三（点击中点吸附）：`"ab"` 每字符 advance 8px，点击局部 x=12：候选边界 0/8/16，12 恰在 8..16 的中点 → 吸附 offset 2（≥中点向右取）——**吸附方向是约定不是推导**，必须写死并在测试里断言（widgets.test 的「点击定位」条就是这条锚点；换实现时它是回归参照）。

## 附录 G：组合键的路线图（Shift+Left 选区纸面稿）

附录 B 说 modifiers 已在事件结构上、控件未消费——接上它需要的最小状态机（毕业选题 C 的第一步）：

```text
状态新增：anchor: number | null（选区锚点；null = 无选区）
Shift+Left：anchor === null ? anchor = caret（先记锚）：不动；caret = max(0, caret - 1)
Shift+Right：对称（caret = min(len, caret + 1)）
无 shift 的移动键：先清 anchor（选区塌缩到 caret）
Backspace/Delete（有选区）：删 [min, max) 区间，caret = min——不再按单字符分支走
渲染：选区高亮 = anchor..caret 区间先画底色带再画文本（第三阶段 span 着色直接复用）
```

五条状态迁移 + 两条派生——选区的工作量集中在**迁移完整性**：每个移动键都要处理「有选区时无 shift」的塌缩分支，漏一个就是悬挂选区 bug（高亮残留但语义已丢）。这就是 §6 边界表给「选区拖拽」留两条工程化路径的原因：状态机小、分支面大——典型的「状态少、迁移多」控件，用黄金用例的边界行一条条锁（Shift 组合 × 8 个移动键 = 8 条最小用例）。
