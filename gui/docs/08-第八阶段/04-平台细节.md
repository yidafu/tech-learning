## 1. HiDPI：逻辑坐标与物理坐标

mini-gui 全栈只有一套坐标——**窗口逻辑像素**（`initWindow(WIDTH, HEIGHT)` 的 WIDTH/HEIGHT）。HiDPI（Retina 2x）下 raylib 的处理方式：`SetConfigFlags(FLAG_WINDOW_HIGHDPI)` 时窗口以物理像素创建、`GetMousePosition` 返回的仍是**窗口坐标系的点**——教学版的坐标系统一在「raylib 给什么就用什么」，缩放系数没有进入内核。这个简化要诚实拆解：

```text
真实框架的三层坐标（mini-gui 缺第三层）：
  逻辑坐标  设计所用（CSS px / Flutter 的 logical pixel）——「同一 UI 在 1x/2x 屏上物理大小一致」
  物理坐标  帧缓冲像素（2x 屏 = 逻辑 × devicePixelRatio）
  坐标换算  逻辑 × scale = 物理，发生在「提交给 GPU/帧缓冲」的最后一刻

mini-gui：initWindow(800, 450) 在 2x 屏上得到 1600×900 物理帧缓冲，
         GetMousePosition 与内核坐标都是 800×450 逻辑系（raylib 内部换算），
         Painter 的 fillRect 也画在逻辑系——raylib 的形状 API 按 DPI 放大。
```

 consequences（后果清单）：文本在高 DPI 下清晰（raylib 字形按设备像素渲染，font.ts 用 32px 底字形）；**内核零 DPI 感知**——布局、命中、绘制全部无缩放分支，这是「坐标合同唯一」红利的自然延伸；代价是**无法做亚像素精细控制**（hairline 边框在 1x 屏会糊，因为没有「0.5 逻辑 px」的显式通道）。HiDPI 变化时需要失效什么？教学版答案：什么都不用失效——内核不知道 DPI 存在；真实框架要失效的是**字形图集与图片资源缓存**（它们按 DPI 物化）。

## 2. 窗口系统：教学版单窗口 vs 真实多窗口

教学版一进程一窗口（`initWindow` 一次），焦点、输入、呈现都绑定在这一个窗口上。真实桌面栈的三层概念账：

```text
窗口管理器（Wayland compositor / macOS WindowServer）
  ↑↑ 合成：每个窗口(表面) 的缓冲合成到屏幕——透明/动画/遮挡
窗口（表面 surface）：有独立缓冲、独立输入焦点
  ↑↑ 嵌入：框架窗口内的子窗口/弹窗
应用：一个进程可多窗口，每窗口一棵渲染树
```

mini-gui 缺失的每一层都有对应的「假实现」：

| 真实能力 | 教学版替代 | 代价 |
|---|---|---|
| 多窗口 | 无（一进程一窗） | Dialog 用窗口内 Overlay 模拟（02 册留的题） |
| 系统合成 | 根图层整段 replay（自己合成自己） | 06 册「第三道防线」的诚实账 |
| 跨窗口拖放 | 无 | — |
| 窗口失焦/激活事件 | raylib 的 isWindowFocused 可查但未接 | 焦点环不区分窗口级焦点 |

**「合成器 vs 应用自绘」的边界**正是第六册图层合成的对照面：mini-gui 的 blit 是应用内合成；真实桌面把窗口缓冲交给合成器混合。这条边界决定了「半透明/圆角外发光」这类效果的真实成本（合成器免费，自绘逐像素）。

## 3. ScriptC 宿主面：从 TS 到原生窗口的通道

platform/ 三件的职责（各册已走读，这里给总账）：

| 文件 | 职责 | 关键决策 |
|---|---|---|
| `raylib-backend.ts` | CommandSink 实现：命令→raylib 调用；scissor 生命周期；endFrame 复位 | 命令自包含 → replay 零上下文 |
| `raylib-measurer.ts` | TextMeasurer 实现：MeasureTextEx 换算 | 与 backend 同字体（switchFont 同步）——「量=画」铁律的宿主侧 |
| `font.ts` | loadUiFont：系统 TTF（含 CJK 码点表）→ 字形图集 | Arial Unicode / Noto 候选；ASCII+CJK 样本码点 |
| `raylib-events.ts` | RaylibEventSource：轮询输入 → UiEvent 流 | 第五阶段的输入抽象（轮询而非回调） |

**环境开关四件套**（demo 全家共享，05 册的回归工具链）：`MINI_GUI_SECONDS`（定时退出）/ `MINI_GUI_FPS`（帧率档）/ `MINI_GUI_SHOT`（退出前截图）/ `MINI_GUI_*` 全部走 `envNumber`（core/config，脚本化可回归）。截图路径：`takeScreenshot(path)` 在 closeWindow **之前**调——第六阶段踩过「endDrawing 后截图拿到纯清屏」的时序坑，注释在 06 demo 顶部。

## 4. ScriptC 编译边界在 demo08 的三次实锤

demo08 原生编译/运行期实抓的三条新边界（前七阶段的清单又长三行，全部有注释出处）：

| 错误码 | 场景 | 修法 |
|---|---|---|
| SC1090（老边界新现场） | `this.makeRow(...)` **字段函数直接调用** | 读局部变量再调：`const make = this.makeRow; make(...)`（事件槽同款——probe8 的老结论在新文件再验证） |
| SC9001（ICE，新现场） | 闭包参数 `as RowLine` 下行 | `if (row instanceof RowLine) row.rebind(...)` 收窄路径 |
| **运行期校验（新）** | 工厂槽 `() => RowLine` 赋给 `(d,i) => RenderObject` 槽——编译过（宽松函数兼容）、**运行期炸**（「槽位返回型需精确匹配」） | 工厂显式标注返回类型 `(): RenderObject => new RowLine()` |

第三条最值得记住：**ScriptC 的函数槽赋值检查比调用检查宽松**——「赋值时宽松兼容、调用时要求精确降级」的组合意味着**能编译过 ≠ 能跑**，运行期校验是最后防线。第八册《工具链》的「三支分工」（怀疑用 tsx / 测试用 vitest / 交付走 ScriptC）在此添第四条：**交付前必须真跑窗口**，编译通过只是入场券。

## 6. Linux 未实测的诚实声明

macOS arm64 全程实测；Linux 通道（X11/Wayland 的 raylib 后端）未跑——工具链层面 scriptc-raylib 的 Linux 构建未验证（第一册大纲已如实标注）。教学上 Linux 差异主要在：字体候选表（font.ts 的 Noto 优先级在 Linux 更常命中）、事件源的按键码位差（X11 键码 vs raylib 归一）、HiDPI 的分数缩放（Wayland 125% 档）。这三处都是「平台层适配点」，内核零改动——层间合同的兑现。

## 7. 本册小结

- mini-gui 全栈一套逻辑坐标，DPI 由 raylib 吸收——内核零缩放分支是「坐标合同唯一」的红利，代价是无亚像素通道
- DPI 变化在真实框架要失效字形/图片缓存；教学版无需失效（没有 DPI 物化层）
- 单窗口教学版的多窗口替代：Dialog=窗口内 Overlay；合成器边界 = 第六册 blit 的对照面
- platform/ 四件职责总账 + 环境开关四件套 = 回归工具链的宿主侧
- demo08 三条 ScriptC 新边界：字段函数局部调用、闭包 as→instanceof、**槽位返回型精确匹配（能编译≠能跑）**——交付前必须真跑窗口
- Linux 未实测如实声明；差异全在平台层适配点，内核零改动

## 附录 A：环境开关的实现（core/config.ts）

```ts
export function envNumber(name: string, fallback: number): number {
  const raw = process.env[name];
  if (raw === undefined) return fallback;
  const v = Number(raw);
  return Number.isFinite(v) ? v : fallback;
}
```

四开关全走它：`MINI_GUI_SECONDS/FPS/SHOT`（SHOT 是字符串直取）。设计要点：**非法值回退默认而非抛错**——回归脚本传错参数不该让窗口闪退（CI 里表现为超时更难查）。回退即「参数无效时的行为可预期」。

## 附录 D：RaylibEventSource 的轮询循环

```ts
  poll(): UiEvent[] {
    const events: UiEvent[] = [];
    while (true) {
      const key = GetCharPressed();            // 字符级（产生文本的键）
      if (key === 0) break;
      events.push(keyEvent(0, key, now()));
    }
    while (true) {
      const k = GetKeyPressed();               // 键码级（功能键）
      if (k === 0) break;
      events.push(keyEvent(0, k, now()));
    }
    ... // 鼠标：位置/按键/滚轮 → pointer/wheel 事件
    return events;
  }
```

轮询而非回调（第五阶段的输入抽象决策）：**事件到达的时序由框架帧循环决定**——回放/录制天然可行（05 册）。双循环的顺序（字符先于键码）保证文本键优先产生编辑语义。

## 附录 E：多窗口的纸面方案（两窗两 owner）

教学版单窗口的多窗扩展纸面稿：每窗口独立 `{ RaylibBackend, PipelineOwner, root }` 三元组 + 一个窗口管理器分派 raylib 事件到对应窗口（按 GetWindowXxx 归属）——「窗口 = 渲染树 + 事件流 + 呈现面」的三元组概念。难点不在内核（每树独立 owner 天然支持），在**焦点跨窗口**（FocusManager 要按窗口分域）与**共享字体图集**（跨窗复用需 backend 共享）。纸面到此——工程化是另一个项目的事。

## 附录 F：macOS 窗口栈对照（我们的 replay 在哪一层）

```text
真实栈：App 内容 → Core Animation 事务 → WindowServer 合成 → 屏幕
mini-gui：App 内容 → 根图层 replay → raylib（GL/Metal 兼容层）→ WindowServer → 屏幕
```

我们的「合成」（blit 命令拷贝）发生在 replay 之前的 CPU 侧；WindowServer 看到的始终是一张不透明窗口缓冲。第六册的诚实账本在此补全：**blit 省的是我们自己的 CPU 工作，窗口合成全程由系统做**——两个「合成」是不同层的同名物。

## 附录 G：分数缩放推演（Wayland 125% 档）

整数倍（2x）时「逻辑 × 2 = 物理」无损；125% 档暴露所有隐藏假设。设逻辑 800×450、scale 1.25：

```text
物理帧缓冲：800 × 1.25 = 1000 ✓；450 × 1.25 = 562.5 → 物理像素必须整数 → 562 或 563（平台 API 各有取舍）
鼠标坐标：合成器给物理坐标，框架除以 scale 回逻辑系——乘除互逆，逻辑系无损；
          但合成器吸附到物理整数格：逻辑 x=101.6 → 物理 127 → 回读 101.6 ✓（1.25 = 5/4，五格一循环）
hairline：0.5 逻辑 px 描边 = 0.625 物理 px → 抗锯齿摊在两个物理像素上各半——「1x 糊、2x 锐、125% 半锐」
文本：字形图集按 1.25 物化（32px 底字形 → 40px 物理），advance 全变——TextLayout 缓存键必须含 scale
```

自测 2 的完整答案落在这里：DPI 热切换要失效的是**一切按 scale 物化的缓存**——字形图集（第三阶段 font.ts 的字形纹理）、TextLayout（advance 变了，缓存键失效）、图片资源；**不用失效**的是布局结果与图层（逻辑几何没变，宿主呈现时才缩放）。判据一句话：**缓存键里含物理量的才要失效**——这条判据比逐项背清单可靠。

## 附录 H：轮询 vs 回调：事件模型对照表

附录 D 循环背后的第五阶段决策，完整论证表：

| 维度 | 轮询（本框架） | 回调（GLFW/浏览器式） |
|---|---|---|
| 事件时序 | 帧循环决定（帧首批量取走） | OS 决定（随时插入线程） |
| 重入风险 | 无（一帧内是有限事件集合） | 有（回调里改树 → 立即又触发事件） |
| 回放/录制 | 天然（poll 的输入就是数组） | 要拦截层（hook 每个注册点） |
| 事件合并 | 免费做（帧内鼠标 move 合并） | 难（每个回调各自节流） |
| 延迟 | 最多一帧（16ms） | 即时 |
| 适用 | 游戏循环 / 教学框架 | 即时响应型工具应用 |

延迟一帧是轮询的真实代价——raylib 本身就是轮询式（GetKeyPressed 取队列），本框架在它之上抽象，两层同构。**教学选轮询的决定性理由是「回放零成本」**：事件源是接口，测试自造数组当源——05 册回放三纪律的物理基础在这张表里。

## 附录 I：事件录制器的纸面设计（回放的另一半）

05 册回放假设「测试自造事件数组」；真实调试要**录制现场**再回放：

```text
录制格式（JSONL，每行一事件）：
  {"t": 16.6, "kind": "key",   "phase": 0, "code": 72, "mods": 0}
  {"t": 33.2, "kind": "wheel", "dy": 1, "x": 200, "y": 120}
录制点：RaylibEventSource.poll 返回前一次 Hook——轮询模型只有一个口
回放：FileEventSource implements EventSource——poll 逐帧吐出 t ≤ 帧时钟的事件
确定性三要点：①帧时钟与事件 t 同源（都用虚拟时钟，别混 wall clock）；
             ②随机性（动画 seed）随录制文件存 seed 字段；
             ③resize 不录（教学版窗口固定，真实版录窗口尺寸变更事件）
```

工作量的真实分布：Hook 一处（轮询的红利）+ FileEventSource（约 30 行）+ 虚拟时钟注入（`frame(dt)` 本来就是 dt 驱动——第一阶段地基的再次兑现）。对照回调模型的录制（hook 每个 addEventListener 注册点 + 重放竞态），工作量差一个量级——**「可回放」不是测试功能，是事件架构的属性**。

## 附录 J：跨平台键码差异的对照账（§6 适配点的展开）

| 事件 | macOS（实测口径） | Linux 风险点 |
|---|---|---|
| 字符键 | GetCharPressed（Unicode 码点） | 同 API；但 fcitx/ibus 桌面可能拦截——字符变空（IME 通道缺席的另一种表现） |
| 功能键 | GetKeyPressed（raylib 归一码） | 键盘布局变码位——raylib 已归一，风险低 |
| 修饰键 | 内部位标志 | Wayland 合成器接管全局快捷键时事件不上达 |

归一化责任已由 raylib 承担（「平台层适配点」的含义）——本框架的 259/262 等常量在 Linux 同值。真正要写平台分支的是 **IME 通道**（preedit 事件 raylib 不透传）——这也是 §6 的三处适配点里没有 IME 的原因：它不是「跨平台差异」，是两边同样的缺席（02 册边界表的跨平台一致缺口）。

## 附录 M：窗口生命周期时序（initWindow 之外的另一半）

```text
initWindow(W, H)
  ├─ 每帧：windowShouldClose() ? ── true ──→ 退出循环
  ├─ events.poll() → 分发 → owner.frame()
  ├─ （MINI_GUI_SECONDS 到点）→ takeScreenshot(SHOT)   ← 必须在 closeWindow 之前
  └─ closeWindow()
```

帧内五步的顺序账（错一步的现象都可实测）：

| 顺序 | 动作 | 顺序错误时的现象 |
|---|---|---|
| 1 | windowShouldClose 检查 | 放最后 = 多画一帧才退（无害但帧数对不上） |
| 2 | poll + 分发 | 事件先于帧到达的处理（本框架帧首批量取，天然一致） |
| 3 | owner.frame() | — |
| 4 | takeScreenshot（末帧内） | **endDrawing 之后截 = 纯清屏**（第六阶段 demo 踩过，注释保留） |
| 5 | closeWindow | 先 close 再截 = 崩溃或空图 |

教学版没有显式处理的四件事（各注「教学版不接 + 真实行为」）：①**resize**（教学版窗口固定；真实框架 resize → 根 markNeedsLayout 全树重排——06 册千盒冷帧 2.85ms 就是 resize 帧的成本预估）；②**多显示器迁移**（逻辑坐标不变、DPI 可能变——附录 G 热切换清单的触发场景）；③**最小化**（raylib 帧循环照跑、无输出；真实框架挂起渲染只保事件轮询）；④**关闭中态**（点 X 到 shouldClose 返回 true 之间还有半帧——截图开关恰好利用了这个末帧窗口）。平台账到此收口：每一条真实行为都有教学版的确切替代或如实缺席。

## 附录 N：DPI 与坐标术语速查

| 术语 | 含义 | 本框架落点 |
|---|---|---|
| devicePixelRatio | 物理/逻辑比值（2x、1.25） | raylib 吸收，内核不见 |
| 逻辑像素（CSS px / dp / pt） | 设计坐标系 | 全栈唯一坐标系 |
| 物理像素 | 帧缓冲真实像素 | 仅宿主呈现侧 |
| hairline | 亚像素描边 | 无显式通道（§1 后果清单） |
| 分数缩放 | 非整数比值（125%/150%） | 附录 G 推演 |
| DPI 热切换 | 运行中跨显示器/改缩放 | 附录 G 失效判据 |
