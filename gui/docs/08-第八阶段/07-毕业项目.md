## 1. 选题决策表

| 选题 | 主考能力 | 依赖阶段 | 适合谁 |
|---|---|---|---|
| A 文件浏览器 | 布局（树+列表）、滚动、虚拟列表、主题 | 二三四六八 | 想把「布局+失效」练成肌肉记忆 |

决策判据（06 册能力地图）：毕业项目应当**把至少一个两星推上三星**——A 推控件库/虚拟化、B 推响应式、C 推文本。三个都推不动「全栈框架」幻觉，选一个深耕。

## 2. 选题 A：文件浏览器（需求书）

**功能面**：目录树（左，可折叠）+ 文件列表（右，虚拟滚动）+ 路径栏（TextField 只读）+ 主题切换。

```text
布局树：row[ 树面板(flex 1, boundary), 分隔条, 列表面板(flex 2, virtual-list) ]
        列表面板：column[ 路径栏(TextField), VirtualList(行高 28, 文件行) ]
数据：文件系统扫描（demo 用内存目录树桩；真实 IO 是宿主层扩展）
```

| 里程碑 | 内容 | 验收断言 |
|---|---|---|
| M1 | 目录树组件（递归折叠） | 折叠/展开后失效账：layout 只在树面板边界内；无头像素探针断行展开标记可见 |
| M2 | 文件列表接虚拟列表 | 10000 文件目录 liveRows ≤ 视口/行高+2；滚动帧 repainted=1 |
| M3 | 双面板联动（点击树 → 列表换目录） | 事件回放：click 树节点 → items.set → keyed 协调 waves+1 |
| M4 | 主题切换 | 切换波后 repainted 只在变色控件所在边界；树身份保留（keyed） |

**考察能力映射**：M1=四阶段布局协议+六阶段失效；M2=八册虚拟列表（哨兵双判/池行记账两个实抓 bug 的现场复用）；M3=七阶段事件→信号→协调闭环；M4=主题 token+同值守卫。

## 3. 选题 B：todo 应用（需求书）

**功能面**：输入框（回车添加）+ 待办列表（勾选/删除）+ 过滤（all/active/done）+ 计数（剩余 N 项）+ 完成动画（划线渐变）。

```text
状态：todos: SignalList<Todo>、filter: SignalN、（derived）remaining = computedN
视图：column[ input(TextField), filterRow(3 按钮), todoList(VirtualList 或 Flex), statsRow(Text) ]
```

| 里程碑 | 内容 | 验收断言 |
|---|---|---|
| M1 | 添加/删除/勾选（signals+keyed） | 事件回放全流程；keyed 断言（删除中间项其余身份不变）；waves 计数与状态变更 1:1 |
| M2 | 过滤三态 | derived 过滤：列表协调只增删不改留项身份；计数文本细粒度 setText |
| M3 | 完成划线动画 | AnimatedValue（透明度/删除线进度）；动画只走 paint 通道（06 册「动画不动布局」验证） |
| M4 | diamond 断言 | remaining 依赖 todos+filter：同波变更 remaining 恰算一次（signals.test 的 diamond 模式迁移） |

**考察能力映射**：M1=七阶段全闭环；M2=computed 惰性+条件依赖；M3=动画系统（05 册「tick 返回值当到点信号」）；M4=glitch-free 实证。B 是「第七阶段毕业」最短路径。

## 4. 选题 C：简易文本编辑器（需求书）

**功能面**：多行编辑（行虚拟滚动）+ 行号栏 + 光标/键盘全集 + 状态栏（行:列）。

```text
模型：行数组 lines: SignalList<string> + 光标 (line, col)
视图：row[ 行号列(虚拟列表，同步滚动), 编辑区(自定义多行控件) ]
```

| 里程碑 | 内容 | 验收断言 |
|---|---|---|
| M1 | 单行编辑升级为多行（Enter 拆行/Backspace 并行） | 行数组断言 + 光标跨行移动回放 |
| M2 | 行号栏虚拟滚动（与编辑区滚动同步） | 万行文件 liveRows 恒定；两面板 scrollTop 一致性断言 |
| M3 | 状态栏行:列实时 | 细粒度 effect（光标信号→setText）；键入时失效账只含状态栏+光标 |
| M4 | IME 边界声明 | 02 册边界表的落地版：ASCII 全键盘可达，CJK 走系统输入法的降级方案写进 README |

**考察能力映射**：M1=文本模型（第三阶段断行器的消费端）；M2=虚拟化+滚动同步（双面板一致性是最难的失效题）；M3=细粒度信号；C 是「两星推三星」的正餐，工作量最大。

## 附录 B：选题 B 的 signals 测试迁移模板

把 `signals.test.ts` 的 diamond 模式迁移到 todo 的 remaining 计数（M4 验收的直接写法）：

```ts
it("remaining：todos 与 filter 同波变更，恰算一次（diamond 迁移）", () => {
  const todos = new SignalList(["a", "b", "c"]);
  const filter = new SignalN(0);                       // 0=all 1=active
  let runs = 0;
  const remaining = computedN(() => {
    runs += 1;
    void filter.get();                                 // 依赖两者
    return todos.get().length;
  });
  effect(() => void remaining.get());
  const before = runs;
  batch(() => { todos.set(["a", "b"]); filter.set(1); });  // 同波两个上游变
  expect(runs).toBe(before + 1);                       // 恰一次——glitch-free 的验收形式
});
```

「同波双上游变、下游恰算一次」是第七阶段机制在业务代码里的标准验收句式——照抄即可。

## 附录 C：选题 C 的多行文本模型（数据结构与光标规范）

```ts
// 模型：行数组 + 规范化光标（教学版最小集）
interface Cursor { line: number; col: number }
const lines = new SignalList([""]);
function normalize(c: Cursor): Cursor {                // 任何移动后都调一次
  const L = Math.max(0, Math.min(c.line, lines.get().length - 1));
  const lineLen = (lines.get()[L] ?? "").length;
  return { line: L, col: Math.max(0, Math.min(c.col, lineLen)) };
}
// 四个编辑原语（每个返回新行数组 + 新光标）：
// insertChar(c, ch) / backspace(c)（行首→与上一行合并）/ deleteFwd(c) / splitLine(c)（Enter）
```

设计要点三条：①**光标规范化集中一处**（移动/编辑后都过 normalize——避免「光标悬在不存在的列」）；②**行合并/拆分是数组级操作**（splice）——触发 lines.set → 行号栏与编辑区的 keyed/虚拟化协调；③**col 用 UTF-16 码元**（与第三阶段 offsetToX 的 offset 同单位）——emoji 等代理对在教学版会拆坏（IME 边界表的同一限制）。

## 附录 F：评审十问（答案要点）

1. **为什么 idle 帧这么便宜？**——欠活清单两队列为空 + 布局缓存短路（0.014ms 实测）。
2. **虚拟列表的池为什么只增不减？**——回落复用；销毁重建贵于保留。
3. **keyed 协调 O(n²) 能接受吗？**——千项内 1ms 量级；超了换 key→index 映射。
4. **signals 的 diamond 怎么保证恰一次？**——seen 去重 + 惰性读取时全量重算。
5. **焦点为什么要双面同步？**——管理器引用（路由用）+ 节点标志（控件守卫用）；只有一面即 demo08 缺陷。
6. **blit 是真合成吗？**——命令拷贝，省 paintSelf 不省命令数（06 册诚实账本）。
7. **为什么不做 z-index？**——子序即 z 序；层叠上下文复杂度不值（09 专题 §8）。
8. **ScriptC 最大的坑？**——能编译≠能跑（槽位返回型运行期校验）；交付前必须真跑窗口。
9. **第三道防线为什么是负收益？**——draw call 单价 8ns，求交比重放贵；GPU 后端反转（06 册附录 B）。
10. **再做一遍会改什么？**——文本 shaping 提前到第三阶段立项；焦点双面同步在第五阶段就测集成。

每问的答案都指向册与数字——评审时按「出处 → 源码 → 实测」三段下钻。
