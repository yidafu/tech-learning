## 阶段目标

学完本阶段，你应该能不查资料做到：

- 写出 signals 三原语的内核实现：读时收集依赖、写时按拓扑序传播、每个 computed 一帧只算一次（glitch-free）
- 用 diamond 依赖图解释朴素实现为什么会算两次、层级排序如何修掉它
- 实现函数组件 → RenderObject 树的挂接与最小 reconcile（同位置同类型复用）
- 实现 keyed 列表更新，并说清它与 React keyed diff 在更新粒度上的差别
- 把主题做成 token 表，控件样式全部查表，热切换主题不重建树

## 实践任务清单

1. signals 内核 + 断言：依赖失效正确、diamond 恰好更新一次、effect 清理不泄漏
2. 最小 reconcile + keyed 列表（头插/删除/移动三个场景断言节点复用而非重建）
3. 用声明式 API 重写第五阶段三件套，统计代码量与更新粒度的变化
4. 对照实验：同一个小场景，全量重渲染 vs signals 的更新次数计数对比

## 阶段自测

1. signal 与 computed 的依赖收集分别在什么时机发生？
2. diamond 问题是什么？按层级排序为什么能保证只算一次？
3. 最小 reconcile 靠什么判断复用？类型不同时会怎样？
4. keyed 列表删除中间一项，无 key 与有 key 的更新行为差在哪？
5. 主题切换为什么能做到不重建树？token 查表发生在哪个阶段？
