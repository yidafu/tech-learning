## 1. 一个坐标系：先分清五种布局在解什么问题

五种布局不是五种「风格」，而是五类不同的**几何合同**。给一组子元素和一块画布，先问两个问题就能选对工具：

```text
Q1 子的位置怎么定？
     排队（一个接一个）      → Flow / Flex
     对号入座（看格子的）    → Grid
     贴边（相对父/兄弟）      → Constraint
     报坐标（自己说了算）     → Absolute
Q2 谁在上面？
     按「后画的在上」        → Stack / Z（所有布局共有的第三根轴）
```

```text
父容器 (w × h)
┌────────────────────────────────────────────┐
│ Flow    │ A B C ┆ D E    ← 装不下就换行      │ 排队型：游标推进
│ Grid    │ ┌─┬──┬─┐                            │ 落座型：先解轨道表
│         │ ├─┼──┼─┤   ← 先算「列宽×行高」再入座  │
│         │ └─┴──┴─┘                            │
│Constr.  │ A[8,8]───────B[贴A右缘-贴父右缘]     │ 贴边型：解线性方程
│         │        C[父中心, 50%宽]              │
│ Abs.    │      ┌────┐ ← x/y 是声明值不是算出来的│ 报坐标型：不解方程
│         │      │浮层│                             │
│ Stack/Z │ 底图 → 内容 → 角标   ← 后画的在上      │ 第三轴：z 序
└────────────────────────────────────────────┘
```

一句话版：**Flex/Flow 管「排」，Grid 管「落」，Constraint 管「贴」，Absolute 管「浮」，Stack 管「叠」**。真实应用的界面是五者的组合：页面骨架用 Grid/Flex，卡片内部用 Flow，表单对齐用 Constraint，角标/浮层用 Absolute，遮罩+对话框用 Stack。

## 2. 共同前提：三句话布局协议（第四阶段立起的）

五种算法看起来差异巨大，但它们**全部**跑在同一条协议上（详见 [../04-第四阶段/03-布局协议.md](../04-第四阶段/03-布局协议.md)）：

1. **约束向下**：父给每个子一套 `BoxConstraints`（min/max 宽高区间）——「你最多多大、至少多大」；
2. **尺寸向上**：子在约束内完成自己的子树布局，回报 `{width, height}`；
3. **位置归父**：子的 `x/y` 由**父**写入——子永远不知道自己的绝对位置。

协议带来两个直接推论，每个布局器都必须回答：

- **给子什么约束？** Flex 给「主轴无界松约束」（量自然宽度）；Grid 给「全松 → 列宽紧 → 格紧」三遍递进；Constraint 直接给「解算结果的紧约束」；Absolute（Positioned）给「双边锚定的紧约束或父的松约束」。**约束策略就是布局算法的身份证**。
- **布局是几遍的？** 本专题五种全是**一遍**（depth-first，每子恰好 layout 一次）——除了 Grid 的 auto 轨道（同一子被量三遍：自然尺寸 → 列宽定形 → 格子定形）和 Flow 的 stretch（第二遍紧约束重排）。遍数是布局器最重要的性能账，每一册都会单独记账。

## 4. 手算文化：为什么每册都有「纸上推导」

本专题的验收标准不是「代码能跑」，而是「**你读完能在纸上算出任意输入的布局结果**」。为此每册遵守三条纪律：

1. **算法写成可执行的判定式**——不是「适当排列」这类描述，而是 `cursor + mainGap + w > maxMain` 这种能逐符号代数字的式子；
2. **每个测试先手算再实跑**——`flow.test.ts` 等文件里的注释就是推导过程，期望值全部来自纸面；
3. **边界都给出确定性规则**——空行必收、余数按列序 +1、乱序推入也能解……歧义在规范里就地杀死。

一个自查样本（Flow 册会完整推导）：容器宽 100，子 [60×30, 60×30, 30×30, 40×40]——

```text
i=0: 行空，必收            → 行1=[60]        行宽 60
i=1: 60+0+60=120 > 100     → 封行1，开行2    行2=[60]        行宽 60
i=2: 60+0+30=90  ≤ 100     → 收              行2=[60,30]     行宽 90
i=3: 90+0+40=130 > 100     → 封行2，开行3    行3=[40]        行宽 40
行高 = 30, 30, 40 → 总高 100；lineCount=3
```

四行演算，三个断言（行数/尺寸/坐标）全部落定。这就是五册反复出现的节奏。

## 5. 与其它阶段的关系

- **向上**（声明式）：这五个布局器目前只在 RenderObject 层。声明式层的对接（`vflex()` / `vgrid()` 这类虚拟节点）留作毕业项目扩展——第七阶段的 VElement 模式可以逐个套用。
- **向下**（绘制）：布局产出的 `x/y/width/height` 是 Painter 坐标系里的一切——第二阶段的裁剪烘焙、第六阶段的重绘边界都以「布局之后的盒子」为输入。
- **横向**（事件）：Grid/Constraint 的子可以重叠（Grid 允许 overlap、Stack 本来就是叠的）——命中测试的**逆序试探**保证「后画的先命中」，见 [06 册第 2 节](./06-堆叠分层Stack.md)。
