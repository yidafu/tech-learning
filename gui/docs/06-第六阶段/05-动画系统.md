# 动画系统：值补间、曲线族与帧率无关的推进

> [返回：第六阶段导览](01-导览.md)
> 对应大纲条目：第六阶段 4（Ticker、插值与曲线、状态机、隐式动画）。
> 本册走读 `core/animation.ts`（129 行）与 `scenes/anim-scene.ts` 的 AnimPanel，全部断言来自 `animation.test.ts`（8 条）+ `anim-scene.test.ts`（3 条）实跑。读完你应当能：手算任意曲线在任意 t 的值、推演半路改向的补间轨迹、说清「为什么动画必须用 dt 推进而不用固定步长」。

## 1. 概念坐标：动画 = 值随时间变形

第六阶段的动画系统刻意做小——只有**数值补间**一件核心能力，其余都是它的组合：

```text
曲线 Curve:      [0,1] → 进度（形状；纯函数，可缓存可手算）
显式 Tween:      from→to + duration，start() 后由 tick(dt) 推进
隐式 AnimatedValue: 只改 target，从「当前值」自动补过去（AnimatedContainer 思想）
AnimationHost:   统一 tick，返回「还有几个活的」
```

分工：**驱动在宿主**（每帧 `tick(dt)`，dt 来自 `getFrameTime()`——帧率无关的根源，§6），**形状在曲线**（§3 一张公式表），**状态在补间对象**（§4/§5 两个类的全部状态字段）。

与「动画 = 每帧改一次位置」的区别要一句话说清：改位置是**应用**，不是动画系统；系统只负责「给一个 0→1 的时间轴，吐出该时刻的值」。HUD 的 `repainted 2` 里，动画的份额只有 `markNeedsPaint()` 那一次失效——其余全是第六阶段前几册的失效机器在转。

## 2. 曲线族：六条曲线一张公式表

`Curves`（逐字段，公式 + 形状一句话）：

| 名称 | 公式 | 形状 | 典型用途 |
|---|---|---|---|
| `linear` | `t` | 匀速 | 进度条、与物理模型对接 |
| `easeIn` | `t³` | 先慢后快 | 退出屏幕（先酝酿） |
| `easeOut` | `1 − (1−t)³` | 先快后慢 | 进入屏幕（落到位）——AnimatedValue 默认 |
| `easeInOut` | `t<0.5 ? 4t³ : 1−(−2t+2)³/2` | 两头慢中间快 | 往返位移（demo 的 animX） |
| `easeOutBack` | `1 + c₃·u³ + c₁·u²`，u=t−1，c₁=1.70158，c₃=c₁+1 | 过冲回落 | 按钮弹一下 |
| `elasticOut` | `2^(−10t) · sin((10t−0.75)·2π/3) + 1` | 弹性衰减 | 呼吸、抖动归位（demo 的 radius） |

**手算两个样本**（测试只断言了形状性质；能代数字才算过关）：

```text
easeInOut(0.5) = 4×0.5³ = 0.5            —— 对称点的恒等性（断言 toBeCloseTo(0.5, 9)）
easeOutBack(0.8)：u = −0.2
  c₃·u³ = 2.70158 × (−0.008) = −0.0216
  c₁·u² = 1.70158 × 0.04    = +0.0681
  f = 1 − 0.0216 + 0.0681 ≈ 1.0465 > 1     —— 过冲（断言 toBeGreaterThan(1)）
```

`elasticOut` 依赖 `sin`——`ScriptC 0.0.35` 的 Math 静态没有三角函数，`core/math.ts` 自带泰勒展开 sin（第三阶段的欠账在这里兑现，文件注释原文「0.0.35 无 Math.sin——elastic 用自带 sin」）。端点归一（`f(0)=0、f(1)=1`）对所有六条曲线用同一条断言锁死（`animation.test.ts` 第一条：tolerance 1e-9）——换曲线族时这条测试是第一道闸。

**ScriptC 边界一处**：`Curves` 里 `2 ** (-10 * t)` 用的 `**`（幂）——0.0.35 支持字面量 `**` 但 `Math.pow` 不在静态白名单，写法要选对。

## 3. Tween：显式补间与「完成回调恰一次」

状态字段就五个：`from / to / duration / curve / elapsed`，外加 `running` 与两个可空函数槽（`onUpdate / onComplete`——ScriptC 规矩：可空而非可选，事件区同款）。

`tick` 逐字：

```ts
  tick(dt: number): boolean {
    if (!this.running) return false;
    this.elapsed += dt;
    const t = clamp(this.elapsed / this.duration, 0, 1);
    const v = lerp(this.from, this.to, this.curve(t));
    const fn = this.onUpdate;
    if (fn !== null) fn(v);
    if (t >= 1) {
      this.running = false;
      const done = this.onComplete;
      if (done !== null) done();
    }
    return this.running;
  }
```

四条时序规则（`animation.test.ts` 逐条锁死）：

| 规则 | 推演 | 断言 |
|---|---|---|
| 值序列按曲线插值 | Tween(0→10, 1s)：tick(0.25)×2 → elapsed=0.5 → v=lerp(0,10,linear(0.5))=**5** | `toBeCloseTo(5, 9)` |
| 到点即停，终值精确 | 再 tick(0.5) → t=1 → v=**10**，返回 false | `toBe(10)` + 返回 false |
| onComplete **恰一次** | 到点那一帧触发；后续 tick 直接被 `!running` 挡住 | `completed === 1` 且再来一次 tick 后 values 仍 3 条 |
| duration=0 立即到终点 | tick 一次 → t=clamp(0.016/0)=1 → v=to | `last === 5`、返回 false |

**返回值语义**是本设计的枢纽：`tick` 返回「是否仍在活动」。宿主拿它统计活动数，活动数为 0 的帧理论上可以跳过失效直接呈现（`AnimationHost.tick` 的活，§7）。

**易错点一处**：`start()` 之后必须 `tick` 才动——`start` 只重置 elapsed 与 running，不推任何值。想在挂上时立刻是起点，得自己调 `onUpdate(from)` 或等第一帧 tick（首帧 dt 大，一次就到位——`《02》`的尖峰免疫结论在这里的机制根源）。

## 4. AnimatedValue：隐式补间与「半路改向」

隐式补间把「目标变了」当作唯一 API（逐字）：

```ts
  /** 设新目标：从「当前值」起补（半路改向不停顿）。 */
  set(target: number): void {
    if (target === this.target && !this.active) return;
    this.from = this.current;   // ← 关键：from 抢救成「此刻值」
    this.target = target;
    this.elapsed = 0;
    this.active = true;
  }
```

**半路改向**是隐式动画的灵魂，手算一遍（测试用例逐字推演，linear 曲线 1 秒 0→100）：

```text
set(100)          → from=0,  target=100
tick(0.25)        → current = lerp(0, 100, 0.25) = 25
set(0)            → from=25（不是 0！）, target=0, elapsed=0
  ——此刻 current 仍是 25，无跳变 ✓（断言 toBe(25)）
tick(0.5)         → current = lerp(25, 0, 0.5) = 12.5   （断言 toBeCloseTo(12.5, 6)）
```

如果 `set` 里 `from = this.from`（新手常见错误），改向瞬间会**跳回起点再补一次**——视觉上是「抽搐」。`from = this.current` 一行就是全部秘密。同值 `set` 短路（`target === this.target && !this.active`）防止无意义的重置（测试第三条：`set(7)` 后 tick 返回 false）。

AnimatedValue 比 Tween 少了 `onUpdate/onComplete` 槽——隐式动画的消费者通常在**每帧 paintSelf 里直接读 `current`**（AnimPanel 就这么用，§6），不需要逐值回调。

## 5. AnimationHost：统一 tick 与活动计数

```ts
  tick(dt: number): number {
    let active = 0;
    for (const t of this.tweens) {
      if (t.tick(dt)) active += 1;
    }
    return active;
  }
```

三条规则：顺序推进（不排序——补间互不依赖）、返回活动数、**到点的动画留在表里**（下帧 tick 被 `!running` 挡住，O(表长) 的空转）。测试：两个 Tween（0.5s / 1s）同时开跑，`host.tick(0.5) === 1`（a 到点停）、再 tick 半秒 → 0。

教学版不做的事，如实列：**无移除 API**（长会话表会涨——工程化时加 `remove()` 或完成后自摘）、**无优先级/暂停单条**、**无 speed 缩放**。每一条都是 ABI 决策，不是遗漏。

## 6. AnimPanel：隐式动画的组装现场

`anim-scene.ts` 的动画面板（逐字，省布局）：

```ts
class AnimPanel extends RenderObject {
  private animX = new AnimatedValue(10, 0.6, Curves.easeInOut);
  private radius = new AnimatedValue(20, 1.2, Curves.elasticOut);
  private xDir = 1;

  /** 每帧推进（dt 秒）；到位自动反向。 */
  tick(dt: number): void {
    if (!this.animX.tick(dt)) {
      this.xDir = -this.xDir;
      this.animX.set(this.xDir > 0 ? 10 : 200);
    }
    if (!this.radius.tick(dt)) {
      this.radius.set(this.radius.target > 25 ? 18 : 30);
    }
    this.markNeedsPaint();
  }

  protected paintSelf(p: Painter): void {
    p.fillRoundedRect({ x: 0, y: 0, width: this.width, height: this.height }, 10, PALETTE.surface);
    p.fillRect({ x: this.animX.current, y: 40, width: 60, height: 60 }, PALETTE.accent);
    p.fillCircle(230, 140, this.radius.current, PALETTE.ok);
  }
}
```

三个组装要点：

**① tick 返回值当「到点信号」用**。`if (!animX.tick(dt))` ——返回 false 即动画结束，当场反向 `set(另一端)`。**隐式补间 + 到点改目标 = 往返动画**，不需要独立的「ping-pong 模式」开关。手算轨迹（easeInOut 0.6s，10↔200）：0.6s 去程 → 到点翻转 → 从当前值（=200，t=1 精确到点）反向 0.6s → 循环。`xDir` 记方向，`set` 的目标在 10/200 间切换——状态机总共一个布尔。

**② paintSelf 直接读 `current`**。动画的值不是状态的一部分，是**读数**：面板没有为动画设任何脏标记字段，`tick` 末尾统一 `markNeedsPaint()`（每帧一次，节制且足够——§8 的失效账）。布局完全不动（`isFixedSize=true`，尺寸 300×200 写死）——**动画只走绘制通道**，这是「动画不动布局」的示范：尺寸/位置动画若走布局通道，每帧 layoutFlush 会连累整行兄弟。

**③ 每帧 markNeedsPaint 是有意的浪费吗**？不是——但也不精确。逐帧失效发生在面板子树（`RenderRepaintBoundary` 包着它，`《04》`的收益算术），失效半径限于一棵 3 命令的子树。更精细的做法是「AnimatedValue.current 变了才标脏」——比较 `this.current !== prev`，静止时（两动画都到位的间隙）可以省掉 markNeedsPaint。教学版选了粗糙版：一行代码，收益场景（动画本来就常动）覆盖 99% 时段。

## 7. 接线：dt 从哪来、tick 谁调

完整链路（`apps/06-pipeline.ts` + `anim-scene.ts`）：

```text
宿主循环 getFrameTime() → dt（上一帧耗时，秒）
  → scene.frame(dt, hudText)
      → animPanel.tick(dt)        动画推进 + markNeedsPaint
      → hud.setText(...)          markNeedsLayout
      → owner.frame()             flushLayout → flushPaint（消化两种脏）
  → rootLayer.replay(backend)     呈现
```

**dt 驱动 = 帧率无关**。30fps 与 120fps 下动画速度一致的算术：到位所需 tick 次数不同（30fps 跑 18 帧、120fps 跑 72 帧），但 Σdt 都 ≈ 0.6s——elapsed 按真实时间累加，帧率只决定采样密度。反例（第一阶段踩过）：固定步长写法 `animX.tick(1/60)` 在 30fps 下动画慢一倍。dt 的尖峰免疫也复述一次：首帧 dt 大 → elapsed 一步跨过半程 → 位移大步到位，肉眼无跳变。

`AnimationHost` 在 demo 里其实**没接线**（AnimPanel 自己管理两个 AnimatedValue）——host 是给「多个动画源」的宿主准备的（比如第八阶段控件库的光标闪烁 + 长按计时）。教学版的取舍：场景对象自己 tick 自己的动画，host 留作多源统一入口。

## 8. 实跑：测试断言清单

`animation.test.ts` 8 条 + `anim-scene.test.ts` 3 条（2026-11-14 实跑，15/15 绿，含 pipeline 7 条）：

```text
✓ 曲线族：端点归一 f(0)=0、f(1)=1（六条曲线同一断言，1e-9）
✓ 单调性与过冲：easeIn(0.5)<0.5、easeOut(0.5)>0.5、easeOutBack(0.8)>1、easeInOut(0.5)≈0.5
✓ Tween：值序列/终值精确/完成回调恰一次/停了不动（values.length===3 锁死）
✓ duration=0：一 tick 到终点
✓ AnimatedValue：到点即停（current 精确 =100）
✓ 半路改向：25 → set(0) 无跳变 → tick 半秒 = 12.5
✓ 同值 set 不触发
✓ AnimationHost：活动数递减到 0
✓ anim-scene：动画面板 tick 后 hud.setText → frame 后 hud 文本进根图层（无头断言）
✓ anim-scene：静态面板图层对象引用不变（blit 的证明——图层没被重录）
✓ anim-scene：frame 返回 repaintedNodes
```

其中「静态面板图层引用不变」是本阶段最有价值的一条断言：它锁的是**合成路径**（`flushPaint` 没碰干净边界），等价于「静态面板的 paintSelf 只在首帧跑过一次」。

## 9. 与其他框架的对照

| 机制 | mini-gui | Flutter | 浏览器 |
|---|---|---|---|
| 显式补间 | `Tween` + 手动 tick | `AnimationController` + `Tween`（同构，多了 vsync 绑定） | WAAPI `Animation` |
| 隐式补间 | `AnimatedValue.set` | `AnimatedContainer` 系隐式 widget | CSS transition |
| 曲线 | `Curves` 函数族 | `Curves`（几乎同名：easeInOut/easeOutBack 全对得上） | `cubic-bezier()` / `steps()` |
| 驱动 | 宿主每帧 `tick(dt)` | `Ticker` 由 `SchedulerBinding` vsync 驱动 | 合成器时钟（transform/opacity 可跳过主线程） |
| 到点信号 | `tick` 返回 false + `onComplete` | `.whenComplete()` / 状态监听 | `transitionend` 事件 |
| 弹簧物理 | 无（多项式曲线族） | `SpringSimulation` 一等公民 | 无原生（WAAPI spring 提案） |

一个值得复述的映射：**CSS transition ≈ AnimatedValue**——「改目标属性，浏览器自动补」与「set(target) 自动从当前值补」是同一思想；CSS 没有「读取当前进度」的一等公民，而 `AnimatedValue.current` 让你在 paintSelf 里直接读——这正是自绘框架比 CSS 可控的地方（demo 的圆半径呼吸，CSS 做不出「半径参与命中计算」的联动）。

## 10. 本册小结

- 动画系统 = 曲线（纯函数）+ 显式 Tween（状态机：elapsed/running）+ 隐式 AnimatedValue（from=current 的半路改向）+ 宿主统一 tick
- 六条曲线一张公式表；端点归一是换曲线族的第一道闸；easeOutBack(0.8)≈1.0465 手算过冲；elasticOut 依赖 math.ts 自带 sin（ScriptC 0.0.35 无 Math.sin）
- Tween 四规则：值序列按曲线插值、到点即停且终值精确、onComplete 恰一次、duration=0 一步到位
- AnimatedValue 的全部秘密在 `set` 的一行：`from = this.current`（半路改向不跳变）；同值 set 短路
- tick 返回「还在活动吗」→ 宿主活动计数 → 全静止帧理论上可跳过失效直呈
- AnimPanel 示范三件事：tick 返回值当到点信号（往返状态机一个布尔）、动画只走绘制通道（isFixedSize + markNeedsPaint）、paintSelf 直接读 current
- dt 驱动帧率无关：30/120fps Σdt 相同；首帧尖峰一步到位；固定步长写法是反面教材
- 诚实清单：host 无移除 API、无弹簧物理、demo 未接 host——每条是取舍不是遗漏

## 附录 A：采样序列手算——30fps 下的 easeInOut

「帧率无关」不该停在口号，代数字走一遍。`animX = AnimatedValue(10, 0.6, easeInOut)`，30fps 的 dt≈0.0333s：

```text
tick 1: elapsed=0.0333  t=0.0556  easeInOut=4×0.0556³=0.00069  v=10+190×0.00069=10.13
tick 2: elapsed=0.0667  t=0.1111  easeInOut=4×0.00137=0.0055   v=11.04
tick 3: elapsed=0.1000  t=0.1667  easeInOut=4×0.00463=0.0185   v=13.52
...
tick 18: elapsed=0.6    t=1      easeInOut=1                    v=200 ✓ 到点反向
```

同一动画在 120fps 下跑 72 tick，每个 tick 的 t 步长只有 1/72——采样密 4 倍，**但 Σ(t·曲线) 走过的形状完全相同**，0.6s 到点的时刻不变。这就是「elapsed 按真实时间累加」的全部含义。手算 tick 1~3 还能看到 easeInOut 的形状：前 1/10 时间只走了 0.7% 的路——慢启动在数字上长这样。

## 附录 B：Tween vs AnimatedValue 选型表

| | Tween | AnimatedValue |
|---|---|---|
| API 风格 | 命令式：from/to/duration 全显式，start() 启动 | 声明式：只 set(target) |
| 起点 | 调用者指定 from | 自动取「当前值」 |
| 半路改向 | 重开一个 Tween（或自己写接力） | 内建：from=current 不跳变 |
| 到点信号 | tick 返回值 + onComplete | tick 返回 false |
| 适用 | 编排（A 完了接 B）、精确控制轨迹 | UI 属性「想要它变成 x」 |
| demo 中的角色 | 第八阶段控件库（按下态补间） | AnimPanel 的位移/半径 |

选择口诀：**编排用 Tween，属性用 AnimatedValue**。两者共享曲线族与 tick 协议，可以互换底层——AnimatedValue 内部其实就是一个「每次 set 重开」的 Tween，读源码时对照 §3/§4 可互相印证。


## 附录 C：elasticOut 全程手算（六帧采样）

elasticOut 是六条曲线里唯一带 sin 的，完整代一遍数字（c₄ = 2π/3 ≈ 2.0944）：

```text
f(t) = 2^(−10t) × sin((10t − 0.75) × 2.0944) + 1

t=0.1: 2^(−1)=0.5      相位=(1−0.75)×2.0944=0.5236   sin=0.5   → 0.5×0.5+1=1.25
t=0.2: 2^(−2)=0.25     相位=1.25×2.0944=2.618        sin=0.5   → 0.25×0.5+1=1.125
t=0.3: 2^(−3)=0.125    相位=1.9635                   sin=0.924 → 0.1155+1=1.115
t=0.5: 2^(−5)=0.03125  相位=3.4034                   sin=−0.26 → −0.008+1=0.992
t=0.7: 2^(−7)=0.0078   相位=5.4978                   sin=−0.71 → −0.0056+1=0.994
t=1.0: 端点直通 = 1（源码特判 t===1）
```

读数：前 0.2 冲过头到 1.25（sin 正半周 + 衰减慢），0.3 附近仍在 1.1 上方，0.5 后首次跌破 1（sin 转负），之后微幅回归——「弹性衰减」在数字上是 **指数包络 × 正弦** 两个因子的乘积。demo 里 radius 用它做呼吸，1.25 倍的初始过冲让圆「弹出去再收回」——曲率可见地映射到了像素半径。

## 附录 D：duration=0 的三个后果

`duration === 0` 在 `tick` 里是个边界雷区，逐行推演（`t = clamp(elapsed / duration, 0, 1)`）：

```text
elapsed=0.016, duration=0 → 除零？TS 数字除法：0.016/0 = Infinity → clamp(∞,0,1)=1 → 一步到终点 ✓
onUpdate 恰好触发一次（t=1 的值 = to），onComplete 同帧触发
返回 false（!running）——本帧即完成，宿主活动数不含它
```

三个后果：①除零在 JS 里不是崩溃而是 Infinity，clamp 收容——这是唯一能让「除零自然语义」成立的原因，换语言（Rust/C）必须显式判零（教学版靠 TS 的数字语义白赚了一层防御，注释里写明）；②「零时长动画」等价于直接赋值 + 一次失效——组件库的「无动画模式」可以复用同一条路径；③`AnimatedValue.set` 对 duration=0 的隐式行为是「下一帧就位」，即视觉上无动画但有失效——引擎侧不区分。
