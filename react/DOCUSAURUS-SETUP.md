# Docusaurus 站点搭建手册（跨项目复刻用）

> 来源：本仓库（React 高阶学习课程文档站）的完整配置过程，2026-11-05，Docusaurus 3.10.2 / Node 24 / npm 11。
> 目标：在任何"一堆 Markdown 内容"的仓库里，约 30 分钟复刻同款文档站。
> 按顺序做即可；第 4 节插件按需选装。

## 0. 目录决策

站点根 = 仓库根（不建 `website/` 子目录）。内容目录移入 `docs/`，**备份/工具类目录留在 docs 外**（否则会被当作文档编译、产生死链和噪音页面）。

```text
repo-root/
├── package.json  docusaurus.config.js  sidebars.js  babel.config.js  .gitignore
├── docs/                 # 全部内容（每个子目录 = 侧边栏一个分类）
│   └── 某内容目录/
│       ├── README.md     # 该分类的索引页（Docusaurus 约定：README.md 自动成为分类索引）
│       ├── 01-xxx.md     # 文件名数字前缀 = 侧边栏顺序
│       └── _category_.json  # { "position": N } 控制分类在侧边栏的排序
├── src/pages/index.js    # 站点首页
├── src/css/custom.css
├── src/components/       # 供 MDX 静态嵌入的 React 组件
└── static/               # 静态资源（图片等）
```

## 1. 手工脚手架（5 个文件，不用 create-docusaurus）

不用 `npx create-docusaurus`：交互式、要求空目录、生成的 demo 还要删。直接手写这 5 个文件更快更干净。

### 1.1 package.json

版本号写 `^3.10.2`（或装的时候让 npm 解析 latest 3.x）：

```json
{
  "name": "my-doc-site",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "dev": "docusaurus start",
    "build": "docusaurus build",
    "serve": "docusaurus serve",
    "clear": "docusaurus clear"
  },
  "dependencies": {
    "@docusaurus/core": "^3.10.2",
    "@docusaurus/preset-classic": "^3.10.2",
    "react": "^19.1.0",
    "react-dom": "^19.1.0"
  },
  "devDependencies": {
    "@babel/preset-env": "^7.26.0",
    "@babel/preset-react": "^7.26.0"
  },
  "browserslist": {
    "production": [">0.5%", "not dead", "not op_mini all"],
    "development": ["last 3 chrome version", "last 3 firefox version", "last 5 safari version"]
  },
  "engines": { "node": ">=18.0" }
}
```

### 1.2 docusaurus.config.js

```js
// @ts-check

// plugins 里按需增删（第 4 节）；不装插件就保持 []
const sitePlugins = [];

/** @type {import('@docusaurus/types').Config} */
const config = {
  title: '站点标题',
  tagline: '一句话副标题',
  url: 'https://example.com',   // 占位，部署时替换
  baseUrl: '/',

  // 中文内容站点：默认语言即中文，无需 i18n 目录
  i18n: { defaultLocale: 'zh-Hans', locales: ['zh-Hans'] },

  onBrokenLinks: 'throw',

  presets: [
    [
      'classic',
      /** @type {import('@docusaurus/preset-classic').Options} */
      ({
        docs: { sidebarPath: require.resolve('./sidebars.js') },
        blog: false,
        // ⚠️ 必须注册，否则 src/css/custom.css 根本不会被打包（不报错、静默失效）
        theme: { customCss: require.resolve('./src/css/custom.css') },
      }),
    ],
  ],

  // 关键：.md 按纯 Markdown 解析（不走 MDX），存量文档零改动迁移
  markdown: {
    format: 'detect',
    // 3.10 起 onBrokenMarkdownLinks 移到这里（顶层位置已废弃）
    hooks: { onBrokenMarkdownLinks: 'warn' },
  },

  themes: [],
  plugins: sitePlugins,

  themeConfig: /** @type {import('@docusaurus/preset-classic').ThemeConfig} */ ({
    navbar: {
      title: '导航栏标题',
      items: [
        { to: '/', label: '首页', position: 'left' },
        {
          type: 'dropdown', label: '目录', position: 'left',
          items: [
            // 用路由字符串 to: 而不是 type:'doc'，避免 docId 解析报错
            { to: '/docs/某内容目录', label: '某内容' },
          ],
        },
      ],
    },
    footer: { style: 'dark', copyright: '© 站名' },
  }),
};

module.exports = config;
```

## 2. 安装与首次构建

```bash
npm install          # ~1300 包，1-2 分钟
npm run build        # 首次 ~1-3 分钟；0 错误 0 警告为过
npm run serve        # 预览构建产物（build/）
```

## 3. 内容接入

1. 内容目录整体 `mv` 进 `docs/`——**目录内部所有相对链接（`xx.md`、`../其他目录/xx.md`）保持原样即可**，Docusaurus 会把 `.md` 相对链接重写成站内路由。
2. 每个目录放 `_category_.json`：`{ "position": N }` 定分类排序。
3. 目录内 `README.md` 自动成为该分类的索引页（页面即分类落地页，侧边栏点击分类名跳到这里）。
4. 指向 docs 外文件的链接（如备份目录）改写成纯文本说明，否则是死链（构建 warn / 路由 throw）。
5. 内容里引用了**尚未创建**的章节文件：建最小占位 stub（front matter title + "撰写中" + 已完成章节链接），否则 `onBrokenLinks: 'throw'` 直接构建失败。

## 4. 增强插件（按需选装）

### 4.1 live codeblock——代码块内直接运行 JS/React

```bash
npm i @docusaurus/theme-live-codeblock@^3.10.2
```

config：`themes: ['@docusaurus/theme-live-codeblock']`。

用法：```` ```jsx live ```` / ```` ```js live ````（代码自动可编辑运行；React 在作用域内，不许 import）。

**react-live 4.x 三条硬规则**（违反即 SyntaxError / 空白，Docusaurus 官网文档的示例已过时）：

1. **inline 模式（默认）把整段代码当一个表达式**：`return (整段代码)`。函数声明、`const` 语句直接报错；多语句用 IIFE 包住（定义 + `return <组件 />`）。
2. **多语句用 `noInline`**：```` ```jsx live noInline ```` + 末尾显式 `render(<组件 />)`。
3. **求值结果必须是 React 元素**：返回字符串/数字渲染为空白，包一层 JSX。

### 4.2 mermaid——Markdown 里画图表

```bash
npm i @docusaurus/theme-mermaid@^3.10.2
```

config 两处：`themes` 加 `'@docusaurus/theme-mermaid'`；`markdown` 加 `mermaid: true`。

用法：```` ```mermaid ```` 代码块，**`.md` 直接可用**（Markdown 层能力，无需 MDX），构建时渲染成 SVG。

### 4.3 docusaurus-graph——全站知识图谱（社区插件）

```bash
npm i docusaurus-graph@^2.0.0
```

config：`plugins: ['docusaurus-graph']`。构建后生成 `build/docusaurus-graph.json`；站点右上角出现图视图按钮，点开是力导向图（需视口 ≥800×720）。

**三条必须知道的机制**：

1. **边只来自 front matter 标签**——正文 markdown 链接不参与建边：

   ```md
   ---
   references:        # 本文 → 目标
     - 目标文件名      # 去掉 .md 的文件名（节点 id = basename）
   sources:           # 目标 ← 本文
     - 来源文件名
   ---
   ```

2. **节点 id 取 basename**：多个目录的 `README.md` 会合并成一个节点（上游设计，无法按目录区分）。
3. 上游扫描 bug：遍历目录时 `_` 开头文件触发 `return` 而非 `continue`——当前布局实测无害，但若某目录的文件排序在 `_category_.json` 之前会被漏扫，留意节点数是否齐全。

给"每目录 README = TOC"的仓库快速建边：批量给每个 README 注入 `references:`（列出该目录全部章节文件名 stem），图立刻从散点变成树。

### 4.4 plugin-rsdoctor——构建产物分析（务必按需启用）

```bash
npm i @docusaurus/plugin-rsdoctor@^3.10.2
```

**不要直接放进 plugins**——实测后果：构建 80 秒 → 15+ 分钟，且其 SDK 在报告写完后让 node 进程不退出（CPU 0% 挂住，需 Ctrl-C）。用环境门控：

```js
if (process.env.RSDOCTOR === 'true') {
  sitePlugins.push(['@docusaurus/plugin-rsdoctor', { rsdoctorOptions: { mode: 'lite' } }]);
}
```

```json
"scripts": { "build:analyze": "RSDOCTOR=true docusaurus build" }
```

报告输出在 `build/.rsdoctor/`（HTML，浏览器直接打开）。

### 4.5 MDX 静态嵌入 React 组件

无需装包（preset 自带）。约定：`.md` 保持纯 Markdown；需要嵌组件的新建 `.mdx`（或在文件 front matter 加 `format: mdx` 单文件切换）。组件放 `src/components/`，`.mdx` 顶部 `import X from '@site/src/components/X'`。注意 MDX 语法限制：正文裸露的 `{}`、`<标签>` 会被当 JSX 解析。

## 5. 踩坑清单（按症状索引）

| 症状 | 原因 | 处理 |
|------|------|------|
| 自定义样式全部不生效（构建不报错） | `src/css/custom.css` 没在 preset 里注册 | preset-classic 选项加 `theme: { customCss: require.resolve('./src/css/custom.css') }`，1.2 模板已含 |
| 页面背景透出底层黑色（嵌入式 webview / 部分安卓内核） | 新版 Infima 亮色主题 `--ifm-background-color: transparent`，普通浏览器画布是白看不出 | custom.css 里显式钉根背景：`html { background-color: #fff } html[data-theme='dark'] { background-color: #1b1b1d }` |
| `MDX compilation failed ... Can't parse URL` | 正文裸 URL 后紧跟全角标点（`打开 http://x:5173，页面…`），被自动链接吞进 URL | URL 用反引号包成行内代码；全库 `grep` 排查"URL 后紧跟非 ASCII" |
| 大量 MDX 语法报错（存量普通 Markdown） | 默认所有 `.md` 走 MDX 解析 | `markdown.format: 'detect'`（`.md`=纯 MD，`.mdx`=MDX） |
| 新增文件后构建仍报旧错 | `.docusaurus` 缓存未感知 | `npm run clear` 后重建 |
| 构建失败：`Docusaurus found broken links` | 链接目标文件不存在（占位章节未写） | 建 stub 或改纯文本；`onBrokenLinks: 'throw'` 只对路由级，markdown 级默认 warn |
| 配置告警 `onBrokenMarkdownLinks deprecated` | 3.10 移到 `markdown.hooks` 下 | `markdown: { hooks: { onBrokenMarkdownLinks: 'warn' } }` |
| live 代码块显示 SyntaxError | react-live 4.x 三规则（见 4.1） | 按规则改写 demo |
| 验证配置改动时语法报错 | 把 `const`/`if` 写进了 config 对象字面量 | 条件逻辑放对象外，对象里只写 `plugins: sitePlugins` |
| npm script 后台跑超时 | 大构建超过命令超时 | 转后台跑 + 轮询日志 |

## 6. 验收流程（复刻后照跑一遍）

1. `npm run build` → 0 ERROR 0 WARNING，`build/docs/` 下每个内容目录都有 `index.html`。
2. `npm run serve` + `curl` 抽查：首页、各分类索引页、各一个深层章节页 → 全部 200。
3. 浏览器实测（curl 验证不了客户端行为）：
   - live 代码块：真实点击交互组件，状态变化正确；
   - mermaid：页面 DOM 里 `svg[id^="mermaid"]` 且节点数正确；
   - 图视图：按钮打开 overlay、canvas 有尺寸、节点带标签。
4. `npm run build:analyze`（如装了 rsdoctor）→ 报告可打开。
