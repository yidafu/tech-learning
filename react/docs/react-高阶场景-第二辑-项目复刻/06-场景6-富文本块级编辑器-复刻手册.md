# 场景 6 复刻手册：富文本块级编辑器（类 Notion）

> 一句话目标：不用 TipTap/ProseMirror，从裸 contenteditable 出发手写一个约 600 行的最小块编辑器内核——block 树 + 扁平 id 索引的文档模型、contenteditable 受控策略（选择状态反接管、IME 组合期不打断）、Enter 拆块 / Backspace 合块 / 拖拽移动三大块级操作、slash 命令面板（含浮层定位）、markdown 快捷输入，最后把文档模型接到 Yjs 概念上（协同接入点）。预计工期：2 周。前置要求：图纸 17 号文件通读（尤其"难点与坑"的 IME 三条纪律）+ DOM Selection/Range API 基本功。

## 0. 目标与总验收

- [ ] **文档模型**：block 树（嵌套 children）+ 扁平 `Map<id, block>` 索引双结构；所有操作（插入/删除/移动/拆分/合并）都是返回新 doc 的纯函数；`toJSON/fromJSON` round-trip 深度相等
- [ ] **受控策略**：DOM 只是从 doc 派生的渲染产物——数据变更后 React 重渲染，选择状态由 `restoreSelection` 反接管回正确位置（caret 不跳开头）；组合期间（拼音输入）不因模型更新打断输入
- [ ] **IME 三纪律**：组合期不消费按键、不 preventDefault、不 dispatch 模型更新——拼音输入"标题"二字全程无闪烁无打断；候选框开着按 Enter 选词不会被 slash 菜单吃掉
- [ ] **块级操作**：段中 Enter 拆两块（inline 样式区间随偏移正确切割）；块首 Backspace 并入上一块（标题并入段落降级为普通文本）；空块 Backspace 删除整块；⠿ 拖拽换位（先删后插一次补偿，相邻上移/下移/远距离三例正确）
- [ ] **slash 面板**：输入 `/` 触发、续输过滤（标题/拼音都能搜到）、↑↓ 循环高亮、Enter 执行、Esc 关闭；浮层贴光标定位且贴底自动翻转；点击菜单项编辑器不失焦（`onMouseDown preventDefault`）
- [ ] **markdown 快捷输入**：`# `/`## `/`- `/`1. `/`[] `/`> ` 空格触发即转块型；块中间输入不误触发（正则锚定块首）
- [ ] **协同接入点**：能说清 block 树 → Yjs 的映射方案（块级 Y.Map + 顺序 Y.Array），并跑通"两个标签页经 BroadcastChannel 交换块级操作、最终一致"的最小演示
- [ ] **回归底线**：以上全部行为有 vitest 纯函数用例 + 一组 Playwright/手工键盘脚本用例兜底

## 2. 里程碑切分

### M1 文档模型：block 树 + 扁平 id 索引（约 2 天）

**目标**：不碰任何 DOM，纯数据层跑通文档模型与全部结构操作。

**做什么**：`BlockDoc`（`blocks: Record<id, BlockNode>` + `rootChildren: string[]`；块嵌套用 `children: string[]` 引用 id）；操作集 `insertBlock / removeBlock / moveBlock / setType / updateText`（全部纯函数，id 用 nanoid，**只生成不回收**——撤销时新旧节点不撞 key）；序列化 `toJSON / fromJSON`。

**验收**：

```bash
npx vitest run src/block-editor/model.test.ts
```

- 插入→删除→undo（外置历史栈）后 doc 与初始深度相等；
- 嵌套两层子块时移动父块，子块 id 不变（引用完整性）；
- toJSON/fromJSON round-trip 相等；孤儿块检测（索引里有但树不可达）返回空。

### M2 contenteditable 受控策略（约 3 天，全册最难）

**目标**：确立"DOM 是渲染器、doc 是唯一真相"的受控契约，选择状态可保存/恢复，IME 期绝对安全。

**做什么**：

1. 每块渲染为 `<div data-block-id contenteditable>`，根容器 `contenteditable=false`（块间焦点跳转自己管）；
2. 输入契约：块的 `onInput` 把 DOM 文本**提交**进模型（marks 区间在受控渲染中由模型生成，输入期间容忍 DOM 领先模型——见坑 2 的"输入窗口"策略）；`beforeinput` 拦截 `insertParagraph/deleteContentBackward`（Enter/Backspace 的原生语义）改为模型操作；
3. 选择模型：`SelectionRef { blockId, offset }`（块内纯文本偏移）；`saveSelection(root)` 用 DOM Selection + `data-block-id` 遍历文本节点换算 offset；模型更新重渲染后 `restoreSelection` 反接管；
4. IME：`compositionstart/end` 置位标记，期间**一切键盘路径提前 return**（§4.2）。

**验收**：在块中间输入中文（拼音组合）无打断；组合结束后 caret 停在组合文本末尾；外部按钮把当前块转为标题（模型更新）后 caret 仍在原字符位置；`document.activeElement` 与 `SelectionRef.blockId` 始终一致（单测 + 手测）。

### M3 块级操作：Enter / Backspace / 拖拽（约 2.5 天）

**目标**：三大键的行为按 Notion 规格表落地（图纸路线 1 的表格即验收基准）。

**做什么**：`splitBlock(doc, id, offset)` / `mergeWithPrev(doc, id)`（§4.1，含 marks 切割与平移）；空块 Backspace 删除整块、非段落空块（空标题/空引用）先降级为段落（Notion 手感）；列表块 lift 一级（本手册把列表实现为"块 type + indent"的扁平模型，嵌套层级=indent 数值，比 PM 的嵌套 schema 简一档——这是最小内核的刻意简化，边界在 §5 坑 6 说明）；⠃ 拖拽用 HTML5 DnD：`dragstart` 记源块 id（dataTransfer），`drop` 先删后插一次补偿。

**验收**：`npx vitest run src/block-editor/splitMerge.test.ts`——拆块/合块对 text+marks 的四种切分组合（区间在左半/右半/跨切点/零宽）全对；标题+段落合并 → 段落（降级）；拖拽三例（相邻上移/相邻下移/远距离）正确；拆块后 undo 一步回到拆前。

### M4 slash 命令面板（约 1.5 天）

**目标**：`/` 触发浮层命令菜单，纯键盘可完整操作。

**做什么**：触发检测（`beforeinput` 插入 `/` 时记录锚点 offset）；query 提取（锚点到 caret 的文本）；浮层定位用 **caret 矩形虚拟锚点**（§4.3）+ 视口边缘翻转；命令清单（标题/列表/待办/引用/代码块/分割线）每项 `command(doc, blockId)` 返回新 doc；执行时先删除 `/query` 文本再执行动作。

**验收**：`/biaoti` 能搜出"标题 1"（拼音 keywords）；菜单打开时 Enter 选词不被吞（IME 守卫）、Enter 执行选中项、Esc 关闭且 caret 不动；页面底部块触发时菜单翻转到光标上方；点击菜单项后焦点回编辑器且命令作用于正确块。

### M5 markdown 快捷输入（约 1 天）

**目标**：行首 `# ` 等六种速记即时转块。

**做什么**：`beforeinput` 的插入空格事件里，取"块首到 caret"的文本匹配 `/^(#{1,3})$/`、`/^-$/`、`/^1\.$/`、`/^\[\]$|^\[x\]$/i`、`/^>$/`，命中即一次模型事务：删除前缀 + `setType`（待办记录 checked 态）；正则全部 `^` 锚定块首，块中间输入永不命中。

**验收**：六种速记各一条用例；"ab# " 不触发；`[x] ` 生成已勾选待办；中文输入法下输入 `#` 再空格同样触发（组合结束后才处理）。

### M6 协同基础：Yjs 概念接入点（约 2 天）

**目标**：block 树映射到 Yjs 数据结构的最小演示跑通，理解"为什么 Y.Map + Y.Array"。

**做什么**（§4.4）：`Y.Doc` 里建 `blocks: Y.Map<id, Y.Map>`（块属性）+ `order: Y.Array<id>`（根级顺序）；本地操作 → 双写（属性进 Y.Map、位置进 Y.Array）；远端 observer → 换算回 BlockDoc；`Y.UndoManager` 只撤销自己的操作。两个标签页经 `y-websocket`（或 BroadcastChannel provider 模拟）互见。

**验收**：双端同时编辑不同块互不覆盖；同块并发改文本，两端最终一致（字符级 CRDT 生效——对照场景 5 的 LWW：块级 LWW 会丢一方的整段文字，这就是属性/字符粒度 CRDT 的必要性）；undo 只回滚自己的操作。

## 3. 关键数据结构

```ts
// src/block-editor/model.ts
export type BlockType =
  | 'paragraph' | 'heading1' | 'heading2' | 'heading3'
  | 'bulletItem' | 'orderedItem' | 'todo' | 'quote' | 'code';

/** inline 样式 = 文本上的半开区间。marks 与 text 分离存储，拆分/合并时按区间切割 */
export interface MarkRange { type: 'bold' | 'italic' | 'code' | 'link'; start: number; end: number; href?: string }

export interface BlockNode {
  id: string;
  type: BlockType;
  text: string;               // 块内纯文本（\n 不出现——换行即拆块）
  marks: MarkRange[];
  checked?: boolean;          // type === 'todo'
  indent: number;             // 缩进层级（列表嵌套的扁平化表达）
  children: string[];         // 子块 id（本内核仅容器块使用：quote/code 可含子块；列表用 indent）
}

export interface BlockDoc {
  blocks: Record<string, BlockNode>; // 扁平 id 索引：O(1) 寻址，React key 的来源
  rootChildren: string[];             // 根级块顺序（渲染顺序的唯一出处）
}

/** 选择状态：块 id + 块内字符偏移。DOM Selection ↔ 模型偏移的换算是 M2 的核心 */
export interface SelectionRef { blockId: string; offset: number }

/** slash 面板状态（受控浮层的三要素：锚点、查询词、高亮下标） */
export interface SlashState {
  anchorOffset: number;   // '/' 所在偏移（执行命令时要删掉的文本区间起点）
  query: string;          // '/' 之后的查询词
  activeIndex: number;
}

export interface SlashItem {
  id: string; title: string; keywords: string[];   // keywords 含拼音别名
  command: (doc: BlockDoc, blockId: string, anchor: number) => BlockDoc;
}
```

## 4. 核心代码摘录

### 4.1 拆块 / 合块算法（M3）

```ts
// src/block-editor/splitMerge.ts —— text + marks 区间的切割与平移
import type { BlockDoc, BlockNode, MarkRange } from './model';
import { nanoid } from 'nanoid';

/** 半开区间 [start,end) 与切点 offset 的关系 → 切割后的左右两份 */
function splitMarks(marks: MarkRange[], offset: number): { left: MarkRange[]; right: MarkRange[] } {
  const left: MarkRange[] = [];
  const right: MarkRange[] = [];
  for (const m of marks) {
    // 与 [0, offset) 求交 → 左半；与 [offset, ∞) 求交 → 右半（右半平移 -offset）
    if (m.start < offset) {
      left.push({ ...m, end: Math.min(m.end, offset) });
    }
    if (m.end > offset) {
      right.push({ ...m, start: Math.max(m.start, offset) - offset, end: m.end - offset });
    }
  }
  return { left, right };
}

/** 平移 marks（合并时右块 marks 整体 + prev.text.length） */
function shiftMarks(marks: MarkRange[], delta: number): MarkRange[] {
  return marks.map((m) => ({ ...m, start: m.start + delta, end: m.end + delta }));
}

/** 标题/引用并入段落时降级；列表并入普通块降级——类型规则集中在这一处 */
function mergedType(prev: BlockNode): BlockNode['type'] {
  return prev.type === 'code' ? 'code' : 'paragraph'; // code 块特殊：可多行合并；其余一律段落
}

/** 拆块续型规则（Notion 行为）：标题/引用 Enter 回落段落（不延续）；
 *  列表/待办/代码块延续同型（待办新项未勾选）——类型规则与 mergedType 一样集中收口 */
function splitChildType(t: BlockNode['type']): BlockNode['type'] {
  return t === 'bulletItem' || t === 'orderedItem' || t === 'todo' || t === 'code' ? t : 'paragraph';
}

/** Enter：把 block 在 offset 处一分为二，右半成为新块插到后面 */
export function splitBlock(doc: BlockDoc, blockId: string, offset: number): BlockDoc {
  const block = doc.blocks[blockId]!;
  const { left, right } = splitMarks(block.marks, offset);
  const newId = nanoid();
  const nextType = splitChildType(block.type);
  const updated: BlockNode = { ...block, text: block.text.slice(0, offset), marks: left };
  const created: BlockNode = {
    id: newId, type: nextType, text: block.text.slice(offset), marks: right,
    checked: nextType === 'todo' ? false : undefined, // 待办延续但新项未勾选；其余类型清掉
    indent: block.indent, children: [],
  };
  const blocks = { ...doc.blocks, [blockId]: updated, [newId]: created };
  const rootChildren = insertAfter(doc.rootChildren, blockId, newId);
  return { blocks, rootChildren };
}

/** Backspace（块首、上一块存在）：并入上一块。返回 null 表示"无可合并"（交给删块逻辑） */
export function mergeWithPrev(doc: BlockDoc, blockId: string): BlockDoc | null {
  const idx = doc.rootChildren.indexOf(blockId);
  if (idx <= 0) return null;
  const prevId = doc.rootChildren[idx - 1]!;
  const prev = doc.blocks[prevId]!;
  const cur = doc.blocks[blockId]!;
  const merged: BlockNode = {
    ...prev,
    type: mergedType(prev),
    text: prev.text + cur.text,                             // 文本拼接
    marks: [...prev.marks, ...shiftMarks(cur.marks, prev.text.length)], // 右块区间平移后追加
    checked: undefined,                                     // 降级为段落时清掉待办勾选态（元字段随类型清洗）
  };
  const blocks = { ...doc.blocks, [prevId]: merged } as typeof doc.blocks;
  delete blocks[blockId];
  return { blocks, rootChildren: doc.rootChildren.filter((id) => id !== blockId) };
}

/** 拖拽移动：先删后插一次补偿（删除使目标索引前移时减一）——与场景 4/图纸 17 同一条纪律 */
export function moveBlock(doc: BlockDoc, fromId: string, toIndex: number): BlockDoc {
  const from = doc.rootChildren.indexOf(fromId);
  if (from < 0 || toIndex === from) return doc;
  const next = [...doc.rootChildren];
  next.splice(from, 1);
  const adjusted = from < toIndex ? toIndex - 1 : toIndex;
  next.splice(Math.min(adjusted, next.length), 0, fromId);
  return { blocks: doc.blocks, rootChildren: next };
}

function insertAfter(list: string[], after: string, value: string): string[] {
  const idx = list.indexOf(after);
  const next = [...list];
  next.splice(idx + 1, 0, value);
  return next;
}
```

### 4.2 IME 保护与选择反接管（M2）

```ts
// src/block-editor/selection.ts —— 受控策略的两个核心机制
import type { SelectionRef } from './model';

/** IME 判定：isComposing 或 keyCode 229（Safari 老版本只给 229）。
 *  参数用结构化形状（KeyboardEvent/InputEvent 都满足），避免联合类型的属性窄化问题。
 *  三纪律：组合期间不消费按键、不 preventDefault、不 dispatch 模型更新 */
export function isComposingEvent(e: { isComposing?: boolean; keyCode?: number }): boolean {
  return e.isComposing === true || e.keyCode === 229;
}

/** DOM Selection → 模型选择。只认 [data-block-id] 块内的 caret；
 *  跨块选区返回锚点块（最小内核不支持跨块 Range 编辑，退化为整块操作） */
export function saveSelection(root: HTMLElement): SelectionRef | null {
  const sel = window.getSelection();
  if (!sel || sel.rangeCount === 0) return null;
  const range = sel.getRangeAt(0);
  const blockEl = closestBlock(range.startContainer, root);
  if (!blockEl) return null;
  const blockId = blockEl.dataset.blockId!;
  return { blockId, offset: textOffsetIn(blockEl, range.startContainer, range.startOffset) };
}

/** 模型选择 → DOM Selection：先找块元素，再把字符偏移换算成 (textNode, offset)。
 *  模型更新触发重渲染后调用——"反接管"就是这一步：DOM 是渲染产物，caret 归模型管 */
export function restoreSelection(root: HTMLElement, ref: SelectionRef): void {
  const blockEl = root.querySelector<HTMLElement>(`[data-block-id="${ref.blockId}"]`);
  if (!blockEl) return;
  const target = domPointAt(blockEl, ref.offset);
  if (!target) return;
  const sel = window.getSelection();
  sel?.removeAllRanges();
  const range = document.createRange();
  range.setStart(target.node, target.offset);
  range.collapse(true);
  sel?.addRange(range);
}

function closestBlock(node: Node, root: HTMLElement): HTMLElement | null {
  let cur: Node | null = node;
  while (cur && cur !== root) {
    if (cur instanceof HTMLElement && cur.dataset.blockId) return cur;
    cur = cur.parentNode;
  }
  return null;
}

/** 字符偏移换算：深度优先累计文本节点长度（marks 渲染成 span 不影响字符计数） */
function domPointAt(blockEl: HTMLElement, offset: number): { node: Node; offset: number } | null {
  const walker = document.createTreeWalker(blockEl, NodeFilter.SHOW_TEXT);
  let remaining = offset;
  let node: Node | null = walker.nextNode();
  while (node) {
    const len = node.textContent?.length ?? 0;
    if (remaining <= len) return { node, offset: remaining };
    remaining -= len;
    node = walker.nextNode();
  }
  // 超出文本末尾（空块/offset==length）：挂到最后一个文本节点末尾，或块元素本身
  const last = blockEl.lastChild;
  if (last) return { node: last, offset: last.textContent?.length ?? 0 };
  return { node: blockEl, offset: 0 };
}

function textOffsetIn(blockEl: HTMLElement, node: Node, nodeOffset: number): number {
  const walker = document.createTreeWalker(blockEl, NodeFilter.SHOW_TEXT);
  let acc = 0;
  let cur: Node | null = walker.nextNode();
  while (cur) {
    if (cur === node) return acc + nodeOffset;
    acc += cur.textContent?.length ?? 0;
    cur = walker.nextNode();
  }
  return acc;
}
```

### 4.3 slash 菜单定位（M4）

```ts
// src/block-editor/slashPosition.ts —— caret 矩形虚拟锚点 + 边缘翻转
export interface Rect { left: number; top: number; bottom: number; right: number }

/** caret 的视口矩形。空块/块首时 collapsed range 可能返回零矩形，兜底用块元素矩形 */
export function caretRect(): Rect | null {
  const sel = window.getSelection();
  if (!sel || sel.rangeCount === 0) return null;
  const range = sel.getRangeAt(0).cloneRange();
  const rects = range.getClientRects();
  if (rects.length > 0) {
    const r = rects[0]!;
    return { left: r.left, top: r.top, bottom: r.bottom, right: r.right };
  }
  // 兜底：插入零宽 span 量出 caret 位置，再移除（Safari 空块场景）
  const span = document.createElement('span');
  span.textContent = '\u200b';
  range.insertNode(span);
  const r = span.getBoundingClientRect();
  span.remove();
  return { left: r.left, top: r.top, bottom: r.bottom, right: r.right };
}

export interface MenuPos { left: number; top: number; placement: 'below' | 'above' }

/** 定位：默认光标下方 4px、左对齐；菜单高 menuH，视口底部放不下时翻转到光标上方 */
export function positionMenu(menuW: number, menuH: number, gap = 4): MenuPos | null {
  const rect = caretRect();
  if (!rect) return null;
  const vw = window.innerWidth, vh = window.innerHeight;
  const left = Math.min(Math.max(8, rect.left), vw - menuW - 8); // 左右越界钳回
  const fitsBelow = rect.bottom + gap + menuH <= vh - 8;
  return fitsBelow
    ? { left, top: rect.bottom + gap, placement: 'below' }
    : { left, top: Math.max(8, rect.top - gap - menuH), placement: 'above' };
}

// 菜单项的两个防失焦细节（图纸路线 3 的坑，最小内核同样适用）：
// <button onMouseDown={(e) => e.preventDefault()} onClick={...}>  // mousedown 阻止焦点转移
// 命令统一 editorRef.focus() 后执行                               // 显式回焦
```

### 4.4 Yjs 概念接入点（M6）

```ts
// src/block-editor/collab.ts —— block 树 → Yjs 的映射（概念演示级）
import * as Y from 'yjs';
import type { BlockDoc, BlockNode } from './model';

/**
 * 映射方案：属性与顺序分离。
 *  - blocks: Y.Map<blockId, Y.Map<块字段>>  —— 每块一个 Y.Map，字段级 CRDT（并发改同块不同字段互不覆盖）
 *  - order:  Y.Array<blockId>               —— 只存 id 顺序，位置合并由 Y.Array 的 CRDT 语义保证
 *  为什么不用一个 Y.Array<BlockNode>：数组元素是整值，并发改块文本会退化为元素级 LWW（丢一方）——
 *  对照场景 5 的 lwwStore：块级 LWW 丢整块，字段级 Y.Map 才保得住并发编辑。
 */
export function toYjs(doc: BlockDoc): Y.Doc {
  const ydoc = new Y.Doc();
  const yBlocks = ydoc.getMap<Y.Map<unknown>>('blocks');
  const yOrder = ydoc.getArray<string>('order');
  for (const block of Object.values(doc.blocks)) {
    yBlocks.set(block.id, blockToYMap(block));
  }
  yOrder.insert(0, doc.rootChildren);
  return ydoc;
}

function blockToYMap(block: BlockNode): Y.Map<unknown> {
  const m = new Y.Map<unknown>();
  m.set('type', block.type);
  m.set('text', block.text);
  m.set('marks', JSON.stringify(block.marks)); // marks 是区间数组，整体 JSON 存（字段级并发合并留给扩展）
  m.set('indent', block.indent);
  if (block.checked !== undefined) m.set('checked', block.checked);
  return m;
}

/** 本地操作 → Yjs 双写：属性写 Y.Map，位置写 Y.Array（order 的 splice 语义用 insert/delete 组合） */
export function applyMove(ydoc: Y.Doc, blockId: string, from: number, to: number): void {
  const yOrder = ydoc.getArray<string>('order');
  ydoc.transact(() => {           // transact：两个写操作合并为一个 undo 单元（Y.UndoManager 的粒度）
    yOrder.delete(from, 1);
    yOrder.insert(from < to ? to - 1 : to, [blockId]);
  });
}

/** 远端变更 → 本地 BlockDoc：observer 换算回扁平索引结构，React 重渲染 */
export function fromYjs(ydoc: Y.Doc): BlockDoc {
  const yBlocks = ydoc.getMap<Y.Map<unknown>>('blocks');
  const yOrder = ydoc.getArray<string>('order');
  const blocks: Record<string, BlockNode> = {};
  for (const [id, ym] of yBlocks.entries()) {
    blocks[id] = {
      id, type: ym.get('type') as BlockNode['type'], text: ym.get('text') as string,
      marks: JSON.parse((ym.get('marks') as string) || '[]'),
      indent: (ym.get('indent') as number) ?? 0,
      checked: ym.get('checked') as boolean | undefined, children: [],
    };
  }
  return { blocks, rootChildren: [...yOrder] };
}

// 接入点三句话（对照图纸 17 路线 9 的"五个要点"）：
// ① 数据面：blocks/order 两个顶层类型；② 感知面：awareness 发光标 SelectionRef（瞬态，不进文档）；
// ③ 撤销面：new Y.UndoManager([yBlocks, yOrder])，trustedOrigins 只加本地 provider——只撤销自己的操作。
```

```ts
// src/block-editor/markdownRules.ts —— 行首速记：空格触发、^ 锚定、一次模型事务
import type { BlockDoc, BlockType } from './model';

interface ShorthandRule {
  /** 匹配"块首到 caret"的整段文本（不含触发空格）。必须整串匹配——块中间输入永不命中 */
  pattern: RegExp;
  apply: (blockType: BlockType) => Partial<{ type: BlockType; checked: boolean }>;
}

const RULES: ShorthandRule[] = [
  { pattern: /^(#{1,3})$/, apply: (m) => ({ type: (['heading1', 'heading2', 'heading3'] as BlockType[])[m.length - 1]! }) },
  { pattern: /^-$/, apply: () => ({ type: 'bulletItem' }) },
  { pattern: /^1\.$/, apply: () => ({ type: 'orderedItem' }) },
  { pattern: /^\[\]$/, apply: () => ({ type: 'todo', checked: false }) },
  { pattern: /^\[[xX]]$/, apply: () => ({ type: 'todo', checked: true }) },
  { pattern: /^>$/, apply: () => ({ type: 'quote' }) },
];

/**
 * 触发时机：beforeinput 的 insertText 且 data === ' '（IME 组合期天然不触发——beforeinput
 * 在组合期间不派发 insertText，第二道保险是 isComposingEvent 守卫）。
 * prefix = 块首到 caret 的文本（不含即将输入的空格）。
 * 返回 null = 无命中，走普通输入；命中 = 删除前缀 + setType 的一次性事务描述。
 */
export function matchShorthand(
  prefix: string,
): { removeLen: number; attrs: Partial<{ type: BlockType; checked: boolean }> } | null {
  if (!prefix) return null;
  for (const rule of RULES) {
    const m = rule.pattern.exec(prefix);
    if (m) return { removeLen: prefix.length, attrs: rule.apply(m[1] ?? prefix) };
  }
  return null;
}

// 事务（两条写操作合并为一次 undo 单元）：
// const next = setType(removePrefix(doc, blockId, offset, hit.removeLen), blockId, hit.attrs);
// 注意顺序：先删前缀再改类型；空块（prefix 占满整块）删除后 text 为空串，正是新块的干净起点。
```

## 5. 坑与调试

1. **受控输入死循环**（症状：输入一个字符光标跳回开头，或输入"吃字"）。根因：`onInput` 同步 setState → 重渲染 → React 用旧模型覆盖 DOM（caret 重置到块首）。修法：输入窗口策略——`onInput` 只把 DOM 文本存进 pending ref，`onBlur/compositionEnd/块切换/结构操作` 时才提交进模型；或用非受控 + 模型单向同步（结构变化才重渲染，文本输入不重渲染本块）。判断标准：打字时 React DevTools 里本块组件不 update。
2. **IME 组合被打断**（症状：拼音敲到一半变成裸字母，候选框消失）。根因：组合期间的 `beforeinput`/`keydown` 被 preventDefault，或组合中 dispatch 了模型更新触发重渲染。修法：§4.2 三纪律；组合期的 DOM 状态视为"租借"给输入法，组合结束（`compositionEnd`）才回收。
3. **拆块后样式区间错位**（症状：加粗从"右半块开头"漏到"左半块结尾"）。根因：marks 区间没按切点切割（整份复制到两块）或右半没平移 `-offset`。修法：`splitMarks` 的四象限单测（区间在左/右/跨切点/零宽）是 M3 的必写用例。
4. **Backspace 合并丢类型**（症状：标题块合并后整段变成大字号）。根因：合并取了 `prev.type`。修法：`mergedType` 集中收口——标题/引用/列表并入段落一律降级（Notion 规则），code 块例外。
5. **拖拽相邻下移失败**（症状：块 A 拖到紧随其后的 B 后面，顺序没变）。根因：先插后删/补偿写错——插入使源索引偏移。修法：固定先删后插 + `from < to ? to - 1 : to` 一次补偿；两种补偿方式（手动减一 vs `tr.mapping`）不混用。
6. **列表嵌套用扁平 indent 的边界**（症状：拖动父列表项"子项"不跟随）。根因：扁平 indent 模型里父子是视觉推断（同 indent 连续块），不是数据引用。修法：最小内核接受此边界（Notion 前 80% 场景够用）；要真嵌套就上 children 引用模型（M1 已预留字段）或直接用 PM 的嵌套 schema——这正是图纸选 TipTap 的理由之一。
7. **slash 菜单点击后命令作用到错误块**（症状：插入的标题跑到别的位置）。根因：点击使编辑器 blur，Selection 丢失，命令拿不到目标块。修法：菜单项 `onMouseDown preventDefault` + 打开菜单时记住 `blockId/anchorOffset`（不依赖实时 Selection）。
8. **协同后 React 不刷新**（症状：Yjs 数据变了，页面没动）。根因：Yjs observer 不在 React 状态体系内。修法：`observeDeep` 回调里 `setDoc(fromYjs(ydoc))`——Yjs 是真相，BlockDoc 是视图投影（与场景 4 的"schema 唯一真相、Model 是投影"同构）。
