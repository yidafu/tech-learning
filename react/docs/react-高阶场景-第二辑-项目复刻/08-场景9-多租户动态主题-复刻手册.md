# 场景 9 复刻手册：多租户动态主题

> 一句话目标：从零复刻一套租户级动态换肤体系——design token 三层化（组件只消费语义 token 的铁律）、运行时换肤（CSS variables 注入 vs CSS-in-JS 的取舍）、租户主题包的远程加载（拉取 + 校验 + 降级链）、canvas 图表世界的 token 镜像同步、暗色模式的正交叠加；核心算法是**token 合并器**：品牌色 → OKLCH 亮度插值生成 12 级色板 → 语义映射 → 四层合并。预计工期：1 周。前置要求：图纸 20 号文件路线 1–4 通读；CSS 自定义属性基础。

## 0. 目标与总验收

- [ ] **token 三层**：`tokens.css` 分基础层（色阶）/ 语义层（`--color-primary` 等）/ 消费层（业务样式只出现语义 token）；stylelint 规则禁硬编码色值，故意写一个 `color: #1890ff` 被 CI 拦截
- [ ] **token 合并器**：`buildOklchScale('#0ea5a4')` 生成 12 级色板（500 号 = 原色，两端向白/黑插值，色相恒定、亮度感知均匀、超域色自动降铬）；`mergeTokens(schema, mode)` 四层合并输出最终变量批——纯函数，同样输入两次输出深度相等
- [ ] **运行时换肤**：`[data-tenant]` 选择器块注入（默认路径）与 JS `setProperty`（预览/动画路径）两法都落地；切租户无"半套主题"中间态、无旧租户变量残留
- [ ] **主题包加载**：远程拉取（带版本、5s 超时）→ 结构校验（hex 格式/半径范围/字体白名单/overrides 键合法性）→ 注入；三层降级链可演示：远端 500 → 用 localStorage 上一版 → 再失败 → 默认主题，全程不白屏
- [ ] **图表同步**：echarts 图表读 token mirror（显式列举的镜像清单 + `theme:changed` 事件），切主题后图表 dispose + 按新主题名重建；镜像"只读不写"
- [ ] **暗色叠加**：租户维度只提供色阶原材料、mode 维度只定义语义映射（正交，2N 组合全部正确）；暗色下品牌色对比度不足自动提亮（WCAG 检测 + 借档）
- [ ] **不发版生效**：运营改主题包发布（version+1）→ 版本号进 URL/缓存键 → 在线用户下一拉取周期拿到新主题，无强刷

## 2. 里程碑切分

### M1 design token 化（约 1 天）

**目标**：三层 token CSS + stylelint 门禁，为后续一切建立"合同"。

**做什么**：`tokens.css`（图纸路线 1 的三层结构原样落）；`.stylelintrc.json` 接 `stylelint-declaration-strict-value`（`ignoreValues` 放行 `transparent/inherit/currentColor/var(--`）；把现有页面样式全部迁移到语义 token。

**验收**：`npx stylelint "src/**/*.css"` 零 error；故意提交 `color: #f53f3f` 在 CI 红（截图归档）；改 `--color-primary` 一处，全站主按钮/链接/选中态同变。

### M2 运行时换肤与 token 合并器（约 2 天，核心里程碑）

**目标**：schema → 变量批的生成器 + 两法注入 + 切换无中间态。

**做什么**：`oklch.ts`（§4.1）与 `mergeTokens.ts`（§4.2）；`inject.ts` 两法（图纸路线 3，方法 B 的"清残留"循环必须保留）；antd `ConfigProvider theme` 桥接一段——同一份 schema 喂 seed token，取舍论证见 §5 坑 2。

**验收**：

```bash
npx vitest run src/theme/generator.test.ts
```

- 色板断言：500 号与输入色近似同色；两端亮度在锚点界内；任意 hex 输入（含荧光绿、深藏青）12 级全部落在 sRGB 域内（降铬生效）；
- 合并器断言：幂等（两次调用深度相等）、overrides 最后应用、dark 与 light 选不同档位、四层顺序不可交换（构造交换后输出不同的用例）；
- 手测：切租户用 DevTools 看 `<style id="tenant-theme">` 整体替换、`documentElement` 上无上一租户残留变量。

### M3 租户主题包加载：拉取 + 校验 + 降级链（约 1.5 天）

**目标**：`loadTenantTheme` 三层降级链（远端 → localStorage 版本化缓存 → 默认主题）。

**做什么**：版本协商（先问 `/theme/version`，唯一禁缓存的轻请求）→ 按版本命名的缓存键（新版本 = 新键，旧键清理）→ 全量拉取（URL 带版本）→ `validateTenantTheme`（图纸补充篇的校验器：hex 正则/半径范围/字体白名单/overrides 键 `--` 开头；error 阻断、warning 放行）→ 注入。校验失败 = 整包作废，用缓存或默认。

**验收**：DevTools 断网 → 用缓存版本（无白屏无闪烁）；清缓存再断网 → 默认主题；mock 坏包（radius: 999）→ 校验错误列表返回、站点用默认主题、console error 有字段定位；发布 version+1 后下一周期拿到新主题（无强刷）。

### M4 图表等非 DOM 场景同步（约 1 天）

**目标**：echarts 主题随 CSS 变量同步，镜像只读。

**做什么**：`tokenMirror.ts`（显式列举镜像清单 + `syncTokenMirror` + `theme:changed` 事件）；`echartsTheme.ts`（mirror → 主题对象，重注册用新名字 `tenant-v{n}`——echarts 主题表按名字缓存，同名覆盖对已初始化实例不生效）；`ThemedChart.tsx`（订阅事件 dispose 重建）。图纸路线 6 整段可抄。

**验收**：切租户后图表系列色/坐标轴/图例同步换肤；切暗色模式图表跟随；DevTools 里 mirror 对象与 `getComputedStyle` 读值一致；全局搜不到图表组件直接调 `getComputedStyle`（收敛验证）。

### M5 暗色模式叠加（约 1 天）

**目标**：正交组合 + 对比度守门。

**做什么**：CSS 侧 `data-tenant` 只替换基础层、`data-mode` 只替换语义映射（图纸路线 4 的两段 CSS）；生成器内 `pickAccessibleStep`（WCAG 相对亮度 → 对比度 → 沿色阶向浅端借档）；antd `darkAlgorithm` 桥接。

**验收**：两租户 × 两模式 2×2 矩阵，`getComputedStyle` 断言四组 `--color-primary` 各不相同且档位符合映射表；极端浅色租户（`#facc15`）暗色下自动提亮至达标档位并有提示日志；切换模式只改 `data-mode` 属性（React 不 re-render 也能变——CSS 级联的复利）。

## 4. 核心代码摘录

### 4.1 品牌色 → OKLCH 亮度插值色板（M2）

```ts
// src/theme/oklch.ts —— sRGB ↔ OKLab(LCH) 转换 + 感知均匀的 12 级色板
// OKLab 系数来自 Björn Ottosson 的公开推导（CSS Color 4 同源），零依赖
import type { Oklch } from './types';

type Rgb = { r: number; g: number; b: number }; // 各通道 0~1

export function hexToRgb(hex: string): Rgb {
  const n = hex.replace('#', '');
  return {
    r: parseInt(n.slice(0, 2), 16) / 255,
    g: parseInt(n.slice(2, 4), 16) / 255,
    b: parseInt(n.slice(4, 6), 16) / 255,
  };
}

export function rgbToHex({ r, g, b }: Rgb): string {
  const to = (x: number) => Math.round(Math.min(1, Math.max(0, x)) * 255).toString(16).padStart(2, '0');
  return `#${to(r)}${to(g)}${to(b)}`;
}

// sRGB（伽马编码）↔ 线性光
const toLinear = (c: number): number => (c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4));
const toGamma = (c: number): number => (c <= 0.0031308 ? c * 12.92 : 1.055 * Math.pow(c, 1 / 2.4) - 0.055);

export function rgbToOklch(hex: string): Oklch {
  const { r, g, b } = hexToRgb(hex);
  const lr = toLinear(r), lg = toLinear(g), lb = toLinear(b);
  // 线性 sRGB → LMS（长中短锥响应）
  const l = 0.4122214708 * lr + 0.5363325363 * lg + 0.0514459929 * lb;
  const m = 0.2119034982 * lr + 0.6806995451 * lg + 0.1073969566 * lb;
  const s = 0.0883024619 * lr + 0.2817188376 * lg + 0.6299787005 * lb;
  // 立方根（OKLab 的关键非线性）
  const l_ = Math.cbrt(l), m_ = Math.cbrt(m), s_ = Math.cbrt(s);
  // LMS' → OKLab
  const L = 0.2104542553 * l_ + 0.7936177850 * m_ - 0.0040720468 * s_;
  const A = 1.9779984951 * l_ - 2.4285922050 * m_ + 0.4505937099 * s_;
  const B = 0.0259040371 * l_ + 0.7827717662 * m_ - 0.8086757660 * s_;
  return { l: L, c: Math.hypot(A, B), h: (Math.atan2(B, A) * 180) / Math.PI };
}

/** OKLCH → sRGB（hex）。c/h 先还原 A/B 分量，再走 OKLab → LMS 的逆变换 */
export function oklchToRgb({ l, c, h }: Oklch): Rgb {
  const hr = (h * Math.PI) / 180;
  const A = c * Math.cos(hr), B = c * Math.sin(hr);
  const l_ = l + 0.3963377774 * A + 0.2158037573 * B;
  const m_ = l - 0.1055613458 * A - 0.0638541728 * B;
  const s_ = l - 0.0894841775 * A - 1.2914855480 * B;
  const L = l_ * l_ * l_, M = m_ * m_ * m_, S = s_ * s_ * s_; // 立方（立方根的逆）
  const lr = 4.0767416621 * L - 3.3077115913 * M + 0.2309699292 * S;
  const lg = -1.2684380046 * L + 2.6097574011 * M - 0.3413193965 * S;
  const lb = -0.0041960863 * L - 0.7034186147 * M + 1.7076147010 * S;
  return { r: toGamma(lr), g: toGamma(lg), b: toGamma(lb) };
}

/** 判定 OKLCH 色是否落在 sRGB 域内（任一分量出 [0,1] 即超域） */
const inGamut = (c: Oklch): boolean => {
  const { r, g, b } = oklchToRgb(c);
  return r >= 0 && r <= 1 && g >= 0 && g <= 1 && b >= 0 && b <= 1;
};

/** 超域降铬：保持 L/H 不变，二分收缩 C 直到入域（8 次迭代精度已足够） */
export function clampChroma(c: Oklch): Oklch {
  if (inGamut(c)) return c;
  let lo = 0, hi = c.c;
  for (let i = 0; i < 8; i++) {
    const mid = (lo + hi) / 2;
    if (inGamut({ ...c, c: mid })) lo = mid; else hi = mid;
  }
  return { ...c, c: lo };
}

/** 12 级色板：档位 → L 锚点（浅端近白、深端近黑，500 = 原色 L）。
 *  H 全程恒定（品牌识别），C 在两端轻微收敛（极浅/极深处高饱和会"脏"） */
const L_ANCHORS: Record<string, number> = {
  '50': 0.977, '100': 0.951, '200': 0.906, '300': 0.849, '400': 0.782, '500': -1, // -1 = 原色 L
  '600': 0.647, '700': 0.559, '800': 0.468, '900': 0.376, '950': 0.28,
};

export function buildOklchScale(primaryHex: string): Record<string, string> {
  const base = rgbToOklch(primaryHex);
  const out: Record<string, string> = {};
  for (const [step, anchor] of Object.entries(L_ANCHORS)) {
    const l = anchor === -1 ? base.l : anchor;
    const cFactor = l > 0.9 ? 0.75 : l < 0.35 ? 0.85 : 1; // 两端收敛铬，中段保持原色铬
    out[step] = rgbToHex(oklchToRgb(clampChroma({ l, c: base.c * cFactor, h: base.h })));
  }
  return out;
}
```

### 4.2 token 合并器：四层合并（M2）

```ts
// src/theme/mergeTokens.ts —— 默认 → 租户色阶 → 模式语义映射 → overrides
import type { Scale, TenantThemeSchema, ThemeMode, TokenBatch } from './types';
import { buildOklchScale } from './oklch';
import { contrastRatio } from './contrast'; // WCAG 相对亮度 + 对比度（图纸路线 4 的实现原样搬）

/** 从 start 档起沿色阶向浅端找第一个对比度达标档（暗色底上主色不够亮时自动提亮） */
export function pickAccessibleStep(
  scale: Record<string, string>, background: string, minRatio = 3, start = '400',
): string {
  const order = ['400', '300', '200', '100', '50'];
  for (const step of order.slice(Math.max(0, order.indexOf(start)))) {
    if (contrastRatio(scale[step]!, background) >= minRatio) return scale[step]!;
  }
  return scale['50']!; // 兜底最浅档
}

/**
 * 合并顺序（不可交换）：
 *  ① 基础层默认值（兜底语义映射，租户数据缺失时仍在）
 *  ② 租户色阶原材料（--tenant-500...，语义层引用它们而非复制值）
 *  ③ 模式语义映射（light/dark 各选档位；dark 对主色做对比度自适应提亮）
 *  ④ overrides 逃生舱（运营手工微调，优先级最高）
 */
export function mergeTokens(schema: TenantThemeSchema, mode: ThemeMode): TokenBatch {
  const scale: Scale = { ...buildOklchScale(schema.brand.primary) } as Scale;
  const vars: Record<string, string> = {};

  // ② 租户色阶：语义层引用档位（var 链）——运营微调色阶时语义层零改动自动跟随
  for (const [k, v] of Object.entries(scale)) vars[`--tenant-${k}`] = v;

  // ③ 模式映射
  if (mode === 'light') {
    vars['--color-primary'] = 'var(--tenant-500)';
    vars['--color-primary-hover'] = 'var(--tenant-400)';
    vars['--color-primary-active'] = 'var(--tenant-600)';
    vars['--color-bg-page'] = '#f7f8fa';
    vars['--color-bg-elevated'] = '#ffffff';
    vars['--color-bg-hover'] = '#f0f1f3';
    vars['--color-text'] = '#1d2129';
    vars['--color-text-secondary'] = '#4e5969';
    vars['--color-border'] = '#e5e6eb';
  } else {
    vars['--color-primary'] = 'var(--tenant-400)'; // 暗色默认提亮一号
    vars['--color-primary-hover'] = 'var(--tenant-300)';
    vars['--color-primary-active'] = 'var(--tenant-500)';
    vars['--color-bg-page'] = '#101418';
    vars['--color-bg-elevated'] = '#1a2029';
    vars['--color-bg-hover'] = '#232a35';
    vars['--color-text'] = '#f2f3f5';
    vars['--color-text-secondary'] = '#a9aeb8';
    vars['--color-border'] = '#333a45';
  }
  vars['--radius-card'] = `${schema.radius.card}px`;
  vars['--radius-button'] = `${schema.radius.button}px`;
  vars['--font-family'] = schema.font.family;

  // 暗色主色对比度守门：默认的 400 档不达标时，主色替换为借档后的具体色值。
  // 这是少数"语义层直写色值"的合法场景——借档结果无法用 var 链表达
  if (mode === 'dark' && contrastRatio(scale['400']!, '#101418') < 3) {
    vars['--color-primary'] = pickAccessibleStep(scale, '#101418', 3, '400');
  }

  // ④ overrides 最后应用
  return { ...vars, ...schema.overrides } as TokenBatch;
}
```

CSS 变量注入（方法 A，默认路径）一行核心：把 `mergeTokens` 的产物拼成 `:root[data-tenant="acme"][data-mode="dark"] { --k: v; ... }` 整体替换 `<style id="tenant-theme">` 的 textContent——单次更新原子生效、同租户重复注入天然幂等、`data-tenant/data-mode` 打在 `<html>` 上留出 CSS 调试入口（图纸路线 3）。

### 4.3 注入与 antd 桥（M2 补全）

```ts
// src/theme/inject.ts —— 方法 A 实现 + 方法 B 的清残留纪律（图纸路线 3）
import type { TenantThemeSchema, ThemeMode } from './types';
import { mergeTokens } from './mergeTokens';

export function injectThemeBlock(tenantId: string, schema: TenantThemeSchema, mode: ThemeMode): void {
  const vars = mergeTokens(schema, mode);
  const decls = Object.entries(vars).map(([k, v]) => `  ${k}: ${v};`).join('\n');
  const css = `:root[data-tenant="${tenantId}"][data-mode="${mode}"] {\n${decls}\n}`;
  let el = document.getElementById('tenant-theme') as HTMLStyleElement | null;
  if (!el) {
    el = document.createElement('style');
    el.id = 'tenant-theme';
    document.head.appendChild(el);
  }
  el.textContent = css; // 整体替换：幂等 + 原子生效
  document.documentElement.dataset.tenant = tenantId; // 正交两维度打到 <html> 上
  document.documentElement.dataset.mode = mode;
}

/** 方法 B（预览/逐 token 动画用）：setProperty 批量写 + 清"上一租户残留" */
export function injectThemeByJS(schema: TenantThemeSchema, mode: ThemeMode): void {
  const vars = mergeTokens(schema, mode);
  const root = document.documentElement;
  for (const [k, v] of Object.entries(vars)) root.style.setProperty(k, v);
  for (const stale of Array.from(root.style)) {          // ★ 清残留：旧有新无的键必须删
    if (stale.startsWith('--') && !(stale in vars)) root.style.removeProperty(stale);
  }
}
```

```tsx
// src/theme/AntdThemeBridge.tsx —— 同一份 schema 喂 antd seed token（图纸路线 2）
import type { ReactNode } from 'react';
import { ConfigProvider, theme as antdTheme } from 'antd';
import type { TenantThemeSchema, ThemeMode } from './types';
import { buildOklchScale } from './oklch';

export function AntdThemeBridge({ schema, mode, children }: {
  schema: TenantThemeSchema; mode: ThemeMode; children: ReactNode;
}) {
  const scale = buildOklchScale(schema.brand.primary); // 与 CSS 变量体系同一个色板源
  return (
    <ConfigProvider
      theme={{
        algorithm: mode === 'dark' ? antdTheme.darkAlgorithm : antdTheme.defaultAlgorithm,
        token: {
          colorPrimary: scale['500'],
          borderRadius: schema.radius.button,
          fontFamily: schema.font.family,
        },
        components: { Card: { borderRadiusLG: schema.radius.card } },
      }}
    >
      {children}
    </ConfigProvider>
  );
}
// 取舍：antd 的 colorPrimary 是具体色值（绕过 CSS 变量），靠 React 重渲染 + cssinjs 重新生成
// 样式生效——两条注入链并存的前提是"同一个 buildOklchScale 输出"，否则组件库与自研组件两色。
```

## 5. 坑与调试

1. **一处 `var(--blue-500)` 漏网**（症状：全站变绿唯独成本徽标还是蓝）。根因：组件直接依赖基础层，绕过了语义映射——漏的不是一处样式，是主题合同的一个条款。修法：M1 的 stylelint 门禁 + code review 见裸色值/基础层 token 一律打回；命名口诀——基础层回答"这是哪个"（灰阶第 100 号），语义层回答"这是什么"（悬浮层底色）。
2. **CSS variables vs CSS-in-JS 的取舍做反**（症状：项目用 styled-components，又强上 CSS 变量体系，两套注入互相打架）。判据：antd v5 项目走"CSS 变量为主 + `ConfigProvider theme` seed token 桥接"（antd v5 弹层在 React 树内，同树生效）；纯 CSS-in-JS 团队则把语义 token 收敛成 TS 常量对象、ESLint `no-restricted-properties` 封死基础层引用。关键是**只留一条注入链**，且 antd 桥与变量体系必须同源（同一个 `buildOklchScale` 的输出喂两端）。
3. **切租户变量残留**（症状：上一租户的 `--tenant-500` 还挂在 root 上，部分组件闪旧色）。根因：方法 B 的 `setProperty` 是覆盖式，"旧租户有、新租户没有"的键会残留。修法：注入后清理循环（遍历 `documentElement.style`，删掉 `--` 开头且不在新 batch 内的键）；或一律走方法 A（style 整体替换天然无此问题）。
4. **三层缓存击不穿**（症状：运营发布新主题，老用户刷新还是旧色，强刷才好）。根因：浏览器/CDN/localStorage 三层都没有"发布事件"感知。修法：版本号进身份——`theme.css?v={version}`、缓存键 `tenant-theme:{id}:v{version}`、logo 等资源 URL 同款；版本号分发请求是唯一禁缓存请求且必须轻量（图纸坑 3）。
5. **echarts 换肤不生效**（症状：切主题图表纹丝不动）。根因一：主题注册同名覆盖对已初始化实例无效；根因二：echarts 实例初始化后不能换主题。修法：重注册用新名字（`tenant-v{++n}`）+ 实例 dispose 重建（M4 的 ThemedChart 模式）。
6. **OKLCH 色板"发灰"**（症状：中间档饱和度明显低于品牌色）。根因：降铬二分过于激进或两端收敛系数太陡。修法：只在超域时降铬（先 `inGamut` 判定）；单测断言"荧光绿输入时 500 档铬值 ≥ 原色铬 × 0.9"（中段 cFactor 恒为 1 保证这一点）。
7. **对比度守门把品牌色改得面目全非**（症状：深色模式主色变成近白）。根因：借档一路借到 50 档。修法：借档下限设在 200（再浅失去品牌识别）；仍不达标输出 warning 提示运营换色，而不是静默改色——可访问性与品牌识别冲突时，把决策交还给人。
8. **FOUC：首帧默认蓝闪一下再变租户绿**。根因：主题异步到达晚于首帧。修法：CSR 在 index.html 内联默认主题关键变量 + 强品牌区骨架；SSR 从 cookie/子域名解析租户、把租户变量内联进首屏 HTML（图纸路线 5）。
