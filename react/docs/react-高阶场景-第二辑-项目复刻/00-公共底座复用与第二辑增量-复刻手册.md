### 2.1 undo/redo 的两个变体与选型

第一辑 00 册给的是 immer `produceWithPatches` 版（补丁流，省内存）；第一辑场景二手册又给过快照式 `useHistory<T>`（全量快照，接入零成本）。第二辑的选型决策表：

| 维度 | 补丁式（createHistoryStore） | 快照式（useHistory） |
|---|---|---|
| 单步状态体积 | 只存 patches（KB 级） | 存整份状态（几十 KB 级） |
| 接入成本 | 每种操作走 `commit(label, recipe)` | 破坏性操作前 `commit(present)` 一行 |
| 适用 | 值编辑极多（属性面板连续输入） | 结构操作为主、状态总量小（画布组件数组、条件树） |

**第二辑推荐**：场景 1/3/5 用**快照式**（编辑对象是"一棵树/一个数组"，总量小，任何操作零差异接入）；场景 2 的节点图用快照式的 `FlowSnapshot { nodes, edges }` 原子快照（图纸 2.6 的论证）。两版代码都在第一辑，直接搬：

```ts
// 补丁式（第一辑 00 册 M7 原样搬运）：适合属性面板的连续值编辑
import { createHistoryStore } from '../store/historyStore'
export const usePropHistory = createHistoryStore<Record<string, unknown>>({})

// 快照式（第一辑场景二手册的 useHistory 原样搬运）：适合结构操作
import { useHistory } from '../store/useHistory'
export function useTreeHistory<T>() {
  return useHistory<T>() // commit(present) / undo(present) / redo(present)
}
```

**验证**：demo 里对同一个对象交替走两种历史（补丁式改 10 次属性、快照式做 3 次结构变更），各自 `cmd+z` 逐步回退互不干扰。

## 3. 增量公共件一：画布坐标系与视口变换（viewport.ts）

**是什么**：场景 1（大屏编辑器）、场景 2（节点图）、场景 5（白板）共享的画布数学——一个 `Viewport { scale, offsetX, offsetY }` 描述"画布坐标系如何映射到屏幕坐标系"，所有交互（点击、拖拽、框选、吸附）都必须经过它换算。图纸：场景 1 的 1.1（scale 适配）与 1.2（坐标换算纪律）、场景 2 的 2.3/2.4（React Flow 的视口）、场景 5 全章（视口模型是白板的第一公民）。

**为什么先做**：三处画布各自实现坐标换算是最常见的翻车源——"编辑器里点不准、吸附差几像素、缩放后拖拽漂移"几乎全是换算口径不统一。把它做成一个纯函数模块，三个场景接同一个真相源。

**接口设计**：

```ts
// src/canvas/viewport.ts —— 画布坐标系与视口变换：三场景共用的数学真相源
export interface Viewport {
  /** 画布 → 屏幕的缩放比：1 = 1:1 */
  scale: number
  /** 画布原点(0,0)在屏幕上的位置（屏幕像素）；平移 = 改这两个值 */
  offsetX: number
  offsetY: number
}

export interface Point { x: number; y: number }
export interface Rect { x: number; y: number; w: number; h: number }

/** 屏幕 → 画布：一切命中检测/拖拽换算的唯一入口 */
export function screenToCanvas(p: Point, vp: Viewport): Point {
  return { x: (p.x - vp.offsetX) / vp.scale, y: (p.y - vp.offsetY) / vp.scale }
}

/** 画布 → 屏幕：渲染参考线/对齐提示回投屏幕时用 */
export function canvasToScreen(p: Point, vp: Viewport): Point {
  return { x: p.x * vp.scale + vp.offsetX, y: p.y * vp.scale + vp.offsetY }
}

/** 内容包围盒 → 视口：让 bbox 恰好装进视口（留 padding），返回应设的 Viewport */
export function fitViewport(bbox: Rect, viewportSize: { w: number; h: number }, padding = 40): Viewport {
  const scale = Math.min(
    (viewportSize.w - padding * 2) / Math.max(bbox.w, 1),
    (viewportSize.h - padding * 2) / Math.max(bbox.h, 1),
    2, // 封顶：内容极小时别放大到离谱
  )
  return {
    scale,
    offsetX: (viewportSize.w - bbox.w * scale) / 2 - bbox.x * scale,
    offsetY: (viewportSize.h - bbox.h * scale) / 2 - bbox.y * scale,
  }
}

/** 缩放锚点：以屏幕上某点为中心缩放（滚轮缩放不"飘"的关键） */
export function zoomAt(vp: Viewport, anchorScreen: Point, nextScale: number): Viewport {
  // 不变量：锚点在缩放前后必须映射到同一画布坐标
  const anchor = screenToCanvas(anchorScreen, vp)
  return {
    scale: nextScale,
    offsetX: anchorScreen.x - anchor.x * nextScale,
    offsetY: anchorScreen.y - anchor.y * nextScale,
  }
}
```

React 侧的容器 hook（把 Viewport 变成受控状态 + 滚轮/拖拽空白平移；场景 1/2/5 各自往里塞业务手势）：

```tsx
// src/canvas/useViewport.ts —— 视口状态 + 滚轮缩放锚点
import { useCallback, useRef, useState, type WheelEvent } from 'react'
import { type Viewport, zoomAt } from './viewport'

const MIN_SCALE = 0.2
const MAX_SCALE = 4

export function useViewport(initial: Viewport = { scale: 1, offsetX: 0, offsetY: 0 }) {
  const [vp, setVp] = useState<Viewport>(initial)
  const containerRef = useRef<HTMLDivElement>(null)

  /** 滚轮缩放：以光标为锚点（ctrl+滚轮是浏览器缩放，务必 preventDefault） */
  const onWheel = useCallback((e: WheelEvent<HTMLDivElement>) => {
    if (!e.ctrlKey && !e.metaKey) return // 普通滚轮留给滚动/平移，按场景决定
    e.preventDefault()
    const rect = containerRef.current?.getBoundingClientRect()
    if (!rect) return
    const factor = e.deltaY < 0 ? 1.1 : 0.9
    setVp(prev =>
      zoomAt(
        prev,
        { x: e.clientX - rect.left, y: e.clientY - rect.top },
        Math.min(MAX_SCALE, Math.max(MIN_SCALE, prev.scale * factor)),
      ),
    )
  }, [])

  return { vp, setVp, containerRef, onWheel }
}

/** 画布层的统一样式：transform 一把梭（GPU 合成，性能好且坐标系天然正确） */
export const canvasLayerStyle = (vp: Viewport): React.CSSProperties => ({
  transform: `translate(${vp.offsetX}px, ${vp.offsetY}px) scale(${vp.scale})`,
  transformOrigin: '0 0',
  position: 'absolute',
  inset: 0,
})
```

**验证**：写 vitest——`screenToCanvas(canvasToScreen(p, vp), vp)` 与 `p` 深相等（往返测试，浮点误差 < 1e-6）；`fitViewport` 对 1920×1080 的 bbox 在 800×600 视口返回 scale ≈ 0.38、内容居中；`zoomAt` 缩放前后锚点的画布坐标不变。

**常见报错与修复**：

1. **缩放后点击偏移**——某处用了 `getBoundingClientRect()` 的屏幕坐标直接当画布坐标。修复：全项目 grep `(clientX|clientY)`，任何参与业务计算的都必须先过 `screenToCanvas`；屏幕坐标只允许出现在事件入口。
2. **滚轮缩放"飘"**——缩放没带锚点（offset 没补偿）。修复：只用 `zoomAt`，禁止手写 `scale * factor` 后直接 set。
3. **1:1 编辑画布被误套视口**——场景 1 图纸 1.2 的结论：大屏编辑器画布默认 1:1（设计稿坐标系），适配缩放发生在**运行态容器**（ScreenContainer），两者别混。编辑器要支持缩放时，视口是"编辑器查看能力"，组件坐标永远是设计稿坐标。

## 4. 增量公共件二：拖拽交互内核（useGestureDrag + applyResize + resolveSnap）

**是什么**：三个可分拆可组合的纯交互件——指针手势（按下/拖动/抬起 + 指针捕获 + 草稿态）、八向缩放换算、对齐吸附求解。图纸：场景 1 的 1.2（八向 handle、反向拖拽计算、吸附线算法）。

**为什么做成内核而不是散在各场景**：三场景的拖拽差异只在"拖什么"（组件/节点/图元），手势与几何换算完全同构；且这里最容易埋"拖出窗口丢事件""每帧写正式状态撑爆 undo 栈"两类跨场景通病。

**接口与实现**（三个函数 + 一个 hook，完整可抄）：

```ts
// src/canvas/gesture.ts —— 拖拽几何：反向拖拽换算 + 吸附求解
import type { Point, Rect } from './viewport'

/** 八向把手：sx/sy 标记控制哪条边（-1 起始边 / 1 结束边 / 0 不影响该轴） */
export const HANDLES = [
  { key: 'nw', cursor: 'nwse-resize', sx: -1, sy: -1 },
  { key: 'n', cursor: 'ns-resize', sx: 0, sy: -1 },
  { key: 'ne', cursor: 'nesw-resize', sx: 1, sy: -1 },
  { key: 'e', cursor: 'ew-resize', sx: 1, sy: 0 },
  { key: 'se', cursor: 'nwse-resize', sx: 1, sy: 1 },
  { key: 's', cursor: 'ns-resize', sx: 0, sy: 1 },
  { key: 'sw', cursor: 'nesw-resize', sx: -1, sy: 1 },
  { key: 'w', cursor: 'ew-resize', sx: -1, sy: 0 },
] as const

const MIN_SIZE = 20

/** 指针位移 → 新矩形。核心是"反向拖拽"：西/北把手固定对侧边，x/y 与 w/h 反向联动 */
export function applyResize(start: Rect, sx: number, sy: number, dx: number, dy: number): Rect {
  let { x, y, w, h } = start
  if (sx === -1) { x = start.x + dx; w = start.w - dx }
  else if (sx === 1) { w = start.w + dx }
  if (sy === -1) { y = start.y + dy; h = start.h - dy }
  else if (sy === 1) { h = start.h + dy }
  if (w < MIN_SIZE) { if (sx === -1) x = start.x + start.w - MIN_SIZE; w = MIN_SIZE }
  if (h < MIN_SIZE) { if (sy === -1) y = start.y + start.h - MIN_SIZE; h = MIN_SIZE }
  return { x, y, w, h }
}

/** 一条对齐参考线：v 竖直（x 坐标）/ h 水平（y 坐标） */
export interface Guide { axis: 'v' | 'h'; offset: number }

const SNAP_THRESHOLD = 6

/** 单轴吸附：被拖元素的每条线 vs 全部候选线，阈值内取绝对差最小者 */
function snapAxis(movingLines: number[], candidates: Guide[], axis: 'v' | 'h'): { delta: number; guide: Guide } | null {
  let best: { delta: number; guide: Guide } | null = null
  for (const line of movingLines) {
    for (const c of candidates) {
      if (c.axis !== axis) continue
      const delta = c.offset - line
      if (Math.abs(delta) > SNAP_THRESHOLD) continue
      if (best === null || Math.abs(delta) < Math.abs(best.delta)) best = { delta, guide: c }
    }
  }
  return best
}

/** 吸附主入口：moving 是跟随指针的原始矩形，siblings 不含被拖元素 */
export function resolveSnap(moving: Rect, siblings: Rect[]): { snapped: Rect; guides: Guide[] } {
  const candidates: Guide[] = siblings.flatMap(r => [
    { axis: 'v' as const, offset: r.x },
    { axis: 'v' as const, offset: r.x + r.w / 2 },
    { axis: 'v' as const, offset: r.x + r.w },
    { axis: 'h' as const, offset: r.y },
    { axis: 'h' as const, offset: r.y + r.h / 2 },
    { axis: 'h' as const, offset: r.y + r.h },
  ])
  const v = snapAxis([moving.x, moving.x + moving.w / 2, moving.x + moving.w], candidates, 'v')
  const h = snapAxis([moving.y, moving.y + moving.h / 2, moving.y + moving.h], candidates, 'h')
  const snapped: Rect = {
    ...moving,
    x: v ? moving.x + v.delta : moving.x,
    y: h ? moving.y + h.delta : moving.y,
  }
  return { snapped, guides: [v?.guide, h?.guide].filter((g): g is Guide => g != null) }
}
```

```tsx
// src/canvas/useGestureDrag.ts —— 手势 hook：捕获 + 草稿层 + 一次 commit
import { useCallback, useRef, useState, type PointerEvent as ReactPointerEvent } from 'react'
import { type Point } from './viewport'

export interface GestureState<T> {
  /** 拖动中的草稿：渲染层优先画它，松手后清空回退正式状态 */
  draft: T | null
  onPointerDown: (e: ReactPointerEvent, start: T) => void
  onPointerMove: (e: ReactPointerEvent) => void
  onPointerUp: () => void
}

/**
 * 通用指针拖拽内核：
 * - pointerdown 时 setPointerCapture：移出元素/窗口不丢事件；
 * - onMove(start, deltaCanvas, event) 返回草稿——delta 已经过视口换算（画布坐标）；
 * - pointerup 一次 commit：一次拖拽 = 一步 undo（外部接历史栈）。
 */
export function useGestureDrag<T>(
  vp: { scale: number; offsetX: number; offsetY: number },
  handlers: {
    onMove: (start: T, delta: Point) => T
    onCommit: (final: T) => void
  },
): GestureState<T> {
  const [draft, setDraft] = useState<T | null>(null)
  const dragRef = useRef<{ start: T; origin: Point } | null>(null)

  const onPointerDown = useCallback((e: ReactPointerEvent, start: T) => {
    e.currentTarget.setPointerCapture(e.pointerId) // 捕获：拖出窗口不丢
    dragRef.current = { start, origin: { x: e.clientX, y: e.clientY } }
  }, [])

  const onPointerMove = useCallback((e: ReactPointerEvent) => {
    const drag = dragRef.current
    if (!drag) return
    // 屏幕位移 → 画布位移：除以 scale，与视口模块的换算纪律一致
    const delta: Point = {
      x: (e.clientX - drag.origin.x) / vp.scale,
      y: (e.clientY - drag.origin.y) / vp.scale,
    }
    setDraft(handlers.onMove(drag.start, delta))
  }, [vp.scale, handlers])

  const onPointerUp = useCallback(() => {
    if (dragRef.current && draft !== null) handlers.onCommit(draft) // 一次拖拽一次 commit
    dragRef.current = null
    setDraft(null)
  }, [draft, handlers])

  return { draft, onPointerDown, onPointerMove, onPointerUp }
}
```

**验证**：demo 画布放三个矩形，拖第四个：靠近兄弟边缘 6px 内出现吸附跳变 + 参考线；按住西把手向右拖到越过东边界，宽度钳在 20px 不翻负；拖动中把鼠标甩出浏览器窗口，事件仍在派发（草稿继续跟随），回窗松手 commit 一次。

**常见报错与修复**：

1. **吸附抖动**——吸附修正把元素挪到阈值边缘，下一帧又脱离。修复：磁滞（进入 6px / 保持 10px）或一次拖拽内锁定首个命中目标（图纸场景 1 的坑清单）。
2. **拖拽结束弹回原位**——commit 的是原始 rect 而不是草稿终值。修复：`onPointerUp` 只 commit `draft`（上面实现的取值顺序就是纪律）。
3. **每帧一次 undo**——pointermove 里直接写正式状态并 commit。修复：草稿层 + 松手一次 commit；undo 粒度 = 一次手势。

## 5. 增量公共件三：协议版本迁移（schema 演进）

**是什么**：一份"旧版本文档 → 当前版本"的迁移链 + 打开文档时的版本协商。第二辑所有会**存库**的协议（场景 1 的 ScreenSchema、场景 2 的 WorkflowDSL、场景 3 的规则条件树、场景 4 的 schema 文档）都躲不开"代码升级了，旧数据怎么办"。图纸：场景 1 的 1.7（物料版本协商）、第一辑 00 册 §4 进阶扩展第 1 条（迁移链铁律）。

**接口设计**：

```ts
// src/protocol/migration.ts —— 协议版本迁移：链式纯函数 + 三档协商
export interface VersionedDoc {
  schemaVersion: string // 如 '1.0.0'
  [key: string]: unknown // 协议本体（ScreenSchema / WorkflowDSL / ConditionTree 均可）
}

/** 单级迁移：from（含）→ 下一版。必须纯函数、必须原样保留 x- 字段 */
export interface MigrationStep {
  from: string
  migrate: (doc: Record<string, unknown>) => Record<string, unknown>
}

export interface Migrator {
  current: string
  steps: MigrationStep[] // 注册顺序无关，migrate 内部按版本排序
}

/** 最小 semver 比较：x.y.z 逐段数值比 */
export function semverGte(a: string, b: string): boolean {
  const pa = a.split('.').map(Number)
  const pb = b.split('.').map(Number)
  return pa[0] !== pb[0] ? pa[0] > pb[0] : pa[1] !== pb[1] ? pa[1] > pb[1] : pa[2] >= pb[2]
}

export type Negotiation =
  | { kind: 'exact' }                        // 版本一致，直接用
  | { kind: 'migratable' }                   // 有迁移路径，升级后用
  | { kind: 'incompatible'; reason: string } // 无路径：降级提示，绝不抛错白屏

export function negotiate(m: Migrator, doc: VersionedDoc): Negotiation {
  if (doc.schemaVersion === m.current) return { kind: 'exact' }
  const hasPath = m.steps.some(s => semverGte(s.from, doc.schemaVersion))
  return hasPath
    ? { kind: 'migratable' }
    : { kind: 'incompatible', reason: `文档版本 ${doc.schemaVersion} 低于最早的迁移起点，无法升级到 ${m.current}` }
}

/** 逐级升级：从 doc.schemaVersion 起沿链爬到 current。纯函数：structuredClone 入参 */
export function migrate(m: Migrator, doc: VersionedDoc): VersionedDoc {
  const chain = [...m.steps]
    .sort((a, b) => a.from.localeCompare(b.from, undefined, { numeric: true }))
    .filter(s => semverGte(s.from, doc.schemaVersion))
  let current: Record<string, unknown> = structuredClone({ ...doc })
  for (const step of chain) {
    current = { ...step.migrate(current), schemaVersion: nextVersionAfter(m, step.from) }
  }
  return current as VersionedDoc
}

/** 找到 from 的下一版（迁移步的隐含目标）；实现上让注册方显式声明更稳，这里取链上下一项 */
function nextVersionAfter(m: Migrator, from: string): string {
  const sorted = [...m.steps].sort((a, b) => a.from.localeCompare(b.from, undefined, { numeric: true }))
  const idx = sorted.findIndex(s => s.from === from)
  return idx >= 0 && idx + 1 < sorted.length ? sorted[idx + 1].from : m.current
}
```

一个真实迁移步的样例（场景 1 的 ScreenSchema 1.4 → 2.0：`font` 数字改名 `fontSize` 字符串——对应图纸 1.7 的破坏性变更例）：

```ts
export const screenMigrator: Migrator = {
  current: '2.0.0',
  steps: [
    {
      from: '1.0.0',
      migrate: doc => ({ ...doc, components: (doc.components as unknown[]).map(c => c) }), // 1.0→1.1：补 layout 字段等
    },
    {
      from: '1.4.0',
      migrate: doc => ({
        ...doc,
        components: (doc.components as Array<Record<string, unknown>>).map(c => ({
          ...c,
          props: { ...(c.props as Record<string, unknown>), fontSize: `${(c.props as { font?: number }).font ?? 14}px`, font: undefined },
        })),
      }),
    },
  ],
}
```

**验证**（vitest）：构造 1.0.0 文档（带 `x-track` 扩展字段），`migrate` 后 `schemaVersion === '2.0.0'`、`x-track` 深相等保留、`props.font` 消失且 `props.fontSize` 为带 px 字符串；`negotiate` 对 `0.9.0` 返回 `incompatible`。

**常见报错与修复**：

1. **迁移后 undo 半新半旧**——迁移函数就地改了传入对象，旧快照被污染。修复：`migrate` 第一行 `structuredClone`（上面已含）；迁移步只返回新对象。
2. **保存时把版本写成最新**——MaterialRef/schemaVersion 必须**保存时刻冻结**为搭建时版本（图纸 1.7 坑 2）。修复：保存链路从文档读取当前版本原样写入，升级只发生在"打开"链路且结果不回写（用户下一次保存才落新版本）。
3. **迁移步漏掉 x- 字段**——迁移步手写 `{ ...新结构 }` 时丢了扩展键。修复：迁移步永远以 `...doc` 起手做浅继承；round-trip 测试里固定放一个 `x-` 字段当哨兵。

## 6. 增量公共件四：Monaco 按需加载（LazyMonaco）

**是什么**：Monaco 是第二辑三处会用到的重型依赖（场景 3 M8 的规则 diff、场景 4 的源码视图、场景 10/毕业项目的语言包 JSON 视图），核心 + json worker 约 300–500 KB。按需加载 = 编辑器代码进独立 chunk，首屏不拉，首次打开代码视图才加载。worker 本地化与完整封装见第一辑 [04 册 M5](../react-复杂场景-项目复刻/04-项目四-JSON-编辑器-复刻手册.md)（monaco-setup.ts / JsonSourceEditor），本册只做"懒入口"这一层。

**接口设计与实现**：


三点工程决策（与第一辑 04 册的结论对齐，此处只列增量）：

2. **单例缓存免费获得**：`React.lazy` 的模块注册表天然缓存——第二次渲染 `LazyMonaco` 零网络请求（Suspense 立即命中）；

**常见报错与修复**：

1. **动态 import 路径是变量**——`import(pkgName)` 无法静态分析，构建不生成 chunk，运行时 404。修复：路径必须字面量（`import('@monaco-editor/react')`）；若要"多编辑器按名懒加载"，用显式映射表 `{ json: () => import('...'), diff: () => import('...') }`。
2. **worker 走了 CDN**——`loader.config` 没接本地 monaco。修复：按第一辑 04 册 M5 的 `monaco-setup.ts` 配置；懒加载只是延迟，不能替代本地化。
3. **加载中布局跳动**——Suspense fallback 没有高度。修复：fallback 固定 `height`（上面实现已含）。

## 7. 增量公共件五：远程 options 拉取的防抖取消层（useRemoteOptions）

**是什么**：远程搜索下拉的统一取数层——防抖 300ms + AbortController 取消在途请求 + 序号守卫丢弃过期响应。图纸：[场景 3 的 3.4 节](../react-高阶场景-第二辑/08-3-4-值编辑器体系-Setter-复用-远程-options-懒加载-防抖-取消.md)（完整版含跨实例缓存层 3.4.3）；消费方：场景 3 的 remote-select/remote-multi-select 编辑器、场景 1 数据映射的候选拉取、场景 2 远程节点（如"选择子流程"）的搜索。

**完整实现**（三防御一件不少，可直接抄）：

```ts
// src/remote/useRemoteOptions.ts —— 防抖 + 取消 + 乱序守卫：远程搜索的三重保险
import { useEffect, useRef, useState } from 'react'

export interface RemoteOption { label: string; value: string }

export interface RemoteSourceSpec {
  /** 搜索接口：返回 { list: Record<string, unknown>[] } */
  url: string
  labelKey?: string // 默认 'name'
  valueKey?: string // 默认 'id'
}

interface RemoteOptionsState {
  options: RemoteOption[]
  loading: boolean
  error: string | null
}

interface SearchResponse { list: Record<string, unknown>[] }

export function useRemoteOptions(
  source: RemoteSourceSpec | undefined,
  keyword: string,
  delay = 300,
): RemoteOptionsState {
  const [state, setState] = useState<RemoteOptionsState>({ options: [], loading: false, error: null })
  const seqRef = useRef(0) // 请求序号：只认最新一次

  useEffect(() => {
    if (!source?.url) return
    const seq = ++seqRef.current
    const controller = new AbortController()      // 取消：上一次 effect 清理时 abort 在途请求
    const timer = setTimeout(async () => {        // 防抖：停止输入 delay 毫秒才发
      setState(s => ({ ...s, loading: true, error: null }))
      try {
        const url = new URL(source.url, window.location.origin)
        url.searchParams.set('keyword', keyword)
        const res = await fetch(url.toString(), { signal: controller.signal })
        if (!res.ok) throw new Error(`搜索接口错误 HTTP ${res.status}`)
        const json = (await res.json()) as SearchResponse
        if (seqRef.current !== seq) return        // 乱序守卫：旧请求晚到，静默丢弃
        const labelKey = source.labelKey ?? 'name'
        const valueKey = source.valueKey ?? 'id'
        setState({
          loading: false,
          error: null,
          options: json.list.map(item => ({
            label: String(item[labelKey] ?? ''),
            value: String(item[valueKey] ?? ''),
          })),
        })
      } catch (e) {
        if ((e as Error).name === 'AbortError') return // 主动取消不算错误
        if (seqRef.current !== seq) return
        setState(s => ({ ...s, loading: false, error: (e as Error).message }))
      }
    }, delay)

    return () => { // 清理：下一次 effect 前，取消计时器与在途请求
      clearTimeout(timer)
      controller.abort()
    }
  }, [source?.url, keyword, delay, source])

  return state
}
```

三个防御各治一种真实事故（缺一不可）：**防抖**治"每键一请求"打爆搜索接口；**取消**治"用户已切走、旧请求仍占连接"；**乱序守卫**治"搜`张`的响应比搜`张三`的后到"——abort 管不到已回到浏览器的响应，只能靠序号比对（图纸 3.4 的原话）。

**验证**：demo 接一个 500ms 延迟的 mock 接口（`setTimeout` 模拟），快速输入"张三丰"——Network 面板只有 1 个请求；输入"张"后 100ms 内改输"李"——"张"的请求状态为 canceled；用两个不同延迟的 mock 让旧请求晚到——下拉最终显示"李"的结果。

**常见报错与修复**：

1. **AbortError 弹错误提示**——把取消当失败。修复：catch 里先判 `(e as Error).name === 'AbortError'` 直接 return（上面已含）。
2. **响应乱序覆盖**——只做了 abort 没做序号。修复：两层都要；effect 每次运行 `++seqRef.current`，落库前比对。
3. **多行同字段并发搜索**——一屏 20 行远程字段各自聚焦各自拉。修复：懒加载（首次聚焦才拉，编辑器组件里控制）+ 图纸 3.4.3 的跨实例缓存层（本册不做，场景 3 册 M4 落地）。

## 8. 复刻坑清单

1. **底座"顺手优化"**：搬运时改了第一辑实现（哪怕一行格式化），后续场景册对底座行为的引用全部失去基准。→ 搬运 = 拷贝 + 改 import 路径，仅此而已；要改先在底座仓库改并跑它的测试。
2. **视口换算散落手算**：某处 `(clientX - rect.left) / scale` 手写了一遍，换视口模型后漏改。→ 全项目只允许 `screenToCanvas` 一个入口，grep 纪律见 §3 验证。
3. **zoomAt 的锚点用了画布坐标**：锚点必须是**屏幕坐标**（事件给的 `clientX/clientY` 减容器 rect），传反了缩放围绕错误中心旋转。
4. **拖拽把手吞了点击**：`listeners` 铺在整块元素上，元素内的按钮点不到。→ 手势绑在把手元素上（第一辑 dnd 内核同款纪律）。
5. **迁移步里访问不存在的字段**：旧版文档没有 `props` 键，`(c.props as ...) .font` 抛 undefined。→ 迁移步对每个访问的字段做 `?? 默认值` 防御——它要吃的是"最老的文档"。
6. **React.lazy 组件每渲染重建**：`lazy(() => import(...))` 写在组件函数体内，每次渲染新 lazy 实例，Suspense 反复挂起。→ lazy 调用必须在模块级（上面实现已含）。
7. **useRemoteOptions 的依赖数组漏 source**：`source` 对象每渲染新建引用，effect 每帧重跑、防抖失效。→ 调用方 `useMemo` 住 source，或依赖数组用 `source?.url`（实现里两者都写了，调用方仍要保证 source 引用稳定）。
8. **序号守卫放错位置**：`seqRef.current !== seq` 判在 setState 之后。→ 必须在写状态**之前**判，否则旧响应已经污染了一次渲染。
9. **草稿态漏渲染**：commit 后正式状态与草稿不一致的那一帧闪烁。→ 渲染层 `const shown = draft ?? official`，一次表达式完成切换。
10. **公共件先于场景"过度设计"**：视口模块提前做了虚拟化、拖拽内核提前做了多点触控。→ 本册只做三个场景**都**要的最小交集，场景特有需求（白板的手写笔、节点图的手势模式）回各场景册做。
