# 场景 5 复刻手册：无限画布白板工具

> 一句话目标：从零复刻一块自研无限画布——视口变换（pan/zoom 仿射矩阵与逆变换）、屏幕→世界坐标的精确命中检测、多选框选与 8 向变换手柄（旋转元素不歪）、协同基础（CRDT/OT 选型一瞥 + 元素级 last-write-wins 简化版）、以及性能三件套（脏区重绘、离屏 canvas 分层、缩放级细节分层）。"无限"的本质是**渲染成本只与可见元素数成正比、与画布总面积无关**。预计工期：1.5 周。前置要求：第一辑 00 手册（命令栈/拖拽思想）+ 图纸 16 号文件路线 1–3 通读。

## 0. 目标与总验收

- [ ] **视口变换**：`screenToWorld/worldToScreen/zoomAt` 通过锚点不变式单测（缩放前后鼠标下的世界点坐标差 < 1e-9）；鼠标压住画布上任意标记连滚 5 档，标记不滑移；zoom 夹在 [0.1, 4]
- [ ] **矩阵内核**：camera 与矩阵互转（`cameraMatrix/invert/apply`），DOM 渲染路径与 canvas 渲染路径共用同一套数学——改一处两处生效
- [ ] **命中检测**：屏幕坐标 → 世界坐标 → 按空间索引 z 序返回命中元素；旋转 30° 的矩形命中用局部系判定（不用虚胖的外接矩形）；命中容差 = 屏幕恒定 4px（`4 / zoom` 换算）
- [ ] **框选与手柄**：橡皮筋框选与元素 bbox 求交（反向拖拽矩形已规范化）；8 向缩放中"旋转元素拖边柄"不歪（先 worldToLocal 再动尺寸）；旋转 Shift 吸附 15°
- [ ] **协同简化版**：两个浏览器标签页（BroadcastChannel 模拟远端）同时增删移元素——并发修改同一元素按 last-write-wins 合并，删赢增（墓碑）、增赢改；删除有墓碑，后到的旧更新不会复活元素
- [ ] **性能**：10 万元素下平移/缩放 ≥ 50fps（rbush 视口裁剪）；拖选区框时 Performance 帧Profile 中不出现 `drawStatic`（分层生效）；zoom=0.2 与 zoom=4 时选中框线宽的屏幕观感一致（反补偿生效）
- [ ] **dpr**：Retina 屏（dpr=2）无模糊；触控板双指捏合走 `wheel + ctrlKey` 分支且不触发浏览器整页缩放

## 2. 里程碑切分

### M1 视口变换：矩阵与逆变换（约 1.5 天）

**目标**：camera 三元组 + 仿射矩阵内核 + 三种平移入口（空格/中键/触控板）全部可用。

**做什么**：

1. `camera.ts`：`Camera { x, y, zoom }` 与 `screenToWorld/worldToScreen/zoomAt`（图纸路线 1 的 15 行核心原样抄，公式推导图纸已给：逆变换 = 逆序执行逆运算，先减平移再除缩放）；
2. `matrix.ts`：2×3 仿射矩阵 `mul/invert/apply` + `cameraMatrix(cam)`（§4 核心代码）——canvas 的 `setTransform(a,b,c,d,e,f)` 与 CSS 的 `translate() scale()` 都由它生成，两条渲染路径共用一份真相；
3. 交互层：`usePanZoom`（图纸路线 2 的 wheel 分发器 + 空格/中键 pointer 平移，`passive: false` 与中键无条件 `preventDefault` 两个坑内置）。

**验收**：

```bash
npx vitest run src/whiteboard/camera.test.ts src/whiteboard/matrix.test.ts
```

- 锚点不变式：随机 10 组 (camera, mouse, factor)，断言 `screenToWorld(mouse, zoomAt(mouse, factor, cam)) ≈ screenToWorld(mouse, cam)`；
- 矩阵一致性：`apply(cameraMatrix(cam), p) === worldToScreen(p, cam)` 对随机 100 点成立；`apply(invert(m), apply(m, p)) ≈ p`；
- 手测：画布放一个"★"，鼠标压住它连缩 5 档不滑移；中键拖拽不触发浏览器自动滚动罗盘。

### M2 元素命中检测（约 1 天）

**目标**：屏幕坐标 → 世界坐标 → 命中元素；空间索引支持 10 万级元素。

**做什么**：

1. `spatialIndex.ts`：rbush 封装（`bulkLoad/insert/update/remove/queryVisible`，图纸路线 3 的 update = remove 旧引用 + insert 新引用语义必须保留）；`shapeBBox` 算旋转外接矩形、笔迹外扩半线宽；

**验收**：`npx vitest run src/whiteboard/hit.test.ts`——轴对齐/旋转 30°/含容差/空点四类用例；10 万矩形 `bulkLoad` + 逐帧 `queryVisible` 耗时 < 2ms（Performance 计时）。

### M3 多选框选与变换手柄（约 2 天）

**目标**：橡皮筋多选 + 选集 8 向缩放 + 旋转 + 对齐吸附线。

**做什么**：`geometry.ts`（`worldToLocal/localToWorld/hitRect/resizeRect/rotateRect/rectsIntersect/normalizeRect`，图纸路线 4 整段可抄——本手册 §4 只保留最常被改错的三个）；`snap.ts` 六线吸附（阈值 `6 / zoom`）；命令栈：拖拽合并为一条命令（pointerdown 记 before，pointerup 构造 `{before, after}`——命令的粒度是"用户意图"不是"帧"）。

**验收**：旋转 30° 的矩形拖"东"边柄只变宽不斜长；跨视口巨大元素平移不消失（bbox 含旋转外接）；框选含反向拖拽；拖动中 6 条参考线吸附出辅助线且 0.2/4 倍 zoom 下吸附观感一致；一次拖拽 = undo 一步。

### M4 协同基础：选型一瞥与 LWW 简化版（约 2 天）

**目标**：理解 CRDT/OT 的分界，并实现"元素级 last-write-wins"的多人同步最小版。

**做什么**：

1. 先读图纸路线 8 的 Yjs 三面（数据面 `Y.Map<id, shape>` / 感知面 awareness / 撤销面 `Y.UndoManager`）建立地图；
2. 自写简化版 `lwwStore.ts`（§4 核心代码）：每个元素带 `(lamportTs, siteId)` 二元组，远程操作按它合并；删除用墓碑（tombstone）；操作通过 BroadcastChannel 模拟网络（两个标签页即"双人"）；
3. 本地命令栈与远端合并解耦：本地操作立刻应用并广播；远端操作走同一 `apply` 入口但不进本地 undo 栈（简化版用"undo 只回滚自己的操作"近似 Y.UndoManager 语义）。

**验收**：双标签页增/删/移元素互见（BroadcastChannel）；同一元素两端并发改名，一端胜出且两端最终一致（刷新后仍一致——状态来自同一 localStorage 快照）；元素删除后，迟到的旧"移动"操作不能复活它（墓碑生效）；`npx vitest run src/whiteboard/lww.test.ts` 含并发三用例。

### M5 性能：脏区重绘、分层、缩放级细节分层（约 2 天）

**目标**：拖选区框不重画全场景；静态层离屏缓存；zoom 相关的"屏幕语义量"全部反补偿。

**做什么**：

1. `CanvasStage`：双 canvas 叠放（静态层在下、交互层在上）+ 单 rAF 调度器 + 分层脏标记（图纸路线 7；教学版 setInterval 轮询要改成"变更处显式 `scheduleStatic()/scheduleInteract()`"）；
2. rbush 视口裁剪接入 `drawStatic`（M2 已有，这里接线）；
3. LOD（缩放级细节分层）：① 屏幕语义量反补偿——`lineWidth = 1.5/zoom`、手柄 `8/zoom`、命中容差 `4/zoom`；② 内容细节分层——zoom < 0.5 时笔迹降级为折线段（不走贝塞尔）、文本用矩形占位；zoom > 2 时才画阴影（图纸路线 7/补充瓦片缓存的思想，先做廉价的细节开关，瓦片缓存留作扩展）。

**验收**：Performance 面板录 10 秒"仅拖选区框"，火焰图无 `drawStatic`；10 万元素平移 ≥ 50fps；0.2→4 逐档缩放，选中框边框与手柄的屏幕观感全程一致；`ctx.lineWidth` 相关断言进单测（`screenLineWidth(cam) === 1.5 / cam.zoom`）。

```ts
// src/whiteboard/types.ts
export interface Camera { x: number; y: number; zoom: number } // x/y：world 原点在屏幕上的位置（CSS 像素）

/** 2×3 仿射矩阵：[a c e; b d f; 0 0 1]，与 canvas setTransform 同序 */
export interface Mat { a: number; b: number; c: number; d: number; e: number; f: number }
export interface Pt { x: number; y: number }
export interface BBox { minX: number; minY: number; maxX: number; maxY: number }

export type ShapeKind = 'rect' | 'ellipse' | 'stroke' | 'text';
export interface ShapeBase { id: string; kind: ShapeKind; z: number }
export interface BoxShape extends ShapeBase {
  kind: 'rect' | 'ellipse' | 'text';
  x: number; y: number; w: number; h: number; rotation: number; // x/y：未旋转时的左上角；rotation 弧度
  fill?: string; text?: string;
}
export interface StrokeShape extends ShapeBase {
  kind: 'stroke';
  points: { x: number; y: number; pressure: number }[];
  color: string; baseWidth: number;
}
export type Shape = BoxShape | StrokeShape;

/** 协同简化版：元素级 LWW。lamportTs 单调递增逻辑钟（每次本地操作 max(已知)+1），siteId 决胜平局 */
export interface LwwMeta { lamportTs: number; siteId: string }
export type Op =
  | { type: 'upsert'; shape: Shape } & LwwMeta
  | { type: 'delete'; id: string } & LwwMeta; // 增/改共享 upsert 语义；删靠墓碑压制

export interface LwwEntry<T> { value: T | null; meta: LwwMeta } // value=null 即墓碑
```

## 4. 核心代码摘录

### 4.1 变换栈：矩阵内核与 camera 互转（M1）

```ts
// src/whiteboard/matrix.ts —— DOM 与 canvas 共用的一份数学
import type { Camera, Mat, Pt } from './types';

export const IDENT: Mat = { a: 1, b: 0, c: 0, d: 1, e: 0, f: 0 };

/** 矩阵复合：mul(m1, m2) 表示"先作用 m2，再作用 m1"（矩阵乘法的 2×3 展开） */
export function mul(m1: Mat, m2: Mat): Mat {
  return {
    a: m1.a * m2.a + m1.c * m2.b,
    b: m1.b * m2.a + m1.d * m2.b,
    c: m1.a * m2.c + m1.c * m2.d,
    d: m1.b * m2.c + m1.d * m2.d,
    e: m1.a * m2.e + m1.c * m2.f + m1.e,
    f: m1.b * m2.e + m1.d * m2.f + m1.f,
  };
}

export function apply(m: Mat, p: Pt): Pt {
  return { x: m.a * p.x + m.c * p.y + m.e, y: m.b * p.x + m.d * p.y + m.f };
}

/** 行列式为 0 不可逆（缩放为 0 时会出现） */
export function invert(m: Mat): Mat | null {
  const det = m.a * m.d - m.b * m.c;
  if (det === 0) return null;
  const invDet = 1 / det;
  return {
    a: m.d * invDet, b: -m.b * invDet,
    c: -m.c * invDet, d: m.a * invDet,
    e: (m.c * m.f - m.d * m.e) * invDet,
    f: (m.b * m.e - m.a * m.f) * invDet,
  };
}

/** camera → 矩阵：先 scale 再 translate（与 worldToScreen 公式严格一致） */
export function cameraMatrix(cam: Camera): Mat {
  return { a: cam.zoom, b: 0, c: 0, d: cam.zoom, e: cam.x, f: cam.y };
}

/**
 * 变换栈：嵌套容器（分组/画板内画板）的世界矩阵 = 栈上矩阵依次复合。
 * 渲染 DOM 时：transform = translate(e,f) scale(a,d)（2×3 无 shear 时等价）；
 * 渲染 canvas 时：ctx.setTransform(a, b, c, d, e, f)——同一个 Mat，两条路径零换算。
 */
export class TransformStack {
  private stack: Mat[] = [IDENT];
  push(m: Mat): void { this.stack.push(mul(this.current(), m)); }
  pop(): Mat | undefined { return this.stack.length > 1 ? this.stack.pop() : undefined; }
  current(): Mat { return this.stack[this.stack.length - 1] ?? IDENT; }
  /** 屏幕点 → 当前局部坐标：求当前矩阵的逆再 apply（局部命中检测的通用入口） */
  toLocal(p: Pt): Pt | null {
    const inv = invert(this.current());
    return inv ? apply(inv, p) : null;
  }
}
```

`zoomAt`（锚点缩放）与 `screenToWorld` 直接用图纸 camera.ts 的实现；它的推导结论一句话背下来：**新平移 = 鼠标位置 − 鼠标下的世界点 × 新缩放**，clamp 命中后必须用实际缩放比 `real = zoom / cam.zoom` 而不是传入 factor。

### 4.2 命中检测：屏幕 → 世界 → 局部（M2）

```ts
// src/whiteboard/hitTest.ts
import type { BBox, BoxShape, Camera, Pt, Shape } from './types';
import { screenToWorld } from './camera';
import type { SpatialIndex } from './spatialIndex';

/** 局部系（原点=元素左上角、未旋转）判定：不用外接矩形凑合——旋转后 bbox 虚胖 */
export function worldToLocal(p: Pt, s: BoxShape): Pt {
  const cx = s.x + s.w / 2, cy = s.y + s.h / 2;
  const cos = Math.cos(-s.rotation), sin = Math.sin(-s.rotation);
  const dx = p.x - cx, dy = p.y - cy;
  return { x: dx * cos - dy * sin + s.w / 2, y: dx * sin + dy * cos + s.h / 2 };
}

export function hitRect(p: Pt, s: BoxShape, tolerance = 0): boolean {
  const l = worldToLocal(p, s);
  return l.x >= -tolerance && l.x <= s.w + tolerance
      && l.y >= -tolerance && l.y <= s.h + tolerance;
}

/** 笔迹命中：先 bbox 粗筛（索引已做），再对相邻点做"点到线段距离"细判 */
export function hitStroke(p: Pt, pts: { x: number; y: number }[], halfWidth: number): boolean {
  if (pts.length === 1) return Math.hypot(p.x - pts[0]!.x, p.y - pts[0]!.y) <= halfWidth + 2;
  for (let i = 1; i < pts.length; i++) {
    if (segDist(p, pts[i - 1]!, pts[i]!) <= halfWidth + 2) return true;
  }
  return false;
}
function segDist(p: Pt, a: Pt, b: Pt): number {
  const dx = b.x - a.x, dy = b.y - a.y;
  const lenSq = dx * dx + dy * dy;
  if (lenSq === 0) return Math.hypot(p.x - a.x, p.y - a.y);
  // 钳到线段范围：命中关心的是"点到线段"而非"点到无限直线"
  const t = Math.max(0, Math.min(1, ((p.x - a.x) * dx + (p.y - a.y) * dy) / lenSq));
  return Math.hypot(p.x - (a.x + t * dx), p.y - (a.y + t * dy));
}

/**
 * 总入口：屏幕点 → 世界点 → 视口附近粗筛 → 按 z 序从上往下细判。
 * tolerance 用"屏幕恒定 4px"语义：zoom 越小世界容差越大，可点面积观感一致（反补偿）。
 */
export function hitTest(
  screen: Pt, cam: Camera, shapes: Map<string, Shape>, index: SpatialIndex,
): Shape | null {
  const world = screenToWorld(screen, cam);
  const tol = 4 / cam.zoom;
  const near: BBox = { minX: world.x - tol * 4, minY: world.y - tol * 4, maxX: world.x + tol * 4, maxY: world.y + tol * 4 };
  const candidates = index.queryVisible(near)
    .map((id) => shapes.get(id))
    .filter((s): s is Shape => Boolean(s))
    .sort((a, b) => b.z - a.z); // z 大者在上，先被命中
  for (const s of candidates) {
    if (s.kind === 'stroke') {
      if (hitStroke(world, s.points, s.baseWidth / 2)) return s;
    } else if (hitRect(world, s, tol)) {
      return s;
    }
  }
  return null;
}
```

### 4.3 框选数学（M3）

```ts
// src/whiteboard/marquee.ts —— 橡皮筋框选：规范化 + 求交 + 笔迹 bbox 参与
import type { BBox, Camera, Pt, Shape } from './types';
import { screenToWorld } from './camera';
import { shapeBBox, strokeBBox } from './spatialIndex';

/** 拖拽可能反向（右下→左上）：先规范化成 min/max 形态，求交才有意义 */
export function normalizeRect(p1: Pt, p2: Pt): BBox {
  return { minX: Math.min(p1.x, p2.x), minY: Math.min(p1.y, p2.y),
           maxX: Math.max(p1.x, p2.x), maxY: Math.max(p1.y, p2.y) };
}

export function rectsIntersect(a: BBox, b: BBox): boolean {
  return a.minX <= b.maxX && b.minX <= a.maxX && a.minY <= b.maxY && b.minY <= a.maxY;
}

/** 框选 = "拖拽矩形的 world bbox" 与 "每个元素 bbox" 求交。
 *  视觉上的橡皮筋矩形画在交互层（屏幕坐标即可），判定一律换算到 world——两套坐标别混用 */
export function marqueeSelect(
  startScreen: Pt, endScreen: Pt, cam: Camera, shapes: Map<string, Shape>,
): string[] {
  const rect = normalizeRect(screenToWorld(startScreen, cam), screenToWorld(endScreen, cam));
  const hit: string[] = [];
  for (const s of shapes.values()) {
    const bbox = s.kind === 'stroke'
      ? strokeBBox({ id: s.id, points: s.points, baseWidth: s.baseWidth })
      : shapeBBox(s);
    if (rectsIntersect(rect, bbox)) hit.push(s.id);
  }
  return hit;
}
```

### 4.4 元素级 LWW 协同简化版（M4）

```ts
// src/whiteboard/lwwStore.ts —— Yjs 之前的"手写一遍"：合并内核 + 操作广播
import type { LwwEntry, LwwMeta, Op, Shape } from './types';

/** LWW 决胜：lamportTs 大者胜；平局比 siteId（字符串比较，全序可复现——两端结论必须一致） */
export function lwwNewer(incoming: LwwMeta, current: LwwMeta): boolean {
  return incoming.lamportTs > current.lamportTs
      || (incoming.lamportTs === current.lamportTs && incoming.siteId > current.siteId);
}

export class LwwBoardStore {
  private entries = new Map<string, LwwEntry<Shape>>();
  private clock = 0; // lamport 逻辑钟：见过的一切 ts 取 max，本地操作 +1

  constructor(private readonly siteId: string,
              private readonly broadcast: (op: Op) => void,
              private readonly onChange: () => void) {}

  /** 本地操作：先推进逻辑钟，立即应用，再广播 */
  upsertLocal(shape: Shape): void {
    const op: Op = { type: 'upsert', shape, ...this.nextMeta() };
    this.apply(op);
    this.broadcast(op);
  }

  deleteLocal(id: string): void {
    const op: Op = { type: 'delete', id, ...this.nextMeta() };
    this.apply(op);
    this.broadcast(op);
  }

  /** 远端与本地的唯一汇入口：删赢增（墓碑压制迟到的 upsert）、LWW 决胜 */
  apply(op: Op): void {
    this.clock = Math.max(this.clock, op.lamportTs); // 逻辑钟对齐
    const cur = this.entries.get(op.type === 'delete' ? op.id : op.shape.id);
    if (cur && !lwwNewer(op, cur.meta)) return;      // 旧操作（含迟到广播）直接丢弃
    if (op.type === 'upsert') {
      this.entries.set(op.shape.id, { value: op.shape, meta: { lamportTs: op.lamportTs, siteId: op.siteId } });
    } else {
      this.entries.set(op.id, { value: null, meta: { lamportTs: op.lamportTs, siteId: op.siteId } }); // 墓碑
    }
    this.onChange();
  }

  /** 渲染视图：墓碑不出现（但保留在 entries 里压制迟到写——这就是"删赢增"的实现位置） */
  visibleShapes(): Shape[] {
    const out: Shape[] = [];
    for (const e of this.entries.values()) if (e.value) out.push(e.value);
    return out;
  }

  private nextMeta(): LwwMeta {
    this.clock += 1;
    return { lamportTs: this.clock, siteId: this.siteId };
  }
}

// 接线：BroadcastChannel 模拟网络层（换 WebRTC/WebSocket 只改这两个函数）
export function createChannel(siteId: string, store: LwwBoardStore): BroadcastChannel {
  const ch = new BroadcastChannel('whiteboard-demo');
  ch.onmessage = (e: MessageEvent<Op>) => {
    if ((e.data as { siteId?: string }).siteId !== siteId) store.apply(e.data); // 不回放自己的消息
  };
  return ch;
}
```

为什么这是"简化版"、它与真 CRDT 的差距要能说清：LWW 是**元素粒度**的整值覆盖——两人同时改同一矩形的 x 和颜色，只有一方的完整 shape 存活（另一方的改动丢失）；Yjs 的 Y.Map 是**属性粒度**的 CRDT，两个属性各自存活。判据：编辑冲突粒度 = 元素级（白板拖动）时 LWW 够用；文本/属性级并发编辑必须真 CRDT。OT 与 CRDT 的分界一句话：OT 需要中心服务器变换操作顺序（Google Docs 路线），CRDT 的合并在数学上保证收敛、服务器只做转发（Yjs 路线）——白板/文档协同选后者，因为"服务端无脑转发"的运维成本碾压"理解文档的中枢"。

协同选型一瞥（M4 的决策依据，面试常考）：

| | OT（Operational Transformation） | CRDT（Yjs/Y.Map） | 元素级 LWW（本册） |
|---|---|---|---|
| 收敛机制 | 中心服务器对并发操作做变换（transform），客户端按服务端顺序回放 | 数据结构自带合并律，任意顺序到达数学上保证收敛，服务器只转发 | 时间戳/站点号全序决胜，整值覆盖 |
| 服务器 | 必须理解操作语义（中枢） | 无脑广播即可 | 同 CRDT（BroadcastChannel 即可模拟） |
| 离线编辑 | 难（依赖服务端顺序裁决） | 天然支持（重连即合并） | 合并粒度粗，长离线后丢并发写 |
| 冲突粒度 | 字符/属性级 | 字符/属性级 | 元素级 |
| 典型适用 | Google Docs 式强一致文档 | 白板/文档/表单协同（Yjs 生态） | 元素互斥编辑的轻量白板、状态同步 |
| 本项目定位 | 不选：中枢运维成本高 | 场景 6 手册 §4.4 的接入点 | M4 亲手写一遍，理解 CRDT 在替你解决什么 |

### 4.5 双层 canvas 调度器（M5）

```ts
// src/whiteboard/scheduler.ts —— 分层脏标记 + 单 rAF：同帧多次标脏只画一次
export class PaintScheduler {
  private dirty = { static: false, interact: false };
  private rafId = 0;
  private afterPaint: Array<() => void> = [];

  constructor(
    private readonly drawStatic: () => void,
    private readonly drawInteract: () => void,
  ) {}

  /** 变更源显式标脏：元素数据/camera 变化标 static；选区/手柄/吸附线/进行中笔迹标 interact */
  markStatic(): void { this.dirty.static = true; this.schedule(); }
  markInteract(): void { this.dirty.interact = true; this.schedule(); }

  private schedule(): void {
    if (this.rafId === 0) {
      this.rafId = requestAnimationFrame(() => {
        this.rafId = 0;
        if (this.dirty.static) this.drawStatic();   // 静态层绘制内部先视口裁剪（rbush queryVisible）
        if (this.dirty.interact) this.drawInteract();
        this.dirty = { static: false, interact: false };
        for (const fn of this.afterPaint.splice(0)) fn(); // 绘制后回调（测试钩子/帧率统计）
      });
    }
  }

  onPaint(fn: () => void): void { this.afterPaint.push(fn); }
  dispose(): void { if (this.rafId !== 0) cancelAnimationFrame(this.rafId); this.rafId = 0; }
}

// LOD（缩放级细节分层）的开关集中在绘制器一处，调度器不感知：
// const detail = cam.zoom < 0.5 ? 'low' : cam.zoom > 2 ? 'high' : 'mid';
// low：笔迹降级折线（跳过贝塞尔平滑）、文本画矩形占位、跳过阴影；
// high：完整贝塞尔 + 阴影；手柄可点面积仍是命中层的 8/cam.zoom（屏幕恒定量）。
```

## 5. 坑与调试

1. **越缩越跑**（症状：鼠标指着一点连缩几档，它滑出视口）。根因：screenToWorld 写成 `screen/zoom - camera`（减除顺序颠倒）。修法：先减平移再除缩放；锚点不变式单测是白板工程性价比最高的一个测试。
2. **旋转元素拖边柄斜着长**（症状：拖"东"边柄矩形一边转一边变平行四边形）。根因：在世界系直接拿指针 Δx 改宽度——旋转后元素的宽方向与世界 x 轴不共线。修法：`worldToLocal` 进局部系改尺寸，新中心 `localToWorld` 回去，rotation 全程不动（图纸路线 4 的 `resizeRect`）。
3. **索引改字段后命中错乱**（症状：拖动后元素"消失"直到刷新）。根因：直接改了 rbush 里缓存的 bbox 对象字段，父节点 MBR 不再罩住它。修法：移动 = `remove(旧引用) → 改数据 → insert(新项)`，绝不全等复用旧对象。
4. **1px 线/手柄随 zoom 忽粗忽细**（症状：zoom=4 选中框细如发丝、zoom=0.2 粗成色带）。根因：屏幕语义量（线宽/手柄/容差）写死在 world 坐标。修法：一律 `/ zoom`；验证法是 0.2→4 逐档缩放观感一致。
5. **wheel preventDefault 静默失效**（症状：触控板捏合把整页缩放了）。根因：wheel 监听默认 `passive: true`。修法：`addEventListener('wheel', fn, { passive: false })` + 无条件 `preventDefault`；容器补 `touch-action: none`。
6. **Retina 模糊**（症状：dpr=2 屏上内容发虚）。根因：canvas 物理分辨率没乘 dpr。修法：`canvas.width = cssW * dpr` + `ctx.setTransform(dpr,0,0,dpr,0,0)`，之后一律按 CSS 像素画。
7. **LWW 平局抖动**（症状：两端并发同一操作，刷新后结果随机翻转）。根因：平局无决胜或用 `Math.random()`。修法：siteId 字符串比较做全序决胜（§4.4），同一组操作任何顺序到达、任何端重放，最终状态一致——把"乱序到达"写进单测（两个 op 交换顺序断言结果相同）。
8. **拖拽 60 帧 60 条 undo**（症状：撤销一次只挪回 1px）。根因：每个 pointermove 都 push 命令。修法：命令只在 pointerup 构造一次（before/after 快照）；过程态直接改数据不入栈。

## 附 2：wheel 分发器（M1 的交互层收口）

```ts
// src/whiteboard/onWheel.ts —— 捏合/滚轮的分发骨架（图纸路线 2 的要点浓缩）
import type { Camera, Pt } from './types';
import { zoomAt } from './camera';

export function createWheelHandler(
  el: HTMLElement,
  getCam: () => Camera,
  setCamera: (c: Camera) => void,
) {
  const onWheel = (e: WheelEvent) => {
    e.preventDefault(); // ① 无条件阻止默认（页面滚动/整页缩放）——前提是 ② 的 passive:false
    const cam = getCam();
    const rect = el.getBoundingClientRect();
    const mouse: Pt = { x: e.clientX - rect.left, y: e.clientY - rect.top };
    if (e.ctrlKey || e.metaKey) {
      // ③ 触控板捏合（Chrome/Firefox 合成为 wheel+ctrlKey）或 Ctrl+滚轮：锚点缩放
      //    exp 曲线：滚轮 delta 是"格"，指数映射让每格手感均匀
      setCamera(zoomAt(mouse, Math.exp(-e.deltaY * 0.01), cam));
    } else {
      // ④ 普通滚动/双指平移：内容跟手 = camera 反向移动；Firefox 的"行"delta ×16 折算像素
      const k = e.deltaMode === 1 ? 16 : e.deltaMode === 2 ? window.innerHeight : 1;
      setCamera({ ...cam, x: cam.x - e.deltaX * k, y: cam.y - e.deltaY * k });
    }
  };
  el.addEventListener('wheel', onWheel, { passive: false }); // ② 非 passive 是 preventDefault 生效的前提
  return () => el.removeEventListener('wheel', onWheel);
}
// 配套 CSS 不能省：容器 touch-action: none（触屏双指手势的第一道闸）、user-select: none。
```
