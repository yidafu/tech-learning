# React 高阶场景第二辑 · 项目复刻手册

> 本目录是《[react-高阶场景-第二辑](../react-高阶场景-第二辑/README.md)》9 个场景的**项目化复刻版**：把每个场景拆成"里程碑 → 每步验收 → 关键代码摘录 → 坑与调试"的施工手册，目标是"照着手册从零做出来，每一步都可运行、可验证"。文档讲"是什么 / 为什么"，手册讲"分几步做出来 / 每步验收什么"——两者配合使用，先读文档看懂原理，再按手册动手施工。

## 两条依赖线：图纸与地基

复刻第二辑的任何场景之前，先认清这套手册站在哪两条线上：

1. **图纸线：第二辑文档（必读）**。每个场景手册都是对应文档的"施工图"——手册里不复述机制论证，直接给施工顺序与验收口径。开工前至少把对应场景的文档通读一遍，卡壳时回到图纸找"为什么"。
2. **地基线：第一辑《[react-复杂场景-项目复刻](../react-复杂场景-项目复刻/README.md)》的公共底座（必备）**。第一辑 00 册的"协议思想 / 注册表 / 递归渲染器 / 表达式引擎 / 受控数据流 / Undo-Redo / dnd 内核 / 大树性能"是第二辑全场景共用的地基；第二辑在它之上新增的跨场景公共件（画布视口变换、拖拽交互内核、协议版本迁移、Monaco 按需加载、远程 options 防抖取消层）收拢在本目录 [00 册](00-公共底座复用与第二辑增量-复刻手册.md)——**先做 00 册，再进场景册**。

## 复刻节奏建议

**第一步永远是 00 册（共用件先行）**。第二辑的搭建器族共享同一批增量公共件：视口变换是场景 1/2/5 的画布地基，拖拽内核与吸附是场景 1/2/3 的交互地基，协议版本迁移与远程 options 防抖取消层贯穿全部场景。这些件每延迟一步落地，后面每个场景都要多写一份临时替代品，最后再痛苦合并。

**场景顺序建议：3 → 1 → 2 → 4 → 5 → 6 → 8/9/10 → 毕业项目**：

1. **场景 3（动态查询构建器）最先做**——它被第二辑标为 ★★★ 全量场景不是偶然：协议（条件树）、递归渲染、Setter 二维化、协议转换、校验、试运行全部在内，且**不依赖画布**，是检验"第一辑内核 + 00 册公共件"成色的最短闭环；
2. **场景 1（页面搭建器）第二**——自由画布 + 物料两层注册表 + 属性面板，把 00 册的视口/拖拽/吸附三件套第一次用在真实编辑器上；
3. **场景 2（工作流节点图）第三**——在场景 1 的画布经验上引入 React Flow 与图数据结构（DAG/拓扑/连线校验），图算法是它独有的增量；
4. 场景 4/5/6 按兴趣与时间选做（4 是"用 schema 编辑 schema"的元编程，5 是视口模型的极限压力，6 独立内核最重）；
5. 场景 8/9/10（权限/主题/i18n）轻量，可穿插在搭建器族之间"换脑子"；
6. **毕业项目（多租户 SaaS 控制台）收官**——把编辑器族产物与平台能力族缝成一个完整系统。

时间紧张时的最小路线：00 → 3 → 1 → 毕业项目（用 3+1 的产物撑起控制台的"规则配置 + 页面搭建"两块核心）。

## 与第二辑 / 第一辑的关系

- **与第二辑文档**：文档是图纸（机制、论证、对标、完整代码），手册是施工图（顺序、验收、摘录、坑的排查口径）。手册中每一步都标注了对应的图纸章节，遇到"为什么这么设计"回文档查。
- **与第一辑复刻手册**：第一辑 00 册是地基，本目录 00 册是"地基复用清单 + 第二辑增量"；第一辑的五个项目（动态表单/Form Builder/仪表盘/JSON 编辑器/低代码平台）是第二辑场景的前置经验——没做过第一辑也能照本目录施工，但"为什么内核能复用"的体感会打折扣，建议至少完成第一辑 00 册与项目一。
- 每册开头 §0 附"验收清单"，逐条打勾即该册复刻完成；全部 11 册完成后，回到第二辑的毕业项目文档对照查缺。
