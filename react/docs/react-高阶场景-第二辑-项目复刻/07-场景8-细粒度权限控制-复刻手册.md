# 场景 8 复刻手册：细粒度权限控制

> 一句话目标：从零复刻一套"角色 / 权限点 / 资源"三级的权限体系——权限判断内核（模板字面量类型约束权限码、受控通配符、资源 ID 实例级判定、ABAC 谓词扩展点）、声明式消费（`<Protected>` + `usePermission`）、路由/菜单/字段三层拦截共用单一数据源、覆盖式缓存失效（切角色热更新）、以及"前端权限只是 UX"的诚实边界（curl 直打接口必须被服务端拦住）。预计工期：1 周。前置要求：图纸 19 号文件路线 1–3 通读；React Context 基本功。

## 0. 目标与总验收

- [ ] **权限模型**：`资源:动作` 权限码由 TS 模板字面量类型推导（typo 编译期红线）；角色是权限集合的别名（运行时判定只见扁平 `Set`）；内核支持通配符（`order:*`，受控使用）与资源 ID（`order:update:123` 实例级）
- [ ] **判定纯函数**：`can('export', 'order')` O(1)；带 `resourceId` 的调用走实例级判定（类权限覆盖实例、实例权限精确匹配）；通配符命中时在开发期 console 提示（审计口）
- [ ] **声明式消费**：`<Protected I a>` 组件（hide/disabled 两策略）与 `usePermission()` hook；全项目权限判定只有这一个入口（ESLint `no-restricted-imports` 封死裸调用）
- [ ] **三层拦截**：一份路由配置树（`meta.permission`）同时生成路由守卫、菜单、面包屑三样——viewer 角色菜单无"告警规则"入口，URL 直达得 403 页（说明三行：没有权限、权限叫什么、找谁开）
- [ ] **字段级脱敏**：表格列 schema 挂 `permission` → 无权列被剔除（filter 策略）；表单字段挂 `permission` → 无权字段禁用占位（disable 策略）；`withMaskedField` HOC 把无权值渲染为 `***`
- [ ] **缓存失效**：`refresh()` 覆盖式替换快照（绝不增量合并——收回权限必须立即生效）；BroadcastChannel 同步多标签页；切角色后路由/菜单/按钮三层在一帧内同步
- [ ] **诚实边界**：能演示"隐藏的删除按钮被 React DevTools 强行渲染后，点击仍被服务端 403 拒绝"（mock 拦截也算）；能说清前端权限三个真实价值（体验/引导/一致性）与一个谬误（安全）

## 2. 里程碑切分

### M1 权限模型与判断内核（约 1.5 天）

**目标**：权限码类型 + 角色别名 + 判定内核（通配符/资源 ID）全部纯函数化，可单测。

**做什么**：§4.1 内核完整实现；角色表用 `satisfies` 保留字面量推断（`RoleKey` 从值派生）；后端下发的码过 `sanitizePermissionCodes` 白名单清洗。

**验收**：

```bash
npx vitest run src/auth/kernel.test.ts
```

用例覆盖：显式码命中；通配符 `order:*` 命中任意动作且打审计日志；实例级 `order:update:123` 对 `can('update','order','123')` 通过、对 `'456'` 拒绝、对类级 `can('update','order')` 拒绝（实例权限不升格为类权限）；非法码被清洗器丢弃并有 DEV 报错；每个角色快照非空。

### M2 声明式控制：`<Protected>` 与 usePermission（约 1 天）

**目标**：消费基建三件套（Provider / hook / 组件）落地，判定函数随快照重建。

**做什么**：AuthProvider（Context value = 快照 + `has/can/refresh`，判定函数 `useMemo` 依赖快照）；`<Protected I a noAccess>`（hide 默认 / disabled + tooltip"为什么"）；`usePermission()`。未登录时空集合兜底（返回 false 不抛错）。

**验收**：viewer 登录时"删除"按钮不渲染、`noAccess="disabled"` 时渲染禁用态带 tooltip；权限热更新后按钮消失/出现（`refresh` 触发，无页面刷新）；组件外调用 `usePermission` 抛出可读错误。

### M3 三层拦截：路由 / 菜单 / 字段（约 2 天）

**目标**：单一数据源派生三样 UI；字段级两种策略落地。

**做什么**：`RouteConfig`（`meta.permission/title/hideInMenu`）→ `generateRoutes`（无权分支整棵剪掉 + PermissionGuard 包有权路由）+ `generateMenu`（同一 `has` 过滤，空分组不渲染）+ `generateBreadcrumb`（回查配置链）；字段级 `filterColumns`（列 filter）/ `disableFields`（表单字段 disable）+ §4.2 脱敏 HOC。实现直接搬图纸路线 3/6 的代码，本手册不重复。

**验收**：`npx vitest run src/auth/layers.test.ts`——三用例：viewer 菜单项数、viewer 的路由树里没有 `/orders/export`、无权列被剔除且禁用字段保留占位；403 页文案含权限中文名与当前账号。

### M4 权限数据加载与缓存失效（约 1 天）

**目标**：登录拉取、切角色热更新、变更广播三条通道。

**做什么**：图纸路线 8 的 `usePermissionSync`（SSE + BroadcastChannel + visibilitychange 兜底）与 RoleSwitcher 原样落地；重点纪律：**refresh 是覆盖式替换**、`buildPermissionSet` 全项目只有一个。

**验收**：切角色后菜单/路由/按钮三层同步变化（20 次来回切换无残留）；A 标签页切角色，B 标签页 1s 内同步；收回权限（mock 返回少了 `order:export`）后按钮立即消失。

### M5 前端权限的诚实声明（约 0.5 天）

**目标**：把"前端权限只是 UX、服务端才是边界"变成可演示的证据与团队文档。

**做什么**：mock 拦截层（`/api/orders/:id` DELETE 无权限码时返回 403）；一段演示：DevTools 里强行把隐藏按钮 `display:block` 后点击 → 请求发出 → 服务端 403；写半页 ADR（团队文档）说明三价值一谬误 + "新增受控控件的降级策略必须声明"（图纸补充篇的矩阵表贴进 PR 模板）。

**验收**：演示链路可复现；ADR 提交；能不看稿回答面试三连——"前端权限为什么不是安全边界""那它的价值是什么""哪些粒度值得做到字段级"。

## 3. 关键数据结构

```ts
// src/auth/types.ts
export const RESOURCES = ['order', 'refund', 'user', 'tenant-setting', 'report', 'alert-rule'] as const;
export type Resource = (typeof RESOURCES)[number];
export const ACTIONS = ['read', 'create', 'update', 'delete', 'export', 'audit'] as const;
export type Action = (typeof ACTIONS)[number];

export type PermissionCode = `${Resource}:${Action}`;

/** 授权条目：三形态——显式码 / 动作通配（受控）/ 实例级（资源 ID 收窄）。
 *  通配符只允许出现在内置角色定义里且必须带注释（图纸"为什么不用通配符"的工程折中） */
export type Grant =
  | PermissionCode                                  // 'order:update'：类权限，任意实例
  | `${Resource}:*`                                 // 'order:*'：动作通配（审计受限）
  | `${Resource}:${Action}:${string}`;              // 'order:update:123'：实例权限

export type RoleKey = 'operator' | 'auditor' | 'admin' | 'viewer';

/** 行级/实例级判定的入参形态——ABAC 的最小扩展点：
 *  未来加金额/部门条件时，扩展此对象而不是改判定签名 */
export interface ResourceCtx {
  resourceId?: string;                              // 行 id / 记录 id
  attrs?: Record<string, unknown>;                  // 资源属性（ownerId、status 等，谓词用）
}

export interface AuthSnapshot {
  user: { userId: string; name: string; tenantId: string };
  roles: RoleKey[];
  grants: ReadonlySet<Grant>;                       // 展开后的扁平授权集合
}
```

## 4. 核心代码摘录

### 4.1 权限判断内核（通配符 + 资源 ID + ABAC 扩展点）

```ts
// src/auth/kernel.ts —— 纯函数，全应用调用频率最高的代码之一
import { ACTIONS, RESOURCES, type Action, type Grant, type PermissionCode, type Resource, type ResourceCtx } from './types';

export const ROLE_GRANTS = {
  operator: ['order:read', 'order:create', 'order:update', 'order:export', 'report:read'],
  auditor: ['order:read', 'refund:read', 'refund:audit', 'alert-rule:read', 'alert-rule:update'],
  admin: [
    'order:*', // ★ 通配符受控使用：仅内置 admin；新增 order:xxx 动作会自动放行 admin——
               //   图纸的警告原样生效，命中时审计日志可见（见 createChecker 的 wildcard 命中分支）
    'refund:*', 'user:*', 'tenant-setting:read', 'tenant-setting:update', 'report:*', 'alert-rule:*',
  ],
  viewer: ['order:read', 'report:read'],
} satisfies Record<string, readonly Grant[]>;
export type RoleKey = keyof typeof ROLE_GRANTS;

export function buildGrantSet(roleKeys: readonly RoleKey[]): ReadonlySet<Grant> {
  const set = new Set<Grant>();
  for (const role of roleKeys) for (const g of ROLE_GRANTS[role]) set.add(g);
  return set; // "角色只是别名"：此刻角色名消失，只剩扁平授权
}

/** 权限码合法性守卫：后端下发的数据不能信任（typo/大小写/未知资源一律丢弃） */
export function isPermissionCode(v: unknown): v is PermissionCode {
  if (typeof v !== 'string') return false;
  const [res, act] = v.split(':');
  return (RESOURCES as readonly string[]).includes(res ?? '') && (ACTIONS as readonly string[]).includes(act ?? '');
}

export function sanitizeGrants(raw: unknown[]): Grant[] {
  const valid = raw.filter(isPermissionCode) as Grant[];
  if (import.meta.env.DEV && valid.length !== raw.length) {
    console.error('[auth] 非法授权被丢弃：', raw.filter((c) => !isPermissionCode(c)));
  }
  return valid;
}

export interface Checker {
  has: (code: PermissionCode) => boolean;
  /** 声明式入口：<Protected I a> 的实现体。resourceId 存在时做实例级判定 */
  can: (action: Action, resource: Resource, ctx?: ResourceCtx) => boolean;
}

export function createChecker(grants: ReadonlySet<Grant>): Checker {
  const has = (code: PermissionCode): boolean => grants.has(code);

  const can = (action: Action, resource: Resource, ctx?: ResourceCtx): boolean => {
    // ① 显式类权限：order:update —— 覆盖任意实例
    if (grants.has(`${resource}:${action}`)) return true;
    // ② 动作通配：order:* —— 命中即审计（受控使用的落点：不是禁止，是留痕）
    if (grants.has(`${resource}:*`)) {
      if (import.meta.env.DEV) console.info(`[auth] wildcard 命中：${resource}:* -> ${action}`);
      return true;
    }
    // ③ 实例级：order:update:123 —— resourceId 存在时精确匹配。
    //    实例权限不升格为类权限：没有 ctx.resourceId 时本分支不生效
    if (ctx?.resourceId !== undefined && grants.has(`${resource}:${action}:${ctx.resourceId}`)) return true;
    return false;
  };

  return { has, can };
}

/** ABAC 扩展点（行级谓词）：主体属性 × 资源属性。先于 checker 使用——
 *  "本人 or 管理员"这个 90% 场景的二元谓词写普通函数，别急着上规则引擎（图纸路线 7 的判据） */
export function canEditOwnRow(
  can: Checker['can'], userId: string, row: { ownerId: string },
): boolean {
  return row.ownerId === userId || can('update', 'order');
}
```

### 4.2 字段级脱敏 HOC

```tsx
// src/auth/withMaskedField.tsx —— 值级脱敏：无权字段渲染 ***，且值不进 DOM（不是 CSS 遮盖）
import type { ComponentType } from 'react';
import { usePermission } from './usePermission';
import type { PermissionCode } from './types';

interface FieldProps { value: unknown; [key: string]: unknown }

/**
 * 用法：const MaskedCost = withMaskedField(CostCell, 'order:cost');
 * 关键决策：脱敏发生在"传值"层（value 替换为 ***）而不是渲染层——
 * 网络面板/React DevTools 里都拿不到真实值；真正的安全仍靠服务端不下发该字段（M5 的边界）。
 */
export function withMaskedField<P extends FieldProps>(
  Component: ComponentType<P>,
  code: PermissionCode,
  mask = '***',
) {
  function Masked(props: P) {
    const { can } = usePermission();
    const hasCode = can(...splitCode(code));
    return <Component {...props} value={hasCode ? props.value : mask} />;
  }
  Masked.displayName = `withMaskedField(${Component.displayName ?? Component.name})`;
  return Masked as ComponentType<P>;
}

// splitCode：'order:cost' -> ['cost', 'order']（Protected 组件同款，集中一处）
function splitCode(code: PermissionCode): [import('./types').Action, import('./types').Resource] {
  const [res, act] = code.split(':');
  return [act as import('./types').Action, res as import('./types').Resource];
}
```

### 4.4 `<Protected>` 声明式组件（M2）

```tsx
// src/auth/Protected.tsx —— hide / disabled 两策略；disabled 必须带"为什么"
import { isValidElement, cloneElement, type ReactElement, type ReactNode } from 'react';
import { usePermission } from './usePermission';
import type { Action, Resource } from './types';

interface ProtectedProps {
  I: Action;
  a: Resource;
  children: ReactNode;
  /** 无权限替代内容。hide 策略下不传 = 整块不渲染 */
  fallback?: ReactNode;
  /** 'hide'（默认）：角色边界——该角色与功能无关；'disabled'：状态门槛——用户该知道功能存在 */
  noAccess?: 'hide' | 'disabled';
  /** disabled 态的解释文案（升级引导/审批中——写清"为什么"与"找谁开"） */
  reason?: ReactNode;
}

export function Protected({ I, a, children, fallback = null, noAccess = 'hide', reason }: ProtectedProps) {
  const { can } = usePermission();
  if (can(I, a)) return <>{children}</>;
  if (noAccess !== 'disabled') return <>{fallback}</>;
  // disabled：要求 children 是单个可接收 disabled 的元素（按钮/输入类）
  if (isValidElement(children)) {
    const child = children as ReactElement<{ disabled?: boolean; title?: string }>;
    return cloneElement(child, {
      disabled: true,
      title: typeof reason === 'string' ? reason : '暂无权限，请联系租户管理员',
    });
  }
  return <>{fallback}</>;
}

// 消费侧对照（结构用组件、逻辑用 hook，别混）：
// <Protected I="export" a="order"><Button>导出订单</Button></Protected>
// <Protected I="delete" a="order" noAccess="disabled" reason="升级行政版可解锁">
//   <Button danger>批量删除</Button>
// </Protected>
// if (usePermission().can('audit', 'refund')) { ... }   // 事件回调里的判定走 hook
```

hide 与 disabled 的产品语义差异（图纸路线 5 的表，实现前一秒先做这个决策）：隐藏 = "系统没有这个功能"（角色边界）；禁用 = "有但你没资格"（状态门槛，带营销价值）。整页 30 个按钮全禁用是设计事故——那说明该走路由级/区块级隐藏。

## 5. 坑与调试

1. **`if (role === 'admin')` 写进组件**（症状：admin 拆成两个角色后全站失准）。根因：把管理概念泄漏进运行时。修法：判定永远基于授权码；角色只出现在分配场景。全局 `grep "role ==="` 清零。
2. **refresh 增量合并**（症状：收回权限后按钮还在）。根因：见 §4.3 错误姿势。修法：覆盖式替换；测试固定写一条"收回"用例（mock 少返回一个码断言按钮消失）。
3. **路由树缓存了旧 `has`**（症状：切角色后菜单变了、点新页面 403，刷新才对）。根因：`generateRoutes` 的 useMemo 依赖漏了 `has`，或 router 实例没随 routes 重建。修法：派生链每环依赖都含 `has`；或选"路由不剪枝、守卫动态判定"方案——两种取舍选一种全链路一致（图纸路线 8 坑）。
4. **权限未就绪渲染成 403 闪变**（症状：刷新时先 403 后正常）。根因：`ready=false` 与"无权限"共用同一 UI。修法：未就绪 return null（外层 Suspense 骨架）；或图纸坑 2 的 Suspense 版 Provider（throw promise）。
5. **通配符静默扩权**（症状：后端新增 `order:refund-audit` 动作，admin 瞬间获得）。根因：`order:*` 的语义是"运行时才知道的全集"。修法：受控使用（仅内置角色 + 注释 + 审计日志）；权限码超过百个确实需要通配时，管理后台"展开成显式码"再下发。
6. **实例权限升格**（症状：只有 `order:update:123` 的人能改所有订单）。根因：判定把实例码当类权限（切掉 resourceId 直接查前缀）。修法：§4.1 ③——`ctx.resourceId` 不存在时实例分支不生效；单测固定这条边界。
7. **字段脱敏只挡了渲染**（症状：无权值仍在网络响应与 DevTools state 里）。根因：脱敏做成 CSS 遮盖或渲染层判断。修法：HOC 在传值层替换（§4.2）；根治靠服务端按角色裁剪响应字段——前端脱敏是体验层，不是安全层（M5 的主线）。
