## 贯穿全程的项目线

| 等级 | 项目 | 覆盖阶段 |
|---|---|---|
| Lv1 | TodoMVC | 阶段 1–2 |
| Lv2 | 迷你组件库 + Storybook | 阶段 3、7 |
| Lv3 | 后台管理系统 | 阶段 4–6、8 |
| Lv4 | Next.js 全栈应用 + 部署 | 阶段 9 |

这张表是整份大纲的"进度存档点"。逐行展开每一级的验收要点——**满足验收再进入下一级**，比赶进度重要得多：

**Lv1：TodoMVC（覆盖阶段 1–2）。** 验收清单：

1. 增删改、双击编辑、勾选完成、清除已完成，全部操作**无一处直接操作 DOM**（纯 state 驱动）。
2. 过滤 Tab（全部/未完成/已完成）的状态放 URL 查询参数，刷新后过滤器不丢。
3. localStorage 持久化：刷新后列表原样恢复（手写 useLocalStorage）。
4. 搜索框防抖 300ms（手写 useDebounce），快速输入只触发一次过滤。
5. 能口头回答三个问题：为什么 setState 后立刻读 state 是旧值；为什么 effect 清理函数能防竞态；`count && <Tag/>` 当 count 为 0 时渲染了什么。

**Lv2：迷你组件库 + Storybook（覆盖阶段 3、7）。** 验收清单：

1. Button / Input / Select / Modal / Tabs 五件套，每个都有完整 TS Props 类型与 JSDoc 注释。
2. Select 是泛型组件（阶段 7 第 3 条的形态），options/value/onChange 三处类型一致。
3. Input 与 Modal 支持 ref 透传（React 19 的 ref-as-prop 写法），Modal 用 createPortal 实现。
4. 每个组件至少一个 Storybook story；受控/非受控双模式至少在 Input 上实现并各有一个 story 演示。
5. 变体系统用 Record 映射或 cva，新增一个变体只改一处映射（阶段 7 第 5 条）。

**Lv3：后台管理系统（覆盖阶段 4–6、8）。** 验收清单：

1. 登录鉴权（受保护路由 + 401 跳转 + 退出），token 失效自动登出。
2. 动态表格：分页（页码同步 URL）、搜索（防抖）、筛选、排序组合生效。
3. 增删改查弹窗：Modal + 表单校验（react-hook-form + zod），删除有 Confirm。
4. 状态分层：服务器状态全走 React Query（含 mutation 后失效重取），UI 状态 Zustand，不互相渗透。
5. 质量线：至少 10 个组件测试 + 1 条 Playwright 登录主流程全绿；Profiler 录制一次并写优化笔记（哪几个组件白渲染了、怎么消掉的）。

**Lv4：Next.js 全栈应用 + 部署（覆盖阶段 9）。** 验收即上一节的"技术验收清单"七条（RSC/Server Action/缓存重验证/NextAuth/无水合错误/E2E/Vercel 线上可用），外加一条体验项：首屏有页面外壳与骨架，没有任何整页白屏或 spinner 风暴。

### 补充：项目翻新循环——用后面的阶段回头改造前面的项目

这张表的四个等级不是"做完就丢"的练习题。每完成一个后续阶段，都应回头把早期项目**按新标准翻新一遍**——翻新比重写新项目性价比高得多：需求已明确、功能已可跑，你只是在同一块画布上换更高级的画法，前后差异就是最直观的能力证据。

**翻新对照表（等级 × 后续阶段的改造动作与验收）。**

| 项目 | 翻新时机 | 改造动作 | 验收 |
|---|---|---|---|
| Lv1 TodoMVC | 阶段 5 完成后 | 组件内 useState 提升为 Zustand store，selector 订阅替换逐层传 props | 行为不变（验收清单 5 问仍答得出），prop drilling 消除 |
| Lv1 TodoMVC | 阶段 7 完成后 | 全量补 Props 类型；过滤 Tab 的字面量联合化；`useLocalStorage` 加运行时守卫（阶段 7 第 7 条） | `npx tsc --noEmit` 零错误 |
| Lv1 TodoMVC | 阶段 8 完成后 | 补 5 个行为测试：增删改、URL 过滤恢复、防抖只触发一次 | `vitest run` 全绿，故意改坏一处能红 |
| Lv2 组件库 | 阶段 7/8 完成后 | Select 泛型化落到类型层验证；每个组件补一个失败分支测试（Modal 关闭时卸载、Select 空列表） | coverage 分支率 ≥ 60%；泛型推断用例（阶段 7 第 3 条）写成测试固化 |
| Lv3 后台 | 阶段 6/8 完成后 | 这就是验收 5 本身：Profiler 档案 + 优化笔记 + 10 测试 + 1 E2E | 见上方验收清单第 5 条 |
| Lv4 全栈 | 复刻 mini-React 后 | （可选）用你复刻的 mini-react 跑 Lv1 的 TodoMVC | 见《[react-源码复刻大纲](../react-源码复刻大纲/README.md)》"验收"一节 |

**翻新的三条铁律。** 其一，**行为不变是前提**：翻新前后 Lv 各自的验收清单必须全部仍然通过（这正是每级验收清单的第二次价值——它是翻新的回归测试）。其二，**测试先行再动刀**：阶段 8 之后的项目，先给要动的模块补测试再翻新，测试就是你的安全网。其三，**一次只换一个维度**：这一轮只换状态方案、下一轮只补类型、再下一轮只补测试——混着改一旦出错无法定位，"翻新"就退化成"重写"。

**翻新实例：Lv1 的状态层翻新（useState → Zustand）长什么样。** 翻新前的 App.tsx 里，过滤状态逐层下传：

```tsx
// 翻新前：TodoApp 持有 filter，两个子组件靠 props 接
export function TodoApp() {
  const [filter, setFilter] = useState<'all' | 'active' | 'done'>('all');
  return (
    <>
      <FilterTabs filter={filter} onChange={setFilter} />
      <TodoList filter={filter} />   {/* TodoList 只为转发 filter 给 TodoItem 又传一层 */}
    </>
  );
}
```

```tsx
// 翻新后：filter 进 store，消费组件各自订阅自己的切片
// src/store/filter.ts
import { create } from 'zustand';

interface FilterState {
  filter: 'all' | 'active' | 'done';
  setFilter: (f: FilterState['filter']) => void;
}

export const useFilterStore = create<FilterState>((set) => ({
  filter: 'all',
  setFilter: (filter) => set({ filter }),
}));

// 组件侧：不再接收 props，直接 selector 订阅
export function TodoList() {
  const filter = useFilterStore((s) => s.filter); // 只订 filter 切片，其他 state 变化不连坐
  /* ... */
}
```

注意这次翻新同时保住了 Lv1 验收第 2 条（过滤状态在 URL 查询参数）：翻新时把"URL ↔ store"的同步放进一个 `useEffect`（阶段 4.4 路由篇的套路），行为完全不变——这就是"换画法不换画"的含义。

**时间预算参考。** Lv1 的状态翻新约 1–2 小时；类型翻新约半天；测试翻新约半天。Lv2 补失败分支测试约半天。每次翻新都值得单独的 commit 序列（"为什么这么改"写进 message，36 的 git 习惯），翻新前后各打一个 tag（`lv1-before-zustand` / `lv1-after-zustand`）——对比两个 tag 的代码就是面试讲解时的现成材料。

**把项目变成简历资产的产出物清单（每级通用）。**

1. README 三件套：一句话价值描述（做了什么、给谁用）、技术栈与版本、GIF 演示或截图（录一次屏 10 分钟，胜过千字描述）。
2. 可点开的东西：Lv4 的线上部署链接；Lv2 的 Storybook 线上预览（可静态部署）；仓库本身的 CI 徽章（lint/typecheck/test 全绿）。
3. 证据文件：Lv3 的 Profiler 优化前后对比笔记、各项目的踩坑笔记节选（34 的工作流第 5 步格式）。
4. commit 历史：小步提交、message 写"为什么这么改"（36 的 git 习惯）——面试官点开 commits 看到的就是你持续数月的工作痕迹。
5. 面试一句话模板：`在 [项目] 里用 [技术] 解决了 [具体场景] 的 [具体问题]，验证方式是 [指标/测试/线上数据]`——每级项目各准备一条，"验证方式"一栏直接从上面四项产出物里取。
6. 反例自查：简历上"精通 X" 的每一项，都要能经受"那你在项目里用它解决过什么具体问题"的追问——答不出具体问题的关键词删掉，产出物清单就是你的弹药库，弹药库里没有的不写。
