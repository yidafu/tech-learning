## 核心资源

- **react.dev**（中文版可用）—— 唯一必读，尤其是 "Learn React" 与 "You Might Not Need an Effect"
- TanStack Query / Zustand / React Router / react-hook-form 官方文档
- [ahooks](https://ahooks.js.org/)：自定义 Hook 最佳实践与源码
- Epic React（Kent C. Dodds 的实战 workshop）
- patterns.dev：组件模式与性能模式图解

逐条说明"读什么、解决什么问题"：

**react.dev（中文版可用）。** 读法：把 "Learn React" 整章按顺序过一遍（它是目前唯一把"思考模型"讲对的教程，如"state 是渲染快照""effect 是与外部系统同步"）；进阶读 "You Might Not Need an Effect"——它直接纠正"什么都往 useEffect 里塞"的本能，是阶段 2 第 5 条的完整版；遇到具体 API 就查 Reference 区（每个 hook 页尾部的"陷阱"小节是精华）。解决什么：90% 的概念疑惑与"React 推荐写法是什么"的权威裁决。

**四个库的官方文档，各读关键章节即可。** TanStack Query：读 "Query Keys" 与 "Query Invalidation" 两章就掌握 80% 日常（缓存的身份与失效是它的全部核心），配合 "Optimistic Updates" 补齐乐观场景——解决"服务器状态怎么管"。Zustand：整站只有十几页，读 "Write State"（含 selector 订阅）与 persist 中间件即可——解决"UI 状态放哪"。React Router：读 "Concepts" 的嵌套路由与 loaders/actions 哲学——解决"路由结构与数据加载的关系"。react-hook-form：读 Getting Started + zodResolver 一页——解决"受控表单性能与校验样板"，阶段 4.1 的终点形态。

**[ahooks](https://ahooks.js.org/)。** 读法：把你在阶段 2 手写过的每个 hook（useDebounce、useLocalStorage、useClickOutside……）在 ahooks 里找到对应实现，对照源码看三件事：边界条件处理（SSR、清理、竞态）、API 设计（为什么多那个 options 参数）、测试怎么写。解决什么：自定义 hook 的"标准答案"参照系——手写版与它的差距就是你的提升点。

**Epic React（Kent C. Dodds 的实战 workshop）。** 读（做）法：按顺序做 "React Hooks" 与 "React Fundamentals" 两个 workshop（免费部分即可），它的形式是"先给你一个会失败的测试，你把实现写绿"——与阶段 8 的测试观完全同构。解决什么：把知识从"看得懂"逼到"写得出"，尤其适合卡在"教程都懂、自己动手就懵"的阶段。

**patterns.dev。** 读法：把 "React Patterns" 与 "Rendering"（性能）两章当图解字典——Compound Components、Render Props、Container/Presentational 每个都有一页动图。解决什么：设计模式时的"命名检索"——你说不清要用的模式叫什么时，翻它最快。

### 补充：分阶段资源补充包

上面是"全程通用"的核心五件；这一组按阶段对口补齐——到哪个阶段再取哪一组，其余先收藏不动。

**TypeScript 侧（对口阶段 7）。**

- TS 官方 Handbook 的 "Narrowing" 与 "Generics" 两章——判别联合、类型守卫、泛型约束的全部细节出处；阶段 7 第 2、7 条的手册级展开。
- Total TypeScript 的免费 Tips 系列（totaltypescript.com/tips）——短条目制，每条一个真实类型问题，适合每天一条当热身。
- react-typescript-cheatsheet（GitHub 社区清单）——事件类型、children、泛型组件的速查版，写组件卡住时比搜索引擎快。

**测试侧（对口阶段 8）。**

- Testing Library 官方文档的 "Common Mistakes with Testing Library" 单页——把"用 getBy 断言不存在""忘 cleanup""变体用错"一次列全，读完等于提前避掉一半坑。
- Playwright 官方 docs 的 "Web-First Assertions" 与 "Authenticating"（storageState）两章——阶段 8 第 6 条只展开了骨架，这两章是完整版。
- MSW 官方 docs（mswjs.io）——handler 组织、延迟模拟、组件测试与 E2E 共用的完整用法（阶段 8 补充第 8 条的展开版）。

**React 19 / Next.js 侧（对口阶段 9）。**

- react.dev 的 "React 19 Upgrade Guide"——升级清单的权威版，阶段 9 补充节的迁移篇以它为准。
- Next.js 官方 Learn 免费课程（nextjs.org/learn）——App Router 全栈实战的官方版，做完等于阶段 9 产出作业的"官方对照答案"。
- Next.js GitHub Releases 与官方博客——**每次升级前必读**，先扫 Breaking Changes 一节能省掉大半天盲查。
- This Week In React（邮件订阅）——生态动态周刊，升级时机与新库选型的信息源。

**原理与源码侧（对口阶段 10）。**

- 《[react-源码复刻大纲](../react-源码复刻大纲/README.md)》（本仓库）——概念层到实现层的主线路径，此处不重复展开。
- didact 的 "Build Your Own React" 教程——复刻大纲的命名与路线源头，做大纲时当第二参照。
- React 官方博客的 "React Labs" 系列——官方对并发、Server Components、Compiler 进行中工作的第一手说明，聊"React 的方向"时的可靠素材。

**按需求检索表（"我想解决 X"直接查这行）。**

| 卡在哪 | 去处 |
|---|---|
| 类型报错看不懂 / 泛型组件写不出 | TS Handbook 两章 + react-typescript-cheatsheet |
| 测试写了总红 / 不知道断言什么 | "Common Mistakes" 单页 |
| E2E 时好时坏 | Playwright "Web-First Assertions" |
| mock 数据三处重复 | MSW docs |
| 升级 React/Next 踩坑 | Upgrade Guide + GitHub Releases |
| 原理答不深 | 源码复刻大纲 + React Labs |

**资源使用的三条纪律（防收藏夹吃灰）。** 其一，**对口才读**：拿到资源先问"它解决我当前哪个场景"，答不上就先收藏；其二，**不配练习不读**：纯读不敲 = 零留存，凡教程必须跟着跑代码（Epic React 的"测试驱动 workshop"形式就是为此设计的）；其三，**两周用不上就归档**：学习资源有保鲜期，两个月后再翻开往往已有更好的版本。
