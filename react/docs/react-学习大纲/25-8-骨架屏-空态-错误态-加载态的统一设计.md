#### 8. 骨架屏 / 空态 / 错误态 / 加载态的统一设计

**是什么。** 任何异步数据在界面上的呈现都逃不开四种状态：**loading**（加载中，骨架屏）、**error**（加载失败，错误态 + 重试）、**empty**（成功但没有数据，空态 + 引导动作）、**success**（成功展示数据）。"四态统一设计"就是定义一个**判别联合类型** + 一个**容器组件**，让所有列表/详情页共享同一套状态渲染，消灭每个页面自己拼 `if (loading) ... if (error) ...` 的重复代码。

**为什么需要。** 类型层面的收益：用三个布尔（`isLoading/isError/isEmpty`）表达状态有 2³=8 种组合，其中"loading 且 error"这种矛盾态在代码里完全合法——bug 温床。判别联合（discriminated union）用 `status` 字段互斥，**矛盾态在编译期就被 TypeScript 排除**，且 narrow 后 `success` 分支自动收窄出 `data`。UI 层面的收益：四态的视觉规范（骨架形状、空态插画、错误按钮）收敛到一个组件，改一次全局生效。

**怎么做（机制分步）。**

*第一步：类型驱动*。定义 `AsyncState<T>`：四个分支，只有 `success` 携带 `data`，只有 `error` 携带 `error` 对象——"什么状态下能访问什么数据"由类型系统保证。

*第二步：状态生产*。写一个 `useAsync` 把任意请求函数转成 `AsyncState`，注意两个细节：**竞态防护**（快速切换参数时旧请求晚到覆盖新结果，用"代数 ref"只认最后一次调用）；**empty 的判定留给调用方**（`isEmpty?: (data) => boolean`），因为"列表 length===0 是空态"而"详情页永远不空"是业务语义。

*第三步：状态消费*。`<AsyncContainer state={...} render={data => ...}>` 容器组件 switch 四分支；骨架屏的**形状与真实内容同构**（表格骨架是行、卡片骨架是块），切换时才不跳版。

**代码示例。** 类型与容器：

```ts
// src/components/AsyncContainer/types.ts
export type AsyncState<T> =
  | { status: 'loading' }
  | { status: 'error'; error: Error }
  | { status: 'empty' }
  | { status: 'success'; data: T };
```

```tsx
// src/components/AsyncContainer/index.tsx
import type { ReactNode } from 'react';
import type { AsyncState } from './types';

/** 骨架行：形状与真实表格行同构，加载完成切换时不跳版 */
function SkeletonRows({ rows }: { rows: number }) {
  return (
    <div className="skeleton" aria-busy="true" aria-label="加载中">
      {Array.from({ length: rows }, (_, i) => (
        <div key={i} className="skeleton-row" />
      ))}
    </div>
  );
}

interface AsyncContainerProps<T> {
  state: AsyncState<T>;
  /** 错误态的重试回调（通常传 refetch） */
  onRetry?: () => void;
  /** 空态自定义内容（默认"暂无数据"） */
  empty?: ReactNode;
  /** 成功态渲染函数：narrow 之后这里一定能拿到 data，不再判空 */
  render: (data: T) => ReactNode;
}

export function AsyncContainer<T>({ state, onRetry, empty, render }: AsyncContainerProps<T>) {
  switch (state.status) {
    case 'loading':
      return <SkeletonRows rows={5} />;
    case 'error':
      return (
        <div className="state state-error" role="alert">
          <p>加载失败：{state.error.message}</p>
          {onRetry && (
            <button onClick={onRetry} className="retry-btn">
              重试
            </button>
          )}
        </div>
      );
    case 'empty':
      return (
        <div className="state state-empty">
          {empty ?? <p>暂无数据</p>} {/* 空态要给"下一步"：如"新建第一条记录" */}
        </div>
      );
    case 'success':
      return <>{render(state.data)}</>;
  }
}
```

状态生产方（`useAsync`，含竞态防护与 empty 判定）：

```ts
// src/hooks/useAsync.ts
import { useCallback, useEffect, useRef, useState } from 'react';
import type { AsyncState } from '../components/AsyncContainer/types';

export function useAsync<T>(
  fetcher: () => Promise<T>,
  deps: unknown[],
  isEmpty?: (data: T) => boolean,
): { state: AsyncState<T>; refetch: () => void } {
  const [state, setState] = useState<AsyncState<T>>({ status: 'loading' });
  // 代数 ref：每次请求自增，响应回来时只认最新一次——防止旧请求晚到覆盖新结果（竞态）
  const generationRef = useRef(0);

  const run = useCallback(async () => {
    const generation = ++generationRef.current;
    setState({ status: 'loading' });
    try {
      const data = await fetcher();
      if (generationRef.current !== generation) return; // 已被更新的请求取代，丢弃
      // empty 的判定是业务语义：列表 length===0 算空，详情页不算——由调用方注入
      setState(isEmpty?.(data) ? { status: 'empty' } : { status: 'success', data });
    } catch (error) {
      if (generationRef.current !== generation) return;
      setState({ status: 'error', error: error instanceof Error ? error : new Error(String(error)) });
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, deps);

  useEffect(() => {
    run();
  }, [run]);

  return { state, refetch: run };
}
```

使用侧（一个用户列表页，四态全部免费获得）：

```tsx
// src/pages/BookList.tsx
import { AsyncContainer } from '../components/AsyncContainer';
import { useAsync } from '../hooks/useAsync';

interface Book {
  id: string;
  title: string;
}

function fetchBooks(): Promise<Book[]> {
  return fetch('/api/books').then((r) => {
    if (!r.ok) throw new Error(`HTTP ${r.status}`);
    return r.json();
  });
}

export function BookList() {
  const { state, refetch } = useAsync(
    fetchBooks,
    [],
    (books) => books.length === 0, // 空列表判定为空态（业务语义在这里注入）
  );

  return (
    <AsyncContainer
      state={state}
      onRetry={refetch}
      empty={
        <div className="empty-books">
          <p>书架还是空的</p>
          <button>去添加第一本书</button> {/* 空态给行动入口，不是死胡同 */}
        </div>
      }
      render={(books) => (
        <ul className="book-list">
          {books.map((book) => (
            <li key={book.id}>{book.title}</li>
          ))}
        </ul>
      )}
    />
  );
}
```

**常见坑。**

- **症状**：页面同时出现"加载中"转圈和"加载失败"红字。**根因**：三个布尔状态并存（`isLoading` 还没置 false，`isError` 已置 true），布尔组合没有任何约束。**修法**：换 `AsyncState` 判别联合，互斥由类型保证。
- **症状**：接口成功返回空数组，页面显示"加载失败"。**根因**：把"没数据"当错误处理，或空态分支被漏写直接落到 error。**修法**：明确区分 error（请求没成功）与 empty（请求成功但无数据），empty 单列分支。
- **症状**：骨架屏切到真实内容时页面跳动。**根因**：骨架是一根大进度条，与内容布局不同构。**修法**：骨架按内容形状画（表格画 N 行、卡片画块），高度与真实内容一致。
- **症状**：快速切换筛选条件，最后显示的是第一次的结果。**根因**：`useAsync` 没做竞态防护，旧响应晚到覆盖。**修法**：generation ref 或 AbortController（4.2 的 useFetch 专题）。
- **症状**：空态是一句干巴巴的"暂无数据"。**根因**：把空态当"结束"，而不是"引导"。**修法**：区分两种空态——初始空（引导创建）与筛选后空（提供"清空筛选"）；空态永远给一个行动按钮。

##### 补充：旧数据垫底（stale-while-refresh）——刷新不再闪回骨架屏

**是什么。** 四态互斥解决的是**首屏**呈现；一旦页面有了数据，"刷新"（换筛选条件、点重试）就不该再把内容抽走闪回骨架屏——旧数据继续垫底展示，容器半透明 + 顶部细进度条表达"正在更新"，失败时旧数据也保留（而不是闪成错误页）。设计上：`refreshing` 变成 success 分支的**附着信息**，error 分支可携带 `staleData`——互斥原则管"有没有内容"，附着信息管"内容的新鲜度"。

**为什么需要。** 闪回骨架屏的代价被严重低估：滚动位置重置、用户正在看的行被抽走、快速连续操作时界面在骨架与内容间抖动。TanStack Query 的 `placeholderData: keepPreviousData`（见《13-4-2-数据请求与服务器状态.md》分页一节）就是这套语义的库内置版；这里在手写 `useAsync` 上补齐它。

```ts
// src/hooks/useAsync.ts 增量改造：data 与 error 不再互斥于"有无内容"
export type AsyncState<T> =
  | { status: 'loading' } // 首载：没有任何旧数据
  | { status: 'empty' }
  | { status: 'success'; data: T; refreshing?: boolean }
  | { status: 'error'; error: Error; staleData?: T }; // 刷新失败也保住旧数据

export function useAsync<T>(
  fetcher: () => Promise<T>,
  deps: unknown[],
  isEmpty?: (data: T) => boolean,
): { state: AsyncState<T>; refetch: () => void } {
  const [state, setState] = useState<AsyncState<T>>({ status: 'loading' });
  const generationRef = useRef(0);
  const lastDataRef = useRef<T | undefined>(undefined); // 上一份成功数据：垫底的来源
  const isEmptyRef = useRef(isEmpty);
  isEmptyRef.current = isEmpty; // 判空函数始终最新，避免闭包陈旧（见补充二坑 2）

  const run = useCallback(async () => {
    const generation = ++generationRef.current;
    // 关键差异：刷新（有旧数据）不切回 loading，而是 success + refreshing
    setState((prev) =>
      lastDataRef.current !== undefined
        ? { status: 'success', data: lastDataRef.current, refreshing: true }
        : { status: 'loading' },
    );
    try {
      const data = await fetcher();
      if (generationRef.current !== generation) return;
      lastDataRef.current = data;
      setState(isEmptyRef.current?.(data) ? { status: 'empty' } : { status: 'success', data });
    } catch (error) {
      if (generationRef.current !== generation) return;
      const err = error instanceof Error ? error : new Error(String(error));
      // 刷新失败：旧数据还在就"数据 + 错误横幅"，只有首载失败才走整屏错误态
      setState(
        lastDataRef.current !== undefined
          ? { status: 'error', error: err, staleData: lastDataRef.current }
          : { status: 'error', error: err },
      );
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, deps);

  useEffect(() => {
    run();
  }, [run]);

  return { state, refetch: run };
}
```

容器侧对应两个分支的渲染变化：

```tsx
// AsyncContainer 的 error 分支：
case 'error':
  if ('staleData' in state && state.staleData !== undefined) {
    return (
      <div className="state-stale" role="alert">
        <div className="stale-banner">刷新失败：{state.error.message}，以下为上次的数据</div>
        {render(state.staleData)}
      </div>
    );
  }
  return /* 原有的整屏错误态 */;

// success 分支：refreshing 时内容半透明 + 顶部进度条，而不是抽走内容
case 'success':
  return (
    <div className={state.refreshing ? 'is-refreshing' : undefined}>
      {render(state.data)}
    </div>
  );
```

**关键取舍。** 旧数据垫底要防"陈旧数据被当成最新"：`refreshing` 与 stale 横幅必须在视觉上明确表达"这不是最新的"；对强一致性场景（余额、库存）宁可闪骨架也不要垫旧数据——这是业务决策不是技术决策。卸载时 `lastDataRef` 随组件一起回收，跨页面保留数据请交给缓存层（4.2 的 Query 缓存）。

##### 补充：高频坑位补遗

- **症状**：调用方给 `deps` 传了对象字面量（`useAsync(fetch, [{ keyword }])`），页面无限循环请求。**根因**：`useCallback` 的依赖对引用做比较，每次渲染都是新对象 → `run` 每次重建 → effect 每次重跑。**修法**：hook 的使用约定必须写死——deps 只放原始值：

  ```tsx
  // ✗ useAsync(fetchUsers, [{ keyword, status }])
  // ✓ useAsync(fetchUsers, [keyword, status])
  ```

- **症状**：判空结果时对时错——"仅看管理员"开关拨了之后，空态/数据态判定不稳定。**根因**：`isEmpty` 没进 `run` 的依赖数组（原文实现里 `useCallback(fn, deps)` 的 deps 是调用方那份），闭包里捕获的是第一次渲染时的 `isEmpty`。**修法**：用 ref 保持最新引用（上面改造版 `isEmptyRef` 的写法），或把 `isEmpty` 一并压平进 deps。
- **症状**：开发环境（StrictMode）Network 面板里首屏请求发了两次。**根因**：StrictMode 的 mount → unmount → mount 双执行 effect，`generationRef` 保证最终状态正确但**请求已经发出**，这是 dev-only 行为。**修法**：接受它（它同时帮你验证了清理逻辑）；真要请求级去重得靠请求层缓存/去重（4.2 的 Query 自带），不要用 ref 抑制第二次 effect——那会掩盖真实 bug。
- **症状**：错误态把 `HTTP 500 Internal Server Error` 加接口路径直接怼在用户脸上。**根因**：`error.message` 是给开发者的，直接当 UI 文案。**修法**：用户可见层给通用文案（"加载失败，请重试"），`error.message` 只进上报日志；错误横幅上不放任何内部细节。
- **症状**：接口很快（<100ms）时，骨架屏一闪而过，比不显示还难受。**根因**：没有"最短展示时间"的消抖。**修法**：骨架至少停留 300ms 再切换——记录开始时间，数据到了也等够时长再setState；这与《15-4-4-路由》坑 2 的 Suspense 骨架闪烁是同一个问题在两个场景的实例。

##### 补充：自测题

1. 为什么三个布尔（`isLoading/isError/isEmpty`）是 bug 温床？判别联合怎么解决的？
   要点：2³=8 种组合里存在"loading 且 error"等矛盾态，类型系统不拦；判别联合用 `status` 互斥，矛盾态编译期排除，narrow 后 `success` 自动收窄出 `data`。
2. error 与 empty 的分界线在哪？判空为什么留给调用方？
   要点：error=请求没成功，empty=成功但无数据；"空列表是空态、详情页永不空"是业务语义，hook 无法预置。
3. 竞态的两个修法（generation ref / AbortController）各自解决到什么程度？
   要点：generation 只丢弃过期结果（请求照发，省不掉流量）；AbortController 连请求一起取消（省流量），但要求接口层支持取消信号。
4. "旧数据垫底"与"四态互斥"矛盾吗？
   要点：不矛盾——互斥管首屏呈现（有没有内容），`refreshing`/`staleData` 是附着信息（内容的新鲜度）；RQ 的 `placeholderData: keepPreviousData` 与"error 时保留上次 data"是同款语义。
5. 骨架屏"与真实内容同构"为什么是硬要求？不同构的症状是什么？
   要点：切换时布局跳动（CLS），用户视线被迫重定位；表格画行、卡片画块，高度与真实内容一致。
6. 空态设计的两种业务形态与各自的行动入口？
   要点：初始空→引导创建；筛选后空→"清空筛选"；空态永远给下一步，不当"结束"处理。
