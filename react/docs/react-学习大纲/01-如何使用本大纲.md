## 如何使用本大纲

这份大纲不是"读完"的，是"写完"的。每一行知识点背后都假设你会打开编辑器敲一遍。在正式进入阶段 0 之前，先花五分钟搞清楚两件事：时间怎么分配（60/20/20），以及哪些内容可以跳过。这两件事直接决定你是 12 周学完，还是三个月后卡在"收藏夹里吃灰"。

### 60/20/20 节奏怎么落地

大纲末尾的《每周节奏建议》给出了比例：60% 写代码、20% 读官方文档、20% 复盘重构。比例本身简单，难点是落到每一天。推荐按"天"切片，而不是按"周"切片——按周规划很容易演变成"前六天摸鱼、周日赶工"。

以每天 90 分钟为例，切成三段：

- **前 50 分钟：写代码（60%）**。打开当天要做的场景，先不看任何资料，徒手写 15–30 分钟；写不出来或跑不通，再去查 react.dev 对应章节，查完回来继续写。这一段的核心纪律是"先动手后查资料"——查来的答案只有在你被卡住之后才会真正被记住。
- **中间 20 分钟：读文档（20%）**。只读当天场景对应的章节（比如今天做列表渲染，就只读 react.dev 的《Rendering Lists》），边读边回头对照自己刚写的代码，找出至少一处"官方做法和我不一样"的地方。禁止从文档第一页顺读到最后一页，那是最舒适也最低效的学习方式。
- **最后 20 分钟：复盘重构（20%）**。写完能跑不代表写好。问自己三个问题：命名能一眼看懂吗？有重复代码可以抽成组件或函数吗？有没有踩坑后绕过去、但没弄明白原因的地方？把绕过的坑补上注释，把"烂代码"改到自己愿意署名的程度。第二天开始新场景之前，先花 5 分钟再扫一眼昨天的文件——"把前一天写的烂代码改好，比多写新代码更有价值"。

如果每天只有 60 分钟，同样按 6:2:2 切：35 分钟写、12 分钟读、13 分钟改。比例比绝对时长重要，因为三个环节缺一不可：只写不读会形成错误的自创习惯；只读不写是"看得懂写不出"；不复盘则同样的错误会连犯三周。

另外，贯穿全程的项目线（TodoMVC → 迷你组件库 → 后台管理系统 → Next.js 全栈应用）不要等阶段结束才启动，而是每完成一个阶段就把学到的手法"回灌"进对应项目里。

### 怎么判断"可以跳过"

引言里说"可按阶段跳过已掌握内容"，但"已掌握"很容易被高估——看过 ≠ 会。判断标准用这三条自测，对着要跳过的场景逐条打分：

1. **盲写测试**：不看任何资料，能从空文件把这个场景写出来并跑通，且能解释每一行为什么这么写。
2. **坑位测试**：能主动说出这个场景的两个经典坑（症状和修法），而不是"好像有个什么坑"。
3. **讲授测试**：能给别人讲清楚这个场景，并回答"为什么必须这样、不这样会怎样"。

命中情况与对应策略：

- **三条全中**：跳过正文，只把这个场景的产出合并进项目（比如直接在商品卡片页里用上它，验证一遍就走）。
- **中两条**：不写独立 demo，但把场景塞进当周产出里顺手做一遍，做完对答案。
- **中一条或零条**：老实按基线流程写 demo。此处的"老实"是划算的——基础阶段的每个坑在后面项目阶段都会以十倍成本重现。

按背景的快捷跳读参考：有 Vue/Angular 经验的开发者，阶段 0、1 可以加速（框架间的"条件渲染/列表/组件通信"概念互通，重点是差异处，差异细节可对照《[延伸篇：React 与其他框架的对比](37-延伸篇-React-与其他框架的对比.md)》再回来读）；从 React 类组件时代过来的开发者，可以直接用函数组件写阶段 1，把全部时间押在阶段 2 的 hooks 心智模型上；完全的新手不要跳阶段 1，它只花一周，却是后面所有内容的语言基础。

最后：跳过不是永久跳过。如果在阶段 4 的项目里发现某个基础场景写不动，回到对应阶段补课，再继续往前——大纲是地图，卡壳点才是你真实的进度。

完成本大纲主体（阶段 1–4）后，Schema 动态表单、拖拽大盘、低代码等复杂场景见《[react-进阶大纲-复杂场景.md](../react-进阶大纲-复杂场景/README.md)》，全景场景见《[react-高阶场景全景图.md](../react-高阶场景全景图/README.md)》。

### 补充：三种高频学习失败模式与修复

大纲把每个知识点组织成"场景 → 机制 → 代码 → 坑"，但失败几乎都发生在动笔之前。下面三种模式各配一个自测与修复清单，命中任意一条，都比多学一个知识点更值得优先处理。

**模式一：教程地狱——跟着敲能跑，合上教程写不出**。

- 症状：跟做时每一步都能跑通；删掉 demo、新建空文件，30 分钟内复原不了，第一行 import 之后就开始犹豫。自测法就这一个：随机挑一个最近跟做的 demo，删掉重写。
- 根因：全程在"复制 + 对答案"，认知负荷全花在"和教程对齐"上。文件结构、命名、先写哪段——所有决策都被教程替你做了，练到的是打字，不是设计。
- 修复清单：
  1. 跟做改为"先猜后看"：每个代码块先停 10 秒，预测下一行，再往下读；猜错的位置才是真知识点，回到对应机制小节重读一遍。
  2. 每跟完一个 demo 立刻"复写"：删掉原文件，只看需求描述（不看代码）重写；写不下去才允许回看，回看处记一笔。
  3. 复写通过后做一个变体（见下一节），换一个数据形状再写一遍。

**模式二：收藏夹瘫痪——一直在准备，从未开始**。

- 症状：收藏了三十篇文章、五个仓库，进度停在阶段 1；每次学习先花二十分钟"找那篇最好的"。
- 根因：囤积资料制造"我在做准备"的错觉，直接替代了学习本身；选项越多，启动成本越高。
- 修复清单：
  1. 资料收敛为两个来源：本大纲 + react.dev 对应章节；其余收藏移出学习路径（不必删，但学习时不再打开）。
  2. 以"场景"为打开单位而不是"资料"：每天直接打开当天的 demo 文件开写。
  3. 临时搜索限 20 分钟，超时把问题记进卡壳台账（见下一节），带着问题继续推进——很多问题会在后续场景里被自然解答。

**模式三：过早追新——demo 还没写完，已经在读源码**。

- 症状：阶段 2 没写完，正在研究并发渲染与 Server Components；单个 demo 反复重构"架构"，两周没有新场景产出。
- 根因：把"知道高级概念"当成了进度，跳过"能徒手写出"的验收；学习目标与当前阶段错位。
- 修复清单：
  1. 每个 demo 设"够用即停"线：跑通 + 能讲清机制 + 坑记进台账，立即翻篇；抽象与优化是阶段 6 的事。
  2. 高级概念记入"停车场清单"（只写标题，不展开），到达对应阶段再取出来。
  3. 每周只认产出验收清单的勾选数，不认"我了解过"这种感觉词。

三种模式共用一个解药：把输入变成可检验的输出。后两节给出两个具体的输出载体——变体改造与进度台账。

### 补充：变体改造法——把一个场景练三遍

一个场景只写一遍，记住的是"这个例子"；改着需求写三遍，记住的才是"这类问题"。规则：代码全部从空文件重写；每遍只改一个维度；动笔前先预测会改哪些代码，写完对照差异。以阶段 1 场景 2 的 `statusMap + satisfies` 为例。

**第一遍（原样复写）**：不看原文，写出四状态徽章、`satisfies Record<Status, StatusMeta>`、`keyof typeof` 派生状态联合类型。这一遍只验收"记没记住"，写不出来就回原文重读，隔天再来。

**第二遍（换数据形状）**：需求改为"进行中要附带进度百分比，其余状态没有"。表结构需要加可选字段，组件还要支持外部传入进度覆盖表里的值：

```tsx
import { useState } from 'react'

interface StatusMeta {
  label: string
  tone: 'gray' | 'blue' | 'green' | 'red'
  /** 仅 loading 有意义：0-100 的进度，初始 0，由外部驱动 */
  progress?: number
}

type Status = 'idle' | 'loading' | 'success' | 'error'

const statusMap = {
  idle: { label: '未开始', tone: 'gray' },
  loading: { label: '进行中', tone: 'blue', progress: 0 },
  success: { label: '已完成', tone: 'green' },
  error: { label: '失败', tone: 'red' },
} satisfies Record<Status, StatusMeta>

function StatusBadge({ status, progress }: { status: Status; progress?: number }) {
  const meta = statusMap[status]
  // 可选字段的消费：外部传了用外部的，否则读表里的；显示前显式比较，既不出现裸 0 也不吞 NaN
  const shown = progress ?? meta.progress
  return (
    <span className={`badge badge--${meta.tone}`}>
      {meta.label}
      {shown !== undefined && shown > 0 ? `（${shown}%）` : null}
    </span>
  )
}

export default function VariantProgress() {
  const [progress, setProgress] = useState(36)
  return (
    <div>
      <StatusBadge status="idle" />
      <StatusBadge status="loading" progress={progress} />
      <input
        type="range"
        min={0}
        max={100}
        value={progress}
        onChange={(e) => setProgress(Number(e.target.value))}
      />
    </div>
  )
}
```

这一遍暴露的取舍：`satisfies` 仍保证"四个状态配齐、值形状正确"，但表达不了"loading 必须带 progress"这种更强的约束——要做到就得把类型改成按状态分化的形状，约束更强、表更难写。当你开始主动权衡这类约束，就已经从"会用"进入"会选"。

**第三遍（换交互）**：需求改为"按钮循环推进状态：idle → loading → success → error → idle"，外加"loading 三秒后自动落定"。前半句是纯事件，现有知识够写；后半句是定时副作用，纯渲染知识写不出来。把定时需求记进卡壳台账，作为进入阶段 2 的第一个动手题。第三遍的价值恰恰是探到边界：能明确说出"哪里写不出来、缺的是什么"，跳级才跳得有质量。

**变体需求卡**（每遍一张，写完贴在 demo 文件顶部注释里）：

```text
变体 N：________
- 改动维度：数据形状 / 交互 / 约束（三选一）
- 新需求一句话：________
- 预判要动的代码：________
- 实际动了哪里、与预判的差异：________
- 新发现的坑：________
```

关键纪律：每遍只改一个维度。同时改三个维度等于写新 demo，你将无法归因"哪份认知来自哪个变化"。

### 补充：进度追踪与卡壳台账

60/20/20 里的"复盘"环节需要一个落点，否则每晚的反思会退化成"感觉今天学了不少"。用两个 markdown 文件固化它，放在仓库根目录、随代码一起进 git。

**`PROGRESS.md`——进度对账**。每个场景一行，状态只允许四个合法值：

```markdown
# 学习进度

| 阶段 | 场景 | 状态 | 完成日期 | 回灌进项目 |
|---|---|---|---|---|
| 1 | 场景 1 JSX | done | 11-03 | 商品卡片页 |
| 1 | 场景 2 条件渲染 | redo | - | - |
| 2 | useState 不可变更新 | wip | - | - |

合法状态：
- todo：未开始
- wip：正在做（任何时刻只允许一行 wip，多行 wip 等于没在做）
- done：通过该文件末尾的产出验收清单（逐项打勾 + 能口头讲解）
- redo：曾标 done，但回灌项目时写不动，退回重做
```

两条规则：`done` 的判据是验收清单而不是"代码能跑"；`redo` 行比十行 `done` 更有价值——它标记的是真实的掌握边界，也是复习时唯一需要重看的行。

**`BLOCKERS.md`——卡壳台账**。任何卡住超过 20 分钟的问题记一行，根因列允许先空着，解决后必须回填——回填的过程就是把"绕过去的坑"变成"讲得清的机制"：

```markdown
# 卡壳台账

| 日期 | 问题 | 卡在哪 | 根因（解决后回填） | 解法/出处 | 状态 |
|---|---|---|---|---|---|
| 11-03 | statusMap[status] 运行时报 undefined | 接口返回 'DONE' 大写 | 键集合与真实取值不一致 | 查表前 status in statusMap 兜底；类型层用 satisfies 收窄 | closed |
| 11-04 | index 作 key 删行后勾选错位 | 时序推不出来 | key 是数据身份，index 只是位置 | 03 文件错案一亲手复现 | open |
```

**每周日复盘清单**（对应 20% 的复盘时间，固定执行一次）：

- [ ] PROGRESS.md：本周新增几行 done？redo 有几行？
- [ ] 挑本周最不满意的一个 demo，用 20 分钟重构到"愿意署名"
- [ ] BLOCKERS.md 的 open 行逐条过：回填根因、关闭、或写明挂起到哪个阶段
- [ ] 项目线回灌：本周至少一个新手法进入 TodoMVC / 商品页
- [ ] 下周计划只列"场景编号 + 日期"，不列形容词
