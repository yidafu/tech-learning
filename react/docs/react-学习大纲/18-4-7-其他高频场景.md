### 4.7 其他高频场景

九个场景各自独立，都是"面试高频 + 业务必用"的投入产出比之王。建议每个场景先写最小 demo，再把产物合进阶段末尾的后台管理系统项目里。

#### 1. 文件上传：进度条、多文件、图片预览、大文件分片

**是什么。** 文件上传看似只是 `<input type="file">` + FormData，但完整实现要覆盖四件事：上传**进度**可视化、**多文件**的队列管理、图片**预览**的内存管理、**大文件**的分片断点策略。

**为什么需要。** 进度条解决"传 200MB 时用户不知道该不该关页面"的焦虑；多文件队列解决"10 个文件 3 个失败，哪些要重传"的可视化；`URL.createObjectURL` 预览解决"选完图立刻看到要传什么"的确认感；分片解决大文件的三个痛点——**浏览器/网关的请求体大小限制**、**弱网下一个包失败全部重来**、**无法利用带宽并发**。

**怎么做（机制分步）。**

*进度条*：关键事实是 **fetch 至今没有上传进度 API**（下载进度可以用 `res.body` 流统计，上传不行）。上传进度只能用 `XMLHttpRequest` 的 `xhr.upload.onprogress` 事件——它属于上传通道（`xhr.upload` 是一个 `XMLHttpRequestUpload` 对象），在请求体分块发出时触发，`e.loaded / e.total` 即百分比（`e.lengthComputable` 为 false 时拿不到 total，比如 chunked 编码）。

*多文件队列*：给每个文件建一条状态记录（排队中 → 上传中 → 成功/失败 + 百分比），UI 渲染队列而不是整页一个进度条。并发用简单的"游标 + 固定 worker 数"池子控制（浏览器对同域名 HTTP/1.1 也就 6 个并发，全并发反而互相挤占）。

*图片预览*：`URL.createObjectURL(file)` 为 Blob 生成一个 `blob:` 开头的内存 URL，**不读文件内容、同步返回**，比 `FileReader.readAsDataURL` 快得多。代价是这个 URL 对应的内存在 `revokeObjectURL` 之前一直被占着——**创建后必须在不再使用时（组件卸载/替换图片）手动 revoke**，这是本条最常见的内存泄漏。

*大文件分片*：三方协议（前端/后端约定三个接口）：

```text
① POST /api/uploads           { filename, size, chunkSize }        → { uploadId, chunkCount }
② POST /api/uploads/chunk     FormData{ uploadId, index, chunk }   → 每片可独立重试
③ POST /api/uploads/:id/complete { chunkCount }                    → 服务端按 index 顺序合并
```

前端用 `file.slice(start, end)` 切片——`slice` 返回的是**视图 Blob，不会把整个文件读进内存**，这是切 2GB 视频也不爆内存的原因。分片用固定并发池上传，每片成功累计字节数算总进度；单片失败只重试那一片；全部完成后调 complete 让服务端按 `index` 顺序拼接（**服务端必须按序拼，不能按到达顺序**）。

**代码示例。** 带 XHR 进度的单文件上传：

```ts
// lib/upload.ts
export interface UploadResult {
  url: string;
}

/** XHR 上传：fetch 没有上传进度事件，进度条只能走这条路 */
export function uploadWithProgress(
  file: File,
  url: string,
  onProgress: (percent: number) => void,
): Promise<UploadResult> {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('POST', url);
    xhr.responseType = 'json';

    // upload.onprogress 是 fetch 至今缺失的能力
    xhr.upload.onprogress = (e) => {
      if (e.lengthComputable) {
        onProgress(Math.round((e.loaded / e.total) * 100));
      }
    };
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(xhr.response as UploadResult);
      } else {
        reject(new Error(`上传失败：HTTP ${xhr.status}`));
      }
    };
    xhr.onerror = () => reject(new Error('网络错误，上传中断'));

    const form = new FormData();
    form.append('file', file); // FormData 会自动设置 multipart/form-data 边界
    xhr.send(form);
  });
}
```

多文件队列组件（含预览的创建与 revoke）：

```tsx
// components/UploadQueue.tsx
import { useEffect, useRef, useState } from 'react';
import { uploadWithProgress } from '../lib/upload';

interface UploadItem {
  id: string;
  file: File;
  previewUrl: string | null; // blob: 预览 URL（非图片为 null）
  status: 'queued' | 'uploading' | 'success' | 'error';
  percent: number;
}

const CONCURRENCY = 3; // 并发上传数：对同域名 HTTP/1.1 超过 6 会排队，3~4 比较稳

export function UploadQueue() {
  const [items, setItems] = useState<UploadItem[]>([]);
  // 保存待 revoke 的 URL，卸载时统一释放
  const objectUrlsRef = useRef<string[]>([]);

  function addFiles(files: FileList | null) {
    if (!files) return;
    const next: UploadItem[] = Array.from(files).map((file) => {
      const isImage = file.type.startsWith('image/');
      // createObjectURL 同步返回 blob: URL，不读文件内容，大图也瞬时
      const previewUrl = isImage ? URL.createObjectURL(file) : null;
      if (previewUrl) objectUrlsRef.current.push(previewUrl);
      return { id: crypto.randomUUID(), file, previewUrl, status: 'queued', percent: 0 };
    });
    setItems((prev) => [...prev, ...next]);
  }

  // 组件卸载时释放所有 blob: URL——不释放就是实打实的内存泄漏
  useEffect(() => {
    const urls = objectUrlsRef.current;
    return () => urls.forEach((u) => URL.revokeObjectURL(u));
  }, []);

  // 从队列里挑出 queued 的文件，按固定并发跑完（游标 worker 池）
  async function startUpload() {
    const pending = items.filter((i) => i.status === 'queued');
    let cursor = 0;

    function patch(id: string, part: Partial<UploadItem>) {
      setItems((prev) => prev.map((i) => (i.id === id ? { ...i, ...part } : i)));
    }

    async function worker() {
      while (cursor < pending.length) {
        const item = pending[cursor++];
        patch(item.id, { status: 'uploading', percent: 0 });
        try {
          await uploadWithProgress(item.file, '/api/upload', (percent) =>
            patch(item.id, { percent }),
          );
          patch(item.id, { status: 'success', percent: 100 });
        } catch {
          patch(item.id, { status: 'error' }); // 单文件失败不拖垮队列，可单独重传
        }
      }
    }
    await Promise.all(Array.from({ length: Math.min(CONCURRENCY, pending.length) }, worker));
  }

  return (
    <div className="upload">
      <input type="file" multiple accept="image/*,.pdf" onChange={(e) => addFiles(e.target.files)} />
      <button onClick={startUpload} disabled={!items.some((i) => i.status === 'queued')}>
        开始上传
      </button>
      <ul className="upload-list">
        {items.map((item) => (
          <li key={item.id} className={`upload-item ${item.status}`}>
            {item.previewUrl ? (
              <img src={item.previewUrl} alt={item.file.name} width={48} height={48} />
            ) : (
              <span className="file-icon">📄</span>
            )}
            <span className="name">{item.file.name}</span>
            {item.status === 'uploading' && <progress value={item.percent} max={100} />}
            <span className="status">
              {item.status === 'queued' && '排队中'}
              {item.status === 'uploading' && `${item.percent}%`}
              {item.status === 'success' && '完成'}
              {item.status === 'error' && '失败'}
            </span>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

大文件分片上传：

```ts
// lib/chunkUpload.ts
const CHUNK_SIZE = 5 * 1024 * 1024; // 5MB 一片：太小则请求数爆炸，太大则单片重试代价高

export async function uploadLargeFile(
  file: File,
  onProgress: (percent: number) => void,
): Promise<string> {
  // ① 初始化：登记文件信息，服务端返回本次上传会话
  const init = await fetch('/api/uploads', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ filename: file.name, size: file.size, chunkSize: CHUNK_SIZE }),
  }).then((r) => r.json() as Promise<{ uploadId: string; chunkCount: number }>);

  const { uploadId, chunkCount } = init;
  let uploadedBytes = 0;
  const indexes = Array.from({ length: chunkCount }, (_, i) => i);
  let cursor = 0;

  // ② 固定 3 并发上传分片；slice 返回视图 Blob，不把整个文件读进内存
  async function worker() {
    while (cursor < indexes.length) {
      const index = indexes[cursor++];
      const blob = file.slice(index * CHUNK_SIZE, (index + 1) * CHUNK_SIZE);
      const form = new FormData();
      form.append('uploadId', uploadId);
      form.append('index', String(index)); // 服务端合并时按 index 排序，不按到达顺序
      form.append('chunk', blob);

      // 单片失败重试 3 次，弱网下比"整文件重来"便宜几个量级
      let lastError: unknown = null;
      for (let attempt = 0; attempt < 3; attempt++) {
        try {
          const res = await fetch('/api/uploads/chunk', { method: 'POST', body: form });
          if (!res.ok) throw new Error(`分片 ${index} HTTP ${res.status}`);
          lastError = null;
          break;
        } catch (err) {
          lastError = err;
        }
      }
      if (lastError) throw lastError;

      uploadedBytes += blob.size;
      onProgress(Math.round((uploadedBytes / file.size) * 100));
    }
  }
  await Promise.all([worker(), worker(), worker()]);

  // ③ 全部就绪后通知服务端按 index 顺序合并
  const done = await fetch(`/api/uploads/${uploadId}/complete`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ chunkCount }),
  }).then((r) => r.json() as Promise<{ url: string }>);
  return done.url;
}
```

**常见坑。**

- **症状**：进度条永远 0 或直接 100。**根因**：用了 fetch（无上传进度）；或监听写成 `xhr.onprogress`（那是**下载**通道）。**修法**：XHR 且绑定在 `xhr.upload.onprogress`。
- **症状**：传几十张图后页面越来越卡，Memory 面板里 blob 持续增长。**根因**：`createObjectURL` 之后从不 `revokeObjectURL`。**修法**：预览 URL 集中管理，卸载/替换时统一释放（队列组件里 `objectUrlsRef` 的做法）。
- **症状**：分片都传成功，合并后的文件打不开。**根因**：服务端按"到达顺序"拼接，并发导致顺序错乱。**修法**：每片带 `index`，服务端按 index 排序后拼接；前端 `slice` 的起止必须严格按 `index * CHUNK_SIZE` 对齐。
- **症状**：选完文件没点上传，列表里什么都没有。**根因**：把预览创建放在 `onChange` 之外（比如点了上传才建），或 `accept` 写错导致选择器里选不了。**修法**：预览在 `onChange` 时同步创建，体验即时。
- **症状**：上传接口 413。**根因**：请求体超过网关（nginx `client_max_body_size` 等）限制。**修法**：调大服务端限制或直接走分片上传——分片本来就是为绕开这个限制设计的。

#### 补充：实战变体——表单与文件的联合提交（两阶段、部分失败恢复、幂等防重）

**是什么。** "新建商品"这类页面 = 表单字段（名称、描述）+ 多张图片。两阶段提交：图片选完即自动上传（每张独立进度条，成功拿到服务器 URL），提交表单时只发 JSON（带 URL 列表）。要处理三个脏边界：图片还在传时用户点了提交、部分图片失败、重复提交。

**为什么两阶段而不是一个 FormData。** FormData 一次性把字段和文件混发，看似简单，代价是：文件与字段绑死，任何一项失败全部重来；无法做单文件进度与单文件重传；后端没法把"传文件"与"建商品"拆成独立接口（事务边界更清晰）。图片多、弱网环境，两阶段是主流；字段少文件少（如头像裁剪后一次提交）用 FormData 反而省事。

**代码示例。** 完整可运行，复用本节的 `uploadWithProgress`：

```tsx
// features/product/ProductCreatePage.tsx
import { useRef, useState } from 'react';
import { uploadWithProgress } from '../../lib/upload';

interface ImageItem {
  id: string;
  file: File;
  url: string | null; // 上传成功后的服务器 URL
  status: 'uploading' | 'success' | 'error';
  percent: number;
}

export function ProductCreatePage() {
  const [name, setName] = useState('');
  const [images, setImages] = useState<ImageItem[]>([]);
  const [submitting, setSubmitting] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const idempotencyRef = useRef(''); // 幂等键：一次"提交意图"一个键

  function patch(id: string, part: Partial<ImageItem>) {
    setImages((prev) => prev.map((it) => (it.id === id ? { ...it, ...part } : it)));
  }

  function uploadOne(item: ImageItem) {
    patch(item.id, { status: 'uploading', percent: 0 });
    uploadWithProgress(item.file, '/api/upload', (percent) => patch(item.id, { percent }))
      .then((res) => patch(item.id, { status: 'success', url: res.url }))
      .catch(() => patch(item.id, { status: 'error', percent: 0 }));
  }

  function addImages(files: FileList | null) {
    if (!files) return;
    for (const file of Array.from(files)) {
      const item: ImageItem = { id: crypto.randomUUID(), file, url: null, status: 'uploading', percent: 0 };
      setImages((prev) => [...prev, item]);
      uploadOne(item); // 选完即自动上传：每张图独立生命周期，失败单独重传
    }
  }

  async function handleSubmit() {
    if (submitting) return; // 同步哨兵防连点（弹层篇 4.5.4 的同款双保险）
    setError(null);

    // 边界一：还有在途上传——阻止提交并给明确指引
    if (images.some((it) => it.status === 'uploading')) {
      setError('还有图片在上传中，请等它们完成');
      return;
    }
    // 边界二：有失败图——产品策略二选一，这里选"禁止提交"（商品无主图是下游脏数据）
    const failed = images.filter((it) => it.status === 'error');
    if (failed.length > 0) {
      setError(`${failed.length} 张图片上传失败，请移除或重试`);
      return;
    }

    setSubmitting(true);
    if (!idempotencyRef.current) idempotencyRef.current = crypto.randomUUID();
    try {
      const res = await fetch('/api/products', {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          // 幂等键：网络超时后用户重点"提交"，服务端凭同一个键去重，不会建出两个商品
          'Idempotency-Key': idempotencyRef.current,
        },
        // 走到这里 status 全部是 success，url 非空（类型上用 ! 收窄）
        body: JSON.stringify({ name, images: images.map((it) => it.url!) }),
      });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      idempotencyRef.current = ''; // 真正成功后才换新键：失败重试必须沿用旧键
      // navigate('/products')（路由跳转见 15 号路由篇）
    } catch {
      setError('创建失败，请重试（已上传的图片无需重传）'); // 两阶段的价值：图片 URL 都还在
    } finally {
      setSubmitting(false);
    }
  }

  return (
    <div className="product-form">
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="商品名称" />
      <input
        type="file"
        multiple
        accept="image/*"
        onChange={(e) => {
          addImages(e.target.files);
          e.target.value = ''; // 选同一文件也能再次触发 change（组件库 Upload 篇坑 1）
        }}
      />
      <ul>
        {images.map((it) => (
          <li key={it.id}>
            {it.status === 'uploading' && <progress value={it.percent} max={100} />}
            {it.status === 'error' && (
              <button type="button" onClick={() => uploadOne(it)}>重试</button>
            )}
            {it.status === 'success' && '✓'}
          </li>
        ))}
      </ul>
      {error && <p role="alert">{error}</p>}
      <button type="button" onClick={handleSubmit} disabled={submitting}>
        {submitting ? '提交中…' : '创建商品'}
      </button>
    </div>
  );
}
```

**关键取舍。**

1. **幂等键的生命周期**：一次"提交意图"全程用同一个键——失败重试沿用（服务端去重的依据），真正成功后才换新。每次点击都生成新键的话，重试会建出重复数据，幂等保护形同虚设。
2. **失败图的策略**：禁止提交（强迫用户处理）vs 允许跳过（先建商品后补图）。内容创建场景选禁止：列表缩略图、搜索索引都依赖主图。
3. **上传时机**：选完即传体验好、提交快，代价是用户可能删掉已传的图（浪费流量）；点提交才统一传省流量但提交慢、且失败恢复粒度回到整单。面向生产者的表单选前者。

#### 补充：边界与防御——取消上传、防重复入队、离开页面拦截

**取消进行中的上传。** `uploadWithProgress` 基于 XHR，XHR 天生支持中断（`xhr.abort()`）；把它桥接到统一的 `AbortSignal` 协议上，调用方就能像 cancel fetch 一样 cancel 上传：

```ts
// lib/uploadWithAbort.ts —— 与 uploadWithProgress 同构，额外接入 AbortSignal
import type { UploadResult } from './upload';

export function uploadWithAbort(
  file: File,
  url: string,
  onProgress: (percent: number) => void,
  signal?: AbortSignal,
): Promise<UploadResult> {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) {
      reject(new DOMException('Aborted', 'AbortError')); // 调用前就已取消
      return;
    }
    const xhr = new XMLHttpRequest();
    xhr.open('POST', url);
    xhr.responseType = 'json';

    const onAbort = () => xhr.abort(); // signal 取消 → 中断 XHR
    signal?.addEventListener('abort', onAbort);
    // abort() 触发的是 onabort（不是 onerror），单独归一成 AbortError
    xhr.onabort = () => reject(new DOMException('Aborted', 'AbortError'));

    xhr.upload.onprogress = (e) => {
      if (e.lengthComputable) onProgress(Math.round((e.loaded / e.total) * 100));
    };
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) resolve(xhr.response as UploadResult);
      else reject(new Error(`上传失败：HTTP ${xhr.status}`));
    };
    xhr.onerror = () => reject(new Error('网络错误，上传中断'));

    const form = new FormData();
    form.append('file', file);
    xhr.send(form);
  });
}
```

队列接入（每项一个 AbortController，"取消"按钮与"移除队列项"共用同一入口）：

```tsx
// UploadQueue 里的取消（节选，接本节正文的队列结构）
const abortMapRef = useRef(new Map<string, AbortController>());

async function uploadQueueItem(item: UploadItem) {
  const controller = new AbortController();
  abortMapRef.current.set(item.id, controller);
  patch(item.id, { status: 'uploading', percent: 0 });
  try {
    const res = await uploadWithAbort(item.file, '/api/upload',
      (percent) => patch(item.id, { percent }), controller.signal);
    patch(item.id, { status: 'success', percent: 100, url: res.url });
  } catch (err) {
    // 区分"用户取消"与"真失败"：取消不算失败，静默归队
    const aborted = err instanceof DOMException && err.name === 'AbortError';
    patch(item.id, aborted ? { status: 'queued', percent: 0 } : { status: 'error' });
  } finally {
    abortMapRef.current.delete(item.id);
  }
}

function cancelItem(id: string) {
  abortMapRef.current.get(id)?.abort(); // 中断网络请求；后续 patch 在 catch 分支完成
}
```

**防重复入队。** "开始上传"按钮连点会把同一批文件入两次队列。UI 层 disabled 之外，入队前按指纹去重：`file.name + file.size + file.lastModified` 三元组相同的文件视为同一个。

**上传中离开页面拦截。** 刷新/关标签页会让全部进度归零（分片上传还会在服务端留孤儿分片）。路由内的写法见 15 号路由篇 4.4.3 的 `useBeforeUnload`；这里给非路由入口（上传队列与路由解耦时）的原生版本：

```ts
// hooks/useUploadLeaveGuard.ts
import { useEffect } from 'react';

export function useUploadLeaveGuard(hasInFlight: () => boolean) {
  useEffect(() => {
    const handler = (e: BeforeUnloadEvent) => {
      if (hasInFlight()) {
        e.preventDefault();
        e.returnValue = ''; // 旧版 Chrome 必需
      }
    };
    window.addEventListener('beforeunload', handler);
    return () => window.removeEventListener('beforeunload', handler);
  }, [hasInFlight]);
}
// 使用：useUploadLeaveGuard(() => items.some((i) => i.status === 'uploading'));
```

注意 `hasInFlight` 用**函数形式**传入：effect 只注册一次监听器，每次事件触发时才读最新队列——把 `items` 放进依赖数组会导致监听器随每次进度更新反复装卸。

#### 补充：高频坑位补遗

（组件库 Upload 篇已列过的 8 个坑——input 不重置、dragover 未 preventDefault、fetch 无进度、手动 Content-Type、受控数组原地改、粘贴焦点、分片 413、MD5 主线程冻结——此处不重复。）

- **症状**：把 `evil.exe` 改名成 `evil.jpg`，`accept="image/*"` 和 `file.type.startsWith('image/')` 全部放行，服务端存了一个假图片。**根因**：浏览器按扩展名推断 `File.type`，不看文件内容。**修法**：入队前读文件头几个字节对照魔数（magic number）：

```ts
// lib/fileMagic.ts —— 按"内容"而不是"扩展名"识别文件类型
const MAGIC: Record<string, number[]> = {
  'image/jpeg': [0xff, 0xd8, 0xff],
  'image/png': [0x89, 0x50, 0x4e, 0x47],
  'image/gif': [0x47, 0x49, 0x46, 0x38], // "GIF8"
  'application/pdf': [0x25, 0x50, 0x44, 0x46], // "%PDF"
};

export async function sniffType(file: File): Promise<string | null> {
  // slice 返回视图 Blob，只读头 4 字节，大文件也瞬时
  const buf = new Uint8Array(await file.slice(0, 4).arrayBuffer());
  for (const [type, magic] of Object.entries(MAGIC)) {
    if (magic.every((b, i) => buf[i] === b)) return type;
  }
  return null;
}
// 入队前：if (await sniffType(file) === null) { toast.error('文件内容不是受支持的图片格式'); return; }
```

- **症状**：把一个上传中的队列项从列表移除，UI 上消失了，几秒后 Network 面板显示它的请求仍然完成、服务端也存了文件。**根因**：移除只改了本地数组，在途请求没人管——产生"用户以为删了、服务器其实收了"的孤儿文件，还白白占用并发名额。**修法**：移除动作必须联动取消——`removeItem` 里先 `abortMapRef.current.get(id)?.abort()`（见上一节的 `cancelItem`）；取消后 catch 分支的 patch 打到已删项上是 no-op，无副作用。
- **症状**：上传成功的回调里立即 `URL.revokeObjectURL(previewUrl)`，列表里的预览图当场裂掉。**根因**：revoke 不影响"已完成的加载"，但会拦住尚未开始的加载；`<img src={blob:...}>` 在 src 复用/重排时重新发起加载就会失败。**修法**：成功后先把 `<img src>` 切到服务器 URL，再 revoke blob URL；或干脆维持本节正文的"卸载时统一 revoke"——几张预览图的内存占用不值得精细管理。
- **症状**：用 `FileReader.readAsDataURL` 做预览，用户选了个 500MB 的视频，页面卡死、内存暴涨。**根因**：readAsDataURL 把整个文件读进内存再转 base64（体积还要 +33%）。**修法**：预览一律 `URL.createObjectURL`（不读文件内容、同步返回，本节正文已讲）；readAsDataURL 只用于"必须拿到文件内容本身"的场景，且读切片——上面魔数校验只读 4 字节就是安全用法。
