## 进阶篇：复杂业务场景

Schema 动态表单、Grafana 式拖拽大盘、拖拽式表单设计器、JSON 编辑器、低代码平台等高难度场景，见 [react-进阶大纲-复杂场景.md](../react-进阶大纲-复杂场景/README.md)（建议完成本大纲阶段 1–4 后进入）。

### 补充：进入复杂场景前的拆解套路与自测门槛

复杂场景大纲教的是"五大场景怎么做"；这一节补两样它不教的东西：**拿到任何一个陌生复杂需求时的拆解套路**（让你敢接大纲之外的场景），和**进入前的自测门槛**（8 题，答不出的回去补对应阶段——复杂场景是在基础能力上加盖，地基缺一角楼就歪）。

**五步拆解法：把陌生复杂需求切成已知小场景。** 面对任何"看起来很大"的前端需求（审批流设计器、看板系统、富文本编辑器……），按固定顺序问五个问题：

1. **数据长什么样？** 找到核心数据结构（通常是一棵 JSON 树或一张图），它决定状态建模方式。问句：能不能用一个 TypeScript 类型描述"一份完整的用户作品"？能——树/Schema 建模（本大纲阶段 7 的类型功夫）；不能（多端实时协同）——问题升维，先解决同步模型。
2. **渲染长什么样？** 数据到 UI 的形状：递归树（设计器、表单）→ 递归渲染器；自由画布（大盘、白板）→ 绝对定位 + 坐标系；表格/流（看板、列表）→ 虚拟化方向（阶段 4.3）。
3. **交互长什么样？** 拆成交互原语的组合：拖拽（阶段 4.7 的 dnd-kit）、编辑（受控/撤销栈）、选中高亮、缩放。复杂交互 = 原语叠加，不存在"没见过的交互"。
4. **性能边界在哪？** 估算节点数量级：百级随便写；千级要 memo 化与局部订阅（阶段 6）；万级要虚拟化与分块渲染。先问数量级再选方案，避免"为万级设计百级需求"的过度工程。
5. **每个切开的子问题，映射回本大纲哪一节？** 映射得上的直接开工，映射不上的才需要去复杂场景大纲或外部找——通常你会发现 80% 的子问题都是学过的。

**走一遍示例（审批流设计器，30 秒口头拆解）。** 数据：节点+连线的图 → 类型建模 `{ nodes: Node[], edges: Edge[] }`；渲染：自由画布（绝对定位 + SVG 画连线）；交互：拖拽摆位（dnd-kit）+ 点击配置侧栏（受控表单）+ 撤销重做（不可变栈）；性能：节点通常 <200，无需虚拟化；映射：类型（阶段 7）+ 拖拽（4.7）+ 表单（4.1）+ 撤销（复杂场景大纲 1-5 Undo/Redo）。一个"没做过的需求"就变成了一张开发清单。

**五大场景 → 前置章节映射表（进入前按右列自查）。**

| 复杂场景 | 核心难点（去那边学） | 前置自查（本大纲） |
|---|---|---|
| Schema 动态表单 | 协议设计、组件注册表、递归渲染 | 阶段 7 泛型组件/工具类型；阶段 4.1 受控表单 |
| 拖拽式表单设计器 | 拖拽 + 画布 + Schema 双向同步 | 19-2 dnd-kit；阶段 3 组件设计模式 |

| 低代码平台整合 | 表达式引擎、Undo/Redo、性能 | 复杂场景大纲通用底座（1.1–1.7）全部 |

**进入前的 8 道自测题（每题一句话答案，答不出 2 题以上先回炉）。**

1. 泛型 Select 什么场景下"必须"泛型？（回调参数类型要跟随 options 的 value 类型，否则调用方拿到宽类型。→ 阶段 7 第 3 条）
2. 受控组件的 value 与 onChange 缺一会怎样？（受控失效：值不更新或更新不受控。→ 阶段 3）
3. 递归渲染器的终止条件写在哪？（Schema 节点无 children/子节点数组为空时渲染叶子组件。→ 复杂场景大纲 1-3）
4. 撤销栈为什么必须存不可变快照或反向操作？（可变对象会被后续修改污染历史。→ 复杂场景大纲 1-5；阶段 2 不可变更新的直觉）
5. 列表多少项开始考虑虚拟化，判断依据是什么？（千级起步；依据是渲染与 DOM 节点数成为瓶颈的实测，不是体感。→ 阶段 4.3/6）
6. dnd-kit 的 sortable 与 draggable 何时选用？（同容器排序用 sortable，跨容器/自由拖用 draggable + 自管理状态。→ 19-2）
7. `JSON.parse` 的返回值直接 `as` 成目标类型，风险在哪？（运行时零校验，结构漂移在渲染深处爆炸；先 unknown 再守卫。→ 阶段 7 第 7 条）
8. 父组件每渲染一次就新建传给递归树的 context/props 对象，大树会怎样？（整树连坐重渲染；需要 memo + 稳定引用或局部订阅。→ 阶段 6）

**拆解结果的产物模板（五步走完，填这张单子进任务清单）。**

```markdown
## [需求名] 拆解单
- 数据模型：[类型定义草稿，含判别联合/泛型]
- 渲染形状：[递归树 / 自由画布 / 虚拟列表，二选一或多选]
- 交互原语：拖拽[范围] / 编辑[哪些字段] / 撤销[要否] / 多选[要否]
- 性能边界：预计节点量 [数量级]，对应策略 [memo / 局部订阅 / 虚拟化 / 无]
- 子问题 → 章节映射：
  1. [子问题] → [大纲章节/复杂场景章节]
  2. [子问题] → ...
  （映射不到的子问题单独列出，去复杂场景大纲或对标开源项目找）
- 风险项：[映射不到的子问题、无把握的性能点]
```

这张单子同时是开发排期（子问题即任务）、自查表（风险项即验证重点）和求助提纲（拿不准的地方拿它去问，比"这个需求怎么做"具体一百倍）。

**门槛不达时的回炉路径。** 8 题里错 3 题以上，不建议硬进复杂场景——先按错的题回对应阶段补一周：泛型与类型（错 1、7）回阶段 7；受控与渲染（错 2、8）回阶段 3、6；列表与拖拽（错 5、6）回 19-2 与阶段 4.3；递归与撤销（错 3、4）直接进复杂场景大纲的通用底座（1-3 递归渲染器、1-5 Undo/Redo），这两个主题在基础大纲只埋了直觉，底座篇才是正式展开。复杂场景的门槛是"基础能力全部在线"，而不是"学完了所有基础内容"。
