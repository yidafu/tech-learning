#### 5. 国际化 i18n（语言包组织、切换、格式化）

**是什么。** i18n（internationalization，i 到 n 中间 18 个字母）指界面文案的多语言支持，三件事：**语言包组织**（文案与代码分离）、**切换**（运行时换语言不刷新）、**格式化**（数字/日期/复数按 locale 呈现）。本条手写一个最小可用的 i18n，理解原理；生产一般直接用 react-i18next。

**为什么需要。** 文案写死在 JSX 里（`<button>确定</button>`）时，加第二种语言等于重写所有页面。i18n 的核心动作是把文案抽成 key：`<button>{t('common:ok')}</button>`，渲染时按当前语言查表。而**格式化**是最容易被忽略的部分：`12,345.67`、`¥12,345.67`、`3 分钟前`、`1 item vs 2 items`——这些不是翻译问题，是 locale 规则问题，浏览器内置的 `Intl` 对象就是干这个的，不需要任何库。

**怎么做（机制分步）。**

*语言包组织*：一个语言一个目录，一个 namespace（命名空间）一个 JSON 文件——`common`（通用按钮/状态）、`user`（用户模块）、`validation`（校验提示）……好处是模块 Ownership 清晰（用户模块的语言包跟着模块走）、加载粒度可控（首屏只加载 common + 首页模块）、避免单个巨型文件 merge 冲突。key 使用 `namespace:点路径` 形式：`t('user:list.title')`。

*切换*：locale 状态放 Context；语言包 JSON 用动态 `import()`（Vite 的 `import.meta.glob` 懒加载），切换时才拉取目标语言；同时更新 `document.documentElement.lang`（影响无障碍朗读、字体选择与搜索引擎）。持久化到 localStorage。

*格式化*：`Intl.NumberFormat`（货币/千分位）、`Intl.DateTimeFormat`（日期时间）、`Intl.RelativeTimeFormat`（"3 分钟前"）、`Intl.PluralRules`（复数类别判断）。它们都以 locale 为第一参数——**格式化天然跟随语言切换，不需要翻译**。

*回退策略*：key 缺失时显示 key 本身（而不是空白），方便发现漏译；生产可加"缺失上报"。

**代码示例。** 语言包（注意两个语言的 key 树必须同构）：

最小 i18n 实现（Provider + t 函数 + 插值 + 懒加载）：

```tsx
// src/i18n/index.tsx
import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useState,
  type ReactNode,
} from 'react';

export type Locale = 'zh-CN' | 'en-US';

type Pack = Record<string, unknown>;

// Vite 的 import.meta.glob：把语言包收集为懒加载函数，切换语言时才真正请求
const modules = import.meta.glob<{ default: Pack }>('../locales/*/*.json');

/** 按 'a.b.c' 点路径在语言包里查找，返回字符串或 undefined */
function lookup(pack: Pack, path: string): string | undefined {
  const value = path.split('.').reduce<unknown>((node, key) => {
    if (node && typeof node === 'object' && key in (node as Pack)) {
      return (node as Pack)[key];
    }
    return undefined;
  }, pack);
  return typeof value === 'string' ? value : undefined;
}

/** 插值：把 { name: 'React' } 填进 "Hello {{name}}" */
function interpolate(template: string, params?: Record<string, string>): string {
  if (!params) return template;
  return template.replace(/\{\{(\w+)\}\}/g, (_, key: string) => params[key] ?? `{{${key}}}`);
}

interface I18nContextValue {
  locale: Locale;
  t: (key: string, params?: Record<string, string>) => string;
  setLocale: (locale: Locale) => void;
}

const I18nContext = createContext<I18nContextValue | null>(null);

export function I18nProvider({ children }: { children: ReactNode }) {
  const [locale, setLocaleState] = useState<Locale>(() => {
    const stored = localStorage.getItem('locale');
    return stored === 'en-US' || stored === 'zh-CN' ? stored : 'zh-CN';
  });
  // packs 按 namespace 存：{ common: {...}, user: {...} }
  const [packs, setPacks] = useState<Record<string, Pack>>({});

  useEffect(() => {
    let cancelled = false; // 防止快速连切语言时旧请求晚到覆盖
    (async () => {
      const entries = await Promise.all(
        Object.entries(modules)
          .filter(([path]) => path.includes(`/${locale}/`)) // 只加载当前语言的全部 namespace
          .map(async ([path, load]) => {
            const ns = path.split('/').pop()!.replace('.json', '');
            return [ns, (await load()).default] as const;
          }),
      );
      if (!cancelled) setPacks(Object.fromEntries(entries));
    })();
    return () => {
      cancelled = true;
    };
  }, [locale]);

  const t = useCallback(
    (key: string, params?: Record<string, string>) => {
      // key 形如 'user:list.title'：冒号前是 namespace，后面是点路径
      const [ns, ...rest] = key.split(':');
      const template = packs[ns] ? lookup(packs[ns], rest.join('.')) : undefined;
      // 缺失回退到 key 本身：界面上直接暴露漏译，而不是白屏或英文混排
      return template ? interpolate(template, params) : key;
    },
    [packs],
  );

  const setLocale = useCallback((next: Locale) => {
    localStorage.setItem('locale', next);
    document.documentElement.lang = next; // 无障碍朗读与浏览器翻译都依赖 lang
    setLocaleState(next);
  }, []);

  const value = useMemo(() => ({ locale, t, setLocale }), [locale, t, setLocale]);
  return <I18nContext.Provider value={value}>{children}</I18nContext.Provider>;
}

export function useI18n(): I18nContextValue {
  const ctx = useContext(I18nContext);
  if (!ctx) throw new Error('useI18n 必须在 I18nProvider 内使用');
  return ctx;
}
```

使用侧 + `Intl` 格式化：

```tsx
// src/pages/UserListHeader.tsx
import { useI18n } from '../i18n';

export function UserListHeader({ total, updatedAt }: { total: number; updatedAt: Date }) {
  const { locale, t, setLocale } = useI18n();

  // Intl 格式化：跟随 locale，不需要进语言包
  const countText = new Intl.NumberFormat(locale).format(total);
  const dateText = new Intl.DateTimeFormat(locale, {
    dateStyle: 'medium',
    timeStyle: 'short',
  }).format(updatedAt);
  const relativeText = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' }).format(
    -Math.round((Date.now() - updatedAt.getTime()) / 60000),
    'minute',
  );

  return (
    <header className="user-header">
      <h1>{t('user:list.title')}</h1>
      <p>
        {countText} · {t('user:list.createdAt', { time: dateText })}（{relativeText}）
      </p>
      <select
        value={locale}
        onChange={(e) => setLocale(e.target.value as 'zh-CN' | 'en-US')}
        aria-label="语言"
      >
        <option value="zh-CN">简体中文</option>
        <option value="en-US">English</option>
      </select>
    </header>
  );
}
```

`Intl` 三个常用对象的输出对照（直观感受 locale 规则差异）：

```ts
new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(1234.5);
// → ¥1,234.50
new Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' }).format(1234.5);
// → 1.234,50 €（德语：句号分组、逗号小数、货币符号在后）

new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' }).format(-1, 'day'); // → 昨天
new Intl.RelativeTimeFormat('en-US', { numeric: 'auto' }).format(-1, 'day'); // → yesterday

// 复数：英语有 one/other 之分，中文没有——这就是 ICU MessageFormat 存在的原因
new Intl.PluralRules('en-US').select(1); // → 'one'
new Intl.PluralRules('en-US').select(2); // → 'other'
new Intl.PluralRules('zh-CN').select(2); // → 'other'（中文只有 other 一类）
```

进阶主题——**运营可改的动态语言包、ICU MessageFormat 复数/性别语法、缺失文案上报、与 Schema 表单联动**，见《react-高阶场景-第二辑.md》场景 10「国际化与动态语言包」。

**常见坑。**

- **症状**：界面出现裸 key（`user:list.title`）。**根因**：语言包漏了这个 key，或 namespace 前缀拼错（`user:list.title` 写成 `users:list.title`）。**修法**：缺失回退显示 key 是特性不是 bug——让漏译立刻可见；上线前写个脚本对比两个语言包的 key 集合差异。
- **症状**：切语言后部分文案没变。**根因**：这些文案没走 `t()`（写死中文），或组件里把 `t()` 结果存进了 state/useMemo（依赖数组没含 locale）。**修法**：全部走 `t()`，`t` 已随 locale 变化，直接渲染即可。
- **症状**：数字/日期没跟随语言变。**根因**：手写格式化（`d.toLocaleDateString()` 传死 locale，或自己拼 `YYYY-MM-DD`）。**修法**：统一用 `Intl` 系列并把 locale 作为第一参数传入。
- **症状**：快速连切语言，界面语言和下拉框不一致。**根因**：异步加载语言包，旧语言的请求晚到覆盖了新的。**修法**：effect 里加 `cancelled` 标记（上面实现），或用 `AbortController`。
- **症状**：上线后才发现"初期写死中文"改造代价巨大。**根因**：文案渗透到了校验消息、枚举 label、后下发字段。**修法**：第一天就上 i18n 骨架，哪怕只有一种语言——这也是第二辑场景 10 反复强调的教训。

##### 补充：首屏就绪与切换过渡态——语言包未加载时的两个"裸奔窗口"

**是什么。** 原文实现有两个时序窗口没有处理：①**首屏**：`packs` 初始值是空对象，语言包靠 `useEffect` 异步加载——第一帧 `t('user:list.title')` 查不到，界面先闪一遍裸 key 再变中文；②**切换中**：`locale` state 立即变化，但新语言包还在网络路上——下拉框已显示 English，文案还是中文，状态错位直到新包到达。

**机制分步。** 三个对策各管一个窗口：

1. **默认语言同步就绪**：`import.meta.glob` 支持 `eager` 选项，把默认语言（zh-CN）的 JSON 直接打进主包，`useState` 初始化时就有值——首帧即正确；其他语言保持懒加载，不增加主包负担；
2. **切换期间显示旧语言而不是裸 key**：`t()` 的查找链从"当前 packs"扩为"当前 packs → 默认语言 packs → key 本身"——新包未到时用户看到的是旧语言（可理解），而不是满屏 key（像坏了）；
3. **把切换态暴露给 UI**：`switching = 用户选择的语言 !== 已加载的语言`，语言选择器据此禁用/加 loading，杜绝连点。

```tsx
// src/i18n/index.tsx（关键增量，其余与原文一致）
const DEFAULT_LOCALE: Locale = 'zh-CN';

// 默认语言 eager：构建期内联进主包，首帧即可用；全部语言仍保持懒加载
const lazyModules = import.meta.glob<{ default: Pack }>('../locales/*/*.json');
const eagerModules = import.meta.glob<{ default: Pack }>('../locales/zh-CN/*.json', {
  eager: true,
});

function buildPacks(mods: Record<string, { default: Pack }>): Record<string, Pack> {
  return Object.fromEntries(
    Object.entries(mods).map(([path, mod]) => [
      path.split('/').pop()!.replace('.json', ''),
      mod.default,
    ]),
  );
}

export function I18nProvider({ children }: { children: ReactNode }) {
  const [locale, setLocaleState] = useState<Locale>(() => {
    const stored = localStorage.getItem('locale');
    return stored === 'en-US' || stored === 'zh-CN' ? stored : DEFAULT_LOCALE;
  });
  // packs 与"它是哪个语言的"绑在一起更新——杜绝 locale 与 packs 各自 setState 的中间态
  const [loaded, setLoaded] = useState<{ locale: Locale; packs: Record<string, Pack> }>(() => ({
    locale: DEFAULT_LOCALE,
    packs: buildPacks(eagerModules),
  }));

  useEffect(() => {
    let cancelled = false;
    (async () => {
      const entries = await Promise.all(
        Object.entries(lazyModules)
          .filter(([path]) => path.includes(`/${locale}/`))
          .map(async ([path, load]) => {
            const ns = path.split('/').pop()!.replace('.json', '');
            return [ns, (await load()).default] as const;
          }),
      );
      if (!cancelled) setLoaded({ locale, packs: Object.fromEntries(entries) });
    })();
    return () => {
      cancelled = true; // 快速连切：旧请求晚到被丢弃
    };
  }, [locale]);

  const t = useCallback(
    (key: string, params?: Record<string, string>) => {
      const [ns, ...rest] = key.split(':');
      const path = rest.join('.');
      // 查找链：当前语言 → 默认语言（eager，永远在场）→ key 本身
      const packs = loaded.packs[ns] ?? buildPacks(eagerModules)[ns];
      const template = packs ? lookup(packs, path) : undefined;
      return template ? interpolate(template, params) : key;
    },
    [loaded],
  );

  // 切换态：选了英文但英文包还没到——选择器据此禁用，避免"看起来切完了其实没切"
  const switching = loaded.locale !== locale;
  const value = useMemo(() => ({ locale, t, setLocale, switching }), [locale, t, switching]);
  /* ...Provider 渲染与原文一致... */
}
```

**关键取舍。** eager 默认语言的代价是主包多出一个语言的 JSON（通常 5~20KB，可接受）；文案量巨大时退一步只 eager `common` 命名空间，业务包仍懒加载。另一条路线是 react-i18next 的 `useSuspense: true`——语言包未就绪时整棵子树走 Suspense 骨架，见《react-高阶场景-第二辑/21-10-国际化与动态语言包.md》10.5。

##### 补充：高频坑位补遗

- **症状**：浏览器语言是英语，但系统地区是中国，`navigator.language` 返回 `"zh"`（只有主子标签），查表 `'zh-CN'` 查不到，回退到了默认语言。**根因**：语言标签匹配没做前缀协商。**修法**：精确匹配 → `startsWith` 前缀匹配 → 兜底，完整实现见第二辑 21-10 的 `detectInitialLanguage`（已展开，此处不重复）。
- **症状**：切换语言后，浏览器标签页标题、书签还是旧语言。**根因**：只更新了 `document.documentElement.lang`，`document.title` 没人管。**修法**：语言包里加 `meta.title` 一类的 key，`useEffect` 里随 locale 同步：

  ```tsx
  useEffect(() => {
    document.title = t('meta.title');
  }, [t]); // t 随 packs/locale 重建，依赖它即可
  ```

- **症状**：key 叫 `nav.v2.0`，`t('user:nav.v2.0')` 永远返回 key 本身。**根因**：点路径查找把 `v2.0` 拆成了 `v2` → `0` 两级，语言包里根本没有这个嵌套。**修法**：约定 key 禁用点号（连字符替代 `nav.v2-0`），或在 `lookup` 里先整串命中再拆路径；上线前用脚本扫描语言包 key 里的非法字符。
- **症状**：在 Node 环境跑组件测试（vitest 无 DOM），Provider 一挂载就抛 `localStorage is not defined`。**根因**：`useState` 初始化器里直接读了浏览器 API。**修法**：初始化器加 `typeof window === 'undefined'` 守卫返回默认值——与 `useTheme` 的 SSR 兜底同一套路。
- **症状**：插值参数是用户昵称，页面被注入了脚本标签。**根因**：翻译结果用 `dangerouslySetInnerHTML` 渲染（为了实现"加粗"之类的富文案）。**修法**：普通文本节点 React 自动转义，永远不要用 innerHTML 渲染 `t()` 结果；确实需要内嵌 JSX/链接的富文案用 Trans 组件方案，见第二辑 21-10。

##### 补充：自测题

1. i18n 的三件事是什么？"格式化"为什么天然跟随语言切换而不需要进语言包？
   要点：语言包组织 / 切换 / 格式化；`Intl` 系列以 locale 为第一参数，数字、日期、复数类别是 locale 规则不是翻译问题。
2. key 缺失时显示 key 本身而不是空白，这为什么是特性？它替代了什么流程？
   要点：漏译在界面上立刻可见，替代"上线后才发现某屏空白"；配合上线前两语言 key 集合 diff 脚本与生产缺失上报。
3. namespace 按模块拆分的三个好处？
   要点：Ownership 清晰（语言包跟模块走）；加载粒度可控（首屏只拉 common + 首页）；避免巨型 JSON 的 merge 冲突。
4. 快速连切语言时界面错乱的根因？两种修法及差别？
   要点：异步加载下旧请求晚到覆盖新结果；`cancelled` 标记只丢弃过期结果（请求仍发出），`AbortController` 连请求一起取消（省流量，但需要接口层配合）。
5. 英文 `1 item / 2 items` 用 `"共 " + n + " 条"` 的拼接思维为什么必然出错？正确的判断机制是什么？
   要点：复数类别是语言语法现象，各语言类别数不同（英 2、俄 4、阿拉伯 6），不可能前端手写；`Intl.PluralRules.select(n)` 判类别 + 语言包按类别给文案，深水区是 ICU MessageFormat（第二辑 21-10）。
6. 页面中英文混排，给出排查顺序。
   要点：混的是写死文案（没走 `t()`）还是 key（缺翻译/拼错 namespace）；再看是否 `t()` 结果被存进 state 导致切语言不更新；最后查插值里拼死的中文。
