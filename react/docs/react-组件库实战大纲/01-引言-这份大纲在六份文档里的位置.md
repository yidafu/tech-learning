## 引言：这份大纲在六份文档里的位置

《[react-学习大纲.md](../react-学习大纲/README.md)》阶段 3 已经让你手写过一套迷你组件库（Button / Modal / Tabs / Select / Input），练的是**组件设计模式**：受控与非受控、组合优于配置、compound components、render props、泛型组件。那一份的产出是"能用的 demo"；本篇要补的是另一半——**"能发布的库"**。两者差别在哪？demo 只需在你自己的浏览器、你自己的样式体系、你自己的交互习惯下成立；库必须同时满足：

- **任意调用方**：受控也行、非受控也行，传 ref 也行、取实例方法也行；
- **任意环境**：SSR 能水合、暗色主题能切、React 18 和 19 都能跑；
- **任意位置**：组件被放进滚动容器、带 transform 的动画容器、嵌套弹层里，行为仍然正确。

把这三条"任意"逐条落地，就得到了 Part A 的九项通用内功。它们不是九个孤立技巧，而是所有复杂组件共享的地基：Select 的键盘导航、Modal 的退出动画、Tooltip 的定位翻转，背后用的是同一批 hook 与同一种思维——**把"用户的一次交互"拆解成状态机的确定转移，而不是一串 if-else 的即兴反应**。

**怎么读本篇**：Part A（本片段）按 A1–A9 顺序讲九项内功，每项都遵循"是什么 → 为什么需要 → 怎么做（机制分步）→ 代码示例 → 常见坑（症状→根因→修法）"。Part B 把这九项内功组合成分级组件清单（Lv1 基础 → Lv4 范式之争），Part C 讲 monorepo / 构建 / 发布。如果你是从 Part B 被某个组件的考点卡住而跳回来看的，直接定位对应小节即可：受控双模式看 A1，一切弹层问题看 A2+A3，键盘与读屏看 A4+A5。

**练习环境**（后续所有代码在同一工程中可运行）：

```bash
npm create vite@latest my-ui -- --template react-ts
cd my-ui
npm i @floating-ui/react clsx tailwind-merge
npm i -D @types/react
```

示例同时兼容 React 18 与 19；涉及两者差异处（ref 透传、useId 格式）会并列给出对照写法。

## Part A：通用内功（组件库的地基，先练这个）

九项内功与 Part B 组件清单的对应关系（先建立"练它为了什么"的地图）：

| 内功 | 服务于哪些组件 | 不练它的直接后果 |
|---|---|---|
| A1 受控/非受控 | Input/Switch/Select/DatePicker 一切带值组件 | 表单里值不同步、回显丢失 |
| A2 弹层体系 | Popover/Select/Tooltip/DatePicker/Modal 定位 | 弹层在视口边缘被裁、滚动时不跟、层级错乱 |
| A3 退出动画 | Modal/Drawer/Toast/Tag 一切会消失的组件 | 关闭瞬间闪没，廉价感明显 |
| A4 焦点管理 | Modal/Tabs/Radio/Menu | 键盘用户被锁死或焦点丢失 |
| A5 键盘与 ARIA | 全部交互组件 | 读屏用户完全不可用，验收被一票否决 |
| A6 事件边界 | 画布编辑器/弹层互斥/滚动锁定 | 原生与 React 监听互相打架 |
| A7 SSR 兼容 | 全部组件 | Next.js 接入即 hydration 报错 |
| A8 ref 体系 | 全部组件 | 消费方拿不到 DOM、类型推导断裂 |
| A9 样式与主题 | 全部组件 | 主题切不动、按需加载失效、包体积爆炸 |

依赖关系大致是：A1 与 A8 是一切组件的 API 面子；A2+A3 构成弹层类组件的身子；A4+A5 是可访问性的里子；A6/A7 是环境的边界的补；A9 决定发布形态。建议按编号顺序练，每项都动手跑通代码再往下走。

### 补充：三份"组件向"文档的分工——本篇、复杂场景、第二辑各练什么

这套学习体系里有三份都在"写组件"，容易混的是它们练的根本不是同一种功力。用一张表把分工焊死（跨全部文档的宏观优先级见 `../react-高阶场景-第二辑/23-与前几份的关系与优先级.md`，本表只讲组件功力的切分）：

| 维度 | 本篇（组件库实战） | 进阶大纲（复杂场景） | 第二辑（高阶场景） |
|---|---|---|---|
| 练什么 | **单个组件的深功力**：把一个 Select/DatePicker 做到"任意调用方、任意环境、任意位置" | **多组件组装成系统**：schema 驱动、注册表分发、递归渲染、撤销重做 | **编辑器家族专项**：搭建器/查询构建器/无限画布这类"组件之上"的产品形态 |
| 单位 | 一个组件 | 一条渲染链 / 一个 store | 一个可交付产品模块 |
| 难度来源 | 边界（IME、SSR、焦点、层叠上下文） | 架构（协议设计、性能、不可变更新） | 规模（多机制协同、与后端契约） |
| 验收 | 键盘走查 + SSR 冒烟 + 双版本 React 通过 | 压测帧率 + 撤销正确性 + 契约测试 | 业务闭环可用 + 性能预算达标 |

**同一能力在两篇里的不同练法**（这是最容易"在错的文档里找答案"的三例）：

- **弹层**：定位、翻转、层级、挂载容器——本篇 A2；弹层里再长出拖拽排序（dnd-kit）——进阶大纲 1-6；弹层铺满整个画布（菜单栏、右键面板）——第二辑 5（无限画布）。
- **受控**：单组件的受控/非受控双模式——本篇 A1；整棵树作为受控数据（schema 单一数据源）——进阶大纲第 2 章；编辑器画布的受控（选区、拖拽态进 store）——第二辑 1/3。
- **主题**：组件库的 token 体系与主题方案选型——本篇 A9；多租户动态换肤的运行时链路——第二辑 9（那篇是"用"token 做产品，本篇是"供"token 做基建）。

判断你该翻哪份的口诀：**卡在"一个组件行为不对"翻本篇；卡在"组件们拼不起来"翻进阶；卡在"要做的是个编辑器"翻第二辑。**

### 补充：练完验收——"能发布"的 12 条硬指标与查漏路径

引言开头说本篇的目标是把 demo 变成"能发布的库"，这里把"能发布"拆成 12 条可勾选的硬指标。全部来自 Part A/B/C 已展开的内容，这里只做收口——查漏时从没过的指标反查对应小节即可：

| # | 指标 | 通过判据 | 出处 |
|---|---|---|---|
| 1 | 受控双模式 | 传 `value` 走受控、只传 `defaultValue` 走非受控，两者切换不丢状态；受控报警零触发 | A1 |
| 2 | 键盘走查 | 拔掉鼠标，Tab/方向键/Esc/Enter 能完成每个组件的全部操作路径 | A5 |
| 3 | 读屏抽查 | VoiceOver/NVDA 过一遍 Modal（焦点圈）、Select（combobox 语义）、Toast（live region） | A4/A5 |
| 4 | 退出动画 | 关闭有过渡；过渡中再打开不炸；`prefers-reduced-motion` 下自动关动画 | A3 |
| 5 | 弹层三环境 | 弹层在滚动容器、transform 祖先、嵌套弹层三处行为正确 | A2 |
| 6 | SSR 冒烟 | `renderToString` + hydrate 无警告；弹层类组件不炸 | A7 |
| 7 | React 18/19 双跑 | 同一套代码两版本测试全绿（ref 透传差异有对照实现） | A8 |
| 8 | ref 与类型 | `ref` 可透传、泛型 Props 推导不塌、公开类型零 `any` 泄漏 | A8 |
| 9 | 主题可换 | 换 token 全库换肤；暗色算法一键切；无硬编码色值残留 | A9 |
| 10 | 包体三档 | es/module、esm、umd（或按需）三产物可用；sideEffects 声明正确 | C2 |
| 11 | 视觉回归 | Storybook 用例 + Chromatic（或同类）基线建立，样式改动 PR 可视比对 | C3 |
| 12 | 版本纪律 | changesets 流程跑通；breaking 有 major、按 semver 出补丁 | C5 |

用法建议：别把它当"毕业考"一次性过——每练完一项内功就把相关指标勾一遍（练完 A5 就勾 2/3），12 条全绿时 Part C 的发布流程就只是手续问题。反过来，如果你的组件库已经在跑，这张表也是**存量体检单**：哪条不过，就说明对应的内功欠账，回到对应小节补课比盲目重构有效。
