## 与前几份的关系与优先级

| 场景 | 内核复用 | 建议优先级 |
|---|---|---|
| 3 查询构建器 | 递归渲染器 + Setter + json-logic | ★★★ 新且高价值，优先做 |
| 8 权限 | 单一数据源 + Provider 模式 | ★★★ 每个中后台都需要 |
| 10 动态 i18n | Provider + 合并策略 | ★★☆ SaaS 刚需 |
| 9 多租户主题 | Token 体系 + Setter | ★★☆ 相对薄，快学 |
| 1/2/4 | 进阶大纲 §3/§4/§5/§6 直接延伸 | 已有基础，按需 |
| 5/6 白板与 Notion | 画布/PM 独立内核 | 长线深扎（4–6 周/个） |

表下逐行展开论证——为什么是这个顺序，而不是拍脑袋：

**行 1：3 查询构建器 ★★★，新且高价值，优先做。** 三个理由叠加。其一，它是本篇唯一全量展开的搭建器新场景：条件树协议是《进阶大纲》§1 递归渲染器内核的第 N 次复用（本篇开篇暗线），你已经为这个内核付过学习成本，这里是复利兑现最猛的地方——QueryGroup/QueryRow 的递归结构与表单渲染器、schema 树同构，做一遍等于把内核再内化一遍。其二，json-logic 协议转换层（条件树 ↔ 后端可执行规则）是"前后端契约能力"的代表作，面试里"高级筛选/告警规则怎么设计"是中后台岗位高频题，且追问链条深（协议设计、校验、试运行、存量规则迁移），做得越深越能区分度。其三，投入产出比好：核心是递归渲染 + 字段元数据 + 纯函数转换器，1–2 周可产出完整可演示的 Demo，不像白板/富文本那样要 4–6 周才见轮廓。它也是毕业项目的业务主角，先做它，毕业项目随时可以收口。

**行 2：8 权限 ★★★，每个中后台都需要。** 普适性是第一理由：权限不是"某类产品"的需求，是所有中后台的地基，学会即终身受用。第二，它是"模式密度"最高的一章：单一数据源（一份路由表生成守卫/菜单/面包屑三样）、Provider 模式、声明式组件（`<Can>`）、TS 字面量约束——每个模式都能迁移到权限之外的无数场景（feature flag、租户功能开关、向导步骤 gating）。第三，实现成本最低：扁平权限码 + Set 查询 + Context，一周内可完成全六粒度，但它展示的"深度"不输任何复杂场景——从路由级到行级 ABAC 的六层递进，每层都有真实的权衡（禁用 vs 隐藏的语义差异、前端权限只是体验层的底线认知）。与行 1 并列 ★★★，建议先做 8 再做 3：8 更小、更快建立正反馈，且它是毕业项目启动时序的第一依赖（权限不通，路由都无法生成）。

**行 3：10 动态 i18n ★★☆，SaaS 刚需。** 必要性毋庸置疑——出海产品这是 P0，"语言包不发版生效"是多租户 SaaS 的硬需求。优先级排在 8 之后的理由是**难度结构**：它的"灵魂"（10.4 合并策略）本质上是一个深合并函数 + 一套校验时序 + 一条 fallback 链，核心代码两三百行就到底了；剩下的宽度（ICU、Intl、RTL、Trans、伪语言）是"面"的知识而非"深"的算法，每个点理解半天即可，真正难的是工程纪律（key 扫描进 CI、类型化 key 从第一天用、pseudo-loc 常态化）——纪律靠习惯不靠智力。建议投入约一周：把 10.4 做透（这是可进简历的架构点），ICU/Intl 过一遍建立"拼接不可翻译"的肌肉记忆，RTL 与翻译平台流程留作认知储备，需要时半天捡起。

**行 4：9 多租户主题 ★★☆ 相对薄，快学。** "相对薄"是准确的自我评估：技术内核就是 token 三层体系（基础 → 语义 → 组件只消费语义）+ CSS 变量注入 + antd ConfigProvider 桥接，没有算法、没有复杂状态，2–3 天可走完主线。它的真正难点不在写代码而在**纪律与边角**：语义 token 铁律（组件硬编码一处色值，主题就漏一处）要靠 stylelint 守护；暗色模式 × 租户品牌色的 2×2 组合要靠对比度检查；canvas 组件读不到 CSS 变量要维护 JS 侧 token mirror；FOUC 要靠"先应用再渲染"的启动时序（毕业项目 2.3 顺带解决）。这些是"知道就有、不知道就翻车"的知识点，密度低但每一颗都是雷。作为热身或穿插任务（比如等 3 的设计稿期间）做掉最合适；也因为它是毕业项目第 ② 份配置，早做完早拼装。

**行 5：1/2/4 已有基础，按需。** 这三个场景分别是《进阶大纲》§6+§4（低代码+拖拽 → 大屏编辑器）、全景图 A4/F2（节点图）、§5+§3（monaco+Setter → schema 编辑器）的直接延伸——内核都学过了，剩下的增量各有侧重：1 的增量集中在分辨率适配三方案与 canvas 重绘；2 的增量在 DAG 校验、自动布局与运行态高频合并更新；4 的增量是"元编程"视角（编辑对象是 schema 本身）。它们的定位是"加深已有技能树"，优先级自然让位于全新场景；按你目标岗位挑（做可视化平台选 1/2，做配置系统选 4）。其中 2（工作流编排器）的协议设计与 json-logic 同构（`{ id, type, next: [...] }` 的邻接结构与条件树、schema 树是一家的），做完 3 再看 2 会有强烈的既视感。

**行 6：5/6 白板与 Notion 长线深扎（4–6 周/个）。** 压轴但必须压后，因为它们与前五个场景**几乎没有内核复用**：白板的视口模型/双坐标系/空间索引是一套几何系统，Notion 类的 PM 文档模型/输入规则/选区协同是一套文本编辑系统——各自都是独立领域的入门费（本篇场景 5、6 的自研实现清单就是那 4–6 周的路线图）。在 SaaS 主线（3/8/9/10 + 毕业项目，约 3–4 周）完成之前启动它们，只会两头都半生不熟。但如果你目标是编辑器类产品岗位（Figma/Notion/白板赛道），这两个场景的简历权重最高，值得在主线收口后作为"第二阶段"整块投入，并把 tldraw（源码质量极高）与 TipTap 官方示例作为精读底本。

一句话总结学习路径：**3 → 8 → 10 → 9 → 毕业项目拼装 →（按岗位）1/2/4 或长线 5/6**。前三步做完，"SaaS 平台层"的完整心智模型就立起来了；毕业项目不是新的学习任务，而是对这条主线的验收仪式。

### 补充：把优先级表落成四周计划——里程碑、验收物与止损线

上面的表回答了"什么先做、为什么"，但没有回答另外两个决定计划能否执行的问题：**做到什么程度算完成**（否则每个场景都能无限打磨）、**超期了砍什么**（否则止损靠情绪）。给每行补上验收物、时间盒与止损线，星星表就从观点变成排期。时间盒按每天 2–3 小时业余投入估算，全职投入减半。

| 顺序 | 场景 | 时间盒 | 验收物（可演示的最小闭环） | 止损线（触发即执行） |
|---|---|---|---|---|
| 1 | 8 权限 | 5 天 | 六粒度各一条可演示路径 + `<Can>` 组件 + 一份路由表派生守卫/菜单/面包屑 | 第 3 天末路由/菜单/按钮三层未跑通 → 砍掉行级 ABAC，进入下一场景 |
| 2 | 3 查询构建器 | 8 天 | 条件树编辑 → json-logic → 试运行面板全链路 Demo + 转换器单测 | 协议转换层单测覆盖率不足 80% 不许开写 UI——宁可在纯函数层多待两天 |
| 3 | 10 动态 i18n | 7 天 | 双包合并 + 缺失 key 上报面板 + 伪语言整站截图 | 10.4 合并策略 3 天未落地 → 停掉 ICU/RTL 等宽度阅读，先保灵魂章节 |
| 4 | 9 多租户主题 | 3 天 | 三层 token + 亮暗 × 品牌色 2×2 组合对比度检查通过 | 超 1 天 → 锁死范围：只做亮色 + 单品牌色 |
| 5 | 毕业项目拼装 | 5 天 | 毕业项目第 5 节验收清单 20 条全绿并录屏 | 差 ≤ 3 条可带 TODO 毕业；超 3 条回对应场景补课，禁止在装配层打补丁 |

三条止损规则，比表里的单行更硬：

1. **超期砍宽度，不砍深度。** 主线场景宁可砍 RTL、ICU 边角这类"面"，也不砍合并策略、单一数据源这类"骨架"——简历与面试的价值在讲得深的那个点，不在"都碰过一下"。
2. **装配层禁止出现业务补丁。** 毕业项目阶段发现的 bug 必须回到对应场景修；在 bootstrap 里为某个场景写 if 补丁，说明该场景没毕业，退回重做。
3. **5/6（白板/Notion）在主线收口前禁止启动。** 写进日历当硬约束：4–6 周量级的深坑一开局，3–4 周的主线必然烂尾；把"主线 20 条验收全绿录屏"设为启动第二阶段的仪式条件。

每周五 10 分钟的周检视三问（检查对象是计划，不是代码）：

- [ ] 本周验收物可演示吗？（能录 30 秒视频才算可演示，"本机能跑"不算）
- [ ] 触发止损线了吗？触发即执行，不接受"再给两天"。
- [ ] 下周第一个任务是不是当前阻塞的解依赖？（例：类型化 key 依赖 tsconfig 的 `resolveJsonModule`，先配它再写 i18n 代码）
- [ ] 验收物沉淀了吗？（录屏归档进"简历素材"目录，Demo 仓库对应毕业项目第 6 节的架构故事——素材在做的过程中长出来，而不是结束后补写）

### 补充：考纲式自测——"必能重建"清单与二刷策略

四周计划回答了"做什么、做多久、何时止损"，还差最后一环：**怎么确认学会了**。验收物检验的是"做出来了"（对着文档与 IDE 完成），自测检验的是"离了文档还在不在"——两者的差距就是"开着参考答案会做、合上不会"的假性掌握。自测只有一种形式：合上文档，白板或空文件作答，做完再翻原文对。

**"必能重建"清单**（每场景只挑"骨架"，不考"面"；任一题答不顺即回炉该节，不重读全章）：

| 场景 | 合上文档的重建题 | 通过标准 |
|---|---|---|
| 3 查询构建器 | 空文件默写 `ConditionNode` 类型 + `toJsonLogic` 全函数（含 between 拆分、in 操作数顺序两个特判） | 一次写对；能口述两个特判为什么存在 |
| 8 权限 | 默写六粒度；口述"禁用 vs 隐藏"各适用什么场景；画出"一份路由表派生守卫/菜单/面包屑" | 能给没做过权限的人 10 分钟讲懂 |
| 10 动态 i18n | 默画 10.4 五步时序（拉取→校验→合并→注入→emit），含失败分支；写出 fallback 链 | 成功 / 顶层校验失败 / 单语言失败三条路径一个不漏 |
| 9 多租户主题 | 默写 token 三层；口述"组件只准消费语义层"违背时的具体后果；FOUC 的防治时序 | 能举出"硬编码一处色值漏一处主题"的连锁反应 |
| 毕业项目 | 口述 allSettled vs all 的取舍；默写三份配置的失败等级表并说明理由；画六段启动时序 | 追问"为什么 X 不是阻塞级"时能给出反例 |

**二刷节奏**（间隔检索，不是重读——重读只产生熟悉感，熟悉 ≠ 会）：

- D+3：合文档重写 `deepMerge` + `validateNamespacePack`（10.4 的灵魂），写完与原文 diff，差异处就是理解偏差所在；
- D+7：白板重画两图——毕业项目六段启动时序、10.4 五步合并时序，并指出两张图的衔接点（bootstrap 的第 ③ 格就是 10.4 的调用方）；
- D+14：对着毕业项目第 5 节验收清单 20 条做"人肉回归"——每条先口述"它会挂在哪一层、什么症状"，再实际操作验证。

**追问三连**（重建题通过后追加问，考"理解"而不是"背过"——答不上说明背下来了但没想通）：

| 场景 | 追问 | 答不上时的回炉点 |
|---|---|---|
| 3 | 为什么 between 要拆成 `>=`/`<=` 两条而不是自定义操作符？ | 2.6：json-logic 无原生 between，自定义操作符意味着后端执行器也要跟着改 |
| 8 | 权限码为什么是扁平字符串（`alert:rule:edit`）而不是权限树？ | 场景 8：扁平码配 `Set.has()` 是 O(1)，树要递归且无法存进 Context 做廉价查询 |
| 10 | 远端包校验失败的回退粒度为什么是"语言"而不是"命名空间"？ | 10.4：一个语言的数据坏了不该牵连其他语言；ns 粒度会把"平台包 zh 坏了"放大成"全站 zh 回退" |
| 9 | token 为什么三层（基础/语义/组件消费）而不是两层？ | 场景 9：少掉语义层，换主题时要改每个组件的取值；语义层是"主题切换只改一处映射"的关键 |
| 毕业项目 | 语言包在 bootstrap 内部完成注入，主题却要等 bootstrap 返回后、渲染前写入——为什么不同？ | 2.3：语言包写入的是数据结构（i18n 资源树），主题写的是 DOM（CSS 变量），后者必须卡在首帧渲染之前 |

| 2026-11-08 | 10 动态 i18n | 默画 10.4 时序 | 部分 | 校验失败与拉取失败的日志级别分不清 | 10.4（四） |

**三种假性掌握的症状与对策**：

- 症状：能看懂代码，合上文档写不出来 → 对策：不是再读一遍，是降低粒度重建——先默写函数签名与分支骨架，再填实现；
- 症状：能写出来，但讲给别人听时对方走神/复述偏差大 → 对策：缺的是"为什么"层，对着追问三连表逐条自问；
- 症状：单点都会，串不成启动时序 → 对策：缺的是全局图，做 D+7 的双图重画，并把每个场景在时序中的位置标出来（这一条直接决定毕业项目拼装能否一次通过）。

**判定标准**用费曼规则：能把某个场景讲给没做过的人听懂、且对方能无偏差复述，该场景才算毕业；讲卡壳的段落就是回炉点，只重做该小节。自测通不过的常见原因不是忘了，而是当初"看懂了"但没"写过"——对照四周计划的验收物自查：凡该场景只有阅读没有产出的，先补产出再自测，否则自测测的只是短期记忆。
