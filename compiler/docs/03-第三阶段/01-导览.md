# 第三阶段导览：语法分析与 AST

> [返回：编译原理学习大纲](../编译原理学习大纲.md)
> 本文是第三阶段的入口：阶段目标、知识点地图、实践任务清单与阶段自测。

**建议时长**：3~4 周（每天 1~2 小时）。这是全程最重的阶段之一：两条技术路线（自顶向下 / 自底向上）都要懂，手写实现走 Pratt + 递归下降混合路线——这是 acorn、swc、rustc 的选择。

## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 给定文法，机械地写出递归下降 parser（函数即非终结符），并计算 FIRST/FOLLOW 集合判定 LL(1)。
2. 用 Pratt 解析器处理任意优先级/结合性的运算符表，解释绑定力模型为什么统一了前缀/中缀/后缀。
3. 说清 LR 家族的演进（LR(0) → SLR → LR(1) → LALR）：状态机规模与前瞻能力的权衡。
4. 设计一套 discriminated union 的 AST 节点体系，带完整 source span。
5. 实现错误恢复（同步点策略），一次扫描报出多个语法错误。

## 知识点地图

### 1. 自顶向下：LL 族

- **推导与归约**：最左推导对应自顶向下（从开始符号长到句子），最右推导的逆过程对应自底向上。
- **递归下降**：每个非终结符一个函数，函数体按产生式右部逐符号：终结符 `match()`、非终结符递归调用。代码与文法几乎逐行对应——这是它易写易调的根本原因。
- **FIRST / FOLLOW**：FIRST(α) = α 能打头的终结符集；FOLLOW(A) = A 后面能跟的终结符集。LL(1) 判定：同一非终结符的多个分支 FIRST 互不相交（ε 分支看 FOLLOW）。
- **左递归消除**：`E → E + T | T` 机械改写为 `E → T E'`、`E' → + T E' | ε`；代价是可读性下降，所以实践中常用循环代替。
- **提取公因子与回溯**：公共前缀改写；packrat/PEG 用记忆化消除回溯的指数爆炸——了解思想即可。

### 2. 运算符优先级：Pratt 解析（重点）

- **绑定力（binding power）模型**：每个运算符一对数值 `(leftPower, rightPower)`；解析表达式时循环"peek 下一个中缀运算符，若其 leftPower 小于当前上下文则停"。
- **前缀/中缀/后缀统一**：前缀（`-x`、`!x`）用 prefix 解析函数；中缀（`a + b`）用 infix；后缀（`a++`、`f(x)`、`a[i]`）可视为超高中缀。三元 `?:`、赋值 `=` 都是绑定力表的普通条目。
- **右结合的表达**：`=` 与 `**` 让 rightPower > leftPower（如 `(2, 3)` vs `(3, 2)`），递归自然右倾；左结合相反。
- **为什么主流**：运算符表是数据不是代码——加一个运算符加一行表项；递归下降写 8 级优先级要 8 层函数互相调用。

### 3. 自底向上：LR 族

- **移进-归约模型**：一个栈 + 输入流；动作二选一：移进一个 token，或把栈顶的若干符号按某产生式归约为非终结符。**句柄** = 当前栈顶恰好该归约的那串符号。
- **LR(0) → SLR → LR(1) → LALR**：LR(0) 只看栈不看前瞻（冲突多）；SLR 用 FOLLOW 缩小归约时机；LR(1) 每个项带精确前瞻集（状态爆炸）；LALR 合并同核心 LR(1) 状态（状态数回到 SLR 级，能力接近 LR(1)）。yacc/bison 生成 LALR。
- **冲突消解**：移进/归约冲突（悬空 else、`1 - 2 - 3`）用优先级 + 结合性声明消解；归约/归约冲突通常是文法 bug，必须改文法。
- **生成器的取舍**：生成器省力但错误信息差、难做增量；现代编译器（GCC 已迁、rustc、swc、acorn）全部手写。

### 4. AST 设计与错误恢复

- **节点体系**：`Expression | Statement | Declaration` 三大 union，每个节点 `{ type: 'BinaryExpression', left, right, operator, start, end }`——discriminated union 让 TypeScript 能精确窄化。对照 ESTree：它就是 JS 的官方 AST 规范，Babel/acorn/eslint 全用它的方言。
- **source span**：`start/end` 覆盖源码区间；合成节点（语法糖脱糖产生）标注 synthetic。sourcemap 与精确报错都靠它。
- **错误恢复**：panic mode——报错后丢弃 token 直到同步点（语句级 `;`，块级 `}`），再继续；这样一次编译报多个错。恢复策略决定"误报率"：恢复太激进会把一个错拖出一串假错。
- **对照阅读**：acorn 的 `parseStatement` 里的分号插入逻辑；babel-parser 的 `hasPlugin` 插件化文法扩展。

## 与 mini 语言项目的关系

本阶段交付 `packages/parser`：`parse(tokens: Token[]): Program`。mini 语言从此有了完整的语法层——if/else、while、fn、块作用域都可用。AST 节点结构直接抄 ESTree（改名空间缩小差异），为第八阶段写 Babel 插件铺路：**mini AST 与 ESTree 同构，意味着你随手就能复用整棵 babel 生态的遍历器思路**。

- [ ] 能解释为什么 `a = b = c` 右结合、`a - b - c` 左结合，并在绑定力表里指出是哪两个数字决定的。
- [ ] 能说清 SLR 与 LR(1) 的差异（FOLLOW 近似 vs 精确前瞻），以及 LALR 为什么是工程折中。
