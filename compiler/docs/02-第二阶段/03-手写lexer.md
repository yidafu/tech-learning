# 手写 lexer：工程实现

> [返回：第二阶段导览](01-导览.md)
> 对应大纲第 2 条。本册是 mini lexer 的主体工程课：Token 结构、主循环、最长匹配、各类字面量的状态机，以及 JS/Python 两个"词法参与语法"的特例。

## Token 结构设计

```ts
export type TokenType =
  // 字面量
  | 'number' | 'string'
  // 标识符与关键字（关键字在扫描后查表升级）
  | 'ident'
  | 'fn' | 'let' | 'if' | 'else' | 'while' | 'return'
  | 'true' | 'false' | 'numberTy' | 'stringTy' | 'boolTy' | 'unitTy'
  // 运算符与标点
  | '+' | '-' | '*' | '/' | '%' | '=' | '==' | '!='
  | '<' | '>' | '<=' | '>=' | '&&' | '||' | '!'
  | '(' | ')' | '{' | '}' | ',' | ';' | ':' | '->'
  // 控制
  | 'eof';

export interface Token {
  readonly type: TokenType;
  readonly lexeme: string;     // 原始文本，永远保留（错误信息与 sourcemap 要用）
  readonly literal?: number | string;  // 解析后的值（仅字面量）
  readonly start: number;      // 源码偏移（含）
  readonly end: number;        // 源码偏移（不含）
}
```

设计要点：

- `lexeme` 与 `literal` 分开：`"3.14"` 的 lexeme 是六个字符，literal 是数值 3.14。**lexeme 永不丢弃**——诊断、sourcemap、minify 全靠原文。
- `start/end` 用偏移量而非 行:列——偏移是机器友好形态，行列在**报错时**才换算（见下一册的行首表）。
- 关键字不单独扫描：先按 ident 扫完整词再查保留字表——DFA 只需要"标识符"一个模式，关键字是**词表**不是**状态**。

### 关键字为什么是独立的 TokenType

`fn` 既可以是 `'ident'`（值恰好是 `fn`），也可以是独立的 `'fn'` 类型——mini 选后者，理由不在语义，在**下游的分派成本**：

| 方案 | parser 侧的样子 | 代价落在谁头上 |
|---|---|---|
| 关键字并入 ident，按值区分 | 每个 `check('ident')` 之后还要比对 `lexeme === 'fn'` | 分派逻辑散落，容易漏判 |
| 关键字独立类型（mini） | `match('fn')` 一次判类型 | 词法侧多一张表，parser 侧零成本 |

把"是不是关键字"的判断**收敛在词法层一次做完**，token 流里就不再有裸的字符串比较——这是"词法给语法供结构化数据"的第一步。ESTree 里关键字不出现在 AST（它们只占语法位置、不占树节点），印证关键字 token 的存在意义就是给 parser 的分派提供判别依据。

反过来，这条设计依赖上一册的结论"关键字是词表不是状态"：十二个关键字若各自展开成 DFA 状态，标识符自动机会膨胀成十几个接受态的判决树；查表方案里 DFA 始终只有"标识符"一个模式（[02-从正则到自动机](02-从正则到自动机.md) 的 mini 词法规则表）。

### start/end：半开区间与统一坐标系

`start` 含、`end` 不含的**半开区间** `[start, end)` 是全流水线的坐标合同，三条理由：

- **相邻 token 首尾相接无缝隙**：`let` 的 end 就是 `x` 的 start，token 间的空隙天然可判定（恒有 `tokens[i].end <= tokens[i+1].start`），trivia（空白与注释）就藏在缝隙里；
- **长度即差值**：`end - start` 直接是词面长度，`src.slice(t.start, t.end) === t.lexeme` 可以做成全量不变量断言（[05-实践-mini语言lexer](05-实践-mini语言lexer.md) 验收标准里就有这条）；
- **跨阶段同构**：AST 节点的 `start/end`（[05-AST设计与错误恢复](../03-第三阶段/05-AST设计与错误恢复.md)）与 Token 完全同型，报错换算行列时一套行首表（[04-词法错误处理与生成器对照](04-词法错误处理与生成器对照.md)）服务到底。

偏移的基准单位也要钉死：JS 宿主里按 **UTF-16 code unit** 计（本册 Unicode 一节展开）。整个工程只用一种偏移，只在最外层（报错展示）换算行列——坐标体系每多一套，sourcemap 就多一类错位 bug。

## 主循环骨架

```ts
export function tokenize(src: string): Token[] {
  const tokens: Token[] = [];
  let pos = 0;

  const isDigit = (c: string) => c >= '0' && c <= '9';
  const isIdentStart = (c: string) => /[A-Za-z_$\p{ID_Start}]/u.test(c);
  const isIdentPart  = (c: string) => /[0-9A-Za-z_$\p{ID_Continue}]/u.test(c);

  while (pos < src.length) {
    const start = pos;
    const c = src[pos];

    if (/\s/.test(c)) { pos++; continue; }          // 空白：跳过
    if (c === '/' && src[pos + 1] === '/') {        // 行注释
      while (pos < src.length && src[pos] !== '\n') pos++;
      continue;
    }

    if (isDigit(c))            { tokens.push(number_()); continue; }
    if (c === '"' || c === "'") { tokens.push(string_()); continue; }
    if (isIdentStart(c))       { tokens.push(identOrKeyword()); continue; }
    const op = operator();                           // 运算符/标点
    if (op) { tokens.push(op); continue; }

    // 走到这里 = 非法字符：报错并跳过（错误恢复见下一册）
    report(pos, `意外字符 '${c}'`); pos++;
  }
  tokens.push({ type: 'eof', lexeme: '', start: pos, end: pos });
  return tokens;
}
```

这个 `while + 分类 → 子程序` 的骨架就是上一册"直接编码 DFA"的落地产物：每个 `if` 分支是一组转移，子程序是接收状态的消费动作。

### 主循环逐字符演算：`let x = 1;`

把骨架当状态机跑一遍（"分支"即各条 `if` 判定的落点）：

| 步 | pos 指向 | 命中分支 | 子程序内动作 | 产出 |
|---|---|---|---|---|
| 1 | `l` | isIdentStart | identOrKeyword 吃满 `let`，查表命中 | token `let` |
| 2 | ` ` | `/\s/` | pos++ | 无 |
| 3 | `x` | isIdentStart | 吃 `x`，查表 miss | token `ident` |
| 4 | ` ` | `/\s/` | pos++ | 无 |
| 5 | `=` | 都不中 | operator：双字符表查 `=␠` miss，单字符命中 | token `=` |
| 6 | ` ` | `/\s/` | pos++ | 无 |
| 7 | `1` | isDigit | number_ 吃 `1`，校验通过 | token `number`（literal 1） |
| 8 | `;` | 都不中 | operator 单字符命中 | token `;` |
| 9 | 越界 | while 退出 | — | token `eof` |

七个 token、九步主循环——空白步只移动指针不产出，这正是"空白不进 token 流"的具象。第 5 步值得盯住：双字符表先查 `=空格`，miss 后才落到单字符 `=`——**最长匹配的裁决发生在 operator() 内部，主循环对它无感**。这份 trace 值得对着自己写的 lexer 重放：每个分支与子程序的对应关系含糊一处，DFA 视角（上一册"直接编码"）就断裂一处。

### eof 哨兵：token 流的收尾合同

主循环退出后补一枚 `{ type: 'eof', lexeme: '', start: pos, end: pos }`。三件事靠它成立：

1. **parser 的 peek 永不越界**：递归下降到处是 `peek().type`，有 eof 兜底就无需处处判"还有没有 token"——空文件的 token 流也有一个 eof，`parse` 的主循环天然终止；
2. **报错可定位**：`consume(';', ...)` 在文件末尾失败时，错误位置就是 eof 的偏移——"期待 `;`，但看到文件末尾"（06 册的 error() 对 eof 有专门话术）；
3. **测试快照稳定**：token 序列永远以 eof 结尾，快照 diff 时能立刻分辨"少了最后一个 token"与"多了半个"。

代价是一条纪律：**eof 之后不再有 token**，任何"多看一个"（peek 两次）的代码都会踩空——需要两 token 前瞻的裁决要么压进 lexer（本册 operator 的双字符表就是"字符级前瞻"），要么给 parser 换窗口制游标。mini 把这类需求全部留在词法层。

## 最长匹配（maximal munch）

规则：**永远吃掉能构成合法 token 的最长字符序列**。`>=` 决不能切分成 `>` 和 `=`。实现：运算符扫描先查双字符表、再退回单字符：

```ts
const TWO_CHAR = new Set(['==', '!=', '<=', '>=', '&&', '||', '->']);

function operator(): Token | undefined {
  const two = src.slice(pos, pos + 2);
  if (TWO_CHAR.has(two)) return makeToken(two as TokenType, 2);
  if ('+-*/%=<>!(){},;:'.includes(src[pos]))
    return makeToken(src[pos] as TokenType, 1);
  return undefined;
}
```

贪心的坑也有：`a-1` 里 `-` 是减号，但 `a->b`（如果 mini 有 `->`）会抢走——所以**双字符优先、单字符兜底**的顺序不能反。JS 的 `/` 更典型：它可能是除号**或**正则字面量的开头——词法器必须看上文（前一 token 是否运算符位置）才能裁决。mini v0.1 不含正则字面量，刻意绕开这个泥潭。

### 手工演算：运算符扫描的裁决序列

三段输入走 operator() 的两步裁决（先双字符表、后单字符表）：

| 输入片段 | 双字符表查 slice(pos, pos+2) | 结果 | 后续 |
|---|---|---|---|
| `>=b` | `>=` 命中 | token `>=` | pos+2 |
| `=-1` | `=-` miss | 单字符兜底 `=` | pos+1，下一轮主循环再吃 `-` |
| `==-1` | `==` 命中 | token `==` | pos+2，下一轮再吃 `-` |

第二行是"最长匹配被手工实现"的现场：若单字符表先查，`=-` 就会被切开——那个例子里恰好语义不变，但那是运气不是设计；换成 `<=` 之外的任何组合都可能出错。**顺序（双先单后）保证正确性，与具体符号无关**。往深处看一眼：`>=` 能被优先吃到，是因为 DFA 在接受态 `>` 之后还有 `=` 转移可走（上一册消费循环一节的"最后接受态"）——双字符表就是这个"多走一步"的手工版；三字符运算符（JS 的 `>>>=`、`...`）在同一思路上再加一层表。**表的层数 = 最长运算符的长度**，mini 两层够用。

### `/` 的两读性：上下文敏感词法的头号样本

JS 的 `/` 可能是除号，也可能是正则字面量的开头：`a / b` 是除，`/ab/.test(s)` 是正则。**词法自身分不出来**——判定需要"上一 token 处在运算符位置还是操作数位置"这个语法层信息：前一 token 是 ident/number/`)`/`]` 则按除号，是运算符/`(`/行首则按正则开头。工业做法是 lexer 记 `prevToken`，扫到 `/` 查它——词法器从此**有了状态**，不再是纯正则语言能描述的机器。V8 更进一步：模板字符串 `${}` 闭合后若语法层发现需要另一种解读，可以让 scanner 从原位置**换模式重扫**——词法不是不可逆的一次性判决，而是可以被语法层叫回来重做的服务。

mini v0.1 没有正则字面量，`/` 永远是除号——这是**用语言设计消掉词法歧义**（与 `.5` 被拒绝同一思路：词法歧义最小化）。哪天给 mini 加正则，第一件事就是把 `prevToken` 请进 lexer。

## 数值字面量

```
123    十进制整数
3.14   小数（必须两侧都有数字：.5 与 5. 都非法）
0xFF   十六进制
1e3    指数
```

状态机（对应 DFA）：`整数部分 → (可选 . 分数部分) → (可选 e 指数部分)`。注意 `.5` 被拒绝是为了让 `.` 永远是标点——**词法歧义最小化是语言设计原则**，不是疏忽。解析成 `number` 用 `Number(lexeme)` 兜底（进制与指数它全认），但要防 `1e`、`1.2.3` 这类残缺——在扫描状态机里拒绝即可，别把残缺词扔给 `Number`。

十进制/指数主干画成自动机（接受态才允许产出 token；十六进制 `0x` 分支从整数状态分叉，为控制图宽略去）：

```mermaid
flowchart LR
    S((起)) -->|0-9| INT((整数进行中))
    INT -->|0-9| INT
    INT -->|.| DOT((见过点))
    DOT -->|0-9| FRAC((小数进行中))
    FRAC -->|0-9| FRAC
    INT -->|e E| E1((指数符号位))
    FRAC -->|e E| E1
    E1 -->|"+" "-"| E2((符号已吃))
    E1 -->|0-9| EXP((指数进行中))
    E2 -->|0-9| EXP
    EXP -->|0-9| EXP
    style DOT fill:#ffe9c7
    style E1 fill:#ffe9c7
```

两个淡色中转态（见过点、指数符号位）都**不是接受态**——这就是 `3.` 与 `1e` 非法的自动机表述：走到那里停机，不接受。

### 手工演算：`3.14e2` 的扫描轨迹

| 步 | 读到 | 状态迁移 | 说明 |
|---|---|---|---|
| 1 | `3` | 起 → 整数进行中 | 进入接受区（至少一位整数） |
| 2 | `.` | → 见过点 | 中转态，暂不接受（`3.` 不合法） |
| 3 | `1` | → 小数进行中 | 重新接受 |
| 4 | `4` | 自环 | 继续接受 |
| 5 | `e` | → 指数符号位 | 又一个中转态（`3.14e` 不合法） |
| 6 | `2` | → 指数进行中 | 最终接受 |

停机后整词校验（05 册的 `NUM_RE`）与这个状态机**判定结果一致**：那条正则编译出的 DFA 与上图同构——"整词扫描 + 整词校验"是"边扫边判状态"的批量版，代价是报错只能说"整词非法"；要精确到哪个字符坏掉就得用状态机版（这个差别在错误诊断质量上回收，见 [04-词法错误处理与生成器对照](04-词法错误处理与生成器对照.md)）。

### 数值规则的设计裁决表

四条边界各是一条语言设计决定：

| 规则 | 裁决 | 理由 |
|---|---|---|
| `.5` 非法 | `.` 永远是标点 | 若允许，成员访问与数字竞争（JS 真踩过：`1.toString()` 语法错误） |
| `5.` 非法 | 点必须两侧有数字 | 同上，`5..toString()` 的可读性崩坏 |
| `1e` 非法 | 指数后必须有数字 | 残缺词整词报错（下一册），不猜 |
| 前导零 `007` | mini 允许，按十进制 7 | 把它当八进制的"省字"设计要额外立规则，白加复杂度 |

对照工业：JS 的数字词法是这门语言里最复杂的状态机之一（二/八/十六进制、BigInt 后缀 `n`、数字分隔符 `_`），V8 的 scanner 为它写了专门的分支族——**数字规则是词法层的"复杂度蓄水池"**，语言每加一种字面量形式，lexer 的这个角落最先长胖。mini 刻意只留十进制/十六进制/指数三件套，"分隔符 `_`"留作练习（见自测）。

## 字符串：转义与多行

```
"a\tb\n"        双引号 + 转义
'...'           单引号同权（v0.1 起两者等价）
"""多行
   字符串"""     三引号原样（raw，无转义）
```

扫描逻辑：一个 `while (pos < len && src[pos] !== quote)` 循环，遇 `\` 消费两字符并解码转义（`\n \t \\ \" \0`），遇 `\n` 在单行字符串里即报"未闭合"。三引号模式吃一切直到 `"""`——它是**词法模式切换**的最简案例（复杂版就是 JS 模板串的 `${}` 模式栈）。

`literal` 的解码在扫描时一次完成（别在 parser 里再解码一遍——字面量的"值"属于词法产物）。

### 手工演算：`"a\tb\n"` 的扫描轨迹

| 步 | 读到 | 动作 | value 累计 |
|---|---|---|---|
| 1 | `"` | 跳过开引号，进入循环 | （空） |
| 2 | `a` | 普通字符，累计 | `a` |
| 3 | `\t` | 消费两字符，`t` 查 ESCAPES 命中 | `a` + 制表符 |
| 4 | `b` | 累计 | `a␉b` |
| 5 | `\n` | 消费两字符，`n` 命中 | `a␉b` + 换行符 |
| 6 | `"` | 循环条件不满足，退出 | — |
| 7 | — | 跳过闭引号，产出 token | `string`，literal 长度 4 |

第 3 步的"消费两字符"是转义扫描的核心不变式：**`\` 永远绑着后一字符一起走**，这保证 `"a\\"` 里第二个 `\` 不会被误判成新转义的起点（它已被第一个 `\` 消费掉）。再看产出：literal 是解码后的 4 字符，lexeme 仍是原始 8 字符（含引号与反斜杠）——"lexeme 永不丢弃"在转义场景才真正显出分量：**报错与 sourcemap 指回用户写的，求值要用用户要的**，两者必须同时可及。

### 非法转义：宽容还是严格

`"\q"` 在 mini 里报一条诊断、跳过这两个字符继续扫（05 册实现）。两种业界态度：

- **宽容（mini）**：未知转义报诊断但不断流——一次编译能看到后续更多错误；
- **严格（Rust；JS 的无标签模板字符串）**：非法转义直接语法错误，不给"凑合"的语义。

宽容的代价是"错误字符串悄悄流进 AST"——第四阶段 checker 若对 string 字面量有运算或比较，要记得诊断数组里已经躺着一条 E01xx。这是"诊断也是 API"（下一册）的又一理由：**层与层之间不只传 AST，还传未消化的错误**。

## 关键字表

```ts
const KEYWORDS = new Map<string, TokenType>([
  ['fn', 'fn'], ['let', 'let'], ['if', 'if'], ['else', 'else'],
  ['while', 'while'], ['return', 'return'],
  ['true', 'true'], ['false', 'false'],
  ['number', 'numberTy'], ['string', 'stringTy'],
  ['bool', 'boolTy'], ['unit', 'unitTy'],
]);

function identOrKeyword(): Token {
  const start = pos;
  while (pos < src.length && isIdentPart(src[pos])) pos++;
  const text = src.slice(start, pos);
  return { type: KEYWORDS.get(text) ?? 'ident', lexeme: text, start, end: pos };
}
```

保留字策略：mini 采用**强保留**（`fn` 不能当变量名）。弱保留（contextual keyword，如 TS 的 `type`）需要 parser 反馈——那是第三阶段的话题，v0.1 不碰。

### 查表时序：为什么是"整词 + 一次哈希"

identOrKeyword 的时序是**先吃满词、再查一次表**。反过来"边扫边判"（每读一字符就在 trie/分支树里走一格）理论上省一次哈希，但：

| 方案 | 代码形状 | 工程现实 |
|---|---|---|
| 整词扫描 + 哈希查表（mini） | 一个 while + `KEYWORDS.get` | 十二个关键字 O(1)；表改起来只动一行 |
| 每字符走 trie / 判决树 | 状态机里嵌关键字逐字分支 | 状态数随关键字增长；工业上以生成器代劳（perfect hash） |

工业实现真正的差异在"查到之后"：V8、rustc、tsc 扫完标识符后做的不是查 Map，而是先把词**驻留（intern）**成内部符号，再以符号做键——同一标识符全文只驻留一次，后续比较退化为整数/指针比较。mini 的规模不需要 intern，但要知道**查表在工业级是怎么变快的：不是换数据结构，是换比较的粒度**。

### 保留字强度的四个档位

"保留"不是开关而是光谱，mini 的强保留只是其中一档：

| 档位 | 语义 | 案例 | 代价 |
|---|---|---|---|
| 强保留 | 关键字任何位置都不能当标识符 | mini v0.1、多数教材语言 | 用户命名空间被词表侵占 |
| 上下文关键字 | 词法上是 ident，parser 按位置解读 | TS 的 `type`/`as`/`from`、C# 的 `yield` | parser 要回查词面，需要语法上下文 |
| 混合 | 核心强保留 + 外围上下文 | JS：`if` 强保留，`of`/`async` 上下文 | 两套机制并存 |
| 无保留 | 词不进关键字表 | 只有玩具语言敢做 | 语法歧义爆炸 |

上下文关键字的判定需要"当前位置处于声明头还是表达式"——那是 parser 的知识，所以词法只能交出 ident、由语法层升格。这条往返（lexer 给 ident → parser 要求当关键字用）正是"词法/语法边界可以移动"的又一次现身（[02-从正则到自动机](02-从正则到自动机.md) 的边界讨论、[02-自顶向下LL族](../03-第三阶段/02-自顶向下LL族.md) 的分派机制）。mini 若未来加 `as` 断言，就得从强保留迁到混合档——`as` 作变量名的老代码才不会破。

## Unicode 与性能细节

- 标识符分类用 `\p{ID_Start}` / `\p{ID_Continue}`（Unicode 标准，不是"字母数字"的想当然）——上面骨架里的 `u` 正则已就位。
- JS 字符串是 UTF-16：`'𝕕'.length === 2`（代理对）。偏移量按 UTF-16 code unit 计（与 ESTree/JS 引擎一致），报错换算行列时同理——**不要自己发明"按码点计数"的第三种偏移**，会和生态打架。
- 性能三则：缓存 `src.length`；`src[pos]` 比 `charAt` 直接；高频分类（数字/空白）用手写区间比较、正则只用于低频的 Unicode 类别。词法是编译器里跑得最频繁的循环之一，但**先正确再快**——第三阶段前不需要任何微优化。

### 一个标识符的三种"长度"

`let 变量名 = 1` 与 `let 𝕕 = 1` 各自的偏移账本（UTF-16 code unit 计）：

| 片段 | 视觉宽度 | 码点数 | UTF-16 长度 |
|---|---|---|---|
| `变量名` | 3 格 | 3 | 3 |
| `𝕕`（U+1D555） | 1 格 | 1 | **2**（代理对） |

第三列与第四列的差，就是"按码点计数"与"按 code unit 计数"的全部分歧。mini 钉死后者，连锁好处：`t.end - t.start` 与 `src.slice(t.start, t.end)` 这两个高频操作**零换算**（JS 字符串 API 原生就是 UTF-16 索引）；报错换算行列时 `column = offset - lineStart` 同样一致；将来接 sourcemap（VLQ 编码按 UTF-16 列计）也是零适配——**坐标系选对，生态接口白拿**。

反过来的坑也要认得：正则的 `.` 与字符类默认按 UTF-16 码元匹配，`/^.$/.test('𝕕')` 是 false（半个代理对不是一个字符），加 `u` 标志后才是 true——所以骨架里所有 Unicode 分类正则都带 `u`。少一个标志，`let 𝕕x = 1` 会在 lexer 层炸出"意外字符"，而错误信息里那半个代理对几乎无法辨认——这类 bug 定位成本极高，值得在写第一行词法正则时就防住。

## 两个特例：ASI 与缩进敏感

**JS 的分号自动插入（ASI）**：词法器在"换行 + 下一 token 无法接续当前语句"时插入 `;`。规则三条：`}` 后、行尾遇受限产生式（return/break/continue/throw）、下一行开头会拼出非法 token。经典坑 `return \n value`——ASI 在 return 后插了分号，value 成了死代码。**词法器读到了"语句能不能接续"的语法信息**，这是词法/语法边界被语言设计者主动打通的例子。

**Python 的缩进**：词法器维护缩进栈，行首缩进变深产出 `INDENT` token、变浅产出 N 个 `DEDENT`、与栈顶比较不等则报错。**BLOCK 结构被编码进 token 流**，parser 因此不需要块产生式。代价是空行/注释/续行的词法规则极其琐碎——两站式设计（词法给语法让渡部分结构职责）的代价样本。

mini v0.1 用显式 `{}` + 强制 `;`——两个特例都写进笔记是为了**理解边界可以被怎样移动**，不是照抄。

### ASI 三条规则的逐条样例

| 规则 | 输入 | ASI 行为 | 结果 |
|---|---|---|---|
| `}` 前补 | `f()\n}` | `}` 前隐式补 `;` | 合法 |
| 受限产生式 | `return\nvalue` | return 后强插 `;` | value 成死代码（经典坑） |
| 无法接续才插 | `a = b\n(c).x()` | 下一行 `(` 语法上**能**接续 → 不插 | 两行被悄悄拼成一个表达式 |

第三行比第二行更危险：ASI 的判断是"下一行开头 token 能否接在当前产生式后"，`(c).x()` 完全接得上——于是不插分号，静默拼行。三条规则共同暴露的事实：**词法器手里握着"换行"这个物理信息，却要用"语法能否接续"来裁决**——信息在词法层、决策依据在语法层，ASI 是两层被迫协作的接口。对比 Python（缩进即结构）与 mini（显式 `;`）：三种"语句边界"方案 = 词法参与语法的三档深度——**每深一档，词法器的状态量与测试面就翻一倍**。

### Python 缩进的手工演算

```python
if a:
    b()
c()
```

缩进栈 `[0]` 起步，逐行演算 INDENT/DEDENT 的产出：

| 行 | 行首列宽 | 与栈顶比较 | 动作 | token 产出 |
|---|---|---|---|---|
| 1 `if a:` | 0 | 等于 0 | 栈不变 | `if a :` + NEWLINE |
| 2 `    b()` | 4 | 4 > 0 | **压栈** [0, 4] | INDENT + `b ( )` + NEWLINE |
| 3 `c()` | 0 | 0 < 4 | **弹栈** [0] | DEDENT + `c ( )` + NEWLINE |
| EOF | 0 | 已平 | 清栈 | 文件尾补 NEWLINE/DEDENT |

第 3 行注意：缩进从 4 跳回 0 只弹到栈里的 0——若代码从 4 跳回 2 而栈里没有 2，词法器直接报"缩进不匹配"。**栈顶不相等 ≠ 弹一层**，这是缩进词法最易写错的一格。块结构（parser 期待 INDENT…DEDENT 包住语句序列）完全由 token 流携带——对照 mini 的 `{`/`}`：**语法信息可以被推到词法层多深是个可调旋钮**，Python 拧到最深，mini 拧到最浅，JS 的 ASI 拧在中间。

## 常见误区

- **"token 结构越富越好，先把 phase/flags 都加上"**：字段是承诺——每加一个字段，所有构造点都要填、快照都要 diff、后续重构都拖着它。mini 五个字段（type/lexeme/literal?/start/end）是"parser 确实会消费"的最小集；trivia、注释关联等留给真正需要的阶段（IDE 在第八阶段）再加；
- **"关键字表用 switch 硬编码更快"**：`switch(lexeme)` 与 Map 查找在十二个词的量级没有任何可测差距，而表是数据——加关键字改一行。性能直觉要花在刀刃上（字符分类、越界检查），不在一次 O(1) 的字典操作上；
- **"空白跳过就行，注释一样"**：语义上对，工程上要分家——注释是"将来要还给 IDE 的信息"（trivia，05 册留了练习），空白不是。混在一起跳过，第八阶段写格式化/lint 时就得重写 lexer；
- **"最长匹配是全局规则，处处贪心"**：最长匹配只在同一套 token 规则内部生效。`a-1` 永远不会切成一个叫 `a-1` 的 token——数字规则要求起点是数字；真正的例外都来自"规则之间竞争"（`/` 的两读性、`.5` 的成员访问），那是设计问题不是算法问题；
- **"literal 解析放到 parser 里做也行"**：功能等价，但"字面量的值属于词法产物"——parser 拿到的 token 应当是终态数据，不该再回头碰 src。放 parser 里做还会错过"扫描时校验、残缺即报错"的最佳时机（下一册的整词跳过策略）；
- **"Unicode 分类用 `\w` 就够了"**：`\w` 是 ASCII 子集，`变量名` 直接被拒。`\p{ID_Start}`/`\p{ID_Continue}` 是 Unicode 标准对标识符起止字符的官方定义，而少一个 `u` 标志就全盘失效；
- **"词法器不该有任何状态"**：理想很美，现实是模式切换（三引号、模板串）、`prevToken`（`/` 裁决）、缩进栈都是状态。正确的目标是**状态显式、可枚举、可测试**——每个模式有进有出、每次转移有用例，而不是"零状态"的洁癖。
