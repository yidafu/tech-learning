# Wasm 专题导览

> [返回：编译原理学习大纲](../编译原理学习大纲.md)
> 本文是 Wasm 专题的入口。定位：[第八阶段选做路线六](../08-第八阶段/01-导览.md)的完整展开——给 mini 语言写**第二个后端**。第五阶段的 mini 走的是"自己设计字节码 + 自己写 VM"；本专题把 lowering 目标换成 **WebAssembly**：一种由浏览器引擎执行的、真实存在的栈式字节码。五册走完，你亲手编译出的模块会在浏览器里跑起来。

## 为什么编译原理学习者要懂 wasm

- **第二个后端 = 后端思维的成人礼**：同一门语言、同一个前端，产出两种目标（自家 VM / wasm）——"IR 设计决定后端好不好写"从口号变成两次真实的 emit 代码；
- **同构免费**：mini 字节码本来就是栈式（`CONST`/`ADD`/`JMP_IF_FALSE`），wasm 也是栈式（`f64.const`/`f64.add`/`if`）——多数指令几乎逐条对译，入门成本极低；
- **真实世界的靶机**：JVM 字节码、CLR、wasm 是"编译目标"三大公开标准；wasm 是其中最新、最简、浏览器原生内置的那个。学它等于给"语言设计 → 指令集 → 执行引擎"补上工业视角。

## 专题地图：三条读法

1. **后端线**（约 2 天，主线）：02 → 03 → 04 → 06——逐层把 mini 编译过去，收官于"mini 源码 → wat → 运行结果"三栏 demo（即第八阶段毕业项目 C 的核）；
2. **格式线**（约 1 天）：02 → 05 前半——字节怎么排、工具链怎么拼，适合"想读懂 wasm-objdump 输出"的读者；
3. **决策线**（约 0.5 天）：05——性能真相与选型决策表，写给"要不要把业务逻辑放进 wasm"的工程判断，不写代码也能读完。

## 与主线的关系

- 第五阶段[字节码设计](../05-第五阶段/03-字节码设计.md)：mini 34 条指令与 wasm 的逐条映射在 03 册——两套栈式指令集互为镜像，学完能对照读任何真实引擎的字节码；
- 第五阶段[解释器实现](../05-第五阶段/04-解释器实现.md)：解释执行 vs 编译执行的差距，在 06 册用同一个 fib 量出来；
- 第八阶段[选做路线六](../08-第八阶段/01-导览.md)：本专题即该路线的展开；毕业项目 C（mini-to-WASM）的验收即 06 册产出；
- [GC 专题 · 免 GC 的内存管理](../10-GC算法专题/05-免GC的内存管理.md)：wasm 的线性内存正是"arena + 手动回收"的世界——04 册把那册的 arena 思想在浏览器里落地。
