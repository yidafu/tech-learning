# Forth 栈机与字典：逆波兰序的极简世界

> [返回：演练场导览](01-导览.md)
> 对应演练场 [playground/forth](https://yidafu.github.io/tech-learning/compiler/playground/forth)。源码：`src/playground/forth.js`（约 230 行）。本册讲清数据栈与字典这两个原语，以及它与第五阶段字节码 VM 的同构关系。

## Forth 世界观：一切经过栈

Forth（Chuck Moore，1970）的哲学激进到只有一个数据结构——**数据栈**，和一种组合方式——**逆波兰序（RPN）**：

```
1 2 + .        \ 等价于 C 语言的 printf("%d", 1 + 2)
```

执行轨迹：`1` 入栈 → `2` 入栈 → `+` 弹两个数压回 3 → `.` 弹栈打印。**没有表达式语法、没有优先级、没有括号**——求值顺序就是书写顺序。HP 的科学计算器用了几十年 RPN，因为它的状态可以随时用 `.s` 看到：计算过程是**完全透明的**。

Forth 程序员写"栈效应注释"来代替类型签名：`dup ( a -- a a )`——左边是执行前的栈，右边是执行后。**这其实就是一个一元算子式的类型系统**（concatenative language 的学术名称由此而来）。

栈效应不只是注释——它是 Forth 世界里**唯一靠谱的接口契约**。内建单词的效应表（右侧从左到右对应栈底到栈顶）：

| 单词 | 栈效应 | 说明 |
|---|---|---|
| `dup` | ( a -- a a ) | 复制栈顶 |
| `drop` | ( a -- ) | 丢弃栈顶 |
| `swap` | ( a b -- b a ) | 交换顶两个 |
| `over` | ( a b -- a b a ) | 复制次顶 |
| `rot` | ( a b c -- b c a ) | 三轮转 |
| `nip` | ( a b -- b ) | 丢掉次顶（= `swap drop`） |
| `tuck` | ( a b -- b a b ) | 复制到次顶（= `swap over`） |

这套组合子的表达力很强——绝大多数"局部变量"场景都能用它消解。第五阶段给 mini VM 写指令集时你会再次遇到同样的选择：是加 LOCAL_LOAD/STORE 指令，还是教会使用者用栈旋转？**栈机的历史答案是后者优先**，所以它的指令集才能小到一页纸。

### tokenize：三行词法器

第一站的词法值得停一分钟——它浓缩了第二阶段手写 lexer 的全部要素：

```js
function tokenize(src) {
  const noComments = src.replace(/\\[^\n]*/g, ' ')   // 行注释 \ 到行尾
                        .replace(/\([^)]*\)/g, ' '); // 块注释 ( … )
  return noComments.match(/\."[^"]*"|\S+/g) ?? [];
}
```

三个设计点：

- **两种注释一个动作**：都替换成空格而不是删除——保持行列位置（虽然教学版不生成诊断位置，习惯先养好；第三阶段[AST设计与错误恢复](../03-第三阶段/05-AST设计与错误恢复.md)会讲位置追踪的代价与做法）；
- **`."` 字符串优先于空白切分**：交替次序 `\."[^"]*"|\S+` 让 `." hello world "` 整体成为一个 token（否则会被空格切开）。**"更长匹配优先"是 lexer 的普遍纪律**（对照第二阶段的 maximal munch：`123abc` 里数字要吃满）；
- **没有类型字段**：token 就是字符串，是不是数字由解释期的 `/^-?\d+$/` 判定——词法与语义的边界被刻意放得很宽。真实 Forth 连"是不是数字"都可以由字典里的单词决定（比如把 `2` 定义成单词），教学版把它钉死在正则上，换来的是 `: 2 ... ;` 这类合法但疯狂的行为不出现。

## 两个原语：栈与字典

```js
// 字典：名字 → 内建函数 或 用户单词的 token 数组
dict.set(name, builtinFn)      // 内建：JS 函数直接操作栈
dict.set(name, bodyTokens)     // 用户定义：: name … ; 的体

// 执行：walk tokens；用户单词递归解释——线程码（threaded code）的雏形
const word = dict.get(t);
if (typeof word === 'function') word(ctx);
else interpret(word, ctx);
```

`: square dup * ;` 把三个 token 存进字典。调用 `5 square` 时递归解释这串 token。**这是第五阶段 FnProto 的直系祖先**：

| Forth | 第五阶段 mini VM | 说明 |
|---|---|---|
| 数据栈 | 求值栈 `stack: Value[]` | 同一个东西 |
| 字典条目（token 数组） | FnProto（字节码数组） | "代码"就是一个可跳转执行的序列 |
| 内建单词（JS 函数） | NATIVE 内建函数 | 运行时与语言的边界 |
| `: name … ;` | `CLOSURE f` + 常量池 | 定义即"存进代码区" |
| 递归 interpret 用户单词 | CALL 压帧 | 控制流 = 调用链 |

区别只在**编码密度**：Forth 存 token 字符串，字节码存数字操作码——一个面向人调试，一个面向机器解释。`ADD` 指令"弹两个压一个"的语义，就是 Forth 里一条 `+` 单词。**读懂 Forth 就读懂了栈式字节码的操作模型。**

### 实现走读：ctx 与四个部件

`run()` 入口构造的 `ctx` 是整个解释器的状态全集，四个部件各管一摊：

```js
const ctx = {
  stack: [],          // 数据栈：唯一的"寄存器组"
  dict: makeDict(),   // 字典：名字 → 单词体
  cells: new Map(),   // 变量仓库：名字 → 当前值（variable 的存储）
  loops: [],          // do…loop 的运行时栈：{ index, limit, bodyStart }
  line: '',           // 行缓冲输出（教学 REPL 的输出聚合）
  out(s) { /* 逐字符攒行，遇 \n 才 flush 给 write */ },
};
```

值得注意的取舍：

- **dict 每次运行重建**（`makeDict()` 现场装内建）：没有全局单例，两次 `run` 互不污染——这是"解释器即纯函数"的最小纪律，对照第五阶段 VM 的实例化设计同源；
- **`loops` 是显式的帧栈**：`do` 压帧（记下 `bodyStart`），`loop` 改 `index` 判断回跳或弹帧，`i` 查栈顶帧——**控制流状态自己管，不寄生在 JS 调用栈上**（对照：用户单词的调用确实寄生在 JS 栈上，见下文"递归即压帧"）；
- **`out` 做行缓冲**：`.s` 输出带换行、`.` 输出带空格，最后 `finally` 里 flush 残行并报告栈状态——收尾输出 `（栈：1 2 3）` 让每次运行结束都能看到**程序留下的栈残影**，这是教学调试的重要反馈。

### 实现走读：主循环的分派顺序

`interpret` 对每个 token 的处理次序本身就是一张"优先级表"：

1. **数字**：`/^-?\d+$/` 匹配 → `parseInt` 入栈，continue（最热的路径最先判）；
2. **字符串字面量**：`."` 开头 → 直接 `ctx.out(...)`，不入栈；
3. **控制流关键字**（`:`、`variable`、`constant`、`if/else/then`、`begin/until`、`do/loop/i`）：switch 特判——它们**消费或改写 token 流本身**（如 `:` 吞到 `;` 为止建字典项）；
4. **其余一切**：查字典——内建函数直接调用，用户单词递归 `interpret`。

这个分派顺序与第二阶段手写 lexer 的骨架（循环 + switch + 默认分支）完全同构，只是粒度从"字符"换成了"token"。第 3 类关键词之所以必须特判，是因为**它们改变解释器自身的状态**（定义新单词、改写循环变量）——语言里的"元操作"永远没法被普通数据驱动的表覆盖。

内建单词的装配用了两个帮助函数，把"弹两个压一个"的模式抽干：

```js
const bin = (name, f) => dict.set(name, (ctx) => {
  const b = ctx.stack.pop(), a = ctx.stack.pop();
  ctx.stack.push(f(a, b));            // 注意弹出顺序：b 先 a 后（b 是右操作数）
});
```

`bin('-', (a, b) => a - b)` 这一行藏着逆波兰序最容易写错的细节：**减法不交换**，`a b -` 是 `a - b`，弹栈时先拿到的是右操作数。给栈机写指令时这个 bug 会陪伴每一个人一次。

另一个细节是**真值约定**：比较运算返回 `-1`（真）或 `0`（假）——经典 Forth 用全 1 位模式当真值（位运算友好），教学实现保留了 `-1`/`0`，`if` 判 `0` 为假。JS 里我们习惯了 truthy/falsy 的宽泛定义，Forth 的世界只有这两个数。

## 控制流：我们的简化与真实 Forth

教学实现里，`if/then`、`do/loop`、`begin/until` 用**配对扫描**实现：

```js
case 'if': {
  if (pop() === 0) i = scanTo(tokens, i, 'then');  // 假：向前跳到 else/then
  continue;
}
```

运行时跳过分支体 = 解释器在 token 数组上"扫"过去。**真实 Forth 不是这样**：`:` 进入编译态，`if` 编译一条 `0BRANCH (addr)` 指令并把地址坑位留在码流里，`then` 回填跳转目标——这正是第五阶段 `patchJump` 跳转回填的完整同型物。我们跳过了"编译态/解释态双模态"这个 Forth 最迷人（也最烧脑）的设计，换取 30 行可通读的控制流。想见识双模态，去找 jonesforth 或 Gforth 的 `IF` 定义源码——它们用 Forth 自己定义自己的控制流（自举）。

### scanTo 的嵌套处理

配对扫描最容易错在嵌套：`if a if b then c then` 里的第一个 `then` 属于内层 `if`。`scanTo` 的解法是深度计数：

```js
const OPENER = { then: 'if', else: 'if', loop: 'do', until: 'begin' };
function scanTo(tokens, from, stop) {
  const opener = OPENER[stop];
  let depth = 0;
  for (let j = from + 1; j < tokens.length; j++) {
    if (tokens[j] === opener) depth++;        // 途中又开一个同族块：+1
    else if (tokens[j] === stop) {
      if (depth === 0) return j;              // 配平了：这就是我的终点
      depth--;
    } else if (stop === 'then' && tokens[j] === 'else' && depth === 0) return j;
  }
  throw new ForthError(`「${tokens[from]}」缺少配对的 ${stop}`);
}
```

三处细节：`OPENER` 表达"停止词属于哪个开词"（then/else 都属于 if）；深度只在**同族词**上计数（`do…loop` 里的 `if` 不会干扰 `until` 的配对）；找不到配对抛错而不是静默跳过。**这与词法阶段"括号计数"是同一个算法**——无栈结构的扁平序列里，配对只能靠计数；这正是第二阶段[从正则到自动机](../02-第二阶段/02-从正则到自动机.md)说"DFA 数不了括号"的反面印证：我们其实是在**用 JS 的调用栈模拟一个计数栈**。

`until` 还需要反向扫描（`scanBackToBegin`）：条件为假时跳回 `begin` 之后重新执行循环体。前后两个方向的扫描合起来，`begin…until` 就成了一个可循环的"双向 goto"。

### do…loop 与循环变量 i

`do` 从栈上弹 `( limit index )`（注意顺序：先弹的是 index，栈顶是 limit——又一个反直觉点），压入 `loops` 帧；`loop` 把 `index+1`，没到 limit 就把解释器下标拨回 `bodyStart`，到了就弹帧。`i` 单词查 `loops` 栈顶取当前 index。

```forth
: sum100  0  101 1 do  i +  loop ;      \ 1..100 累加 = 5050
```

`i` 的查栈顶而非查"自己的循环"——意味着嵌套循环里 `i` 永远指最内层（真实 Forth 用 `j` 取外层）。这是**帧栈式循环变量的标准行为**，与第五阶段 VM 的调用帧栈同一模型。

## 变量：栈模型下的可变状态

```
variable count      \ 定义一个"单元格"，名字即地址
0 count !           \ ( x addr -- )：把 0 存进 count
count @             \ ( addr -- x )：读出来
: bump  count @ 1 + count !  count @ . ;
```

Forth 的变量是**显式的地址操作**——`@`/`!` 就是 load/store 指令的 REPL 形态。对照第三~四阶段：`count` 这个 Identifier 不像现代语言那样"自动"解析成值，你必须自己声明"我要读（@）还是写（!）"。现代语言把这件事交给编译器（左值/右值分析、`resolvedTo` 引用边），Forth 把它交给人。

### 实现走读：地址就是名字

教学实现里 `variable count` 的落地只有三行：

```js
case 'variable': {
  const name = tokens[++i];
  ctx.dict.set(name, (c) => c.stack.push(name));   // "地址"就用名字表示
  ctx.cells.set(name, 0);                          // 仓库建格子，初值 0
  continue;
}
```

- `count` 本身是个**内建单词**：执行效果是把"地址"（这里就是名字字符串）压栈——对照真实机器：符号名即地址（没有重定位的静态世界）；
- `@` 弹出名字查 `cells`；`!` 弹两个（值在下、地址在上——`( x addr -- )` 的栈效应写法已经标明栈顶是 addr）；`+!` 是读改写的组合原子；
- **无效地址检测**：`@`/`!` 发现名字不在 `cells` 里就抛"无效地址"——这是 mini VM 里"类型错误的运行时替身"：静态类型语言在编译期拦下的"把这个当变量用"，动态世界只能在运行时验。

`constant` 更有意思：弹一个值，把名字绑成"压这个值"的内建单词——**常量折叠进了字典**。`3 constant three` 之后 `three` 与字面量几乎等价（差的只是每次 push 一个闭包捕获的值）。真实 Forth 的 constant 会被编译器内联进指令流——第五阶段讲常量池时会再遇到这个"定义即优化机会"的思想。

## 手工推演：递归阶乘的每一步

`fact` 示例是栈式思维的期末考试，值得逐步推演。先看代码：

```forth
: fact  dup 2 < if  drop 1  else  dup 1 - fact *  then ;
5 fact .
```

以 `3 fact` 为例（`5 fact` 同型，只是递归深两层），只跟踪外层调用：

| 步骤 | 执行到 | 栈（底→顶） | 发生了什么 |
|---|---|---|---|
| 1 | `3` | 3 | 入栈 |
| 2 | `dup` | 3 3 | 复制一份——给比较用，原值留给后面 |
| 3 | `2 <` | 3 0 | 弹 (3,2) 算 3<2 = 假（0）。真值约定：真 = -1，假 = 0 |
| 4 | `if`（假） | 3 | `pop()===0` → 扫描跳到 else 之后 |
| 5 | `dup` | 3 3 | 第二次复制——给减法用，原值留给最后的乘法 |
| 6 | `1 -` | 3 2 | 算 3-1 |
| 7 | `fact` | 3 2 → 3 2 | 用户单词：递归 interpret `[dup 2 < if drop 1 else …]`；内层最终把 2 变成 2 留在栈上（同样的流程再展开一层） |
| 8 | `*` | 6 | 3 × 2 |
| 9 | `.` | （空） | 弹出打印：`6 ` |

两个 `dup` 各司其职：第一个给 `<` 提供比较副本（保住原 n），第二个给 `-` 提供被减数（保住原 n 给最后的 `*`）。**栈式编程的心法：每一步操作先问"栈上还剩谁、谁还要被后面用到"——dup/drop 就是从这里长出来的**。删掉第二个 dup，第 6 步的栈变成 `3`（1-1 时弹掉了仅有的组合），递归调用 `fact` 时栈上没有 n-1——要么下溢报错、要么算出错误值。在演练场里亲手试一次，报错信息会教你。

注意第 7 步的**递归机制**：`fact` 的体是 token 数组，调用它 = `interpret(bodyTokens, ctx)`——JS 调用栈上压了一层新帧，但**数据栈是同一个**（ctx 全程传递）。这正是第五阶段"CALL 压帧、共享求值栈"的形状：控制栈与数据栈分离。递归的深度由 JS 栈兜底（教学版没有栈深限制），真实 Forth 靠操作系统栈。

顺带看清"调用一个单词"的全部成本：**一次 JS 函数调用 + 查一次 Map + 逐 token 分派**。真实 Forth 的线程码把这三步合成"跳到目标代码"——这也是为什么 Forth 系统"解释执行"却能有编译级速度的原因之一：它的"解释"本来就只剩一条间接跳转。第五阶段 VM 性能讨论（[04-解释器实现](../05-第五阶段/04-解释器实现.md)）会量化"分派开销"这件事，此处先建立直觉：**解释器的成本大头不在算法，在分派**。

## 一图流：解释器全景

```mermaid
flowchart TB
    SRC[源码文本] --> TK[tokenize<br>剥注释 + 正则切词]
    TK --> MAIN[interpret 主循环]
    MAIN -->|数字| PUSH[入栈]
    MAIN -->|."字符串"| OUT[直接输出]
    MAIN -->|控制流关键字| CF[if/else/then<br>do/loop<br>begin/until]
    MAIN -->|其余| DICT{查字典}
    DICT -->|JS 函数| BUILTIN[内建单词执行<br>直接操作 stack/cells]
    DICT -->|token 数组| USER[用户单词<br>递归 interpret = 线程码雏形]
    DICT -->|查无| ERR[未知单词 报错]
    CF --> SCAN[scanTo / scanBackToBegin<br>配对扫描移动 i]
    SCAN --> MAIN
    BUILTIN --> STACK[(ctx.stack)]
    USER --> MAIN
    STACK --> MAIN
```

与第五阶段 VM 的结构图并排挂出来会几乎重合：tokenize ↔ lexer/compiler 前端；主循环 ↔ `while + switch` 分派；内建单词 ↔ NATIVE 指令；用户单词 ↔ CALL。**差异只有一处**：VM 吃的是数字操作码（编译器已把名字解析成下标），Forth 吃的是字符串（查表在运行时做）——"把查表提前到编译期"就是从解释器走向编译器的第一步。

## 为什么 Forth 值得每个编译器学习者玩一周

- **透明性**：`.s` 随时看栈，每个单词的效应都能注释清楚——调试即观察。
- **极简的完整**：两百行实现里有定义、递归、控制流、可变状态——图灵完备的最小工程形态。
- **历史地位**：Forth 是"语言即虚拟机"思想的源头之一；PostScript（打印机语言）、JVM 字节码、我们的 mini VM，栈模型一脉相承。NASA 的航天器上至今跑着 Forth。
- **线程码的真实形态**：真实 Forth 编译成"一串地址"（每个地址指向下一段代码），解释器退化成 `jmp *[ip]` 一条机器指令——"编译"与"解释"的分界线在这里模糊到不存在。这为理解 JIT（第七阶段）提供了最朴素的前置：**优化编译器做的事，本质是把"解释分派"折叠成"直接跳转"**。

### 栈模型的家族谱

把"Forth 的直系后代与亲戚"排成一张表（每个都能在主线某阶段找到回声）：

| 语言/格式 | 与 Forth 的血缘 | 主线对应册 |
|---|---|---|

### 与真实 Forth 的差异清单

把教学版与工业 Forth（Gforth/jonesforth）的差异列全，避免"学了个假 Forth"的疑虑：

| 维度 | 教学版 | 真实 Forth |
|---|---|---|
| 单词体 | token 字符串数组 | 线程码（地址序列），三种变体 ITC/DTC/CTC |
| 控制流 | 解释时配对扫描 | 编译期生成 0BRANCH/BRANCH + 地址回填 |
| 双模态 | 无 | `:` 进编译态，`[` `]` 切换，IMMEDIATE 词在编译期执行 |
| 变量地址 | 名字字符串 | 真实内存地址（cell 对齐） |
| 数据类型 | 只有整数 | 单元格 + 双精度 + 浮点栈（独立 F 栈） |
| 自举 | 不适用 | Forth 源码定义 Forth（含 if/loop 的定义本身） |
| 局部变量 | 无 | 部分系统支持 `{ a b }` 语法（后期标准） |

其中"双模态"最值得再讲一句：Forth 的 `:` 之后进入编译态，普通单词被**编译**进定义体（存地址），而标了 IMMEDIATE 的单词（`if`、`then`、`loop` 就是）在编译期**立即执行**、负责生成代码——**语言的控制流是库里的一批宏**。这套机制是 Lisp 宏（[02-Lisp元循环解释器](02-Lisp元循环解释器.md)）的孪生思想：语言的扩展点开在"定义新定义"的地方。

用一段"如果教学版做双模态"的伪代码把回填机制看穿（与第五阶段 patchJump 逐行对上）：

```
解释态:  1 2 + .                    ← 边读边执行
编译态:  : abs dup 0 < if negate then ;
              │       │    │
              │       │    └─ then: 取出坑位 → 填入当前地址（回填！）
              │       └─ if: 弹标志，编译 BRANCH_IF_FALSE [坑位]，跳过目标未定
              └─ dup/0/<：逐词编译进定义体
```

坑位（hole）与回填（backfill）是"两遍编译"的最小形态：**前向跳转的目标还不存在，只能先留空、走到定义点再补**。if/else/then、begin/until 的区别只是回填发生在"then 处"还是"until 处"，以及跳转方向（向前/向后）。教学版的 `scanTo` 用"运行时扫一遍"替代了这两个动作——功能等价，时机不同；而"时机"正是解释与编译的分界线本身。

### 错误面：三类报错的教学价值

解释器的报错点不多，但每一处都对应一类"语言设计决策"，值得列出来：

| 报错 | 触发 | 对应的深层问题 |
|---|---|---|
| `栈下溢（操作数不够）` | `pop()` 空栈 | 静态类型/栈效应检查缺位的运行时代价——这正是第四阶段 checker 要在编译期消灭的错误 |
| `未知单词：xxx` | 字典查无 | 名字解析失败的运行时版；对照第四阶段"未声明的变量"——静态语言编译期报，动态/栈机报在执行时 |
| `「if」缺少配对的 then` | scanTo 扫到头 | 结构错误（块没闭合）——对照第三阶段的"期待的 token 没出现"，这里是它的无栈版（计数扫描） |
| `无效地址：xxx` | `@`/`!` 查 cells 无此名 | "把非变量当变量用"的运行时替身 |
| `i 只能在 do…loop 里用` | loops 空栈查顶 | 作用域规则的运行时版——`i` 的作用域就是循环帧栈的深度 |

看规律：**动态语言的每一类运行时报错，都能在静态语言里找到一个编译期对应物**。演练场四个解释器都在演示"没有编译期检查时，这些错误去哪了"——它们没有消失，只是搬到了运行时、以更难定位的面目出现。这是理解"为什么要有 checker"的最直观教材。

## 常见误区

- **"Forth 没有类型系统"**：有——栈效应注释就是类型系统（输入栈形状 → 输出栈形状），只是没被机器检查。工业 Forth 项目靠纪律与 `stack effect comment` 约定维持正确性；研究界的强类型 concatenative 语言（如 Cat/Factor 的部分检查）证明这套类型可以形式化；
- **"逆波兰序只是没有括号的语法糖"**：不是糖，是**求值模型**——它决定了实现里可以没有"表达式解析"这个阶段（第二、三阶段的工作整体消失），错误也更早暴露（操作数不够当场栈下溢，而不是解析到一半报歧义）；
- **"栈机比寄存器机慢是定论"**：栈机指令更短（无操作数编码）、实现更简单；寄存机指令更少但更长。物理机选了寄存器，**虚拟机**大量选栈（JVM/Wasm/CLR）——因为字节码密度与可移植性优先。Wasm 专题[表达式与结构化控制流](../11-Wasm专题/03-表达式与结构化控制流.md)里你会看到这套栈模型的现代版；
- **"`i` 是全局变量"**：它查的是 `loops` 栈顶帧——循环变量是**帧栈上的相对引用**，嵌套循环各持各的（外层要用 `j`）。与"闭包捕获变量"是两种正交的变量定位机制；
- **"教学版控制流的扫描跳转只是偷懒"**：它诚实地展示了"解释器在指令流上移动 ip"这件事的本质——`i = scanTo(...)` 就是 `ip = target`。真实 Forth 的区别只在**何时**算出 target（编译期 vs 运行期），"ip 移动"的模型一字不差。

## 动手扩展清单（从易到难）

按顺序做完这五个扩展，栈机的肌肉记忆就建起来了（每个都在 20 行以内）：

1. **`nip ( a b -- b )`**：`dict.set('nip', ...)` 弹两个压回第二个——练"栈效应即实现规格"；
2. **`tuck ( a b -- b a b )`**：用 `swap over` 组合或直接操作数组——练组合子视角；
3. **`depth ( -- n )`**：压入当前栈深——`.s` 的可编程版；
4. **`max2 ( a b -- max )`**：用 `< if else then` 写——练"真值 = -1"的分支；再用 `max` 内建对照；
5. **`fizzbuzz`**：`1 101 do … loop` 里配合 `i 15 mod 0 = if` 嵌套分支——练 `do/loop` + `i` + `mod` 的合奏（mod 的实现取了"非负余数"约定，与 JS 的 `%` 不同，试试 `-7 3 mod`）。

第 5 题会自然引出"栈上放不下那么多中间值"的痛——这正是真实 Forth 程序员写 `>r`/`r>`（返回栈暂存）的原因，也解释了为什么现代栈语言（Factor、Joy）会补局部变量语法。
