# 演练场导览：多范式语言核心最小集

> [返回：编译原理学习大纲](../编译原理学习大纲.md)
> 本文是演练场的入口：定位、分册索引、四种语言的范式地图与使用建议。所有解释器都在[演练场首页](https://yidafu.github.io/tech-learning/compiler/playground)在线可跑（本地 `npm run dev` 后是 `/playground`）。

**建议用法**：每个演练场先把示例跑一遍、改几行看结果，再回来读分册讲解，最后打开 `compiler/src/playground/` 里的源码通读——四个解释器互不依赖，每个两三百行，一次读完不费劲。

## 为什么要有演练场

主线是用 TypeScript 造一门 mini 语言——一条垂直的、工业风格的深挖。但编译原理这门课的另一条传统路径是**横向采样**：挑几种范式差异最大的语言，各自实现一个"语言核心最小集"（minimal core），在两三百行里看清一门语言的全部骨架。

两条路互相照亮：

- mini 语言的每个阶段（词法/语法/语义/IR/VM）都能在演练场里找到**同构或反例**；
- 演练场里的每个语言都故意"残缺"——残缺之处正是主线要补的工程环节（错误恢复、类型检查、字节码）。

## 范式地图：四个最小核心各自回答什么问题

| 问题 | 回答者 | 一句话答案 |
|---|---|---|
| 计算到底是什么？ | λ 演算 | 代入（β-归约）就是计算；布尔、数、递归都能编码出来 |
| 程序为什么能"自己处理程序"？ | Lisp | 语法即数据（S-表达式），eval 一条规则吃遍天 |
| 不用寄存器与变量，机器还能怎么工作？ | Forth | 一切经过数据栈；"语言"就是字典里可组合的单词 |
| 不写"怎么做"，只写"是什么"，行吗？ | Prolog | 行——把求解交给合一 + 回溯搜索 |

## 实现约定

- **源码位置**：`compiler/src/playground/{lambda,lisp,forth,prolog}.js`，默认导出 `{ title, tagline, examples, run }` 供页面组件消费；纯 JS、零依赖，Node 里也能直接跑测试。
- **零依赖是刻意的**：不用任何解析器生成器或语言库——演练场的意义就在于"核心小到可以整体装进脑子"。
- **教学简化都有注释**：例如 Forth 的控制流是配对扫描而非真正的编译期分支指令、Prolog 不支持 cut——每个简化点在分册里都有"与真实实现的差异"说明。
