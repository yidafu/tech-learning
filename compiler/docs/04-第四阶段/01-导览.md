# 第四阶段导览：语义分析与类型系统

> 本文是第四阶段的入口：阶段目标、知识点地图、实践任务清单与阶段自测。

**建议时长**：3 周（每天 1~2 小时）。语法管"长得对不对"，语义管"说得通不通"。本阶段给 mini 语言装上"理解能力"：作用域解析 + 类型检查，交付一个能给出精确诊断的 checker。

## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 实现嵌套作用域的符号表（作用域树），正确处理遮蔽、重定义与声明顺序。
2. 说清词法作用域 vs 动态作用域、静态语义 vs 动态语义的分界。
3. 实现自底向上的类型综合检查：表达式类型 = 子表达式类型的函数。
4. 讲解结构化 vs 名义化类型系统，并举 TypeScript 结构化的例子。
5. 解释 Hindley-Milner 推导的合一算法直觉，说清泛型"擦除"与"单体化"两种实现。
6. 把诊断信息做到 ESLint 级别：错误码、行列定位、修复建议。

## 知识点地图

### 1. 符号表与作用域

- **静态 vs 动态语义**："变量必须先声明"是静态（编译期可判），"数组下标越界"是动态（运行期才知道）。checker 只管静态。
- **作用域树**：每个块一个 `Scope { parent, symbols: Map<string, Symbol> }`；查找沿 parent 链上溯。`var`/`let`/`const` 的差异本质是"符号挂到哪个作用域节点 + 声明顺序语义"。
- **遮蔽与重定义**：内层同名声明遮蔽外层（合法）；同层重定义（大多数语言报错）。查重必须在"同一作用域"判定——写错就会把合法遮蔽误杀。
- **TDZ**：`let x = x + 1` 中右值引用在"已声明未初始化"区间——词法作用域静态可判（位置比较），JS 用运行时检查兜底。静态版是本阶段练习。
- **自由/绑定变量**：函数体内引用但非本函数声明的变量 = 自由变量；它决定了第五阶段闭包要捕获什么。resolve 阶段把每个引用 resolve 到唯一 Symbol 声明。

### 2. 类型系统

- **类型的代数**：基础类型（number/string/bool/unit）、函数类型 `(A, B) → C`、复合（数组 `A[]`、记录 `{x: A}`）；函数类型是"高阶"的起点。
- **结构化 vs 名义化**：TypeScript 按"形状"判等（`{x: 1}` 可赋给 `{x: number}`）；Java/Kotlin 按名字判等。结构化的代价：声明合并、循环引用的检查复杂度。
- **综合（synthesis）**：表达式类型自底向上算——`BinaryExpr` 的类型 = 两个操作数类型的函数（`number × number → number`，`string × string → string`）。这是实现的主干。
- **检查（checking）模式**：上下文类型自顶向下压——TS 的 `f((x) => x.length)` 能推出参数类型靠它。两种模式配合即"双向类型检查"（bidirectional）。
- **any/unknown**：any 关闭检查（拓扑序上的"万能洞"），unknown 强制收窄（`typeof` 判别后才能用）。语义差一天壤——一个让错误穿过，一个把错误拦在收窄处。

### 3. 类型推导（进阶）

- **Hindley-Milner**：`let f = (x) => x` 推出 `f: α → α`——用**合一（unification）**解类型方程：把两个类型树匹配、变量绑定、冲突即错。α 在不同调用点实例化（多态 let）。
- **泛型两种实现**：擦除（uniform representation，TS/Java：泛型只存在于检查期，运行时统一表示）vs 单体化（monomorphization，Rust/C++：每个实例化生成独立代码，性能好编译慢）。
- **tsc 对照**：字面量类型宽化（`let x = "a"` → string）、控制流收窄（`if (typeof x === 'string')` 块内 x 是 string）——narrowing 是"类型随控制流变化的 数据流分析"，与第七阶段的数据流分析同源。

### 4. 检查器工程化

- **双遍架构**：pass 1 resolve——遍历 AST 建符号表、绑定引用；pass 2 check——类型检查（这时引用已能 O(1) 查到声明）。一遍混合写也可以，但双遍对错误信息与增量编译更友好。
- **诊断对象设计**：`{ code: 'E012', severity, message, start, end, hints?: [{ text, fix? }] }`——错误码稳定（工具可编程依赖）、hint 给修复建议（"是否想用 `let`？"）。
- **LSP 关联**：hover 显示符号类型 = 符号表查询；补全 = 作用域内符号枚举；重命名 = 引用图遍历。checker 是 IDE 智能的地基。

## 与 mini 语言项目的关系

交付 `packages/checker`：`check(program: Program): { ok, diagnostics }`。mini 语言从"能解析"升级到"能拦错"——`"a" + 1`、未声明变量、参数个数不匹配都逃不掉。resolve 产出的"引用 → 声明"边还免费给了第五阶段：闭包捕获列表直接从自由变量算。
