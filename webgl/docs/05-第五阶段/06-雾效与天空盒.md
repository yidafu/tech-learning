## 5.1 雾效：距离雾与高度雾

### 5.1.1 雾的物理：参与介质与外散射

雾不是「贴上去的灰色」，是空气中的水滴/尘埃参与光传播的结果，两种效应：

- **外散射（out-scattering）**：视线方向的光被介质散射走，物体变暗变远——雾「遮住物体」的来源；
- **内散射（in-scattering）**：别处（包括太阳）的光被介质散射**进**视线——雾「本身发亮」、逆光发白的来源。

实时渲染的简化：雾的颜色是常量（或简单的太阳方向函数），只对「外散射」建模——片元颜色与雾色按**雾因子**插值：

$$color_{final} = mix(fogColor,\; color,\; transmittance)$$

透射率（transmittance）T 由光学深度 τ 决定：$T = e^{-\tau}$，这是 Beer-Lambert 定律。**不同雾效的差别只在 τ 怎么算**。

Beer-Lambert 不用背，它就是一条微分方程的解：光走过一小段路径 ds，被介质散射掉的部分正比于路径长度与介质密度 ρ，即 $\frac{dT}{ds} = -\rho\, T$（剩余得越多、被扣得越多）。两边积分得到 $T = e^{-\int \rho\, ds}$，指数上那个积分就是光学深度 τ——**τ = 密度沿视线路径的累积**。后面 5.1.2 与 5.1.3 的全部推导，都是在不同密度假设下算这个积分：

| 密度假设 | τ 的算法 | 得到的雾 |
|---|---|---|
| 均匀介质（ρ 常数） | τ = ρ·d（乘法） | 距离雾（5.1.2） |
| 随高度指数衰减 ρ(y) | 沿视线积分（解析解） | 高度雾（5.1.3） |
| 更真实的介质（噪声、流体） | 数值积分/体积渲染 | 本阶段不涉及 |

内散射在实时管线里的位置：本节的 GLSL 用「雾色朝太阳方向增亮」的 pow 近似代替真实积分，这个雾色参与的是**场景片元的颜色混合**；它不是自发光体，所以天空盒片元、后处理 pass 都不会再叠一次雾（5.3.3 末尾的纪律）。

### 5.1.2 距离雾：三种 τ 与 GLSL

距离雾假设介质密度均匀，τ = d · density（d 是片元到相机距离）：

| 模型 | 透射率公式 | 特征 |
|---|---|---|
| 线性雾（linear） | $T = clamp\big(\frac{fogEnd - d}{fogEnd - fogStart}\big)$ | 有清晰起止距离，老硬件最便宜 |
| 指数雾（exp） | $T = e^{-d \cdot density}$ | 无截止点，自然衰减，最常用 |
| 指数平方雾（exp2） | $T = e^{-(d \cdot density)^2}$ | 近处更干净、远处衰减更陡 |

三者的关系值得多看一眼，它们不是三个无关的选项：

1. **线性雾是指数雾的廉价近似**。把 $e^{-x}$ 在小区间做一阶泰勒展开 $e^{-x} \approx 1 - x$，再把这条切线用 fogStart/fogEnd 两个参数钉住两端——线性雾「有起点有终点」的形态正是这个近似的人为痕迹：真实雾永远渐近于零、没有「雾到此为止」的边界，线性雾在 fogEnd 处硬截断（T=0），物体在边界附近「突然消失」的穿帮来源于此；
2. **指数平方雾是指数雾的「对比增强版」**。指数里多了平方，近处（x < 1）衰减更慢（近景更干净）、远处（x > 1）衰减更快（远景更快吞没）——「山脚清晰、山谷尽头白茫茫」的地形场景常用；
3. 三种公式的参数单位一致：density 的单位是 **1/世界单位**，fogStart/fogEnd 是世界单位——density = 0.045 意味着光每走约 22 个单位衰减到 1/e。参数必须与场景尺度匹配，同一个 0.045 在「米制展厅」里浓得看不见、在「天文单位的太阳系」里等于没有雾（毕业项目两案的尺度差了几个数量级，雾参数不可复用，见 [04-毕业项目-需求书](../06-第六阶段/04-毕业项目-需求书.md)）。

```glsl
// 三种距离雾的 GLSL（接在光照计算之后、色调映射之前）
vec3 applyDistanceFog(vec3 color, float dist, vec3 rayDir, vec3 sunDir) {
  float density = 0.045;                       // 按场景尺度调
  float T = exp(-dist * density);              // 指数雾；线性/平方按上表替换
  // 阳光方向的增强（内散射的廉价近似）：朝着太阳看，雾更亮
  float sunAmount = max(dot(rayDir, sunDir), 0.0);
  vec3 fogColor = mix(vec3(0.5, 0.6, 0.7),     // 常规雾色（天空灰蓝）
                      vec3(1.0, 0.9, 0.7),     // 阳光色
                      pow(sunAmount, 8.0));
  return mix(fogColor, color, T);
}
```

**雾色从哪来**，三档做法按需升级：常量色（最便宜，本例默认）；采样天空盒在地平线方向的颜色（远景与背景自动一致，只需一次 cubemap 采样）；按高度/方向的梯度函数（美术可控性最高）。pow 的指数控制太阳增亮的角度范围——指数越大，「亮斑」越集中在正对太阳的方向。

两个位置纪律：**d 用视空间距离**（`length(viewPos)`，而不是 viewPos.z——斜着看时 z 会骗人）；**雾在光照后、色调映射前的 HDR 线性空间做**（实践任务 P5 里切到 ACES 后雾色过灰，多半是顺序错了）。

### 5.1.3 高度雾：对密度分布积分的推导

真实雾贴地：密度随高度指数衰减 $\rho(y) = \rho_0 \, e^{-b \, y}$（b 是衰减系数，y=0 是雾最浓的基准高度）。此时 τ 不再是简单乘积，要沿视线积分：

$$\tau = \int_0^{d} \rho(y_0 + t \cdot rayDir_y)\, dt = \rho_0 \int_0^{d} e^{-b(y_0 + t\, rayDir_y)}\, dt$$

推导逐步走（自测第 2 题要求能默写）：

1. 把与 t 无关的常数提出来：$\rho_0\, e^{-b\, y_0} \int_0^{d} e^{-b \cdot rayDir_y \cdot t}\, dt$；
2. 令 $c = b \cdot rayDir_y$，剩下的是最基础的指数积分 $\int_0^d e^{-ct} dt = \frac{1 - e^{-cd}}{c}$（c = 0 时取极限得 d）；
3. 代回 c，得到：

$$\tau = \frac{\rho_0 \, e^{-b\, y_0}}{b \cdot rayDir_y}\,\big(1 - e^{-b\, rayDir_y\, d}\big)$$

水平方向（rayDir_y → 0）时分母趋零，用洛必达或直接取极限 $\tau \to \rho_0\, e^{-b y_0} \cdot d$——着色器里加个 epsilon 分支即可。这就是 Inigo Quilez 那版著名高度雾公式的来源，写成 GLSL：

```glsl
// 高度雾：密度指数衰减 + 沿视线积分的解析解
vec3 applyHeightFog(vec3 color, float dist, vec3 rayDir, vec3 sunDir, float camY) {
  float b       = 0.08;    // 高度衰减系数（1/世界单位）
  float rho0    = 0.12;    // 基准高度（y=0）的密度
  float dy      = rayDir.y;                       // 视线方向的竖直分量
  float eps     = 1e-4;
  // τ = rho0 * exp(-b * y0) / (b*dy) * (1 - exp(-b * dy * d))
  float tau = rho0 * exp(-b * camY) / max(b * dy, eps) * (1.0 - exp(-b * dy * dist));
  tau = abs(tau);                                  // dy 为负（向下看）时分子分母同负，取绝对值
  float T = exp(-tau);
  // 阳光内散射（同 5.1.2，高度雾场景逆光感更明显）
  float sunAmount = max(dot(rayDir, sunDir), 0.0);
  vec3 fogColor = mix(vec3(0.5, 0.6, 0.7), vec3(1.0, 0.85, 0.6), pow(sunAmount, 4.0));
  return mix(fogColor, color, T);
}
```

行为验证（自测要能口算）：相机在雾层上方（camY 大）向下看深谷，τ 大、谷底被雾吞掉；平视远处，dy≈0 退化为距离雾。**距离雾描述「多远」，高度雾描述「多低」**，两者可以叠着用（τ 相加）。

两个只属于高度雾的参数语义：**b 的倒数 1/b 是「雾层特征厚度」**——密度衰减到基准值 1/e 的高度差，b = 0.08 意味着每升高约 12.5 个单位雾就薄一层；**camY 必须用相机当前世界高度**（不是 0，也不是场景原点），相机爬升时整片雾「沉」下去——正是山谷航拍镜头里那种行为。

### 5.1.4 参数速查与调参顺序

| 参数 | 属于 | 单位 | 调大时 |
|---|---|---|---|
| density | 指数/指数平方雾 | 1/世界单位 | 整体更浓，远处更快消失 |
| fogStart / fogEnd | 线性雾 | 世界单位 | 起雾更晚/截止更远 |
| ρ0（rho0） | 高度雾 | 1/世界单位 | 雾层整体更浓 |
| b | 高度雾 | 1/世界单位 | 雾层更薄（衰减更快），山谷感更强 |
| 雾色两个端点 | 两者 | 线性 RGB | ——（美术决策） |
| pow 指数 | 太阳内散射 | 无量纲 | 逆光亮斑更集中 |

调参顺序建议（避免在错误参数上空转）：先定**雾色**（对照天空盒地平线，5.3.3 的纪律）——颜色不对，浓度怎么调都「脏」；再定**浓度**（distance 或 ρ0），从明显过浓往回收，直到「最远可见物体刚好半隐」；最后才是高度雾的 b 与艺术性微调。两种雾叠加时 τ 相加后再算一次透射率（$T = e^{-(\tau_{dist} + \tau_{height})}$），不要把两次 mix 串着做——串着 mix 会让雾色被混合两次、近处也蒙一层灰。

### 5.1.5 雾与管线其他环节的交互清单

雾插在「光照之后、色调映射之前」，与前后每个环节都有明确的边界约定，逐个说清（排查「雾怪怪的」时按这张清单过）：

| 环节 | 雾要不要参与 | 原因 |
|---|---|---|
| 深度/阴影 pass | 不参与 | 该 pass 只写深度、不产生颜色（[02-阴影与PCF软阴影](02-阴影与PCF软阴影.md) 1.1.2） |
| 不透明物体的光照 | 之后参与 | 光照算完才得到「被雾衰减前的真色」 |
| 透明物体 | 各自片元先算雾，再走 alpha 混合 | 先混色后算雾会把两个不同距离的片元当成同一深度，玻璃近雾远清的层次感丢失 |
| bloom | 在雾之后 | 逆光雾面的亮部（内散射）是真实光效，应当能溢出辉光 |
| 色调映射 / gamma | 在雾之后 | 雾色是线性 HDR 的参与者，不是最终显示色 |
| 天空盒 | 不算距离雾 | 无限远，按公式必被雾吞没；一致性靠「雾色取天光色」（5.3.3） |

其中「透明物体先雾后混」最常被做错：把雾放在整帧末尾一次性套（比如当后处理 pass），所有透明片元就都按同一个屏幕距离起雾——前一层玻璃与后一层玻璃的雾深浅完全一样，视觉上「雾浮在玻璃表面」而不是「雾在玻璃后面的空气里」。正确位置是在每个透明材质的片元着色器里（与不透明物体同一套 applyFog），这也是雾效必须做成着色器内函数、而不是独立后处理 pass 的根本原因。

## 5.2 cubemap 天空盒

### 5.2.1 cubemap 是什么

立方体贴图（Cubemap）是六张正方形纹理的集合，拼成一个以相机为中心的「盒子内壁」。采样时不用 UV，用**三维方向向量**：GPU 根据向量绝对值最大的分量选定一个面，剩下两个分量除以它得到面内 UV。天空盒（Skybox）把远景环境（天空、群山、星云）画在这个无限大的盒子上。

面选择与 UV 映射的规则是 GL 规范定死的（不是实现自由），以 +X 面为例：主轴为 x，则 s = (−z/|x| + 1)/2、t = (−y/|x| + 1)/2——注意分子上的**负号**：各面的 2D 图像坐标与 3D 方向不是直觉对应，六个面各有约定：

| 主轴（最大分量） | 采样面 | s 分量 | t 分量 |
|---|---|---|---|
| +x | POSITIVE_X | −z / \|x\| | −y / \|x\| |
| −x | NEGATIVE_X | +z / \|x\| | −y / \|x\| |
| +y | POSITIVE_Y | +x / \|y\| | +z / \|y\| |
| −y | NEGATIVE_Y | +x / \|y\| | −z / \|y\| |
| +z | POSITIVE_Z | +x / \|z\| | −y / \|z\| |
| −z | NEGATIVE_Z | −x / \|z\| | −y / \|z\| |

这套符号约定平时被 `samplerCube` 完全藏起来，只在两处会现形：手写「方向 ↔ 面像素」的转换工具时（可视化调试、CPU 侧卷积预览）；以及 5.2.2 生成 cubemap 时配六个捕获相机的 forward/up——那组 (forward, up) 表（见 [08-基于图像的光照](08-基于图像的光照.md) 7.2.2）与本表是同一份约定的两种写法，对不上就会出现常见坑第 3 条的「一面歪一格」。

为什么用六个面而不是一张等距圆柱投影（equirectangular）纹理？等距柱状图在两极过度采样（一行像素被压成一点）、经度方向在接缝处不连续；cubemap 六面采样密度均匀、且 GPU 采样路径有硬件优化。这也是第四阶段 IBL（见 3.4）要求环境图先转成 cubemap 的原因。

### 5.2.2 生成：从 equirect 到 cubemap

HDRI 环境图通常以 equirect（2:1 经纬图）分发，需要转成 cubemap。做法：为六个面各建一个离屏 FBO，跑一个「方向采样」片段着色器，把每个面像素的方向向量转成 equirect 的经纬 UV 去采原图：

```glsl
// equirect_to_cubemap.frag —— 对 cube 的 6 个面各跑一次
#version 300 es
precision highp float;
in vec3 vWorldDir;              // 当前面像素对应的方向（由全屏四边形 + 面变换得到）
out vec4 fragColor;
uniform sampler2D uEquirect;    // 2:1 的 HDR 环境图
const vec2 invAtan = vec2(0.1591, 0.3183);   // 1/(2π), 1/π
void main() {
  vec3 d = normalize(vWorldDir);
  vec2 uv = vec2(atan(d.z, d.x), asin(d.y)); // 方向 → 经纬
  uv = uv * invAtan + 0.5;                   // 经纬 → [0,1]
  fragColor = vec4(texture(uEquirect, uv).rgb, 1.0);
}
```

```javascript
// 六面循环：渲染到 cubemap 的六个附件面（WebGL2）
const faces = [
  [gl.TEXTURE_CUBE_MAP_POSITIVE_X, lookAtMatrixFor(+X)], /* ...共 6 面 */
];
gl.bindTexture(gl.TEXTURE_CUBE_MAP, cubeTex);
for (const [faceTarget, faceView] of faces) {
  gl.framebufferTexture2D(gl.FRAMEBUFFER, gl.COLOR_ATTACHMENT0, faceTarget, cubeTex, 0);
  gl.viewport(0, 0, FACE_SIZE, FACE_SIZE);
  renderFace(faceView); // 画全屏三角形，顶点着色器输出该面的 3D 方向
}
gl.generateMipmap(gl.TEXTURE_CUBE_MAP); // 预过滤 IBL 依赖 mip；仅采样天空盒可不生成
```

工程上四个容易忽略的细节（examples/09-pbr-ibl 的 `ibl.ts` 是这段代码的完整版）：

1. **用 `texStorage2D` 一次性分配不可变存储**（六个面同尺寸同格式），再逐面挂 FBO 渲染——比六次 `texImage2D` 声明了完整的存储意图，驱动能给出更优布局；渲染到 cubemap 面时**深度测试与面剔除都应关掉**（捕获相机在单位立方体中心，开着剔除会把六个面全剔没）；
2. **equirect 原图的 `TEXTURE_WRAP_S` 必须 REPEAT**：经度方向是周期坐标，u=0 与 u=1 是同一条经线，接缝处的双线性插值要能「跨界取样」；配 CLAMP_TO_EDGE 会在接缝处拉出一条细缝（[08-基于图像的光照](08-基于图像的光照.md) 7.7.2 专门讲这类缝）；
3. **`generateMipmap` 的时机在六面全部渲染完之后**——中途生成，后渲的面不在已有 mip 里；而且它只对「需要按粗糙度选级」的预过滤贴图是必需的，纯显示用天空盒可以省（省 1/3 显存）；
4. **从哪拿 equirect**：网络上分发的 HDRI 多为 RGBE 编码的 .hdr 文件，需要一个几十行的 RGBE 解码器转成浮点纹理（[08-基于图像的光照](08-基于图像的光照.md) 7.2.5 有完整实现）；demo 的另一条路是**程序化生成**——全屏三角形跑一个天空着色器直接渲出 equirect，零外部素材，教学与调试最省事。

### 5.2.3 采样与「无缝」

天空盒着色器的关键：**顶点位置本身就是采样方向**。同时把视图矩阵的平移扔掉（天空盒在「无限远」，相机平移不该引起视差）：

```glsl
// skybox.vert
#version 300 es
layout(location = 0) in vec3 aPosition;   // 单位立方体角点，同时是方向
uniform mat4 uProj;
uniform mat4 uView;
out vec3 vDir;
void main() {
  vDir = aPosition;
  // mat4(mat3(uView))：丢弃平移，只留旋转 —— 相机平移对无限远天空无效
  gl_Position = (uProj * mat4(mat3(uView)) * vec4(aPosition, 1.0)).xyww; // 见 5.3 的深度技巧
}
```

```glsl
// skybox.frag
#version 300 es
precision highp float;
in vec3 vDir;
out vec4 fragColor;
uniform samplerCube uSkybox;   // 注意采样器类型是 samplerCube
void main() {
  fragColor = vec4(texture(uSkybox, normalize(vDir)).rgb, 1.0);
}
```

为什么必须 `samplerCube` 而不是自己按 5.2.1 的表选面：规范级无缝采样（下一自然段）与双线性过滤都内建在硬件采样器里，手写选面在面的边界必然产生像素级错位；此外 `texture()` 对 cubemap 会自动处理方向向量未归一化的情况（按主轴分量归一），着色器里的 `normalize` 更多是给后续计算（反射方向）用的。

**接缝问题**分两种：equirect 直接采样时的经度 0/2π 接缝（转成 cubemap 后天然消失，这是 5.2.2 那步转换的红利）；cubemap 面与面的边界——**WebGL2（ES 3.0）规范保证 cubemap 采样是无缝的（seamless filtering）**，边界像素会参考相邻面做双线性插值，前提是六张面的内容在边界处本身连续（同一张 equirect 转出来的必然连续）。WebGL1 时代需要手动 padding 或 `TEXTURE_WRAP_R` 补救，WebGL2 不必。

两个仍然可能出现「缝」的场景要能区分：用了 `textureLod` 手动选 mip 时（mip 链生成不完整，高级 mip 缺失采到黑）；预过滤卷积在面边界采样数不足导致亮度不均（这是采样质量问题不是接缝，[08-基于图像的光照](08-基于图像的光照.md) 7.7 有专述）。

### 5.2.4 程序化天空：零素材的第三条路

天空盒的内容来源不止「下载一张 HDRI」：examples/09-pbr-ibl 的第 0 步是**用一个天空着色器现场渲出 equirect**——全屏三角形覆盖 2:1 经纬视口，片元着色器按方向计算颜色，产出的浮点纹理再走 5.2.2 的转换。它的合成配方是三层，每层都对着一个物理直觉：

1. **天顶到地平线的渐变**：视线仰角 d.y 从 1 到 0，颜色从天顶蓝过渡到地平线亮灰（`pow` 控制过渡曲线的陡度）；d.y < 0 的下半球混向地面色，保证环境图「六面俱全」（俯视的辐照度卷积也要有数据）；
2. **太阳盘**：方向与 `SUN_DIR` 的夹角余弦过一个高次幂（如 1024）得到一个极小的圆盘，乘上**远超 1 的辐亮度系数**（demo 量级 260）——这一步是整条 IBL 链路的「HDR 之源」，太阳不亮，预过滤贴图里就没有可反射的高光；
3. **大气光晕**：低次幂（如 12）的宽波叠一层微光，柔化太阳周边。

程序化路线的取舍：优点是**零外部素材、太阳方向是 uniform**——太阳一挪，天空、直接光照（共用同一个 `SUN_DIR`）、IBL 资产可以整体联动重生成，教学与参数实验极其方便；缺点是观感「干净得像示意图」，缺少云、地形剪影等真实细节。成品项目通常是「程序化打样、HDRI 收尾」：调参阶段用前者，上线前换成实拍环境图，管线一字不改——这正是「环境图只是数据源、天空盒是采样结构」分层的价值。

顺带一个单位提醒：程序化天空输出的也是辐亮度（线性 HDR），不要在生成着色器里做色调映射或 gamma——它是要被卷积、被反射的**数据**，不是给人看的最终画面（「颜色走 gamma，数据走线性」的纪律在环境图上同样成立，见 [04-PBR入门](04-PBR入门.md) 3.3.2）。

## 5.3 天空盒与场景深度的技巧

### 5.3.1 技巧一：xyww 把天空压到深度最远处

`gl_Position = ... .xyww` 把 NDC 的 z 分量直接置为 w/w = 1（深度缓存里的最远值 1.0），配合：

```javascript
// 天空盒绘制顺序与状态
renderOpaqueScene();                      // 1. 先画所有不透明物体（正常写深度）
gl.depthFunc(gl.LEQUAL);                  // 2. 深度测试改成 <=
gl.depthMask(false);                      //    天空不写深度
renderSkybox();                           // 3. 最后画天空盒
gl.depthFunc(gl.LESS);                    // 4. 恢复默认
```

原理：天空盒像素的深度恒为 1.0（最远），深度测试 LEQUAL 只在「该像素前面没有几何体」（深度缓冲还是清屏值 1.0）时通过——**天空被所有不透明几何体自动遮挡，且天空盒被遮挡的片元在片元着色前就被早退（early-z），shader 一次都不用跑**。不这么做的代价：先画天空盒则遮挡它的几何体要先画完一遍天空再覆盖（overdraw 浪费，天空盒是大面积全屏三角形，浪费不小）；关掉深度测试则要靠渲染顺序硬扛，透明物体一多必错。

examples/09-pbr-ibl 的主循环就是这套序列的活样本，且多了一步容易被忘的状态：**画天空盒前 `disable(CULL_FACE)`、画完 `enable` 复原**——捕获/天空的相机在立方体内部，看到的是面的**背面**，绕序与正面相反，开着面剔除会把整片天空剔没。加上这一步，完整的状态清单变成五行：

| 步 | 调用 | 目的 |
|---|---|---|
| 1 | `renderOpaqueScene()` | 不透明物体正常写深度 |
| 2 | `depthFunc(LEQUAL)` | 天空只在没有几何处通过测试 |
| 3 | `depthMask(false)` | 天空不写深度（不挡后续透明物体） |
| 4 | `disable(CULL_FACE)` | 从盒内看绕序是反的 |
| 5 | 画完复原：`depthMask(true)` / `depthFunc(LESS)` / `enable(CULL_FACE)` | 状态不泄漏（第四阶段状态托管的价值场景） |

### 5.3.2 技巧二：视锥剔除的边界情况

天空盒的立方体跟随相机（「无限远」的几何实现是：把立方体中心放在相机位置，尺寸大于远裁剪面）。两个衍生坑：立方体若小于远裁剪面会被裁掉一部分；用 5.3.1 的 xyww 技巧时立方体实际顶点坐标无所谓（z 已被改写），但 x/y 仍要覆盖视锥——偷懒的做法是把立方体尺寸取远裁剪距离的 2 倍以上。

顺带一提：天空盒立方体本体**不应进视锥剔除系统**（它永远可见、永远全屏），场景管理时给它打个「永不剔除」的标记，免得 [12-视锥剔除与场景管理](12-视锥剔除与场景管理.md) 的包围盒测试把它当成普通盒体误伤。

### 5.3.3 环境反射：从天空盒到材质

天空盒不只是背景，它是**场景的环境光源**。最直接的应用是镜面反射（第二阶段能力的延伸）：

```glsl
// 环境反射：视线方向关于法线反射后采 cubemap
vec3 viewDir = normalize(uCamPos - vWorldPos);
vec3 reflectDir = reflect(-viewDir, N);
vec3 envColor = texture(uSkybox, reflectDir).rgb;
// 金属高反射（metallic=1）+ 低粗糙度时，envColor 直接占主导
vec3 color = mix(diffuseLighting, envColor, fresnelAndMetalness);
```

把这段与第四阶段的 IBL 串起来看：`texture(uSkybox, reflectDir)` 是「未滤波的环境采样」，只对完美镜面成立；粗糙表面应该采样**预过滤环境贴图**（按 roughness 选 mip，见 3.4）——普通天空盒纹理与预滤波贴图是同一张环境图的不同处理阶段。天空盒（直接显示）、环境反射（一次采样）、IBL（离线卷积）是同一份 cubemap 数据的三层用法，这是「雾效与天空盒」条目挂在大纲 PBR 条目之后的原因。

| 用法 | 输入 | 处理 | 每像素成本 | 适合表面 |
|---|---|---|---|---|
| 天空盒显示 | 方向 | 无（一次采样） | 1 次采样 | 背景 |
| 环境反射 | 反射向量 R | 无 | 1 次采样 | 完美镜面（roughness≈0） |
| IBL | N 与 R | 离线卷积出辐照度/预过滤/LUT | 3 次采样 | 任意粗糙度（[04-PBR入门](04-PBR入门.md) 3.4） |

雾与天空盒的配合收尾：天空盒片元**不做距离雾**（它在无限远，全都会被雾吞掉），但雾色应与天空盒地平线颜色接近，否则远处物体淡出时与背景脱节——美术上的「雾色取天光色」就是这条工程纪律。

## 5.4 性能账单与 P5 验收

成本先记账（都是每像素量级，但数量级差得远）：

- **距离雾**：一次 `length`、一次 `exp`、若干乘加——个位数 ALU 指令，在全屏 pass 里通常测不出差异；
- **高度雾**：多两三次 `exp` 与除法，仍属「便宜」；
- **天空盒**：每像素一次 cubemap 采样（被遮挡的片元因 early-z 零成本，5.3.1）——真正要警惕的是它的**带宽**：RGBA16F 的大尺寸 cubemap 在移动端是显存与带宽双重大头；
- **量化方法**：分 pass 埋点对比开/关雾的两帧（[07-性能优化与调试](07-性能优化与调试.md) 6.5.2 的 FrameStats，或 [10-GPU性能度量与剖析](10-GPU性能度量与剖析.md) 的分段 GPU 计时）。

对照 [01-导览](01-导览.md) 的 P5 验收标准逐条落盒：

- [ ] 距离雾与高度雾可切换，切换后近景/远景行为差异符合 5.1.2/5.1.3 的预期（高度雾「低处浓」、距离雾「远处浓」）；
- [ ] 两种雾的透射率曲线可视化过一次（把 T 直接当灰度输出调试），确认无水平亮线（dy 除零）、无边缘深浅不均（用了 viewPos.z）；
- [ ] 天空盒在场景任意位置观察无接缝（原地旋转一圈 + 移动中观察面边界）；
- [ ] 相机移动时天空盒「无限远」（对照物：远处山与天空无相对位移，视差为零——`mat4(mat3(uView))` 生效的判据）；
- [ ] 天空被前景物体正确遮挡，且遮挡处无天空盒片元的着色开销（Spector 抓帧看 skybox draw 的片元数，见 [07-性能优化与调试](07-性能优化与调试.md) 6.5.1）；
- [ ] 雾色与天空盒地平线颜色一致性肉眼可过（截图对比）。

## 常见坑

1. **忘了丢掉视图矩阵平移**——`uView` 直接乘，相机移动时天空盒跟着走且产生视差，「无限远」穿帮。必须 `mat4(mat3(uView))`。
2. **`samplerCube` 与 `sampler2D` 混用**——cubemap 绑定到 sampler2D 的纹理单元（或反之），采样返回黑或垃圾。纹理类型、采样器类型、绑定目标三者必须一致（`gl.TEXTURE_CUBE_MAP`）。
3. **六面生成时没统一面变换**——某一面 lookAt 的 up 或 target 写错，转换出的 cubemap 一面内容错位/镜像，采样时天空「歪一格」。调试技巧：先把六面直接可视化贴出来对比。
4. **深度技巧忘了改回 depthFunc**——LEQUAL 状态泄漏到下一帧的不透明 pass，z-fighting 概率上升。状态用完必须复原（第四阶段状态托管的价值场景）。
5. **雾用 viewPos.z 而不是 length(viewPos)**——屏幕边缘的物体距离被低估，四周雾明显比中心浅。
6. **雾放在色调映射之后**——雾色被 gamma 二次扭曲，颜色发闷；正确顺序是光照 → 雾 → bloom → 色调映射。
7. **高度雾 dy 的 epsilon 分支丢了**——水平视线（dy≈0）除零，画面出现一条水平亮线或黑线。
8. **画天空盒忘了关面剔除**——相机在盒内看到的全是背面，开着 CULL_FACE 整片天空消失，且控制台无任何报错（examples/09-pbr-ibl 的主循环里这一步带注释提醒）。
9. **equirect 源图配了 CLAMP_TO_EDGE**——经度接缝处双线性无法跨界取样，转出的 cubemap 在对应经线上留一条细缝；经度方向必须 REPEAT（5.2.2 细节 2）。
10. **雾参数跨场景复制**——density/b 的单位是 1/世界单位，从米制 demo 抄到尺度大几个数量级的场景里，雾要么浓成实心要么完全不存在；换场景先换算尺度再调参。
