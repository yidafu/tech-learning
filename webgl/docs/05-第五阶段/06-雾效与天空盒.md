## 5.1 雾效：距离雾与高度雾

### 5.1.1 雾的物理：参与介质与外散射

雾不是「贴上去的灰色」，是空气中的水滴/尘埃参与光传播的结果，两种效应：

- **外散射（out-scattering）**：视线方向的光被介质散射走，物体变暗变远——雾「遮住物体」的来源；
- **内散射（in-scattering）**：别处（包括太阳）的光被介质散射**进**视线——雾「本身发亮」、逆光发白的来源。

实时渲染的简化：雾的颜色是常量（或简单的太阳方向函数），只对「外散射」建模——片元颜色与雾色按**雾因子**插值：

$$color_{final} = mix(fogColor,\; color,\; transmittance)$$

透射率（transmittance）T 由光学深度 τ 决定：$T = e^{-\tau}$，这是 Beer-Lambert 定律。**不同雾效的差别只在 τ 怎么算**。

### 5.1.2 距离雾：三种 τ 与 GLSL

距离雾假设介质密度均匀，τ = d · density（d 是片元到相机距离）：

| 模型 | 透射率公式 | 特征 |
|---|---|---|
| 线性雾（linear） | $T = clamp\big(\frac{fogEnd - d}{fogEnd - fogStart}\big)$ | 有清晰起止距离，老硬件最便宜 |
| 指数雾（exp） | $T = e^{-d \cdot density}$ | 无截止点，自然衰减，最常用 |
| 指数平方雾（exp2） | $T = e^{-(d \cdot density)^2}$ | 近处更干净、远处衰减更陡 |

```glsl
// 三种距离雾的 GLSL（接在光照计算之后、色调映射之前）
vec3 applyDistanceFog(vec3 color, float dist, vec3 rayDir, vec3 sunDir) {
  float density = 0.045;                       // 按场景尺度调
  float T = exp(-dist * density);              // 指数雾；线性/平方按上表替换
  // 阳光方向的增强（内散射的廉价近似）：朝着太阳看，雾更亮
  float sunAmount = max(dot(rayDir, sunDir), 0.0);
  vec3 fogColor = mix(vec3(0.5, 0.6, 0.7),     // 常规雾色（天空灰蓝）
                      vec3(1.0, 0.9, 0.7),     // 阳光色
                      pow(sunAmount, 8.0));
  return mix(fogColor, color, T);
}
```

两个位置纪律：**d 用视空间距离**（`length(viewPos)`，而不是 viewPos.z——斜着看时 z 会骗人）；**雾在光照后、色调映射前的 HDR 线性空间做**（实践任务 P5 里切到 ACES 后雾色过灰，多半是顺序错了）。

### 5.1.3 高度雾：对密度分布积分的推导

真实雾贴地：密度随高度指数衰减 $\rho(y) = \rho_0 \, e^{-b \, y}$（b 是衰减系数，y=0 是雾最浓的基准高度）。此时 τ 不再是简单乘积，要沿视线积分：

$$\tau = \int_0^{d} \rho(y_0 + t \cdot rayDir_y)\, dt = \rho_0 \int_0^{d} e^{-b(y_0 + t\, rayDir_y)}\, dt$$

把与 t 无关的项提出来，令 $u = b \cdot rayDir_y \cdot t$ 换元，积分结果是初等函数：

$$\tau = \frac{\rho_0 \, e^{-b\, y_0}}{b \cdot rayDir_y}\,\big(1 - e^{-b\, rayDir_y\, d}\big)$$

水平方向（rayDir_y → 0）时分母趋零，用洛必达或直接取极限 $\tau \to \rho_0\, e^{-b y_0} \cdot d$——着色器里加个 epsilon 分支即可。这就是 Inigo Quilez 那版著名高度雾公式的来源，写成 GLSL：

```glsl
// 高度雾：密度指数衰减 + 沿视线积分的解析解
vec3 applyHeightFog(vec3 color, float dist, vec3 rayDir, vec3 sunDir, float camY) {
  float b       = 0.08;    // 高度衰减系数（1/世界单位）
  float rho0    = 0.12;    // 基准高度（y=0）的密度
  float dy      = rayDir.y;                       // 视线方向的竖直分量
  float eps     = 1e-4;
  // τ = rho0 * exp(-b * y0) / (b*dy) * (1 - exp(-b * dy * d))
  float tau = rho0 * exp(-b * camY) / max(b * dy, eps) * (1.0 - exp(-b * dy * dist));
  tau = abs(tau);                                  // dy 为负（向下看）时分子分母同负，取绝对值
  float T = exp(-tau);
  // 阳光内散射（同 5.1.2，高度雾场景逆光感更明显）
  float sunAmount = max(dot(rayDir, sunDir), 0.0);
  vec3 fogColor = mix(vec3(0.5, 0.6, 0.7), vec3(1.0, 0.85, 0.6), pow(sunAmount, 4.0));
  return mix(fogColor, color, T);
}
```

行为验证（自测要能口算）：相机在雾层上方（camY 大）向下看深谷，τ 大、谷底被雾吞掉；平视远处，dy≈0 退化为距离雾。**距离雾描述「多远」，高度雾描述「多低」**，两者可以叠着用（τ 相加）。

## 5.2 cubemap 天空盒

### 5.2.1 cubemap 是什么

立方体贴图（Cubemap）是六张正方形纹理的集合，拼成一个以相机为中心的「盒子内壁」。采样时不用 UV，用**三维方向向量**：GPU 根据向量绝对值最大的分量选定一个面，剩下两个分量除以它得到面内 UV。天空盒（Skybox）把远景环境（天空、群山、星云）画在这个无限大的盒子上。

为什么用六个面而不是一张等距圆柱投影（equirectangular）纹理？等距柱状图在两极过度采样（一行像素被压成一点）、经度方向在接缝处不连续；cubemap 六面采样密度均匀、且 GPU 采样路径有硬件优化。这也是第四阶段 IBL（见 3.4）要求环境图先转成 cubemap 的原因。

### 5.2.2 生成：从 equirect 到 cubemap

HDRI 环境图通常以 equirect（2:1 经纬图）分发，需要转成 cubemap。做法：为六个面各建一个离屏 FBO，跑一个「方向采样」片段着色器，把每个面像素的方向向量转成 equirect 的经纬 UV 去采原图：

```glsl
// equirect_to_cubemap.frag —— 对 cube 的 6 个面各跑一次
#version 300 es
precision highp float;
in vec3 vWorldDir;              // 当前面像素对应的方向（由全屏四边形 + 面变换得到）
out vec4 fragColor;
uniform sampler2D uEquirect;    // 2:1 的 HDR 环境图
const vec2 invAtan = vec2(0.1591, 0.3183);   // 1/(2π), 1/π
void main() {
  vec3 d = normalize(vWorldDir);
  vec2 uv = vec2(atan(d.z, d.x), asin(d.y)); // 方向 → 经纬
  uv = uv * invAtan + 0.5;                   // 经纬 → [0,1]
  fragColor = vec4(texture(uEquirect, uv).rgb, 1.0);
}
```

```javascript
// 六面循环：渲染到 cubemap 的六个附件面（WebGL2）
const faces = [
  [gl.TEXTURE_CUBE_MAP_POSITIVE_X, lookAtMatrixFor(+X)], /* ...共 6 面 */
];
gl.bindTexture(gl.TEXTURE_CUBE_MAP, cubeTex);
for (const [faceTarget, faceView] of faces) {
  gl.framebufferTexture2D(gl.FRAMEBUFFER, gl.COLOR_ATTACHMENT0, faceTarget, cubeTex, 0);
  gl.viewport(0, 0, FACE_SIZE, FACE_SIZE);
  renderFace(faceView); // 画全屏三角形，顶点着色器输出该面的 3D 方向
}
gl.generateMipmap(gl.TEXTURE_CUBE_MAP); // 预过滤 IBL 依赖 mip；仅采样天空盒可不生成
```

### 5.2.3 采样与「无缝」

天空盒着色器的关键：**顶点位置本身就是采样方向**。同时把视图矩阵的平移扔掉（天空盒在「无限远」，相机平移不该引起视差）：

```glsl
// skybox.vert
#version 300 es
layout(location = 0) in vec3 aPosition;   // 单位立方体角点，同时是方向
uniform mat4 uProj;
uniform mat4 uView;
out vec3 vDir;
void main() {
  vDir = aPosition;
  // mat4(mat3(uView))：丢弃平移，只留旋转 —— 相机平移对无限远天空无效
  gl_Position = (uProj * mat4(mat3(uView)) * vec4(aPosition, 1.0)).xyww; // 见 5.3 的深度技巧
}
```

```glsl
// skybox.frag
#version 300 es
precision highp float;
in vec3 vDir;
out vec4 fragColor;
uniform samplerCube uSkybox;   // 注意采样器类型是 samplerCube
void main() {
  fragColor = vec4(texture(uSkybox, normalize(vDir)).rgb, 1.0);
}
```

**接缝问题**分两种：equirect 直接采样时的经度 0/2π 接缝（转成 cubemap 后天然消失，这是 5.2.2 那步转换的红利）；cubemap 面与面的边界——**WebGL2（ES 3.0）规范保证 cubemap 采样是无缝的（seamless filtering）**，边界像素会参考相邻面做双线性插值，前提是六张面的内容在边界处本身连续（同一张 equirect 转出来的必然连续）。WebGL1 时代需要手动 padding 或 `TEXTURE_WRAP_R` 补救，WebGL2 不必。

## 5.3 天空盒与场景深度的技巧

### 5.3.1 技巧一：xyww 把天空压到深度最远处

`gl_Position = ... .xyww` 把 NDC 的 z 分量直接置为 w/w = 1（深度缓存里的最远值 1.0），配合：

```javascript
// 天空盒绘制顺序与状态
renderOpaqueScene();                      // 1. 先画所有不透明物体（正常写深度）
gl.depthFunc(gl.LEQUAL);                  // 2. 深度测试改成 <=
gl.depthMask(false);                      //    天空不写深度
renderSkybox();                           // 3. 最后画天空盒
gl.depthFunc(gl.LESS);                    // 4. 恢复默认
```

原理：天空盒像素的深度恒为 1.0（最远），深度测试 LEQUAL 只在「该像素前面没有几何体」（深度缓冲还是清屏值 1.0）时通过——**天空被所有不透明几何体自动遮挡，且天空盒被遮挡的片元在片元着色前就被早退（early-z），shader 一次都不用跑**。不这么做的代价：先画天空盒则遮挡它的几何体要先画完一遍天空再覆盖（overdraw 浪费，天空盒是大面积全屏三角形，浪费不小）；关掉深度测试则要靠渲染顺序硬扛，透明物体一多必错。

### 5.3.2 技巧二：视锥剔除的边界情况

天空盒的立方体跟随相机（「无限远」的几何实现是：把立方体中心放在相机位置，尺寸大于远裁剪面）。两个衍生坑：立方体若小于远裁剪面会被裁掉一部分；用 5.3.1 的 xyww 技巧时立方体实际顶点坐标无所谓（z 已被改写），但 x/y 仍要覆盖视锥——偷懒的做法是把立方体尺寸取远裁剪距离的 2 倍以上。

### 5.3.3 环境反射：从天空盒到材质

天空盒不只是背景，它是**场景的环境光源**。最直接的应用是镜面反射（第二阶段能力的延伸）：

```glsl
// 环境反射：视线方向关于法线反射后采 cubemap
vec3 viewDir = normalize(uCamPos - vWorldPos);
vec3 reflectDir = reflect(-viewDir, N);
vec3 envColor = texture(uSkybox, reflectDir).rgb;
// 金属高反射（metallic=1）+ 低粗糙度时，envColor 直接占主导
vec3 color = mix(diffuseLighting, envColor, fresnelAndMetalness);
```

把这段与第四阶段的 IBL 串起来看：`texture(uSkybox, reflectDir)` 是「未滤波的环境采样」，只对完美镜面成立；粗糙表面应该采样**预过滤环境贴图**（按 roughness 选 mip，见 3.4）——普通天空盒纹理与预滤波贴图是同一张环境图的不同处理阶段。天空盒（直接显示）、环境反射（一次采样）、IBL（离线卷积）是同一份 cubemap 数据的三层用法，这是「雾效与天空盒」条目挂在大纲 PBR 条目之后的原因。

雾与天空盒的配合收尾：天空盒片元**不做距离雾**（它在无限远，全都会被雾吞掉），但雾色应与天空盒地平线颜色接近，否则远处物体淡出时与背景脱节——美术上的「雾色取天光色」就是这条工程纪律。

## 常见坑

1. **忘了丢掉视图矩阵平移**——`uView` 直接乘，相机移动时天空盒跟着走且产生视差，「无限远」穿帮。必须 `mat4(mat3(uView))`。
2. **`samplerCube` 与 `sampler2D` 混用**——cubemap 绑定到 sampler2D 的纹理单元（或反之），采样返回黑或垃圾。纹理类型、采样器类型、绑定目标三者必须一致（`gl.TEXTURE_CUBE_MAP`）。
3. **六面生成时没统一面变换**——某一面 lookAt 的 up 或 target 写错，转换出的 cubemap 一面内容错位/镜像，采样时天空「歪一格」。调试技巧：先把六面直接可视化贴出来对比。
4. **深度技巧忘了改回 depthFunc**——LEQUAL 状态泄漏到下一帧的不透明 pass，z-fighting 概率上升。状态用完必须复原（第四阶段状态托管的价值场景）。
5. **雾用 viewPos.z 而不是 length(viewPos)**——屏幕边缘的物体距离被低估，四周雾明显比中心浅。
6. **雾放在色调映射之后**——雾色被 gamma 二次扭曲，颜色发闷；正确顺序是光照 → 雾 → bloom → 色调映射。
7. **高度雾 dy 的 epsilon 分支丢了**——水平视线（dy≈0）除零，画面出现一条水平亮线或黑线。
