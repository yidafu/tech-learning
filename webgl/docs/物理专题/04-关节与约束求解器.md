## 4.1 约束是什么：C(x) = 0 的建模思想

### 概念：把"关系"写成方程

物理引擎对世界的全部状态是一个大向量 x（所有物体的位置，N 个质点共 3N 个数）。**约束就是加在 x 上的一个等式**：

$$C(x) = 0$$

满足所有约束方程的状态构成一个低维曲面（**约束流形**，constraint manifold）——模拟的每一步都要把系统"按"回这个曲面。游戏物理里的关节全是这类方程：

| 关系 | 约束方程 | 玩法例子 |
|---|---|---|
| 定距（杆/绳） | C = \|p₂ − p₁\| − L = 0 | 摆锤、链条、提灯 |
| 共点（球窝） | C = p₂ − p₁ = 0（3 行） | 布娃娃肩、项链结 |
| 共线（铰链/滑轨） | 若干点积方程 = 0 | 门、抽屉、电梯 |
| 速度关系（马达） | Ċ 要求 = v_target | 传送带、绞盘 |
| 接触（02） | C = 穿透 ≥ 0（**不等式**） | 地面、墙 |

最后一行点破延续性：**不等式约束（inequality constraint）C ≥ 0** 只在违反方向上生效——绳只在拉长时绷紧、接触只在穿透时推开、4.7 的锥角只在越界时拉回。02 的非穿透接触就是不等式约束的一种；本篇主线是等式约束（equality constraint），不等式在绳与马达处出场。

### 推导：距离约束完整展开

以最经典的距离约束为例，把符号一次立全：两质点 p₁ = (x₁, y₁, z₁)、p₂ = (x₂, y₂, z₂)，静止长度 L：

```text
C(p₁, p₂) = |p₂ − p₁| − L
           = √((x₂−x₁)² + (y₂−y₁)² + (z₂−z₁)²) − L = 0
```

**手算**：L = 2 时——

```text
p₁ = (0,0,0)、p₂ = (3,0,0)：C = 3 − 2 = +1    被拉长 1 m（绳会绷紧，杆要修）
p₁ = (0,0,0)、p₂ = (1,0,0)：C = 1 − 2 = −1    被压短（只有杆在乎）
p₂ = (2,0,0)：C = 0，恰好满足无需动作
```

刚性杆两个方向都要解（等式）；绳只解 C > 0（不等式）——同一方程，求解时机不同，4.4 实现。

### 概念：位置层面 vs 速度层面——两种求解哲学

发现 C ≠ 0 之后怎么修？这里有整条分岔路口，01 与本篇各走一边：

| | 位置法（01 §1.3 PBD） | 速度法（本篇主线） |
|---|---|---|
| 直接修改对象 | 位置：把点**挪回**流形 | 速度：施加冲量让 J·v = 0，位置靠下一轮积分跟上 |
| 位置误差 | 一步消掉（投影） | 由偏置速度 bias 渐进消除（4.3） |
| 刚度 | 由迭代次数决定（有效刚度 1−(1−k)ᴺ），还随 dt 变 | 显式物理参数（erp 或频率 ω，单位是 rad/s） |
| 动量 | 不严格守恒（位置直接搬） | 冲量等大反向，严格守恒 |
| 每步成本 | 每遍一次开方 | prepare 一次开方 + 每遍十几次乘加 |
| 主场 | 布料、绳网（海量弱约束） | 关节、机构（少量强约束） |

一句话总结取舍：**PBD 用简单换刚度可控性——"多迭代就更硬"，但"硬多少"没有物理单位；速度法把刚度写成频率（"这个关节以 5 Hz 振动、阻尼比 0.9"），可调、可复现，代价是要推一点微积分**。两者不互斥：布娃娃常用"速度法骨架 + 位置法限制"（4.7 正是这么干的），布料-刚体耦合更是两边各管一段。

## 4.2 雅可比：约束的速度方程 J·v = 0

### 概念：对时间求导，位置方程变速度方程

位置约束 C(x) = 0 对时间求导（链式法则），得到**速度约束**：

$$\dot C = \frac{\partial C}{\partial x}\cdot \dot x = J\cdot v = 0$$

J 是 **雅可比矩阵（Jacobian matrix）**——C 对每个位置分量的偏导排成的一行向量。它把约束翻译成"速度的线性组合必须为零"：杆不能伸长 → 沿杆方向的速度差为零；门把手走圆弧 → 垂直圆弧平面的速度为零。**求解器全部工作在速度层面，J 是唯一的翻译官。**

好消息是：游戏物理的 J 从不需要"会算任意函数"——每个关节的 J 都是手推一次写死的几行代码。下面把距离约束的 J 完整推一遍。

### 推导：手推距离约束的 J

记 d = p₂ − p₁ = (dx, dy, dz)，C = |d| − L。先求 |d| 对 d 的偏导：

```text
|d| = √(dx² + dy² + dz²)
∂|d|/∂dx = dx/√(dx²+dy²+dz²)    （dy、dz 同理）
→ ∂|d|/∂d = d/|d| =: n          （沿连线方向的单位向量）
```

再求 d 对 p₁、p₂ 的偏导（d = p₂ − p₁ 逐分量）：∂d/∂p₁ = −I、∂d/∂p₂ = +I。链式法则串联：

```text
∂C/∂p₁ = ∂|d|/∂d · ∂d/∂p₁ = n·(−1) = −n
∂C/∂p₂ = n·(+1)               = +n
J = [∂C/∂p₁  ∂C/∂p₂] = [ −nᵀ   nᵀ ]     （1×6 一行）
```

于是速度方程：J·v = n·(v₂ − v₁) = 0——**沿杆方向相对速度为零**（杆不伸缩），垂直杆方向的分量不受限（两端仍可绕着转）。这就是"约束掉一个自由度"的解析含义。

### 概念：有效质量 m* = 1/(J·M⁻¹·Jᵀ)

施加约束冲量只能沿 Jᵀ 方向（约束力不做份外功，这也等于高斯最小约束原理的结论）。设冲量 P = λ·Jᵀ，λ 是**拉格朗日乘子（Lagrange multiplier）**——一个标量"约束力强度"。速度变化 Δv = M⁻¹·Jᵀλ，把它代回速度方程，λ 前面的系数就是：

$$J M^{-1} J^{T} = \frac{1}{m^*}\quad\Rightarrow\quad m^* = \frac{1}{J M^{-1} J^{T}}$$

m* 叫**有效质量（effective mass）**：**沿约束方向推这对物体，等效于推动一个质量为 m* 的单体质点**——冲量除以有效质量就是约束违反速度的变化量（与 02 §2.3"冲量除以 invMass 之和"是同一视角）。质点的质量是标量，距离约束代入：

```text
J·M⁻¹·Jᵀ = |n|²·invMass₁ + |n|²·invMass₂ = w₁ + w₂        （n 是单位向量）
m* = 1/(w₁ + w₂) = m₁m₂/(m₁ + m₂)                          ——即两体动力学里的约化质量
```

静态端 w = 0 时 m* = m_另一端；两端等重时 m* = m/2。**与 02 的呼应**：把接触也看成约束（J = [−n, n]，n 为接触法线），J·M⁻¹·Jᵀ = invMass_A + invMass_B——02 §2.3 的冲量分母就是这个式子，法向冲量公式 j_n = −(1+e)·v_n/(invMass_A + invMass_B) 正是 4.3 将要推的 λ 公式带上目标速度的版本。**02 已经写过一个单约束求解器，本篇把它一般化。**

### 数值手算：J、m*、一次完整求解

m₁ = 1（w₁ = 1）、m₂ = 3（w₂ = 1/3），L = 2，当前 p₁ = (0,0,0)、p₂ = (2.5,0,0)，v₁ = (0,0,0)、v₂ = (1,0,0)（正在分离）。暂不管位置误差，只解速度违反：

```text
n = (2.5,0,0)/2.5 = (1,0,0)
J·v = n·(v₂ − v₁) = 1                    正以 1 m/s 沿杆分离 → 违反
m* = 1/(1 + 1/3) = 0.75
λ = −m*·(J·v) = −0.75
冲量 λ·Jᵀ 分配：Δv₁ = λ·(−n)·w₁ = +0.75 → v₁′ = (0.75, 0, 0)
              Δv₂ = λ·(+n)·w₂ = −0.25 → v₂′ = (0.75, 0, 0)
验证：J·v′ = 0.75 − 0.75 = 0 ✓
动量：前 1×0 + 3×1 = 3；后 1×0.75 + 3×0.75 = 3 ✓（冲量内力不改变总动量）
```

注意结果：杆刚性"粘连"了两球，碰后同速——这正是杆（等式约束）与弹性碰撞（e > 0 的不等式接触）的行为差异。

## 4.3 拉格朗日乘子法：λ = −m*·(J·v + bias)

### 推导：一步到位的乘子公式

联立三件事：① 冲量沿 Jᵀ：Δv = M⁻¹·Jᵀλ；② 目标速度方程 J·v′ = 0；③ v′ = v + Δv。代入：

```text
J·(v + M⁻¹Jᵀλ) = 0
J·v + (J M⁻¹ Jᵀ)·λ = 0
λ = −(J M⁻¹ Jᵀ)⁻¹ · (J·v) = −m*·(J·v)          ← 4.2 手算用的就是它
```

但 4.2 手算只保住了"速度不再违反"，位置误差 C 还躺在那里——只解速度，位置会**漂移（drift）**：每步积分引入的小误差无人清理，摆锤的绳会慢慢变长（常见坑 1）。修法：给速度方程加一个**偏置速度 bias**，要求解完后 J·v′ = −bias，即两端以 bias 的速度相互靠近，下一步积分顺手消掉一部分 C：

$$\lambda = -m^*\cdot\left(J v + \underbrace{\frac{\beta}{h}\,C}_{bias}\right)$$

这就是**鲍姆加特稳定化（Baumgarte stabilization）**——02 §2.3 已经用它修穿透，那里的 bias = (β/dt)·max(depth − slop, 0) 与上式逐字对应（穿透就是 C < 0 的接触约束）。β ∈ (0.1, 0.3) 是"每步消掉的位置误差比例"：β = 0.2 表示每步修 20%，约 5 步修完。β 过大同样会**凭空注入能量**（02 的教训原样适用）。

### 概念：软约束——erp/cfm 与频率/阻尼参数化

Baumgarte 的 β 是经验值。更工程化的参数化来自"约束等效于弹簧阻尼"：给约束指定**固有频率 ω（rad/s）**与**阻尼比 ζ**，可以同时推出偏置强度与"软度"：

```text
λ = −(J·v + bias) / (wSum + γ)          （wSum = J M⁻¹ Jᵀ，γ 为软度项）

bias = C · ω / (2ζ + hω)                 （等价 Baumgarte：erp = hω/(2ζ + hω)）
γ    = 1 / (m* · h · ω · (2ζ + hω))      （cfm：约束力混合项，加在分母让冲量变小）
```

直觉三条：**ω 调"硬"**——ω→∞ 时 bias→C/h（一步全修）、γ→0（刚性极限）；**ζ 调"闷"**——ζ 大则修得慢、冲量小；**γ > 0 让约束允许被拉伸**——分母变大、λ 变小，多余违反留下不修，这正是"软"的本体。这就是速度法"刚度可调"的来源：参数是物理单位（Hz、阻尼比），不随迭代次数漂移——PBD 做不到这一点。经验值：布娃娃关节 ω = 2π×(4~10) rad/s、ζ = 0.8~1.2；近刚性杆直接 Baumgarte β = 0.1~0.3、γ ≈ 0。γ 还兼职数值润滑油：分母永不为零，wSum 极小时（两端都近乎静态）不会除零爆炸。

**手算（软 vs 硬，同一组数据）**：沿用 4.2 的场景（C = +0.5、J·v = 1、m* = 0.75），h = 1/60：

```text
硬杆（β = 0.2、γ = 0）：bias = 0.2×60×0.5 = 6
  λ = −(1 + 6)/(4/3) = −5.25 → v₁′ = 5.25、v₂′ = −0.75
  验证 J·v′ = −0.75 − 5.25 = −6 = −bias ✓（精确到达目标靠近速度）

软杆（f = 5 Hz → ω ≈ 31.4、ζ = 1）：
  erp = hω/(2ζ+hω) = 0.524/2.524 ≈ 0.21 → bias ≈ 0.21×60×0.5 ≈ 6.2
  γ = 1/(0.75×0.524×2.524) ≈ 1.0 → 分母 4/3 + 1.0 ≈ 2.33
  λ = −(1 + 6.2)/2.33 ≈ −3.1 → v₁′ ≈ 3.1、v₂′ ≈ −0.03
  J·v′ = 1 − 3.1×(4/3) ≈ −3.1 ≠ −6.2：只到达一半目标——差的那截就是"软"允许的余量
```

### 一步算法伪码

```text
每个固定步 h：
  ① 积分：半隐式欧拉（01 §1.2），重力等外力先行
  ② prepare（每约束一次）：算方向 n（J 的块）、wSum（J·M⁻¹·Jᵀ）、C；bias = (β/h)·C（本步常量）
  ③ 迭代 k 遍（为什么迭代见 4.5），每遍顺序对每个约束：
       jv = J·v                        # 用【最新】速度测违反
       λ  = −(jv + bias) / (wSum + γ)
       v ← v + λ·M⁻¹·Jᵀ               # 冲量分给两端，动量守恒
```

### 完整代码：约束基类与距离关节（含 bias）

```typescript
// physics/constraints/Constraint.ts —— 最小物理体（01 §1.4 RigidBody 的最小子集）与关节基类
export interface JointBody {
  x: number; y: number; z: number;       // 位置
  vx: number; vy: number; vz: number;    // 速度
  invMass: number;                       // 逆质量（静态锚点为 0；永远用它，01 的约定）
}

/** 关节基类：prepare（每步一次）+ solve（每迭代一次）两阶段 */
export abstract class Constraint {
  err = 0;               // 最近一次 solve 的 |J·v + bias|（残差诊断，4.5）
  erp = 0.2;             // 每步修正位置误差的比例（Baumgarte β）
  cfm = 0;               // 软度 γ：>0 时约束允许被拉伸（软约束）

  constructor(readonly a: JointBody, readonly b: JointBody) {}

  abstract prepare(h: number): void;  // 每步一次：J 方向、wSum、bias（本步内视为常量）
  abstract solve(): void;             // 每迭代一次：测 J·v → 求 λ → 施冲量（读最新速度）
}
```

```typescript
// physics/constraints/DistanceJoint.ts —— 刚性杆（rod）与绳（rope）
export class DistanceJoint extends Constraint {
  private nx = 0; private ny = 0; private nz = 0;   // n = (p₂−p₁)/|p₂−p₁|：J 的两块
  private wSum = 0;                                 // J·M⁻¹·Jᵀ = w₁ + w₂
  private bias = 0;
  private active = true;

  // rest：静止长度 L；rope：true 只拉不推（不等式），false 刚性杆（等式）
  constructor(a: JointBody, b: JointBody, readonly rest: number, readonly rope = false) {
    super(a, b);
  }

  prepare(h: number): void {
    const dx = this.b.x - this.a.x, dy = this.b.y - this.a.y, dz = this.b.z - this.a.z;
    const dist = Math.sqrt(dx * dx + dy * dy + dz * dz);
    this.wSum = this.a.invMass + this.b.invMass;
    if (dist < 1e-9 || this.wSum === 0) { this.active = false; return; } // NaN 防御（01 坑 2）
    const C = dist - this.rest;                              // > 0 被拉长
    this.active = this.rope ? C > 0 : true;                  // 绳松弛时休眠
    this.nx = dx / dist; this.ny = dy / dist; this.nz = dz / dist;
    this.bias = (this.erp / h) * C;                          // Baumgarte 偏置速度
  }

  solve(): void {
    if (!this.active) return;
    const jv = this.nx * (this.b.vx - this.a.vx)
             + this.ny * (this.b.vy - this.a.vy)
             + this.nz * (this.b.vz - this.a.vz);            // J·v：沿杆分离速度
    this.err = Math.abs(jv + this.bias);
    const lambda = -(jv + this.bias) / (this.wSum + this.cfm);
    // 冲量 λ·Jᵀ 分配：a 得 −λn·wa，b 得 +λn·wb（等大反向，动量守恒）
    const ja = lambda * this.a.invMass, jb = lambda * this.b.invMass;
    this.a.vx -= this.nx * ja; this.a.vy -= this.ny * ja; this.a.vz -= this.nz * ja;
    this.b.vx += this.nx * jb; this.b.vy += this.ny * jb; this.b.vz += this.nz * jb;
  }
}
```

对照 4.3 手算逐行可查：jv 即 J·v，lambda 即 λ，`(this.wSum + this.cfm)` 即分母 1/m* + γ。绳（rope）只加了三行——不等式约束的最小干预。

## 4.4 常用关节库：五种关节，一套框架

本节的实现策略：**复杂关节 = 标量基元约束的组合**。工业引擎（Box2D/cannon-es）的每个关节也是由 1~5 行标量约束方程拼装的——掌握了 4.3 的"一行约束求解"，就掌握了全部。

### 平面约束：一切"轴"类关节的原子

```typescript
// physics/constraints/PlaneJoint.ts —— 平面约束 (p_b − p_a)·n = 0
// 把 b 钉在"过 a、法线 n 的平面"上。铰链、滑轨都靠它拼
export class PlaneJoint extends Constraint {
  private bias = 0; private wSum = 0;
  private readonly nx: number; private readonly ny: number; private readonly nz: number;

  constructor(a: JointBody, b: JointBody, nx: number, ny: number, nz: number) {
    super(a, b);
    const len = Math.sqrt(nx * nx + ny * ny + nz * nz);      // 构造时归一化一次
    this.nx = nx / len; this.ny = ny / len; this.nz = nz / len;
  }

  prepare(h: number): void {
    this.wSum = this.a.invMass + this.b.invMass;
    const C = (this.b.x - this.a.x) * this.nx                // b 到平面的带符号距离
            + (this.b.y - this.a.y) * this.ny
            + (this.b.z - this.a.z) * this.nz;
    this.bias = (this.erp / h) * C;
  }

  solve(): void {
    if (this.wSum === 0) return;
    const jv = this.nx * (this.b.vx - this.a.vx)
             + this.ny * (this.b.vy - this.a.vy)
             + this.nz * (this.b.vz - this.a.vz);
    this.err = Math.abs(jv + this.bias);
    const lambda = -(jv + this.bias) / (this.wSum + this.cfm);
    const ja = lambda * this.a.invMass, jb = lambda * this.b.invMass;
    this.a.vx -= this.nx * ja; this.a.vy -= this.ny * ja; this.a.vz -= this.nz * ja;
    this.b.vx += this.nx * jb; this.b.vy += this.ny * jb; this.b.vz += this.nz * jb;
  }
}
```

J 的推导与距离约束同构：C = (p_b − p_a)·n 对 p_a 的偏导是 −n、对 p_b 是 +n，J = [−nᵀ, nᵀ]，只是 n 来自设计者而非连线。

### 距离关节（绳/摆）与点对点关节（布娃娃肩）

**距离关节**即 4.3 的 DistanceJoint：摆锤（锚 + 杆）、链条、缰绳（rope = true）。**点对点关节（point-to-point，球窝关节 ball-and-socket）**要求两个锚点重合，是三维的（3 行方程）：

```text
粒子版：C = p_b − p_a = 0，J = [ −I₃  I₃ ]（3 行；质量为标量 → 三轴互不耦合、独立求解）
刚体版（接 03）：锚点随刚体旋转，要求 p_a + r_a 与 p_b + r_b 重合
        Ċ = v_a + ω_a×r_a − v_b − ω_b×r_b
        J = [ I  −[r_a]×  −I  [r_b]× ]      （[r]× 为叉积矩阵：[r]×ω = r×ω）
```

粒子版三轴互不耦合，实现就是同一模板的三行标量约束；静态端 invMass = 0 时它退化成"锚到世界点"——布娃娃悬挂、窗帘吊环都是它。

### 铰链关节（门）与滑轨关节（prismatic）

**铰链（hinge）= 点重合 + 轴对齐**。门的把手走圆弧：圆 = 球面（到铰链定长）∩ 平面（垂直铰链轴）。粒子版两件现成基元直接拼：

```typescript
// physics/constraints/makeHinge.ts —— 铰链的粒子版：定长 + 平面 = 圆弧
export function makeHinge(
  world: { add(c: Constraint): void }, hinge: JointBody, handle: JointBody,
  ax: number, ay: number, az: number,          // 铰链轴方向（如门轴竖直 (0,1,0)）
): void {
  const rest = Math.hypot(handle.x - hinge.x, handle.y - hinge.y, handle.z - hinge.z);
  world.add(new DistanceJoint(hinge, handle, rest));    // 球面：到铰链点定长
  world.add(new PlaneJoint(hinge, handle, ax, ay, az)); // 平面：法线 = 铰链轴
}
```

刚体版的门还有"轴对齐"两行——门板平面不能翻起、只能绕轴转（x_b、y_b 是门上垂直于轴的两根随体轴）：

```text
C₄ = a·x_b = 0，C₅ = a·y_b = 0
Ċ₄ = ω_h·(a×x_b) + ω_b·(x_b×a)   → J₄ = [ 0, (a×x_b)ᵀ, 0, (x_b×a)ᵀ ]
```

**滑轨关节（prismatic joint）是铰链的对偶**：锁平动留转动 ↔ 锁转动留平动。粒子版 = 两个 PlaneJoint（两个不平行法线把点钉在直线上）：

```typescript
// physics/constraints/makeRail.ts —— 滑轨的粒子版：直线 = 两个平面的交线
export function makeRail(
  world: { add(c: Constraint): void }, a: JointBody, b: JointBody,
  dx: number, dy: number, dz: number,          // 轨道方向
): void {
  const len = Math.sqrt(dx * dx + dy * dy + dz * dz);
  const ex = dx / len, ey = dy / len, ez = dz / len;
  const hx = Math.abs(ex) < 0.9 ? 1 : 0, hy = 1 - hx, hz = 0;  // 与 e 最不平行的坐标轴
  const n1x = hy * ez - hz * ey, n1y = hz * ex - hx * ez, n1z = hx * ey - hy * ex; // h×e
  const n2x = ey * n1z - ez * n1y, n2y = ez * n1x - ex * n1z, n2z = ex * n1y - ey * n1x; // e×n1
  world.add(new PlaneJoint(a, b, n1x, n1y, n1z));
  world.add(new PlaneJoint(a, b, n2x, n2y, n2z));
}
```

刚体滑轨另需锁转动的行（轴对齐 2 行 + 禁绕轴自转 1 行，公式同铰链 C₄/C₅ 的形式）。电梯、抽屉、枪栓都是它。

### 马达关节：驱动约束 + 冲量钳制

马达不消灭自由度，而是**驱赶**它：把目标从 J·v = 0 换成 J·v = v_target，再限制约束力上限。注意不等式（力上限）必须用**累计冲量钳制**：每遍只施加增量、总量在迭代间共享后统一夹紧——这正是 02 摩擦锥 |j_t| ≤ μ·j_n 的同款套路，也是绳/锥角等一切不等式约束的正规解法：

```typescript
// physics/constraints/MotorJoint.ts —— 沿方向 d 把相对速度推到 targetSpeed
export class MotorJoint extends Constraint {
  private dx: number; private dy: number; private dz: number;
  private wSum = 0; private maxImpulse = Infinity; private accImpulse = 0;

  constructor(a: JointBody, b: JointBody,
              dx: number, dy: number, dz: number,     // 驱动方向（内部归一化）
              public targetSpeed = 0,                 // 目标相对速度（b 相对 a，沿 d）
              public maxForce = Infinity) {           // 力上限：|总冲量| ≤ maxForce·h
    super(a, b);
    const len = Math.sqrt(dx * dx + dy * dy + dz * dz);
    this.dx = dx / len; this.dy = dy / len; this.dz = dz / len;
  }

  prepare(h: number): void {
    this.wSum = this.a.invMass + this.b.invMass;
    this.maxImpulse = this.maxForce * h;              // 力上限 × 步长 = 冲量上限
    this.accImpulse = 0;                              // 不做暖启动，每步从零累计
  }

  solve(): void {
    if (this.wSum === 0) return;
    const jv = this.dx * (this.b.vx - this.a.vx)
             + this.dy * (this.b.vy - this.a.vy)
             + this.dz * (this.b.vz - this.a.vz);
    const lambda = -(jv - this.targetSpeed) / (this.wSum + this.cfm); // 目标非零
    const old = this.accImpulse;                      // 累计式：总量钳制、增量生效
    this.accImpulse = Math.min(Math.max(old + lambda, -this.maxImpulse), this.maxImpulse);
    const applied = this.accImpulse - old;
    this.err = Math.abs(jv - this.targetSpeed);
    const ja = applied * this.a.invMass, jb = applied * this.b.invMass;
    this.a.vx -= this.dx * ja; this.a.vy -= this.dy * ja; this.a.vz -= this.dz * ja;
    this.b.vx += this.dx * jb; this.b.vy += this.dy * jb; this.b.vz += this.dz * jb;
  }
}
```

绞盘（targetSpeed > 0）、刹车（targetSpeed = 0 + 小 maxForce）、传送带（对碰到的每个物体挂一个马达）、门缓慢开合——都是这一类的参数组合。铰链马达（绕轴角速度目标）把 d 换成轴向并作用于角速度项，需要 03 的 ω。

## 4.5 迭代求解器：PGS 主循环

### 概念：为什么多个约束要迭代

单个约束一步解完。但真实骨架里约束**共享物体**：解"肩"改了上臂速度，"肘"刚测好的 J·v 立刻作废。两种对策：

- **Jacobi 式**：所有约束先用旧速度各算各的，冲量攒齐一次施加——并行友好但收敛慢；
- **Gauss–Seidel 式**：顺序过约束，每个都读**最新**速度——同样成本收敛约快一倍，本篇与主流引擎都用它。加投影（钳制不等式冲量）后即**投影高斯-赛德尔（projected Gauss–Seidel，PGS）**——Box2D/cannon-es 的"顺序冲量（sequential impulses）"求解器本质就是它。

关键直觉：**一遍 PGS，约束的影响沿"约束-物体图"传播一跳**。链条第 20 节的误差，要 20 遍迭代才能被锚点"感觉到"——这就是长链需要更多迭代的根本原因，迭代次数买的是信息传播距离。

### 完整代码：ConstraintWorld（PGS 循环 + 收敛判断）

```typescript
// physics/constraints/ConstraintWorld.ts —— 质点 + 约束的 PGS 求解世界
import { Constraint, JointBody } from "./Constraint";

export class ConstraintWorld {
  readonly bodies: JointBody[] = [];
  readonly constraints: Constraint[] = [];
  gravityY = -9.81;
  iterations = 10;            // PGS 遍数：怎么选见下文实测
  residualTol = 1e-3;         // 收敛阈值（残差速度，m/s）

  addBody(x: number, y: number, z: number, mass: number): JointBody {
    const b: JointBody = { x, y, z, vx: 0, vy: 0, vz: 0, invMass: mass > 0 ? 1 / mass : 0 };
    this.bodies.push(b);
    return b;
  }
  add(c: Constraint): Constraint { this.constraints.push(c); return c; }

  step(h: number): void {
    // ① 积分：半隐式欧拉（01 §1.2），先速度后位置
    for (const b of this.bodies) {
      if (b.invMass === 0) continue;
      b.vy += this.gravityY * h;
      b.x += b.vx * h; b.y += b.vy * h; b.z += b.vz * h;
    }
    // ② prepare：J 方向、有效质量、bias 每步只算一次（迭代内是常量）
    for (const c of this.constraints) c.prepare(h);
    // ③ PGS：顺序过全部约束，重复至收敛或预算用尽
    for (let k = 0; k < this.iterations; k++) {
      let worst = 0;
      for (const c of this.constraints) {
        c.solve();
        if (c.err > worst) worst = c.err;
      }
      if (worst < this.residualTol) break;   // 提前收敛：省下的迭代白赚
    }
  }
}
```

### 实测：摆锤链长度 vs 迭代次数

```typescript
// demo-chain.ts —— 摆锤链：挂 30 s 后量"总伸长"（相对 links×L）
function makeChain(w: ConstraintWorld, links: number): void {
  const L = 0.3;
  let prev = w.addBody(0, 2, 0, 0);                        // 静态锚
  for (let i = 0; i < links; i++) {
    const cur = w.addBody(0.02 * i, 2 - (i + 1) * L, 0, 1); // 微小错位让它摆起来
    w.add(new DistanceJoint(prev, cur, L));
    prev = cur;
  }
}
// 扫描：links ∈ {5, 20} × iterations ∈ {5,10,20,40}，各 1800 步后量 |tail − head| − links×L：
```

典型量级（erp = 0.2、60 Hz，具体数字随参数浮动，看趋势不看末位）：

| 场景 | 5 遍 | 10 遍 | 20 遍 | 40 遍 | 建议 |
|---|---|---|---|---|---|
| 5 节链 | 伸长约 2% | < 0.5% | ~0 | — | 8–10 遍足够 |
| 20 节链 | 末端明显甩动 | ~5% | ~2% | ~0.5% | ≥ 30 遍，或 4 子步 × 10 遍 |

两条工程结论：**短链 10 遍是甜点**，再多是浪费；**长链加迭代的收益递减，换子步（substep）更划算**——子步同时改善积分误差与信息传播（每子步重新 prepare、误差不会跨子步累积），代价是总成本线性乘子步数。**收敛判断**看残差：把每遍的 `worst` 打出来，若曲线早早平台化，说明剩余违反来自系统本身（质量比、刚度设置），加迭代无用，该调参数或加子步。引擎里还有一招**暖启动（warm starting）**：把上一步的冲量作为本步初值，稳态场景收敛显著加快——本篇最小集每步从零解，规模小无所谓。

## 4.6 实战一：双摆——约束系统的混沌入门

双摆是"两个距离关节 + 重力"的全部故事，却是混沌动力学的标准教具：完全确定的方程、指数发散的轨迹。它同时是约束求解器的体检台——能量漂移多少、约束保持多稳，一目了然。

```typescript
// demo-double-pendulum.ts —— 双摆：同参数两次模拟，初始角差 1e-4 度
import { ConstraintWorld } from "./constraints/ConstraintWorld"; // DistanceJoint 同理
const H = 1 / 60;

function makeDoublePendulum(deg1: number, deg2: number): ConstraintWorld {
  const w = new ConstraintWorld();
  w.iterations = 8;
  const L = 1;                                        // 两杆等长
  const t1 = (deg1 * Math.PI) / 180, t2 = (deg2 * Math.PI) / 180;
  const pivot = w.addBody(0, 2.2, 0, 0);              // 静态锚（invMass = 0）
  const m1 = w.addBody(Math.sin(t1) * L, 2.2 - Math.cos(t1) * L, 0, 1);
  const m2 = w.addBody(Math.sin(t1) * L + Math.sin(t2) * L,
                       2.2 - Math.cos(t1) * L - Math.cos(t2) * L, 0, 1);
  w.add(new DistanceJoint(pivot, m1, L));
  w.add(new DistanceJoint(m1, m2, L));
  return w;
}

function energy(w: ConstraintWorld): number {         // 机械能：求解器质量的体温计
  let e = 0;
  for (const b of w.bodies) {
    if (b.invMass === 0) continue;
    const m = 1 / b.invMass;
    e += 0.5 * m * (b.vx * b.vx + b.vy * b.vy + b.vz * b.vz) + m * 9.81 * b.y;
  }
  return e;
}

const A = makeDoublePendulum(120, 10);                // 大能量初态（混沌区）
const B = makeDoublePendulum(120, 10.0001);           // 初始角差万分之一度
const E0 = energy(A);
for (let n = 0; n < 1800; n++) {                      // 30 s
  A.step(H); B.step(H);
  if (n % 60 === 0) {
    const a = A.bodies[2], b = B.bodies[2];
    console.log(`${n / 60}s  轨迹分离 ${Math.hypot(a.x - b.x, a.y - b.y).toExponential(2)} m  能量漂移 ${(energy(A) / E0 - 1).toExponential(2)}`);
  }
}
```

典型行为（120°/10° 初态）：前几秒轨迹分离停在 1e-5~1e-4 m 量级，随后**大约每秒翻一倍**，10–15 s 后到达米级（摆长尺度）饱和——指数发散，即**混沌**；特征时间由**莱雅普诺夫指数（Lyapunov exponent）**刻画，能量越高发散越快。两个观察维度要分清：

1. **轨迹分离是物理，不是 bug**：两次模拟用同一个求解器、同样的漂移，它们彼此发散说明系统本身对初值敏感——把初态换成 (30°, 0°)（小能量），分离只线性缓慢增长，系统近似周期运动。混沌是参数的函数，值得亲手扫一遍；
2. **能量漂移是求解器误差**：E(t) 相对 E₀ 的偏差应在百分之几内（erp 越大注能越多、迭代越少漂移越大）。它是你调 erp/iterations 的客观标尺——比"看起来像不像"可靠得多。

把两条曲线画进 canvas（01 §1.3 的渲染接法），双摆轨迹的"蝴蝶翅膀"是最好的桌面壁纸。

## 4.7 实战二：布娃娃最小版

### 概念：粒子骨架——关节共享质点，骨骼定距

布娃娃（ragdoll）的最小可行结构：**躯干四肢各放一个质点，关节处相邻骨骼共享端点，每根骨骼一条距离约束**。质点版没有姿态，所以"肩关节"体现为"上臂质点被躯干与肘两端拽住"；刚体版的球窝关节（锚点偏移 + 3 行 C = 0）等 03 的状态量。11 个质点的骨架：

```text
head ← chest ← pelvis：躯干三质点，再加一条 pelvis–head 对角约束（三角化，躯干折不断）
chest ── upperArmL ── foreArmL；chest ── upperArmR ── foreArmR（两臂各两段）
pelvis ── thighL ── shinL；pelvis ── thighR ── shinR（两腿各两段）
```

```typescript
// physics/ragdoll/makeRagdoll.ts —— 11 质点布娃娃：骨骼 + 三角化 + 锥角限制
import { ConstraintWorld } from "../constraints/ConstraintWorld";
import { DistanceJoint } from "../constraints/DistanceJoint";
import { JointBody } from "../constraints/Constraint";
import { ConeLimit } from "./ConeLimit";

export interface Ragdoll {
  bodies: Record<string, JointBody>;
  limits: ConeLimit[];
}

export function makeRagdoll(world: ConstraintWorld, ox: number, oy: number, oz: number): Ragdoll {
  const P: Record<string, JointBody> = {};
  const node = (name: string, dx: number, dy: number, mass: number) =>
    (P[name] = world.addBody(ox + dx, oy + dy, oz, mass));
  // 躯干重、四肢轻（质量分配对收敛的影响见常见坑 3）
  node("pelvis", 0, 1.00, 8); node("chest", 0, 1.45, 8); node("head", 0, 1.80, 4);
  node("upperArmL", -0.30, 1.45, 1.5); node("foreArmL", -0.60, 1.45, 1.0);
  node("upperArmR", 0.30, 1.45, 1.5);  node("foreArmR", 0.60, 1.45, 1.0);
  node("thighL", -0.12, 0.55, 2.5);    node("shinL", -0.12, 0.10, 1.5);
  node("thighR", 0.12, 0.55, 2.5);     node("shinR", 0.12, 0.10, 1.5);

  const bone = (a: string, b: string) => {
    const A = P[a], B = P[b];                          // rest 取初始距离：零误差起步（坑 5）
    world.add(new DistanceJoint(A, B, Math.hypot(B.x - A.x, B.y - A.y, B.z - A.z)));
  };
  bone("pelvis", "chest"); bone("chest", "head"); bone("pelvis", "head");  // 躯干三角化
  bone("chest", "upperArmL"); bone("upperArmL", "foreArmL");
  bone("chest", "upperArmR"); bone("upperArmR", "foreArmR");
  bone("pelvis", "thighL"); bone("thighL", "shinL"); bone("pelvis", "thighR"); bone("thighR", "shinR");

  const limits = [                                     // 锥角限制：肩、膝（初始姿态都在锥内）
    new ConeLimit(P.chest, P.upperArmL, P.head, P.pelvis, 95),
    new ConeLimit(P.chest, P.upperArmR, P.head, P.pelvis, 95),
    new ConeLimit(P.thighL, P.shinL, P.pelvis, P.thighL, 100),
    new ConeLimit(P.thighR, P.shinR, P.pelvis, P.thighR, 100),
  ];
  return { bodies: P, limits };
}
```

### 锥角限制：概念实现（位置层）

**锥角限制（cone limit）**是布娃娃不自残的关键：每关节一个参考方向 + 半角 θ，子骨骼方向不得越出锥面——肩臂不会捅穿躯干、膝盖不会反折。刚体引擎的真锥角限制是角速度约束（J 行含叉积，需要 03 的 ω）；粒子骨架用**位置层近似**（取舍与 02"直接分离 vs Baumgarte"同款）：

```typescript
// physics/ragdoll/ConeLimit.ts —— 锥角限制（概念实现：位置投影 + 外扩速度清除）
export class ConeLimit {
  private cosLim: number;
  private sinLim: number;

  constructor(
    private root: JointBody, private tip: JointBody,        // 被限制的骨骼 root→tip
    private refRoot: JointBody, private refTip: JointBody,  // 参考方向（父骨骼延伸）
    readonly halfAngleDeg: number,
    private percent = 0.3,                                  // 每步修正比例（02 的 percent）
  ) {
    const a = (halfAngleDeg * Math.PI) / 180;
    this.cosLim = Math.cos(a); this.sinLim = Math.sin(a);
  }

  /** 每步 PGS 之后调用（位置层，不进迭代循环） */
  apply(): void {
    const w1 = this.root.invMass, w2 = this.tip.invMass, wSum = w1 + w2;
    if (wSum === 0) return;
    // 参考方向 r（父骨骼）与骨骼方向 c，都归一化
    let rx = this.refTip.x - this.refRoot.x, ry = this.refTip.y - this.refRoot.y,
        rz = this.refTip.z - this.refRoot.z;
    const rl = Math.hypot(rx, ry, rz);
    if (rl < 1e-9) return;
    rx /= rl; ry /= rl; rz /= rl;
    let cx = this.tip.x - this.root.x, cy = this.tip.y - this.root.y,
        cz = this.tip.z - this.root.z;
    const cl = Math.hypot(cx, cy, cz);
    if (cl < 1e-9) return;
    cx /= cl; cy /= cl; cz /= cl;
    const cosA = cx * rx + cy * ry + cz * rz;
    if (cosA >= this.cosLim) return;                 // 锥内：不等式约束，不动作
    let ux = cx - cosA * rx, uy = cy - cosA * ry, uz = cz - cosA * rz;  // 偏出方向
    const ul = Math.hypot(ux, uy, uz);
    if (ul < 1e-9) return;
    ux /= ul; uy /= ul; uz /= ul;
    const qx = rx * this.cosLim + ux * this.sinLim;
    const qy = ry * this.cosLim + uy * this.sinLim;
    const qz = rz * this.cosLim + uz * this.sinLim;
    // ① 位置：把 tip 沿 (q − c) 拉回每步 percent 比例，按逆质量分配（01 §1.3 的分配）
    const mx = (qx - cx) * cl * this.percent, my = (qy - cy) * cl * this.percent,
          mz = (qz - cz) * cl * this.percent;
    this.root.x -= mx * (w1 / wSum); this.root.y -= my * (w1 / wSum); this.root.z -= mz * (w1 / wSum);
    this.tip.x += mx * (w2 / wSum);  this.tip.y += my * (w2 / wSum);  this.tip.z += mz * (w2 / wSum);
    // ② 速度：清除继续外扩的分量（相对速度沿 u 的正分量）
    const rvx = this.tip.vx - this.root.vx, rvy = this.tip.vy - this.root.vy,
          rvz = this.tip.vz - this.root.vz;
    const out = rvx * ux + rvy * uy + rvz * uz;
    if (out > 0) {
      const k1 = out * (w1 / wSum), k2 = out * (w2 / wSum);
      this.root.vx += k1 * ux; this.root.vy += k1 * uy; this.root.vz += k1 * uz;
      this.tip.vx -= k2 * ux;  this.tip.vy -= k2 * uy;  this.tip.vz -= k2 * uz;
    }
  }
}
```

### 与动画系统融合：active ragdoll

纯物理布娃娃躺得真实，但站不起来、跑不动。**主动布娃娃（active ragdoll）**把两者混合：动画系统（[04-第四阶段/06-动画系统](../04-第四阶段/06-动画系统.md)）按骨骼 FK 输出目标姿态，物理给每个质点挂一个"姿态马达"把它往目标拽，约束随后保证关节不断裂——混合权重决定谁说了算：

```typescript
// physics/ragdoll/PoseDriver.ts —— 动画驱动 + 物理扰动的混合
export class PoseDriver {
  blend = 0.85;       // 1 = 全动画，0 = 纯布娃娃；中间值 = 受击踉跄、濒死挣扎
  kp = 40; kd = 8;    // PD 增益：ω = √40 ≈ 6.3 rad/s、ζ = kd/(2√kp) ≈ 0.63——4.3 的参数化

  /** 每步在积分前调用；targets 来自 06-动画系统的骨架世界坐标（FK 后） */
  apply(w: { bodies: Record<string, JointBody> },
        targets: Map<string, { x: number; y: number; z: number }>, h: number): void {
    for (const [name, t] of targets) {
      const b = w.bodies[name];
      if (!b || b.invMass === 0) continue;
      const s = this.blend;
      b.vx += (s * this.kp * (t.x - b.x) - s * this.kd * b.vx) * h;   // 软马达 = 4.4 马达的
      b.vy += (s * this.kp * (t.y - b.y) - s * this.kd * b.vy) * h;   // 无上限弹簧版
      b.vz += (s * this.kp * (t.z - b.z) - s * this.kd * b.vz) * h;
    }
  }
}
```

// demo-ragdoll.ts —— world = new ConstraintWorld()、iterations = 8、

三条融合纪律：**blend 权重的渐变就是动画混合（06 的 cross-fade）思想在物理侧的镜像**——受击 0.2、死亡 0、起身缓回 0.85；**blend = 1 时不要过物理**——直接让动画写节点更准也更省（01 §1.4"一个节点一个写入者"）；**姿态马达的 kp/kd 用 4.3 的频率/阻尼语言标定**，而不是拍脑袋——角色"僵"与"瘫"的区别就是 ω 和 ζ 的区别。

## 4.8 取舍与迁移：这套求解器能撑到哪

先算一笔账：一次约束求解约 30 次浮点运算，100 个约束 × 10 遍 = 3 万次/步，60 Hz 下约 200 万次/秒——对 CPU 是零头。**瓶颈从来不是算力，是收敛质量**：耦合越紧（长链、质量比悬殊、关节与接触混解），顺序求解越难在预算内收敛。经验边界三档：**主场**——摆/双摆/几节短链/窗帘绳、单个布娃娃（11 体 15 约束 + 锥角），稳且准；**勉强**——20 节以上长链、鞭子（30+ 遍或子步）；**换引擎**——关节与接触堆叠混解（机构压在货堆上，两类约束互相打架）、百级刚体 + CCD。

**换引擎时看什么**（选型背景见 00 导览与 02 §2.7）：

- **cannon-es**：顺序冲量求解器（PGS 家族，与本篇同宗），纯 TS 单线程，iterations 可调、关节齐全（DistanceLock/Hinge/Prismatic/Motor 一应俱全，参数语义与本篇一一对应：maxForce 即 4.4 的冲量钳制、collideConnected 管相连体是否互碰）。读得懂本篇就读得懂它的源码；
- **rapier**：**TGS（truncated Gauss–Seidel）**求解器——把一步切成子步、每子步少量迭代，恰好就是 4.5"长链换子步"结论的引擎级实现，长链与质量比场景收敛明显更好；加上岛屿（island）划分与并行调度、WASM，规模上千刚体。约束"优先级"两家都没有显式接口——工程上靠刚度分层（重要关节硬、次要关节软）与求解顺序近似，本篇 4.3 的软约束参数化就是干这个的；
- **迁移路径**：01 §1.4 的 PhysicsLoop 抽象保证渲染绑定层（boundNode、interpolate）原样保留；重写的是世界内核——本篇的 Constraint 子类换成引擎的 joint API，玩法侧只认"目标速度、力上限、频率/阻尼"这些物理参数，两边语义可直接对译。

## 常见坑

1. **约束漂移（drift）**：只解速度不清位置误差，摆绳每步被重力"借走"一点长度，几分钟垂到地上——症状是"绳变长、杆变橡皮"。修法就是 4.3 的 bias；但 bias 过大（β > 0.5）会注能弹跳，等价于 02 的 Baumgarte 教训。另注意 bias 与软度公式里都有 h——换 dt 手感全变（绳突然变松或变弹），这是 01 §1.1"物理必须固定步长"的又一实证；
2. **迭代不足的抖动**：链条末端"甩鞭子"或每帧微抖——残差没压下去。把每遍的 `worst` 打出来：随遍数指数下降 → 加遍数；早早平台 → 不是遍数问题，是质量比或刚度配置（下一条），换子步；
3. **质量比悬殊时收敛慢**：轻物体拖重物体（布娃娃手臂拽躯干、气球拽铁球），m* ≈ 轻者质量，重物几乎不动、轻物被反复打飞——PGS 的收敛速率随质量比恶化，100:1 已很吃力。缓解：gameplay 层钳质量比（角色肢体通常人为限制在 10:1 内）、重物所在约束加子步、或给重链暖启动；
4. **生成即违反**：初始摆位不在约束流形上（双摆两杆没摆到位、布娃娃手脚穿模），首步 C 巨大 → bias 巨大 → 首帧冲量爆炸。防御与 02 坑 5 同款：rest 取初始距离（4.7 的 bone() 就是这么写的）、或前三步 erp 置 0；
5. **J 的符号错一处 = 火箭**：偏导差个正负号，冲量把违反越推越大，两帧内 NaN。防御：每类关节写"两质点拉伸"单测，断言解后 J·v′ = 0 且动量不变（4.2 手算就是现成用例）——等价于 02 用"等质量弹性对撞速度互换"当接触的守门测试。
