## 7.1 切空间为什么存在

### 概念：法线贴图里的法线住在哪个坐标系

法线贴图（normal map）存的不是绝对方向，而是"相对表面自身"的扰动方向。这个"表面自身"的坐标系叫切空间（tangent space），约定三根轴：

- z 轴：沿顶点插值得到的"未扰动法线"N，指向表面外侧；
- x 轴：沿纹理 u 增长的方向，称切线 T（tangent）；
- y 轴：沿纹理 v 增长的方向，称副切线 B（bitangent；早期文献误写 binormal，bitangent 才是正确术语）。

法线贴图每个纹素存切空间法线经 `n * 0.5 + 0.5` 编码后的 RGB。最常见的"平坦"纹素是 (128, 128, 255)：解码 `(0.502, 0.502, 1.0) * 2 - 1 = (0, 0, 1)`，即"沿 N 不扰动"。UV 坐标与纹理采样的机制在第二阶段纹理篇 2.1 已讲（见 [02-第二阶段/03-纹理.md](../02-第二阶段/03-纹理.md)），本篇只回答它没回答的问题：**为什么必须专门造一个坐标系**。

### 为什么不能直接存世界空间

假设法线贴图直接存世界空间法线（world-space normal map），三个场景立刻崩：

1. **模型一转全错**：世界空间方向与姿态绑定。角色抬一下手臂，手臂上的法线还是抬手前烘出来的世界方向，光照整体"错位"；
2. **纹理复用（tiling）不可能**：一面砖墙纹理在 UV 上重复 16 次，同一纹素出现在 16 处朝向不同的墙面上。一个固定的世界向量表达不了"同一块砖、16 种朝向"——只有"相对表面"的表示才能随表面到处贴；
3. **镜像 UV 不可能**：镜像复用一半 UV 的模型，左半与右半需要互为镜像的法线，固定方向存不了。

中间方案是对象空间法线贴图（object-space normal map）：存模型局部方向，随模型整体旋转，但仍不能 tiling、不能镜像，骨骼蒙皮（第四阶段动画篇 5.3 的顶点变形）下也会失效——因为它绑的是"网格的姿态"，而切空间绑的是"网格上每个点的局部几何"，蒙皮时切向量随顶点一起变换即可。结论：**纹理内容描述"相对表面的倾斜"，坐标系由网格逐顶点提供**——两者分工，才有复用性。

一个对偶值得记住：第二阶段光照篇 4.1 推导过法线要用逆转置矩阵变换（[02-第二阶段/05-光照.md](../02-第二阶段/05-光照.md)）；而切向量是表面两点的差，像方向向量一样**直接乘 model 的 3×3** 就是正确变换。法线与切线在"怎么变换"上恰好是一对偶——后面 7.3、常见坑都会用到。

### 数值直觉

手算一遍切空间的"意义"。某顶点处 T 指向世界 +X、B 指向世界 +Z、N 指向 +Y。法线贴图纹素解码得切空间法线 (0.6, 0, 0.8)（朝 u 方向倾斜约 37°），则世界空间法线：

```text
N_world = 0.6·T + 0·B + 0.8·N = 0.6·(1,0,0) + 0.8·(0,1,0) = (0.6, 0.8, 0)
```

同一张法线贴图贴到另一个朝向的面（比如 T 指向 −Z 的面上），同一个纹素自动解释为朝 −Z 倾斜的世界法线。**纹素值不变、含义随表面走**——这就是切空间存在的全部理由，也是 7.2 要构建 TBN 的原因。

## 7.2 TBN 基构建：从三角形顶点与 UV 推导 T 与 B

### 概念

TBN（Tangent-Bitangent-Normal）是以 T、B、N 三向量为列的正交标架。实践中逐顶点只存 T（与 `aNormal` 一样的 attribute，多带一个 w 分量存手性），B 在着色器里用 `cross(N, T) * w` 重建——省一个 attribute 且保证正交。数据来源有两种：DCC 烘焙时直接写进网格文件（glTF 的 `_TANGENT`），或运行时从"位置 + UV"算出来。自研框架（第三阶段 Geometry 生成器、第四阶段 glTF 加载器）两条路都要支持，本节推导第二种。

### 推导：dU 方程组求解

切线的数学定义是 $\partial P / \partial u$：u 走一个单位，位置移动多少。取三角形 $V_0 V_1 V_2$，位置 $P_0, P_1, P_2$，UV $(u_0,v_0), (u_1,v_1), (u_2,v_2)$。光栅化对 UV 做线性插值，所以在三角形内部认为 T、B 是常量（平面近似），两条边可以写成：

```text
E1 = P1 − P0 = (u1−u0)·T + (v1−v0)·B
E2 = P2 − P0 = (u2−u0)·T + (v2−v0)·B
```

记 $u_1 = u_1 - u_0$、$v_1 = v_1 - v_0$、$u_2, v_2$ 同理，写成矩阵形式（T、B、E 均为列向量）：

$$\begin{bmatrix} E1 & E2 \end{bmatrix} = \begin{bmatrix} T & B \end{bmatrix} \begin{bmatrix} u_1 & u_2 \\ v_1 & v_2 \end{bmatrix}$$

解出基矩阵（右乘 2×2 系数矩阵的逆，det = $u_1 v_2 - u_2 v_1$）：

$$\begin{bmatrix} T & B \end{bmatrix} = \begin{bmatrix} E1 & E2 \end{bmatrix} \cdot \frac{1}{\det}\begin{bmatrix} v_2 & -u_2 \\ -v_1 & u_1 \end{bmatrix}$$

展开就是经典的两个式子：

```text
T = (v2·E1 − v1·E2) / det
B = (u1·E2 − u2·E1) / det
```

det 接近 0 的几何含义：三个 UV 点几乎共线（或精确镜像对折），三角形在"纹理空间"里没有面积，切线方向不可定义——运行时按退化三角形跳过。

**手算例子**。取 $P_0=(0,0,0)$、$P_1=(2,0,0)$、$P_2=(0,2,1)$；UV 斜切的情形 $(0,0), (1,0), (1,1)$：

```text
E1 = (2,0,0)   E2 = (0,2,1)
(u1,v1) = (1,0)   (u2,v2) = (1,1)   det = 1·1 − 1·0 = 1
T = (1·E1 − 0·E2)/1 = (2,0,0)
B = (1·E2 − 1·E1)/1 = (0,2,1) − (2,0,0) = (−2,2,1)
```

检查：T·B = 2·(−2) + 0 + 0 = **−4 ≠ 0**。T、B 都落在三角形平面内（与几何法线都垂直），但**互相不正交**——UV 斜切（v 随 u 一起增长）让"纹理的轴"在表面上斜了。光照要的是正交标架，于是需要格拉姆-施密特（Gram–Schmidt orthogonalization）。

### 格拉姆-施密特正交化与手性（w 分量）判断

接上例。几何法线 $N = \mathrm{normalize}(E1 \times E2) = (0,-2,4)/\sqrt{5} \approx (0, -0.447, 0.894)$。三步：

```text
① T' = normalize(T − N·(N·T))          本例 N·T = 0，T' = (1,0,0)
② w  = sign( dot(T × B, N) )           T×B = (0,−2,4)，与 N 同向 → w = +1
③ B' = w · normalize(N × T')           N×T' = (0,4,2)，归一化 B' = (0, 0.894, 0.447)
```

w 就是**手性（handedness）**：T×B 与 N 同向记 +1、反向记 −1。它何时会是 −1？**UV 镜像**。把上例 UV 改成 $(0,0), (1,0), (0,-1)$（v 轴翻转，等效镜像贴图），重算得原始 B 翻到平面另一侧，T×B 与 N 反向，w = −1。着色器里一行 `vec3 B = cross(N, T) * aTangent.w;` 同时处理正常与镜像两种情况——w 存进切线 attribute 的第四分量，这就是"切线是 vec4"的原因。跳过正交化直接用 T、B 的后果：斜切 UV 的模型光照有可感知的"歪斜"，镜像处高光直接烧坏（见常见坑 1）。

### 完整代码：computeTangents（TypeScript）

```typescript
// math/tangents.ts —— 逐顶点切线生成（可并入 minmath 或 Geometry 工具集）
export interface TangentGeometry {
  positions: Float32Array;                  // 每顶点 3 个
  normals: Float32Array;                    // 每顶点 3 个（须已生成）
  uvs: Float32Array;                        // 每顶点 2 个
  indices: Uint16Array | Uint32Array;
}

/**
 * 计算逐顶点切线。输出 outTangents（每顶点 4 个：xyz = 正交化后的 T，w = 手性 ±1）。
 * 副切线不存储，着色器里 cross(N, T) * w 重建。
 * 约定：累加按"顶点索引"而不是位置——UV 接缝两侧若已被拆成不同顶点索引，
 * 平均天然不跨缝（见下文 seams 处理）。
 */
export function computeTangents(
  geo: TangentGeometry,
  outTangents: Float32Array,
): void {
  const { positions, normals, uvs, indices } = geo;
  const vertexCount = positions.length / 3;
  const tanAcc = new Float32Array(vertexCount * 3); // 未正交化切线累加器
  const bitAcc = new Float32Array(vertexCount * 3); // 未正交化副切线累加器

  // —— 第一遍：逐三角形求面切线，累加到三个顶点 ——
  for (let i = 0; i < indices.length; i += 3) {
    const i0 = indices[i], i1 = indices[i + 1], i2 = indices[i + 2];
    const p0 = i0 * 3, p1 = i1 * 3, p2 = i2 * 3;
    const t0 = i0 * 2, t1 = i1 * 2, t2 = i2 * 2;

    const e1x = positions[p1] - positions[p0];
    const e1y = positions[p1 + 1] - positions[p0 + 1];
    const e1z = positions[p1 + 2] - positions[p0 + 2];
    const e2x = positions[p2] - positions[p0];
    const e2y = positions[p2 + 1] - positions[p0 + 1];
    const e2z = positions[p2 + 2] - positions[p0 + 2];

    const du1 = uvs[t1] - uvs[t0], dv1 = uvs[t1 + 1] - uvs[t0 + 1];
    const du2 = uvs[t2] - uvs[t0], dv2 = uvs[t2 + 1] - uvs[t0 + 1];

    const det = du1 * dv2 - du2 * dv1;
    if (Math.abs(det) < 1e-10) continue;    // UV 退化（共线/镜像对折），跳过
    const r = 1 / det;

    // T = (dv2·E1 − dv1·E2)·r；长度编码 UV 密度（u 拉伸 2 倍则 T 短一半），累加时保留
    const tx = (dv2 * e1x - dv1 * e2x) * r;
    const ty = (dv2 * e1y - dv1 * e2y) * r;
    const tz = (dv2 * e1z - dv1 * e2z) * r;
    // B = (du1·E2 − du2·E1)·r
    const bx = (du1 * e2x - du2 * e1x) * r;
    const by = (du1 * e2y - du2 * e1y) * r;
    const bz = (du1 * e2z - du2 * e1z) * r;

    for (const idx of [i0, i1, i2]) {
      tanAcc[idx * 3] += tx; tanAcc[idx * 3 + 1] += ty; tanAcc[idx * 3 + 2] += tz;
      bitAcc[idx * 3] += bx; bitAcc[idx * 3 + 1] += by; bitAcc[idx * 3 + 2] += bz;
    }
  }

  // —— 第二遍：逐顶点格拉姆-施密特 + 手性 ——
  for (let v = 0; v < vertexCount; v++) {
    const nx = normals[v * 3], ny = normals[v * 3 + 1], nz = normals[v * 3 + 2];
    let tx = tanAcc[v * 3], ty = tanAcc[v * 3 + 1], tz = tanAcc[v * 3 + 2];
    const bx = bitAcc[v * 3], by = bitAcc[v * 3 + 1], bz = bitAcc[v * 3 + 2];

    const lenSq = tx * tx + ty * ty + tz * tz;
    if (lenSq < 1e-20) {                    // 无有效切线（无 UV / 全退化三角形）
      // 兜底：取与 N 不平行的任意向量叉出 T，保证 attribute 有合法值
      tx = Math.abs(ny) < 0.999 ? 0 : 1;
      ty = Math.abs(ny) < 0.999 ? 1 : 0;
      tz = 0;
    }

    // ① 施密特：去掉 T 在 N 上的分量，再归一化
    const dotNT = nx * tx + ny * ty + nz * tz;
    tx -= nx * dotNT; ty -= ny * dotNT; tz -= nz * dotNT;
    const invLen = 1 / Math.hypot(tx, ty, tz);
    tx *= invLen; ty *= invLen; tz *= invLen;

    // ② 手性：T×B 与 N 同向为 +1
    const cxx = ty * bz - tz * by;
    const cxy = tz * bx - tx * bz;
    const cxz = tx * by - ty * bx;
    const w = (cxx * nx + cxy * ny + cxz * nz) < 0 ? -1 : 1;

    outTangents[v * 4] = tx;
    outTangents[v * 4 + 1] = ty;
    outTangents[v * 4 + 2] = tz;
    outTangents[v * 4 + 3] = w;
  }
}
```

### 顶点级切线的平均与 seams 处理

共享一个顶点的多个三角形切线不同（各面的 UV 梯度不同），逐顶点值取平均——这正是上面"累加器"的作用。平均的两个注意点：

1. **平均的是未归一化切线**。面切线的长度编码"UV 密度"（手算例：u 拉伸 2 倍、T 短一半），大三角形对平均值应有大权重，而三角形面积恰好体现在共享边向量的长度里——先归一化再平均会丢掉这个权重；
2. **UV 接缝（seam）绝不能跨缝平均**。接缝两侧是"同一位置、不同 UV 走向"，切线方向合法地不同，平均会把两边都拉错。工程上分两种情况：
   - 网格数据按**顶点索引**拆分了接缝（glTF 等格式的常态：同一位置在缝两侧是两个 vertex）——本节代码按顶点索引累加，天然不跨缝，无需处理；
   - 引擎做过顶点焊接（weld/merge，按位置合并索引）——必须先按 `(position, uv)` 对重新拆分，或按该对做分组平均。焊接后直接算切线，接缝处会出现一条"光照缝"，是自研加载器最容易踩的坑之一。

标准答案的存在性说明：业界事实标准是 Mikktspace——一套规定了平均顺序与手性约定的切空间生成参考实现，DCC 烘焙与引擎渲染两侧都用它，接缝才能对上。自研实现要点一致（逐面累加、缝拆分、w 手性），但与外部烘焙的法线贴图混用时，若出现"沿 UV 缝的细亮线"，优先怀疑两边切空间约定不一致。

## 7.3 切空间与世界空间互转：TBN 矩阵的两种用法

### 概念：一个矩阵，两个方向

以 T、B、N 为列的 3×3 矩阵就是切空间到目标空间（模型/世界）的**换基矩阵**（本专题 [01-线性代数深化](01-线性代数深化.md)）：

$$\mathrm{TBN} = \begin{bmatrix} T_x & B_x & N_x \\ T_y & B_y & N_y \\ T_z & B_z & N_z \end{bmatrix}$$

着色时要做的转换有两等价路线：

- **方案 A（正向）**：把采样到的切空间法线变换到世界空间，光照全在世界/视空间做；
- **方案 B（逆向）**：把光照相关的向量（L、V）变换到切空间，光照在切空间做。

### GLSL 对比

方案 A——世界空间光照，片元里把法线"搬出来"：

```glsl
// —— 方案 A：法线贴图采样后乘 TBN（WebGL2 / GLSL 300 es 片元着色器核心）——
in vec3 vTangent;      // 已变换到世界空间并归一化（顶点着色器完成）
in float vTangentW;    // 手性 ±1（切线 attribute 的第四分量，顶点着色器直传）
in vec3 vNormal;
in vec2 vUV;
uniform sampler2D uNormalMap;

vec3 getWorldNormal() {
  vec3 N = normalize(vNormal);                 // 插值会缩短，必须重归一化
  vec3 T = normalize(vTangent - N * dot(N, vTangent)); // 插值后重正交化（可选但推荐）
  vec3 B = cross(N, T) * vTangentW;
  mat3 TBN = mat3(T, B, N);                    // 列构造：TBN * v_tangent = v_world

  vec3 nT = texture(uNormalMap, vUV).xyz * 2.0 - 1.0;  // 解码到 [-1,1]
  return normalize(TBN * nT);                  // 切空间 → 世界空间
}
// 之后 L、V、Blinn-Phong/PBR 全部在世界空间照常进行
```

方案 B——切空间光照，把 L、V"搬进去"：

```glsl
// —— 方案 B：逆变换光照向量到切空间 ——
in vec3 vTangent;
in float vTangentW;
in vec3 vNormal;
in vec3 vWorldPos;
in vec2 vUV;
uniform sampler2D uNormalMap;
uniform vec3 uLightPos;
uniform vec3 uCameraPos;

void main() {
  vec3 N = normalize(vNormal);
  vec3 T = normalize(vTangent - N * dot(N, vTangent));
  vec3 B = cross(N, T) * vTangentW;

  vec3 nT = texture(uNormalMap, vUV).xyz * 2.0 - 1.0;

  // TBN 正交 ⇒ 逆 = 转置：v_tangent = transpose(TBN) * v_world，即分别点乘三列
  vec3 L = normalize(uLightPos - vWorldPos);
  vec3 V = normalize(uCameraPos - vWorldPos);
  vec3 Lt = normalize(vec3(dot(L, T), dot(L, B), dot(L, N)));
  vec3 Vt = normalize(vec3(dot(V, T), dot(V, B), dot(V, N)));

  // 全部光照计算（漫反射、高光、视差采样……）都在切空间用 nT、Lt、Vt 进行
  float ndl = max(dot(nT, Lt), 0.0);
  // ...
}
```

### 对比与性能

| 维度 | 方案 A（法线出切空间） | 方案 B（光照进切空间） |
|---|---|---|
| 每片元矩阵运算 | 1 次 `mat3 * vec3`（约 9 乘 6 加） | 2 次转置乘（各 3 点积）≈ 2 倍于 A |
| 与世界空间效果协同 | 直接兼容：环境反射、IBL、雾、世界空间光源 | 要在切空间做完再转回世界，来回转换反而更贵 |
| 切空间多纹理套件（视差贴图 POM、各向异性高光） | 每次采样都要把视线转世界再回来，别扭 | 视线、光线天然在纹理轴坐标系里，视差偏移直接加在 UV 上 |
| 插值正交性 | TBN 插值后失正交——好在重归一化 + Schmidt 一步能救 | 同样问题，但 `transpose ≠ inverse` 会让 Lt 方向有微小变形 |

结论：**只用一张法线贴图时选 A**（one mat-vec 就完，且与世界空间后处理无缝）；**要做视差遮挡贴图（parallax occlusion mapping）等"在纹理轴上反复采样"的效果时选 B**。两条路线数学等价，差别只在"谁被变换"与变换次数。

## 7.4 微分几何三件套：切平面、法曲率、高度图重建法线

### 切平面

表面一点 P 处的切平面（tangent plane）是所有过 P 的表面曲线的速度向量张成的平面：$\{X \mid (X - P) \cdot N = 0\}$。TBN 就是切平面的一组正交标架。切平面的意义：光照模型（Lambert、Cook-Torrance）全部定义在"N 与切平面"这组一次近似上，法线贴图改变 N，等于"谎报切平面"。

### 法曲率直觉

用含 N 的平面去截表面，得到一条截线，截线在 P 处的曲率（带符号：沿 N 方向凸为一种、凹为另一种）叫法曲率（normal curvature）。直觉三点：

- 法线贴图是**假装曲率**：几何没弯，光照按弯的算，轮廓（silhouette）仍然是直的——近看墙面砖缝"立体"，侧看轮廓却平直，就是假曲率的破绽；
- 位移/细分是**真曲率**：顶点真的动了，轮廓跟着弯；
- 法曲率符号翻转的地方是"鞍点"，平滑着色（顶点法线平均）会把鞍点附近的光照抹平——低多边形风格用面法线（flat shading）反而保真。

### 从高度图重建法线：推导与实现

高度图（height map）h(u, v) 存"沿法线方向的抬升"。把它看成参数曲面 S(u, v) = (u, v, h(u, v))（把高度放在 z/法线轴上），两个切向量：

$$S_u = \frac{\partial S}{\partial u} = (1, 0, h_u), \qquad S_v = (0, 1, h_v)$$

法线垂直于两个切向量，取叉积：

$$N \propto S_u \times S_v = (0 \cdot h_v - h_u \cdot 1,\;\; h_u \cdot 0 - 1 \cdot h_v,\;\; 1 \cdot 1 - 0 \cdot 0) = (-h_u,\; -h_v,\; 1)$$

$$\boxed{N = \mathrm{normalize}(-h_u, -h_v, 1)}$$

梯度指向"高处"，法线要指向"背离高处"的方向，所以前两项带负号。若纹理 v 轴与几何 y 轴方向约定不一致（第二阶段纹理篇 2.5 的 UNPACK_FLIP_Y 老坑同源），$h_v$ 的符号要翻。

**手算例子**：3×3 高度图，中心一个尖：

```text
0 0 0
0 1 0          中心 (1,1)：h_u = (h[2,1] − h[0,1])/2 = (0−0)/2 = 0
0 0 0                          h_v = 0          → N = (0,0,1)   塔尖朝外，对
左邻 (0,1)：h_u 用单侧差分 = (h[1,1] − h[0,1])/1 = 1
             h_v = (h[0,2] − h[0,0])/2 = 0       → N = normalize(−1, 0, 1) ≈ (−0.707, 0, 0.707)
```

左邻的坡面朝 −u（远离尖峰）倾斜 45°，符合直觉。

中心差分（central difference）$h_u \approx (h[x+1] - h[x-1])/2$ 比单侧差分多一阶精度（误差 O(Δ²) vs O(Δ)），边界退化为单侧。强度参数 strength 的正确位置是**乘在梯度上**（斜率缩放），不是乘在结果法线上：

```typescript
// math/heightmap.ts —— 高度图 → 法线贴图（离线工具版，输出可直接当纹理上传）
export function heightMapToNormalMap(
  height: Float32Array, width: number, heightSize: number,
  strength = 1.0,                 // 梯度缩放：斜率 = strength × Δh / Δuv
  wrap = true,                    // 环绕地形取 true，孤立贴图取 false
): Uint8Array {
  const out = new Uint8Array(width * heightSize * 4);
  const at = (x: number, y: number): number => {
    if (wrap) {
      x = ((x % width) + width) % width;          // 环绕采样，无缝 tiling
      y = ((y % heightSize) + heightSize) % heightSize;
    } else {
      x = Math.min(Math.max(x, 0), width - 1);    // 边界 clamp，退化为单侧差分
      y = Math.min(Math.max(y, 0), heightSize - 1);
    }
    return height[y * width + x];
  };
  for (let y = 0; y < heightSize; y++) {
    for (let x = 0; x < width; x++) {
      const gx = (at(x + 1, y) - at(x - 1, y)) * 0.5 * strength;  // h_u
      const gy = (at(x, y + 1) - at(x, y - 1)) * 0.5 * strength;  // h_v
      const inv = 1 / Math.hypot(gx, gy, 1);
      const i = (y * width + x) * 4;
      out[i]     = Math.round((-gx * inv) * 0.5 + 0.5) * 255;
      out[i + 1] = Math.round((-gy * inv) * 0.5 + 0.5) * 255;
      out[i + 2] = Math.round((1.0 * inv) * 0.5 + 0.5) * 255;
      out[i + 3] = 255;
    }
  }
  return out;
}
```

运行时直接在地形着色器里算，可以省一张纹理、还让强度可调：

```glsl
// 地形片元：实时高度差分（uHeightMap 为 R8/R16F 线性纹理，wrap = REPEAT）
uniform sampler2D uHeightMap;
uniform float uTexelSize;   // 1.0 / 地形纹理分辨率
uniform float uStrength;    // 世界尺度斜率缩放

vec3 heightToNormal(vec2 uv) {
  float hL = texture(uHeightMap, uv - vec2(uTexelSize, 0.0)).r;
  float hR = texture(uHeightMap, uv + vec2(uTexelSize, 0.0)).r;
  float hD = texture(uHeightMap, uv - vec2(0.0, uTexelSize)).r;
  float hU = texture(uHeightMap, uv + vec2(0.0, uTexelSize)).r;
  vec2 grad = vec2(hR - hL, hU - hD) * (0.5 * uStrength);
  return normalize(vec3(-grad, 1.0));   // 与离线公式一致
}
```

注意此法线在"切空间"（z 沿几何法线）。地形通常已按世界坐标生成（heightmap 的 xz 对齐世界轴），可直接当世界法线用；对一般网格，它要与 7.2 的 TBN 配合。

## 7.5 距离与最近点

求交回答"碰没碰"，最近点（closest point）回答"差多远"——后者适用面更广：拾取高亮（点到三角形距离小于阈值做描边）、碰撞检测（距离小于半径和即接触）、距离场（distance field）类效果。第五阶段雾效篇 5.1 的距离雾用的是"片元到相机"的距离（[05-第五阶段/06-雾效与天空盒.md](../05-第五阶段/06-雾效与天空盒.md)）；点到场景表面的距离场是它的推广。以下四个算法是几何库的标配。

### 点到线段

线段参数化 $C(t) = A + t(B-A),\; t \in [0,1]$。最小化 $|P - C(t)|^2$：对 t 求导为零，得无约束解 $t = \frac{(P-A)\cdot(B-A)}{|B-A|^2}$，再夹回 [0,1]（无约束解在线段外时最近点就是端点）。

**手算**：A=(0,0,0)、B=(4,0,0)。P=(2,1,0)：t = (2,1,0)·(4,0,0)/16 = 8/16 = 0.5，C=(2,0,0)，距离 1。P=(-3,0,0)：t = -12/16 = -0.75 < 0，夹到 0，C=A=(0,0,0)，距离 3。

```typescript
/** 点 P 到线段 AB 的最近点与距离平方 */
export function closestPointOnSegment(
  p: Readonly<Vec3>, a: Readonly<Vec3>, b: Readonly<Vec3>,
): { point: Vec3; distSq: number } {
  const abx = b.x - a.x, aby = b.y - a.y, abz = b.z - a.z;
  const apx = p.x - a.x, apy = p.y - a.y, apz = p.z - a.z;
  const abSq = abx * abx + aby * aby + abz * abz;
  const t = abSq > 1e-12
    ? Math.min(Math.max((apx * abx + apy * aby + apz * abz) / abSq, 0), 1)
    : 0;                                        // 退化线段：退回点 A
  const point = new Vec3(a.x + abx * t, a.y + aby * t, a.z + abz * t);
  const dx = p.x - point.x, dy = p.y - point.y, dz = p.z - point.z;
  return { point, distSq: dx * dx + dy * dy + dz * dz };
}
```

### 点到 AABB

AABB 是三对半平面（slab）的交，到凸体的最近点 = 逐轴把 P 夹回盒内：

```typescript
/** 点到 AABB 的最近点（min/max 为盒两角） */
export function closestPointOnAABB(
  p: Readonly<Vec3>, min: Readonly<Vec3>, max: Readonly<Vec3>,
): Vec3 {
  return new Vec3(
    Math.min(Math.max(p.x, min.x), max.x),
    Math.min(Math.max(p.y, min.y), max.y),
    Math.min(Math.max(p.z, min.z), max.z),
  );
}
```

**手算**：min=(0,0,0)、max=(2,2,2)，P=(3,1,-1) → C=(2,1,0)，距离 √2。P 在盒内时结果就是 P 自己（距离 0），无需特判。拾取的"悬停高亮"常用它：光标射线命不中三角形，但到 mesh 包围盒距离小于阈值时仍给出"靠近了"的提示（配合第四阶段交互篇 4.3 的包围体思路）。

### 点到三角形：七个区域

点到三角形的最近点落在三角形所在平面的投影上，但投影可能在三角形外。平面上一点相对三角形的"势力范围"分成七个 Voronoi 区域：三个顶点区、三条边区、内部区。Ericson《Real-Time Collision Detection》5.1.5 的算法按顺序测试各区域，每步只做点积：

```typescript
/** 点到三角形 ABC 的最近点（Ericson 5.1.5，全点积实现，无除法直到必要处） */
export function closestPointOnTriangle(
  p: Readonly<Vec3>, a: Readonly<Vec3>, b: Readonly<Vec3>, c: Readonly<Vec3>,
): Vec3 {
  const sub = (u: Readonly<Vec3>, v: Readonly<Vec3>) =>
    new Vec3(u.x - v.x, u.y - v.y, u.z - v.z);
  const dot = (u: Readonly<Vec3>, v: Readonly<Vec3>) => u.x * v.x + u.y * v.y + u.z * v.z;

  const ab = sub(b, a), ac = sub(c, a), ap = sub(p, a);
  const d1 = dot(ab, ap), d2 = dot(ac, ap);
  if (d1 <= 0 && d2 <= 0) return a.clone();              // 顶点 A 区

  const bp = sub(p, b);
  const d3 = dot(ab, bp), d4 = dot(ac, bp);
  if (d3 >= 0 && d4 <= d3) return b.clone();             // 顶点 B 区

  const vc = d1 * d4 - d3 * d2;
  if (vc <= 0 && d1 >= 0 && d3 <= 0) {                   // 边 AB 区
    const v = d1 / (d1 - d3);
    return new Vec3(a.x + ab.x * v, a.y + ab.y * v, a.z + ab.z * v);
  }

  const cp = sub(p, c);
  const d5 = dot(ab, cp), d6 = dot(ac, cp);
  if (d6 >= 0 && d5 <= d6) return c.clone();             // 顶点 C 区

  const vb = d5 * d2 - d1 * d6;
  if (vb <= 0 && d2 >= 0 && d6 <= 0) {                   // 边 AC 区
    const w = d2 / (d2 - d6);
    return new Vec3(a.x + ac.x * w, a.y + ac.y * w, a.z + ac.z * w);
  }

  const va = d3 * d6 - d5 * d4;
  if (va <= 0 && d4 - d3 >= 0 && d5 - d6 >= 0) {         // 边 BC 区
    const w = (d4 - d3) / (d4 - d3 + (d5 - d6));
    const bc = sub(c, b);
    return new Vec3(b.x + bc.x * w, b.y + bc.y * w, b.z + bc.z * w);
  }

  const denom = 1 / (va + vb + vc);                      // 内部区：重心坐标
  const v = vb * denom, w = vc * denom;
  return new Vec3(
    a.x + ab.x * v + ac.x * w,
    a.y + ab.y * v + ac.y * w,
    a.z + ab.z * v + ac.z * w,
  );
}
```

**手算**：A=(0,0,0)、B=(2,0,0)、C=(0,2,0)，P=(3,1,0)。直觉路径：P 在平面 z=0 上，重心解 s=1.5、t=0.5（P = A + s·AB + t·AC），s+t=2>1 → 落在边 BC 一侧；再对 BC 线段做"点到线段"：t' = (P−B)·(C−B)/|C−B|² = 0 → 最近点是 B=(2,0,0)，距离 √2。与算法的区域判定结果一致。

### 线段-线段最近点：骨骼胶囊碰撞的直觉

胶囊体（capsule）= 一条线段上所有点半径 r 的并集。两根骨骼各绑一条胶囊，碰撞判定就是**两线段的最近距离 < r1 + r2**（第四阶段动画篇 5.3 的骨骼是线段链，见 [04-第四阶段/06-动画系统.md](../04-第四阶段/06-动画系统.md)）。线段-线段最近点（Ericson 5.1.9）：对两条参数化线段的参数 (s, t) 联立求最小距离，把无约束解分别夹回 [0,1]，一个夹完重解另一个：

```typescript
/** 两线段 S1=(p1,q1)、S2=(p2,q2) 的最近点对（Ericson 5.1.9） */
export function closestPointsSegmentSegment(
  p1: Readonly<Vec3>, q1: Readonly<Vec3>,
  p2: Readonly<Vec3>, q2: Readonly<Vec3>,
): { c1: Vec3; c2: Vec3; distSq: number } {
  const d1 = new Vec3(q1.x - p1.x, q1.y - p1.y, q1.z - p1.z);
  const d2 = new Vec3(q2.x - p2.x, q2.y - p2.y, q2.z - p2.z);
  const r  = new Vec3(p1.x - p2.x, p1.y - p2.y, p1.z - p2.z);
  const a = d1.dot(d1), e = d2.dot(d2), f = d2.dot(r);
  const clamp01 = (x: number) => Math.min(Math.max(x, 0), 1);
  let s = 0, t = 0;

  if (a <= 1e-12 && e <= 1e-12) {                 // 两点 vs 点
    // s = t = 0
  } else if (a <= 1e-12) {                        // S1 退化成点
    t = clamp01(f / e);
  } else {
    const c = d1.dot(r);
    if (e <= 1e-12) {                             // S2 退化成点
      s = clamp01(-c / a);
    } else {
      const b = d1.dot(d2);
      const denom = a * e - b * b;                // <= 0 表示两线段方向平行
      if (denom > 1e-12) s = clamp01((b * f - c * e) / denom);
      t = (b * s + f) / e;
      if (t < 0) { t = 0; s = clamp01(-c / a); }       // t 夹到 0，重解 s
      else if (t > 1) { t = 1; s = clamp01((b - c) / a); } // t 夹到 1，重解 s
    }
  }
  const c1 = new Vec3(p1.x + d1.x * s, p1.y + d1.y * s, p1.z + d1.z * s);
  const c2 = new Vec3(p2.x + d2.x * t, p2.y + d2.y * t, p2.z + d2.z * t);
  return { c1, c2, distSq: c1.distanceToSquared(c2) };
}

/** 骨骼胶囊碰撞：两线段最近距离 < r1 + r2 */
export function capsulesOverlap(
  p1: Readonly<Vec3>, q1: Readonly<Vec3>, r1: number,
  p2: Readonly<Vec3>, q2: Readonly<Vec3>, r2: number,
): boolean {
  const { distSq } = closestPointsSegmentSegment(p1, q1, p2, q2);
  return distSq < (r1 + r2) * (r1 + r2);   // 平方比较，免开方
}
```

**手算**：S1 从 (0,0,0) 到 (2,0,0)，S2 从 (1,1,-1) 到 (1,1,1)。d1=(2,0,0)、d2=(0,0,2)、r=(-1,-1,1)；a=4、e=4、f=2、c=-2、b=0，denom=16，s=(0·2−(−2)·4)/16=0.5，t=(0+2)/4=0.5 → c1=(1,0,0)、c2=(1,1,0)，距离恰为 1。若两胶囊半径和 ≥ 1，即碰撞。

## 7.6 求交方法汇总表

第四阶段交互篇已实现并推导了三件套（屏幕坐标到射线的完整逆变换见 4.1），本节做汇总引用并补齐缺口，不重复推导：

| 求交 | 核心方法 | 复杂度量级 | 出处 |
|---|---|---|---|
| 射线-球 | 一元二次判别式 | 约 10 次浮点运算 | 交互篇 4.3.2（[04-第四阶段/05-交互系统.md](../04-第四阶段/05-交互系统.md)） |
| 射线-AABB | slab method 三轴区间交集 | 约 24 次 | 同上 4.3.2 |
| 射线-三角形 | Möller–Trumbore（克莱姆法则） | 约 46 次（两次叉积三次点积） | 同上 4.2 |
| 射线-平面 | $t = \frac{(P_0 - O)\cdot n}{D \cdot n}$，一行公式 | 2 点积 + 1 除 | 本节下方补 |
| 射线-OBB | 变换到局部复用 slab | AABB + 两次基变换 | 本节补全 |
| 射线-圆环 | 四次方程 / 数值迭代 | 解析解病态，不推荐 | 本节成本讨论 |
| 射线-网格 | 逐面 Möller–Trumbore | O(T)；BVH 降到 O(log T) | 交互篇 4.3.1 |

**射线-平面**：射线 $O + tD$ 与平面 $(X - P_0)\cdot n = 0$，代入解出 t；$D \cdot n \approx 0$ 为平行。它是包围体和三角形求交的"原型"——slab method 本质是三对平面的区间求交。

### 射线-OBB：先变换到局部

定向包围盒（OBB，Oriented Bounding Box）= 有旋转的 AABB。求交的干净做法：**把射线变换到盒子的局部标架**（用盒的旋转矩阵的转置——正交阵的转置即逆——乘原点和方向），盒在局部就是轴对齐的，复用 slab method：

```typescript
/** 射线-OBB：变换到局部复用 AABB slab（交互篇 intersectAABB） */
export function intersectOBB(
  origin: Readonly<Vec3>, direction: Readonly<Vec3>,
  center: Readonly<Vec3>,
  axes: readonly [Vec3, Vec3, Vec3],   // 盒的三根单位轴（世界空间，如物体的旋转列）
  halfExtents: readonly [number, number, number],
): number | null {
  // 世界 → 局部：平移到盒心，再用 axes^T（点乘三轴）做旋转的逆
  const ox = origin.x - center.x;
  const oy = origin.y - center.y;
  const oz = origin.z - center.z;
  const localOrigin = new Vec3(
    axes[0].x * ox + axes[0].y * oy + axes[0].z * oz,  // 点乘第 0 轴
    axes[1].x * ox + axes[1].y * oy + axes[1].z * oz,
    axes[2].x * ox + axes[2].y * oy + axes[2].z * oz,
  );
  const localDir = new Vec3(
    axes[0].x * direction.x + axes[0].y * direction.y + axes[0].z * direction.z,
    axes[1].x * direction.x + axes[1].y * direction.y + axes[1].z * direction.z,
    axes[2].x * direction.x + axes[2].y * direction.y + axes[2].z * direction.z,
  );
  const min = new Vec3(-halfExtents[0], -halfExtents[1], -halfExtents[2]);
  const max = new Vec3(halfExtents[0], halfExtents[1], halfExtents[2]);
  return intersectAABB(localOrigin, localDir, min, max);  // 第四阶段交互篇 4.3.2
}
```

关键正确性：变换只用旋转（正交），**不改长度**，所以局部解出的 t 直接就是世界距离——省掉换算。若盒还带非一致缩放，方向被缩放后长度改变，t 必须按交互篇 4.2.2 末尾的方法换算回世界距离（方向变换后记录长度、除回去）。

### 射线-圆环与网格逐面：成本讨论

- **射线-圆环（torus）**：把射线参数化代入圆环隐式方程 $(\sqrt{x^2+z^2} - R)^2 + y^2 - r^2 = 0$，消根号后得到 t 的**四次方程**。四次方程有解析解（Ferrari 公式），但分支极多、数值上病态（相近根导致精度丢失），实时渲染几乎不用；实践两条路：牛顿迭代对 t 数值求根，或者干脆用细分后的网格逐面求交。结论：除非真的需要精确圆环（CAD 类应用），把圆环 tessellate 后走"包围盒 + 逐面"更划算；
- **网格逐面求交的成本**：每三角形一次 Möller–Trumbore（约 46 次浮点运算），2 万面网格每帧一次拾取 = 约 90 万次运算，尚可；但若每帧对几十个物体、或反向（每三角形对多条阴影射线），必须上 BVH（Bounding Volume Hierarchy）：三角形分组成树，粗测大盒再深入，O(T) 降为 O(log T)——交互篇 4.3.1 已给出两级包围体的架构位置，BVH 的构建（中轴/表面积启发式划分）属于性能需要时的下一步。

## 常见坑

1. **UV 镜像处 TBN 翻转**：切线没存 w 分量（或着色器忘了 `cross(N, T) * w`），镜像贴图的那半边 B 方向反了，法线贴图的 x 扰动整体取反——症状是**沿镜像缝两侧明暗跳变、高光"内翻"**。排查：渲一张"切空间 T 可视化"（T*0.5+0.5 输出），沿镜像缝看颜色是否连续；
2. **非均匀缩放下切空间错误**：切向量是表面两点的差，应**直接乘 model 的 3×3**；法线才乘逆转置（第二阶段光照篇 4.1 的推导）。两个典型错法：图省事把切线也喂给 normalMatrix（方向被逆转置扭错）；或反过来把法线乘了 model 3×3。此外即使两者各自正确变换，非均匀缩放后世界空间的 T 与 N 一般**不再正交**，片元里要重做一次施密特正交化（7.3 方案 A 代码里那行就是）；
3. **焊接顶点导致跨 UV 缝平均**：接缝两侧切线被平均成错误方向，出现"光照缝"。按 `(position, uv)` 分组平均或拆分顶点（7.2 末）；
4. **高度图强度单位不匹配**：强度乘在结果法线上而不是梯度上，或不同分辨率的高度图用同一个 strength——法线时陡时平。斜率 = Δh/Δ(世界距离)，Δ(世界距离) = texelSize × 网格间距，换分辨率要重算；
5. **法线贴图被当作 sRGB 纹理解码**：法线存的是方向编码（线性数据），被 sRGB 解码后 (128,128,255) 变成 (0.216,0.216,1.0) 而非 (0.5,0.5,1.0)，法线整体"趴"向 N，光照变平。色彩纪律见本系列 [08-色彩数学](08-色彩数学.md) 8.6；
6. **DCC 烘焙的 Y 通道方向不一致**：DirectX 约定与 OpenGL 约定的法线贴图绿通道相反（"Y-"与"Y+"），直接混用出现诡异的凹凸反转。加载器提供 `normalMapFlipY` 开关，或统一在采样后 `nT.y *= uFlipY;`。
