# 3. 材质与着色器系统

## 3.1 Shader 封装：编译缓存与 program 池

### 3.1.1 设计动机：编译是"每进程一次"的成本，别按物体付费

第二阶段每次初始化都现场编译 shader：`createShader` → `source` → `compile` → `createProgram` → `attach` → `link`。一次链接数十毫秒，100 个同材质物体若各持一份 program，初始化白白多付 99 次编译，而且**同名 uniform 的 location 在不同 program 里互不相通**，缓存 location 的机会也被打散。Shader 封装要达成三件事：

1. **编译错误可读**：把报错行号对回源码行打印，否则 GLSL 报错（"ERROR: 0:57"）就是猜谜。
2. **program 复用**：相同（源码 + 宏定义）组合全进程只链接一次——program 池（program pool）。
3. **shader 对象即用即删**：link 完成后 attach 的两个 shader 可以 delete，驱动内部保留已链接副本。

### 3.1.2 方案对比

| 方案 | 缓存键 | 优点 | 缺点 |
|---|---|---|---|
| 每个 Mesh 自建 program | 不缓存 | 隔离好 | 内存与编译时间翻倍，location 无法共享 |
| 按材质类缓存一个 program | 材质类名 | 简单 | 无法支持宏开关（同材质不同 defines） |
| 源码哈希 + defines 键（本方案） | hash(vs) + hash(fs) + defines 序列化 | 宏变体天然支持，全局唯一 | 需要稳定哈希函数与键序列化 |

第三方案的缓存键形如 `8f3a12c2|b71d9e04|USE_MAP,USE_SKINNING`，序列化时 defines 按**字典序**排列——顺序不同内容相同的 defines 必须命中同一键，否则"缓存"变成"缓存泄漏"。

### 3.1.3 完整核心代码：编译、报错定位与 ProgramCache

```typescript
// renderer/shader/ProgramCache.ts
const enum ShaderType { Vertex, Fragment }

/** 把源码带上行号打印，让 GLSL 报错行号可读 */
function numberedSource(source: string): string {
  return source
    .split("\n")
    .map((line, i) => `${String(i + 1).padStart(3)} | ${line}`)
    .join("\n");
}

function compileShader(
  gl: WebGL2RenderingContext,
  type: number,
  label: ShaderType,
  source: string,
): WebGLShader {
  const shader = gl.createShader(type);
  if (!shader) throw new Error("createShader 返回 null（上下文可能已丢失）");
  gl.shaderSource(shader, source);
  gl.compileShader(shader);
  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    const info = gl.getShaderInfoLog(shader) ?? "（无日志）";
    const head = label === ShaderType.Vertex ? "顶点着色器" : "片元着色器";
    // 报错里的行号基于注入 defines 之后的最终源码，
    // 因此错误信息里打印的是注入后的源码（defines 注入见 3.4.3）
    throw new Error(`${head}编译失败：\n${info}\n----- 源码 -----\n${numberedSource(source)}`);
  }
  return shader;
}

/** djb2 字符串哈希：短、稳定、够用（不用于安全） */
export function hashString(str: string): string {
  let h = 5381;
  for (let i = 0; i < str.length; i++) {
    h = ((h << 5) + h + str.charCodeAt(i)) >>> 0; // h * 33 + c
  }
  return h.toString(16);
}

export interface ShaderDefineValue {
  [key: string]: boolean | number | string;
}

export class ProgramCache {
  private pool = new Map<string, { program: WebGLProgram; refCount: number }>();

  /** 取或建 program；defines 序列化前先排序保证键稳定 */
  acquire(
    gl: WebGL2RenderingContext,
    vertexSource: string,
    fragmentSource: string,
    defines: ShaderDefineValue = {},
  ): WebGLProgram {
    const defineKey = Object.keys(defines)
      .filter((k) => defines[k] !== false)
      .sort() // 字典序！顺序不同内容相同必须同键
      .map((k) => (defines[k] === true ? k : `${k}=${defines[k]}`))
      .join(",");
    const key = `${hashString(vertexSource)}|${hashString(fragmentSource)}|${defineKey}`;

    const hit = this.pool.get(key);
    if (hit) {
      hit.refCount++;
      return hit.program;
    }

    // 3.4 节：defines 注入发生在编译前（此处调用 injectDefines）
    const vsFinal = injectDefines(vertexSource, defines);
    const fsFinal = injectDefines(fragmentSource, defines);

    const vs = compileShader(gl, gl.VERTEX_SHADER, ShaderType.Vertex, vsFinal);
    const fs = compileShader(gl, gl.FRAGMENT_SHADER, ShaderType.Fragment, fsFinal);
    const program = gl.createProgram();
    if (!program) throw new Error("createProgram 返回 null");
    gl.attachShader(program, vs);
    gl.attachShader(program, fs);
    gl.linkProgram(program);
    // link 完 shader 即可删：驱动保留已链接副本
    gl.deleteShader(vs);
    gl.deleteShader(fs);

    if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
      const info = gl.getProgramInfoLog(program) ?? "（无日志）";
      throw new Error(`program 链接失败（key=${key}）：${info}`);
    }

    this.pool.set(key, { program, refCount: 1 });
    return program;
  }

  /** 材质 dispose 时归还引用，归零删除（防止变体无限增长，见 1.3.4） */
  release(gl: WebGL2RenderingContext, program: WebGLProgram): void {
    for (const [key, entry] of this.pool) {
      if (entry.program === program) {
        if (--entry.refCount <= 0) {
          gl.deleteProgram(program);
          this.pool.delete(key);
        }
        return;
      }
    }
  }

  get size(): number {
    return this.pool.size;
  }
}

// 全局单池：整个 GL 上下文共享（每上下文一个，多 canvas 场景按上下文存）
export const programCache = new ProgramCache();
```

设计要点：`release` 用引用计数而非直接删除，因为多个 Material 实例可能共享同一变体（比如 100 个不同颜色的 Mesh 共用 `USE_MAP` 变体）。这与 1.3 的"共享资源谁负责销毁"约定配套。

## 3.2 uniform 反射与自动上传

### 3.2.1 设计动机：手写 location 表是体力活加事故源

第二阶段的上传代码是手写的：`gl.getUniformLocation(program, "u_color")`，然后按类型手调 `uniform4f`/`uniformMatrix4fv`/`uniform1i`。三个问题：每个新 shader 抄一遍；类型对不上不报错只画错（`uniform4f` 传给 `vec3` 直接静默失败）；sampler 的纹理单元（texture unit）分配靠人脑记账。WebGL 自带反射（reflection）能力：**program 链接后可以枚举出全部活跃 uniform（active uniform）的名字、类型、数量**——框架应该在链接后自动做一次，把"人脑记账"变"机器记账"。

### 3.2.2 方案对比

| 方案 | 上传时机 | 优点 | 缺点 |
|---|---|---|---|
| 手写 location 表 | 每帧手调 | 直观 | 每 shader 重复劳动，类型错误静默 |
| 反射 + 每帧全量上传 | 每帧对每个 active uniform 上传 | 逻辑简单 | uniform1f 也每帧传，浪费 |
| 反射 + 值缓存跳过（本方案） | 每帧遍历，但值没变就跳过 | 自动化且去掉冗余调用 | 多一份 lastValue 内存 |

"活跃"二字值得强调：编译器会剔除**没被使用的** uniform，`getActiveUniform` 枚举不到它们，`getUniformLocation` 对它们返回 null。所以反射收集的是"着色器真正消费的集合"，恰好就是需要上传的集合——手写表反而容易写出永远传不上去的死 uniform。

### 3.2.3 完整核心代码：UniformBlock 反射与类型分派上传

```typescript
// renderer/shader/UniformBlock.ts
export type UniformValue =
  | number
  | boolean
  | Float32Array        // Vec2/3/4、Mat3/4、标量数组
  | Int32Array          // int/ivec 数组
  | { texture: WebGLTexture; unit: number }; // 采样器

interface ActiveUniform {
  name: string;                  // 去 [0] 后缀后的名字
  location: WebGLUniformLocation;
  type: GLenum;
  size: number;                  // >1 表示数组
  textureUnit: number;           // 仅 sampler 使用
  lastValue: UniformValue | null; // 值缓存，跳过冗余上传
}

export class UniformBlock {
  private uniforms = new Map<string, ActiveUniform>();
  private nextTextureUnit = 0;

  constructor(private gl: WebGL2RenderingContext, program: WebGLProgram) {
    this.reflect(program);
  }

  /** 链接后执行一次：getActiveUniform 枚举 + location 缓存 + sampler 单元分配 */
  private reflect(program: WebGLProgram): void {
    const gl = this.gl;
    const count = gl.getProgramParameter(program, gl.ACTIVE_UNIFORMS) as number;
    for (let i = 0; i < count; i++) {
      const info = gl.getActiveUniform(program, i);
      if (!info) continue;
      // 数组 uniform 的 name 形如 "u_lights[0]"，
      // 去掉 [0] 后整个数组可用一个 location + uniform*fv 一次上传
      const name = info.name.replace(/\[0\]$/, "");
      const location = gl.getUniformLocation(program, name);
      if (location === null) continue;

      let textureUnit = -1;
      if (info.type === gl.SAMPLER_2D || info.type === gl.SAMPLER_CUBE) {
        textureUnit = this.nextTextureUnit++; // 反射期一次性分配单元
      }
      this.uniforms.set(name, {
        name, location, type: info.type, size: info.size,
        textureUnit, lastValue: null,
      });
    }
  }

  /** 每帧上传：遍历反射表，值变化才下发 */
  upload(values: Record<string, UniformValue>, state: StateCache): void {
    const gl = this.gl;
    for (const u of this.uniforms.values()) {
      const value = values[u.name];
      if (value === undefined) continue; // 材质没提供，着色器用默认值
      if (this.sameValue(u.lastValue, value)) continue; // 值没变，跳过
      this.uploadOne(u, value, state);
      u.lastValue = value;
    }
  }

  private sameValue(a: UniformValue | null, b: UniformValue): boolean {
    if (a === b) return true; // 引用相等快速路径（Float32Array 常复用同一实例）
    if (typeof a === "number" && typeof b === "number") return a === b;
    if (a instanceof Float32Array && b instanceof Float32Array) {
      if (a.length !== b.length) return false;
      for (let i = 0; i < a.length; i++) if (a[i] !== b[i]) return false;
      return true;
    }
    return false;
  }

  private uploadOne(u: ActiveUniform, value: UniformValue, state: StateCache): void {
    const gl = this.gl;
    switch (u.type) {
      case gl.FLOAT:        gl.uniform1f(u.location, value as number); break;
      case gl.FLOAT_VEC2:   gl.uniform2fv(u.location, value as Float32Array); break;
      case gl.FLOAT_VEC3:   gl.uniform3fv(u.location, value as Float32Array); break;
      case gl.FLOAT_VEC4:   gl.uniform4fv(u.location, value as Float32Array); break;
      case gl.FLOAT_MAT3:   gl.uniformMatrix3fv(u.location, false, value as Float32Array); break;
      case gl.FLOAT_MAT4:   gl.uniformMatrix4fv(u.location, false, value as Float32Array); break;
      case gl.INT:
      case gl.BOOL:         gl.uniform1i(u.location, value as number); break;
      case gl.SAMPLER_2D:
      case gl.SAMPLER_CUBE: {
        const t = value as { texture: WebGLTexture; unit: number };
        const target = u.type === gl.SAMPLER_CUBE ? gl.TEXTURE_CUBE_MAP : gl.TEXTURE_2D;
        // 纹理绑定走 StateCache（02 册），单元是反射期分配的固定单元
        state.bindTexture(t.unit, target, t.texture);
        gl.uniform1i(u.location, t.unit);
        break;
      }
      default:
        throw new Error(`未支持的 uniform 类型 ${u.type}（${u.name}）`);
    }
  }
}
```

四个设计决策展开：

1. **`[0]` 后缀必须去掉**。数组 uniform `u_lights[8]` 反射出来的 name 是 `u_lights[0]`，`getUniformLocation(program, "u_lights")` 拿到的单个 location 配合 `uniform3fv` + 24 长数组可一次上传整个数组；如果按 `u_lights[3]` 单元素逐个取 location 上传，八根光源就是八次调用。
2. **sampler 纹理单元在反射期分配**，而不是上传期。单元号对每个 program 是固定的，`uniform1i(location, unit)` 甚至只需设一次（上面的值缓存会保证）。换纹理只动 `bindTexture`，不动 `uniform1i`。
3. **值缓存以"引用相等 + 数组逐元素"两级比较**。`Float32Array` 若每帧 new 一个新实例，逐元素比较仍能识别"值没变"；鼓励用户复用数组实例走快速路径。
4. **`uniformMatrix4fv` 第二参恒 false**：我们不做列主序/行主序转置，minmath 就是列主序（第三阶段约定），转置开关是给错记矩阵的人准备的逃生门，不开。

## 3.3 材质参数到 uniform 的映射

### 3.3.1 设计动机：用户该说"我要红色"，而不是"我要往 location 0x5f 传 1,0,0,1"

UniformBlock 解决了"怎么传"，材质（Material）解决"传什么"：它是**面向用户的参数集合 + 面向渲染器的 uniform 字典**之间的翻译层。同时渲染器还需要一批"框架算好的矩阵"（model/view/projection/normal），这些不是用户参数，属于**内置 uniform（built-in uniforms）**——命名约定以 `u_` 前缀统一，材质字典里保留同名键由渲染器在 draw 时注入。

### 3.3.2 方案对比：参数怎么声明

| 方案 | 用户写法 | 变更材质参数 | 适用 |
|---|---|---|---|
| 子类强类型字段 | `mat.color.set(1,0,0)` | setter 里标脏 | 固定几种材质，类型提示最好 |
| 松散字典 | `mat.uniforms.u_color = [...]` | 直接赋值 | 灵活但无提示、易拼错名字 |
| 强类型字段 + 自动同步字典（本方案） | `mat.color.set(1,0,0)` | 同步时打包进 uniforms | 兼得：字段有类型，上传走统一字典 |

第三方案的关键是**同步时机**：draw 前由 `syncUniforms()` 把强类型字段打包成字典。字段到 uniform 键的映射用声明式元数据写一次：

```typescript
// scene/Material.ts
import { programCache } from "../renderer/shader/ProgramCache";
import { UniformBlock, UniformValue } from "../renderer/shader/UniformBlock";
import { StateCache } from "../renderer/StateCache";
import { Color } from "../math/Color";

/** 字段 -> uniform 键的映射元数据（声明式，子类填表） */
interface UniformMapping {
  property: string;      // Material 上的强类型字段名
  uniform: string;       // GLSL 里的 uniform 名
}

export abstract class Material {
  private static nextId = 1;
  readonly id = Material.nextId++;       // 渲染队列排序键（03 册），创建即定
  transparent = false;

  /** 用户不直接碰这个：由 syncUniforms 填充 + 渲染器注入内置矩阵 */
  readonly uniforms: Record<string, UniformValue> = {};

  /** 宏开关（3.4 节）：决定 program 变体 */
  readonly defines: Record<string, boolean | number | string> = {};

  protected abstract readonly mappings: UniformMapping[];
  abstract readonly vertexShader: string;
  abstract readonly fragmentShader: string;

  private program: WebGLProgram | null = null;
  private block: UniformBlock | null = null;

  /** 渲染器调：确保 program 与反射表就绪（含宏变体） */
  acquireProgram(gl: WebGL2RenderingContext): WebGLProgram {
    if (this.program === null) {
      this.program = programCache.acquire(
        gl, this.vertexShader, this.fragmentShader, this.defines,
      );
      this.block = new UniformBlock(gl, this.program); // 反射只做一次
    }
    return this.program;
  }

  /** 渲染器每帧 draw 前调 */
  uploadUniforms(
    gl: WebGL2RenderingContext, state: StateCache,
    mesh: Mesh, camera: Camera,
  ): void {
    this.syncUniforms();
    // 内置 uniform 注入：框架算好的矩阵（normalMatrix 见 03 册 2.1.4 坑 2）
    const m = mesh.matrixWorld; // 已是列主序 Float32 兼容
    this.uniforms["u_model"] = m;
    this.uniforms["u_view"] = camera.viewMatrix;
    this.uniforms["u_projection"] = camera.projectionMatrix;
    this.uniforms["u_normalMatrix"] = mat3NormalFromMat4(m);
    this.block!.upload(this.uniforms, state);
  }

  /** 强类型字段打包进字典（子类实现或由映射表驱动） */
  protected syncUniforms(): void {
    for (const map of this.mappings) {
      const v = (this as unknown as Record<string, Color | number>)[map.property];
      if (v instanceof Color) {
        this.uniforms[map.uniform] = v.toArray();
      } else if (typeof v === "number") {
        this.uniforms[map.uniform] = v;
      }
    }
  }

  dispose(gl: WebGL2RenderingContext): void {
    if (this.program) programCache.release(gl, this.program);
    this.program = null;
    this.block = null;
  }
}
```

```typescript
// scene/materials/PhongMaterial.ts —— 子类示例：声明式映射
export class PhongMaterial extends Material {
  color = new Color(1, 1, 1);
  shininess = 32;
  map: Texture | null = null;

  protected readonly mappings: UniformMapping[] = [
    { property: "color", uniform: "u_color" },
    { property: "shininess", uniform: "u_shininess" },
  ];

  readonly vertexShader = shaderlib.phongVert;
  readonly fragmentShader = shaderlib.phongFrag;

  constructor() {
    super();
    // 贴图开关：有没有贴图是两个 program 变体（3.4 节）
    this.defines["USE_MAP"] = false;
  }

  setMap(map: Texture | null): this {
    this.map = map;
    this.defines["USE_MAP"] = map !== null;
    // defines 变了 -> 现有 program 失效，归还并置空
    this.invalidateProgram();
    if (map) this.uniforms["u_map"] = { texture: map.glTexture, unit: -1 };
    return this;
  }
}
```

注意 `setMap` 里 defines 变化后 `invalidateProgram()`（Material 基类方法：release 旧 program、置空缓存）——defines 是**构造期参数**而不是**帧间可变参数**，改 defines 等于换变体，频率应该是"设置一次、长期不变"。

### 3.3.3 常见坑

1. **同名 uniform 在不同 program 里 location 不同**。location 缓存必须挂在 program 上（UniformBlock 的实例字段），挂在全局或材质上，换 program 就串号。
2. **uniform 名拼错无提示**。反射表里没有 `u_colour`（用户拼错）时上面代码是"跳过"，开发期应改为告警。建议在 `upload` 里加 dev 模式校验：字典里的键若不在反射表中，`console.warn` 一次（只告警一次，避免刷屏）。
3. **纹理对象在 CPU 侧被 dispose 但字典还引用**。上传时 `bindTexture` 传的是已删除的 texture 对象，驱动行为未定义（多半画黑或维持旧图）。AssetCache 卸载纹理时应通知引用它的材质（07 册 6.2 的依赖方向反转）。
4. **把 `u_model` 之类的内置键暴露给用户覆盖**。注入顺序若在用户字典打包之后，用户值被静默覆盖；顺序反了则是用户能覆盖框架值——两种行为选一个写进文档，本框架选"内置最后注入、不可覆盖"。

## 3.4 #define 宏开关与 uber shader（变体管理）

### 3.4.1 设计动机：一个着色器装下所有功能开关

有贴图画贴图、没贴图画纯色；蒙皮网格要多四根权重 attribute、静态网格不要——为每种组合写一份 GLSL，源码文件数按组合爆炸。uber shader（超着色器）思路：**一份源码 + 预处理宏开关**，GLSL 里用 `#ifdef` 圈住可选路径，编译期由 defines 决定哪段参与编译。变体（variant）= 源码 + defines 的组合产物。

```glsl
// 片元着色器片段：宏圈住的可选路径
#ifdef USE_MAP
  vec4 texel = texture(u_map, v_uv);
  baseColor *= texel;
#endif
#ifdef USE_SKINNING
  // 法线也要跟随骨骼变换（用 jointMatrix 的 3x3 部分）
  normal = mat3(u_jointMatrix[int(a_joints.x)]) * normal;
#endif
```

好处不止省文件：未走到的 `#ifdef` 分支整体不编译，**运行时零开销**——这是与"运行时 if 分支"的本质区别，GPU 分支两个路径都要算，宏分支只算命中的。

### 3.4.2 方案对比与变体爆炸

| 方案 | 变体数（n 个独立开关） | 管理 |
|---|---|---|
| 每组合手写源码 | 手写文件数 = 2^n | 不可维护 |
| uber shader + 全量预编译 | 2^n 个 program | 编译时间爆炸（8 个开关 256 变体） |
| uber shader + 按需编译缓存（本方案） | 只编译场景实际用到的组合 | 需要约束开关组合（互斥组） |

按需编译的关键风险是**组合爆炸**：独立开关每加一个，理论变体翻倍。两个治理手段：

1. **互斥组**：`LIGHT_MODE = NONE | PHONG | BLINN_PHONG` 用一个带值宏（`#define LIGHT_MODE 2`）而不是三个布尔宏，把 2×2 变体合成 3 选 1。
2. **变体上限熔断**：ProgramCache 超过阈值（比如 64）时告警——真需要 64 个变体说明开关设计有问题，该重构的是宏而不是缓存。

### 3.4.3 完整核心代码：defines 注入与变体键

```typescript
// renderer/shader/injectDefines.ts —— 编译前注入宏
export function injectDefines(
  source: string,
  defines: Record<string, boolean | number | string>,
): string {
  const lines: string[] = ["#version 300 es"]; // 注入点必须在最前（GLSL3 版本声明必须第一行）
  for (const key of Object.keys(defines).sort()) {
    const v = defines[key];
    if (v === false) continue;         // false = 不定义
    lines.push(v === true ? `#define ${key}` : `#define ${key} ${v}`);
  }
  // 去掉源码里原有的版本行（防止重复声明），其余原样拼接
  const body = source.replace(/^#version\s+.*\n/, "");
  return [...lines, body].join("\n");
}
```

```typescript
// 变体管理全景：Material.defines -> ProgramCache 键 -> 独立 program
// 使用侧效果（P3 实践任务的验收标准）：
const matA = new PhongMaterial();          // defines: { USE_MAP: false }
const matB = new PhongMaterial();          // defines: { USE_MAP: false }
matA.setMap(brickTexture);                 // defines: { USE_MAP: true }
// matA.acquireProgram() 键: "<hash>|<hash>|USE_MAP"     -> 新编译 program #1
// matB.acquireProgram() 键: "<hash>|<hash>|"            -> 新编译 program #2

```

对照 three.js 的现实映射：`material.defines` + `WebGLPrograms.getProgramCacheKey` 就是这套机制的工业版；它把"材质类型 + 光照环境 + 开关"全部序列化进缓存键，变体数靠"宏总量克制"控制。读源码时先找 `getProgramCacheKey`，就找到了变体管理的入口。

### 3.4.4 常见坑

1. **`#version` 必须是注入后源码的第一行**，前面多一个空行都报错。注入函数因此先拼版本行（见上面代码），并剔除源码自带版本行。
2. **defines 值变化后旧 program 未失效**。用户改了 `defines` 但没走 `setMap` 这类封装方法（直接 `mat.defines.USE_MAP = true`），program 还是旧变体，画面与代码不符。对策：`defines` 用 Proxy 或 getter/setter 拦截赋值自动 `invalidateProgram()`，至少在文档写明"改 defines 需调 invalidate"。
3. **宏变了，attribute 布局也变**（USE_SKINNING 开启后多出 a_joints/a_weights 两个 attribute）。VAO 若在变体切换前录制，绑定 attribute 的位置对不上。本框架的 VAO 延迟到首绘创建（1.3.3），并且 material 变化会导致 geometry 重新检查 attribute 绑定——这是 02/04 两册交叉的坑，值得在自测第 5 题再想一遍。
4. **字符串宏注入拼出非法 GLSL**。`#define NAME ${userInput}` 若 user input 含换行/分号，轻则编译错、重则注入。宏值只应允许枚举白名单。
