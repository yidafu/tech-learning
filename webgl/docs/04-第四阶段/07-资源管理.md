# 6. 资源管理

## 6.1 加载队列与 Promise 化

### 6.1.1 设计动机：从"回调地狱"到"可组合的加载"

第二阶段加载贴图的写法是 `new Image()` + `onload` 回调，一张图一层回调，一个模型（1 个 JSON + 2 个 bin + 4 张图）嵌套出来就是六级金字塔。ES6 的 Promise（期约）把"完成/失败"变成值的一部分，`async/await` 让依赖关系写成同步顺序。框架要做的封装是三件事：

1. **统一入口**：任何资源 `load(url): Promise<T>`，调用方不关心是 fetch、Image 还是 AudioBuffer；
2. **去重**：同一 URL 并发请求两次（两个 mesh 引用同一贴图），只发一次网络请求、返回同一个 Promise 实例；
3. **并发调度**：浏览器同域名 HTTP 并发有上限（HTTP/1.1 典型 6 个），一次性 fetch 50 个资源反而互相拖慢——排队、限制在飞（in-flight）数量。

### 6.1.2 方案对比

| 方案 | 做法 | 进度 | 取消 |
|---|---|---|---|
| 直接 fetch 各处散调 | 零封装 | 无 | AbortController 手动接 |
| Promise 全局缓存（本方案基础） | Map<url, Promise> | 无 | 差 |
| 缓存 + 并发队列 + 进度聚合（本方案） | Scheduler 排队、去重、loaded/total 事件 | 有 | 单任务 AbortController |

取消（cancellation）要诚实：Promise 一旦创建无法"取消"，只能让底层动作（fetch 的 AbortController）停止、让 Promise 落到 rejected。迷你框架实现"队列级取消"（清空未开始的任务），进行中任务不做中途放弃——把复杂度花在更高频的需求上。

### 6.1.3 完整核心代码：并发调度与 Loader 基类

```typescript
// resource/Scheduler.ts —— 并发限制队列
export class Scheduler {
  private active = 0;
  private readonly queue: (() => void)[] = [];

  constructor(private readonly maxConcurrent = 4) {}

  /** 包一层任务：超过并发上限时排队，空位出现时唤醒 */
  async run<T>(task: () => Promise<T>): Promise<T> {
    if (this.active >= this.maxConcurrent) {
      await new Promise<void>((resolve) => this.queue.push(resolve));
    }
    this.active++;
    try {
      return await task();
    } finally {
      this.active--;
      this.queue.shift()?.(); // 唤醒下一个排队者
    }
  }
}

// resource/Loader.ts —— Promise 化基类：去重 + 进度
export type ProgressHandler = (loaded: number, total: number) => void;

export abstract class Loader<T> {
  /** url -> in-flight promise；完成后迁入 done 缓存 */
  private readonly inflight = new Map<string, Promise<T>>();
  private readonly done = new Map<string, T>();
  private readonly scheduler = new Scheduler(4);
  /** 全局进度：本 loader 承载的所有任务聚合 */
  loaded = 0;
  total = 0;
  onProgress: ProgressHandler | null = null;

  load(url: string): Promise<T> {
    // 1) 已完成：直接命中
    const cached = this.done.get(url);
    if (cached) return Promise.resolve(cached);
    // 2) 在飞：返回同一个 promise（去重的关键）
    const pending = this.inflight.get(url);
    if (pending) return pending;

    this.total++;
    const promise = this.scheduler.run(() =>
      this.fetch(url, (loadedBytes, totalBytes) => {
        // 细粒度进度（fetch 流式 Content-Length）向上聚合
        this.onProgress?.(this.loaded + loadedBytes / Math.max(totalBytes, 1), this.total);
      }),
    )
      .then((data) => this.parse(data, url))
      .then(
        (asset) => {
          this.loaded++;
          this.inflight.delete(url);
          this.done.set(url, asset);
          this.onProgress?.(this.loaded, this.total);
          return asset;
        },
        (err) => {
          // 失败也出队：允许重试（下次 load 重新入队）
          this.inflight.delete(url);
          throw new Error(`加载失败 ${url}：${(err as Error).message}`);
        },
      );
    this.inflight.set(url, promise);
    return promise;
  }

  /** 子类实现：拿到原始数据（ArrayBuffer/text/Image），报告进度 */
  protected abstract fetch(url: string, onProgress: ProgressHandler): Promise<unknown>;
  /** 子类实现：原始数据 -> 框架对象（Geometry/Texture/AnimationClip...） */
  protected abstract parse(data: unknown, url: string): T | Promise<T>;

  /** 释放：只清缓存，GPU 对象的 delete 由 02 册 dispose 协议负责 */
  clear(): void {
    this.inflight.clear();
    this.done.clear();
    this.loaded = this.total = 0;
  }
}
```

```typescript
// resource/loaders.ts —— 两个最简子类示例
export class TextureLoader extends Loader<Texture> {
  protected async fetch(url: string): Promise<unknown> {
    const image = new Image();
    image.crossOrigin = "anonymous"; // 跨域贴图必须，否则 canvas 被污染、texImage2D 报错
    await new Promise((resolve, reject) => {
      image.onload = resolve;
      image.onerror = () => reject(new Error("图片解码失败"));
      image.src = url;
    });
    return image;
  }
  protected parse(image: unknown): Texture {
    return Texture.fromImage(image as HTMLImageElement); // 上传 GPU 由渲染层首绘时做
  }
}

export class BufferLoader extends Loader<ArrayBuffer> {
  protected async fetch(url: string, onProgress: ProgressHandler): Promise<unknown> {
    const resp = await fetch(url);
    if (!resp.ok) throw new Error(`HTTP ${resp.status}`);
    const total = Number(resp.headers.get("Content-Length") ?? 0);
    // 流式读取聚合进度（Content-Length 缺失时退化为无进度）
    if (!resp.body || total === 0) return await resp.arrayBuffer();
    const reader = resp.body.getReader();
    const chunks: Uint8Array[] = [];
    let loaded = 0;
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      chunks.push(value);
      loaded += value.byteLength;
      onProgress(loaded, total);
    }
    return concatChunks(chunks, loaded);
  }
  protected parse(data: unknown): ArrayBuffer {
    return data as ArrayBuffer;
  }
}
```

## 6.2 依赖管理

### 6.2.1 设计动机：一个 glTF 引用一串外部资源

`.gltf` 主文件是 JSON，它的网格数据在 `.bin`、贴图在 `.png`、蒙皮逆矩阵在 accessor 里——**主文件只是目录，真正的资源是引用图（reference graph）**。依赖管理要回答四个问题：相对 URI 怎么解析（6.2.2）、依赖失败怎么传播（6.2.3）、共享资源怎么避免重复加载（6.1 已答：URL 去重）、资源卸载时依赖关系怎么联动（6.2.4）。

### 6.2.2 URI 解析：相对路径的基准是"引用者的位置"

glTF 内部引用分三类，解析规则各不相同：

| 引用形态 | 例子 | 解析 |
|---|---|---|
| data URI | `data:application/octet-stream;base64,AAA...` | 就地解码，不产生网络请求 |
| 绝对 URL | `https://cdn.example.com/tex.png` | 直接用 |
| 相对路径 | `textures/diffuse.png` | 相对**主文件的 URL** 解析 |

```typescript
// resource/resolveURI.ts
export function resolveURI(uri: string, baseURL: string): string {
  if (uri.startsWith("data:")) return uri;           // data URI 原样返回
  return new URL(uri, baseURL).href;                 // 相对路径基于主文件 URL
}

/** data URI 解码：base64 或百分号编码文本 -> ArrayBuffer */
export function decodeDataURI(uri: string): ArrayBuffer {
  const match = /^data:([^;,]+)?((?:;[^,]+)*),(.*)$/s.exec(uri);
  if (!match) throw new Error(`非法 data URI：${uri.slice(0, 32)}...`);
  const [, , params, payload] = match;
  if (params?.includes(";base64")) {
    const bin = atob(payload);
    const bytes = new Uint8Array(bin.length);
    for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
    return bytes.buffer;
  }
  const text = decodeURIComponent(payload);
  return new TextEncoder().encode(text).buffer;
}
```

易错点：`new URL(uri, base)` 的 base 必须是**目录**形式的 URL——`https://host/models/a.gltf` 作为 base 时相对路径 `tex.png` 会正确解析到 `https://host/models/tex.png`（URL 构造器自动去掉最后一段文件名）。但如果你自己拼 base（比如 `location.href` 加路径），漏掉文件名就会全部 404。

### 6.2.3 失败传播与部分加载

依赖加载失败的传播规则要显式设计，否则出现"模型加载了一半，场景里挂着半截节点"：

1. **必需依赖失败 -> 整个资源 reject**：`.bin` 拉不到，整个 glTF reject，不产出"没有网格的节点树"；
2. **可选依赖失败 -> 降级 + 告警**：某张贴图 404，材质降级为纯色并 `console.warn`（渲染不能因为一张装饰贴图全挂）；
3. **reject 时回滚已加载依赖的引用**：调用方拿到 reject 后可能放弃这个模型，AssetCache 的引用计数要把这次预占的引用还回去——否则资源永远"被引用"，无法卸载。

```typescript
// 失败传播的形状（GLTFLoader 内部）
async loadDependencies(json: GLTFJSON, baseURL: string): Promise<Deps> {
  const buffers = await Promise.all(
    json.buffers.map(async (b) => {
      const uri = resolveURI(b.uri, baseURL);
      return b.uri === undefined
        ? (await this.glbBuffer)          // GLB 二进制块（内嵌 buffer）
        : this.bufferLoader.load(uri);    // 走 6.1 去重队列
    }),
  );
  // 任一 reject：Promise.all 整体 reject -> 上层 catch 回滚引用计数
  // 贴图改为 allSettled：允许部分失败降级
  const images = await Promise.allSettled(
    json.images.map((img) => this.textureLoader.load(resolveURI(img.uri, baseURL))),
  );
  return { buffers, images };
}
```

### 6.2.4 缓存与卸载的联动

AssetCache（资产缓存）在 Loader 的 URL 缓存之上再加**引用计数**，解决"两个模型共享一张贴图，卸载一个不能删掉另一个还在用的图"：

```typescript
// resource/AssetCache.ts —— 引用计数骨架
export class AssetCache {
  private refs = new Map<string, { asset: unknown; count: number }>();

  retain<T>(url: string, asset: T): T {
    const entry = this.refs.get(url);
    if (entry) entry.count++;
    else this.refs.set(url, { asset, count: 1 });
    return asset;
  }

  /** 归零才真正 dispose；dispose 委托给 02 册的 Disposable 协议 */
  release(url: string, dispose: (asset: unknown) => void): void {
    const entry = this.refs.get(url);
    if (!entry) return;
    if (--entry.count === 0) {
      dispose(entry.asset);
      this.refs.delete(url);
    }
  }
}
```

## 6.3 简版 glTF 加载器

### 6.3.1 先看懂 JSON：glTF 2.0 的"目录结构"

一个 `.gltf` 文件的核心字段（加载器需要的全部）：

```jsonc
{
  "asset": { "version": "2.0" },              // 版本闸门
  "scene": 0,                                  // 默认场景索引
  "scenes": [{ "nodes": [0] }],                // 场景 -> 根节点列表
  "nodes": [{ "mesh": 0, "skin": 0,            // 节点：TRS 或 matrix + 引用
              "translation": [0,0,0], "rotation": [0,0,0,1], "scale": [1,1,1],
              "children": [1,2] }],
  "meshes": [{ "primitives": [{ "attributes": { "POSITION": 0, "NORMAL": 1, "TEXCOORD_0": 2 },
                                 "indices": 3, "material": 0, "mode": 4 }] }],
  "materials": [{ "pbrMetallicRoughness": { "baseColorFactor": [1,1,1,1],
                                            "baseColorTexture": { "index": 0 },
                                            "metallicFactor": 0, "roughnessFactor": 1 },
                  "alphaMode": "OPAQUE", "doubleSided": false }],
  "accessors": [{ "bufferView": 0, "componentType": 5126, "count": 12345,
                  "type": "VEC3", "byteOffset": 0 }],
  "bufferViews": [{ "buffer": 0, "byteOffset": 0, "byteLength": 148140, "target": 34962 }],
  "buffers": [{ "uri": "model.bin", "byteLength": 200000 }],
  "skins": [{ "joints": [1,2,3], "inverseBindMatrices": 4 }],
  "images": [{ "uri": "diffuse.png" }],
  "textures": [{ "source": 0 }]
}
```

三张映射表记牢，解析就是查表：

- **数字索引即外键**：`nodes[i].mesh` 指向 `meshes[i]`，一切引用按索引查表；
- **componentType -> 元素字节**：5120 BYTE(1)、5121 UNSIGNED_BYTE(1)、5122 SHORT(2)、5123 UNSIGNED_SHORT(2)、5125 UNSIGNED_INT(4)、5126 FLOAT(4)；
- **type -> 分量数**：SCALAR 1、VEC2 2、VEC3 3、VEC4 4、MAT4 16。

### 6.3.2 分步实现清单（P6 的施工图）

| 步骤 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 1. JSON 解析与校验 | .gltf 文本 | glTF 对象 | 校验 `asset.version` 主版本是 2 |
| 2. buffers 加载 | `buffers[].uri` | `ArrayBuffer[]` | data URI 就地解码；GLB 用二进制块；走 6.1 队列 |
| 3. bufferViews 切片 | buffer + bufferView | 视图（offset/length） | 只是记录区间，不复制数据 |
| 4. accessors 实例化 | bufferView + accessor | `TypedArray` | componentType/type 查表定构造器；处理 byteOffset/byteStride |
| 5. 材质映射 | materials[] | `Material` 实例 | baseColorFactor/colorTexture -> uniforms；metallic/roughness 进 defines 开关；alphaMode=BLEND -> transparent=true |
| 6. 网格 primitive | meshes[] + accessors | `Geometry` | POSITION/NORMAL/TEXCOORD_0 -> attributes；indices -> 索引缓冲；mode=4 三角形 |
| 7. 节点层级 | nodes[] | `Node3D` 树 | **matrix 与 TRS 同在时以 matrix 为准**；children 递归挂接；注意 glTF 的 rotation 是四元数 (x,y,z,w) |
| 8. 蒙皮 | skins[] | `Skeleton` | joints 数组建骨骼引用；inverseBindMatrices 从 accessor 读（每骨 16 float） |
| 9. 场景组装 | scenes[scene] | 根 `Node3D` | 根节点包一层返回；动画 clips（若有）一并转成 5.1 的轨道结构 |

### 6.3.3 核心代码：accessor 到节点层级的四个关键函数

```typescript
// resource/gltf/GLTFLoader.ts（节选核心路径）

const COMPONENT_BYTES: Record<number, number> = {
  5120: 1, 5121: 1, 5122: 2, 5123: 2, 5125: 4, 5126: 4,
};
const TYPE_COUNT: Record<string, number> = {
  SCALAR: 1, VEC2: 2, VEC3: 3, VEC4: 4, MAT2: 4, MAT3: 9, MAT4: 16,
};
const CTOR: Record<number, new (n: number) => ArrayBufferView> = {
  5120: Int8Array, 5121: Uint8Array, 5122: Int16Array,
  5123: Uint16Array, 5125: Uint32Array, 5126: Float32Array,
};

/** 步骤 3+4：accessor -> TypedArray（零拷贝视图或按 stride 重建） */
function accessorToTypedArray(
  buffers: ArrayBuffer[], gltf: GLTFJSON, accessorIndex: number,
): ArrayBufferView {
  const acc = gltf.accessors[accessorIndex]!;
  const view = gltf.bufferViews[acc.bufferView]!;
  const buffer = buffers[view.buffer]!;
  const compBytes = COMPONENT_BYTES[acc.componentType]!;
  const count = acc.count * TYPE_COUNT[acc.type]!;

  // 无 stride（或 stride 恰等于紧密打包长度）：直接视图，零拷贝
  const tightStride = compBytes * TYPE_COUNT[acc.type]!;
  if (view.byteStride === undefined || view.byteStride === tightStride) {
    const byteOffset = (view.byteOffset ?? 0) + (acc.byteOffset ?? 0);
    return new (CTOR[acc.componentType]!)(buffer, byteOffset, count);
  }

  // 有交错 stride（多 attribute 共享一个 bufferView）：逐元素抽取
  const Ctor = CTOR[acc.componentType]!;
  const src = new Ctor(buffer, view.byteOffset + (acc.byteOffset ?? 0));
  const out = new Ctor(count);
  const comps = TYPE_COUNT[acc.type]!;
  for (let i = 0; i < acc.count; i++) {
    for (let k = 0; k < comps; k++) {
      out[i * comps + k] = src[(i * view.byteStride!) / compBytes + k]!;
    }
  }
  return out;
}

/** 步骤 5：glTF 材质 -> 框架材质 */
function buildMaterial(gltf: GLTFJSON, index: number, textures: Texture[]): Material {
  const m = gltf.materials[index]!;
  const pbr = m.pbrMetallicRoughness;
  const mat = new PBRMaterial(); // 简版：当作带宏的 Phong 用（第五阶段真 PBR）
  if (pbr?.baseColorFactor) {
    mat.color.fromArray(pbr.baseColorFactor);
  }
  if (pbr?.baseColorTexture) {
    // GLTF 纹理坐标约定：v 轴与图片上下相反 -> UNPACK_FLIP_Y 不开，shader 里 1.0 - v
    mat.setMap(textures[gltf.textures[pbr.baseColorTexture.index]!.source!]!);
  }
  mat.transparent = m.alphaMode === "BLEND";          // 渲染队列分组（03 册）
  mat.defines["DOUBLE_SIDED"] = m.doubleSided === true;
  return mat;
}

/** 步骤 7：节点层级（matrix 与 TRS 同在时 matrix 优先——glTF 规范规定） */
function buildNodeTree(gltf: GLTFJSON, index: number,
                       meshes: Mesh[], skins: Skeleton[]): Node3D {
  const def = gltf.nodes[index]!;
  const node = new Node3D(def.name ?? "");

  if (def.matrix) {
    node.matrix.fromArray(def.matrix);     // 列主序直接进
    node.matrixAutoUpdate = false;         // 静态矩阵，用户接管（03 册 2.2.3）
  } else {
    if (def.translation) node.position.fromArray(def.translation);
    if (def.rotation) node.quaternion.fromArray(def.rotation); // (x,y,z,w)
    if (def.scale) node.scale.fromArray(def.scale);
  }
  if (def.mesh !== undefined) {
    const mesh = meshes[def.mesh]!;
    if (def.skin !== undefined) {
      (mesh as SkinnedMesh).skeleton = skins[def.skin]!;
      // 蒙皮节点必须加进树（骨骼要参与 matrixWorld 更新），即使不可见
    }
    node.add(mesh);
  }
  for (const childIndex of def.children ?? []) {
    node.add(buildNodeTree(gltf, childIndex, meshes, skins));
  }
  return node;
}

/** 入口：串起 9 步 */
export class GLTFLoader extends Loader<Node3D> {
  protected async fetch(url: string): Promise<unknown> {
    const resp = await fetch(url);
    if (!resp.ok) throw new Error(`HTTP ${resp.status}`);
    return resp.text();
  }

  protected async parse(text: unknown, url: string): Promise<Node3D> {
    // 步骤 1：JSON + 版本闸门
    const gltf = JSON.parse(text as string) as GLTFJSON;
    if ((Number(gltf.asset.version.split(".")[0]) ?? 0) < 2) {
      throw new Error("仅支持 glTF 2.x");
    }
    // 步骤 2：buffers（去重队列 + data URI 内嵌）
    const buffers = await Promise.all(
      (gltf.buffers ?? []).map((b) =>
        b.uri === undefined
          ? Promise.reject(new Error("简版加载器不拆 GLB，请用 .gltf + .bin"))
          : b.uri.startsWith("data:")
            ? Promise.resolve(decodeDataURI(b.uri))
            : this.bufferLoader.load(resolveURI(b.uri, url)),
      ),
    );
    // 步骤 2b：贴图（可失败降级，6.2.3）
    const textures = await this.loadTextures(gltf, url);
    // 步骤 5/6/8/9：材质、网格、蒙皮、组装（同构流程，按 6.3.2 清单展开）
    const materials = (gltf.materials ?? []).map((_, i) => buildMaterial(gltf, i, textures));
    const meshes = (gltf.meshes ?? []).map((m) => buildMesh(gltf, m, buffers, materials));
    const skins = (gltf.skins ?? []).map((s) => buildSkeleton(gltf, s, buffers));
    const sceneIndex = gltf.scene ?? 0;
    const root = new Node3D(`scene:${sceneIndex}`);
    for (const nodeIndex of gltf.scenes[sceneIndex]!.nodes) {
      root.add(buildNodeTree(gltf, nodeIndex, meshes, skins));
    }
    return root;
  }
}
```

### 6.3.4 常见坑

1. **glTF 是右手系、Y 向上，贴图 v 轴与 PNG 上下相反**。不要开 `UNPACK_FLIP_Y`（第二阶段给普通贴图开过的习惯），在 shader 里 `uv.y = 1.0 - uv.y` 或导出时翻转。开了 FLIP_Y 再翻 shader 就是双重翻转。
2. **byteStride 忽略**：很多导出器把 POSITION/NORMAL 打包进同一个 bufferView（交错存储，interleaved），不处理 stride 读出的是错位数据——症状是"法线像噪点"。6.3.3 的两分支处理是必须的。
3. **node.matrix 与 TRS 并存**：规范规定 matrix 优先。只读 TRS 会拿到默认值，模型全部堆在原点。
4. **indices 的 componentType 是 5123/5125**（无符号），用 Int16Array 接会得到负索引，drawElements 直接报错。查表选构造器（6.3.3 的 CTOR 表）。
5. **accessor.byteOffset 是相对 bufferView 的**，完整偏移 = `bufferView.byteOffset + accessor.byteOffset`。漏加前者，第一组数据永远对、后面全错——极具迷惑性。
6. **蒙皮模型的骨骼节点没进树**：skin.joints 引用的 node 若没挂在场景树（有的导出器把骨架放 `scenes[].nodes` 之外），`updateMatrixWorld` 摸不到它们，jointMatrix 全是垃圾。加载完把骨骼根强制挂到返回根节点下。
