# 第四阶段导览：框架架构与工程化

> [返回：WebGL 与 3D 框架学习大纲](../WebGL与3D框架学习大纲.md)
> 本文是第四阶段（重点阶段）的总导览：说明阶段目标、分册索引、阅读路线、实践任务清单与阶段自测；各知识点正文见本目录分册。

## 阶段目标

前三个阶段做完，手里已经有：一套手写数学库（minmath）、一个能转的渲染循环、Geometry 生成器和 Mesh 抽象——能写 demo，但还不能叫"框架"。demo 与框架的差距不在功能多少，而在三件事：

1. **结构**：功能长在什么骨架上。分层不清的代码每加一个特性都在还债，分层清楚的代码每加一个特性都在攒资产。
2. **托管**：谁替用户管 WebGL 的脏活——状态切换、着色器编译、显存回收、资源依赖。框架的本质是"把易错的事收走"。
3. **工程**：能不能被别人 `npm install`。类型、模块边界、测试、打包发布，是从"我的代码"到"一个库"的最后一公里。

本阶段结束时，你应该交付一个有名字、有 npm 包、有在线示例站的迷你 3D 框架：分层清晰、状态托管、场景图 + 渲染队列 + 材质系统 + 拾取 + 动画 + glTF 加载全部自研，并具备可回归的单元测试。

## 阅读路线

02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 是主线，基本是"骨架到血肉、功能到交付"的顺序：

1. **02 是地基**，后面每一册都在它的分层里落位，必须最先读。
2. **03、04 是渲染主链路**（先确定"画什么、怎么排"，再确定"用什么材质画"），两者顺序也可对调，但都应在 05 之前完成。
3. **05、06 相对独立**，可按兴趣穿插；06 的蒙皮依赖 07 的 glTF 数据会更顺手，但原理讲解不依赖。
4. **07 依赖 03（场景图节点）与 04（材质）的产物**，放在功能册之后。
5. **08、09 收尾**：工程化是把前六册的代码"定型"的过程，最后完成定名与发布。

每册结构固定：设计动机 → 方案对比 → 完整核心代码（TypeScript）→ 常见坑 → 本节自测。代码约定沿用第三阶段的 minmath API（`Mat4.multiply(out, a, b)` 等静态函数风格），不再重复推导数学库本身。

## 实践任务清单

"看懂"不算数，跑起来才算。每册正文内嵌小实践，此处汇总为阶段总任务，建议按序完成：

- [ ] P1（配合 02）：实现 StateCache 并接入渲染循环，用计数器对比缓存开启/关闭的 gl 状态调用次数，截图或记录数字。
- [ ] P2（配合 03）：构造 1000 节点深的场景树，对比"每帧全量更新矩阵"与"脏标记更新"的每帧耗时（`performance.now()` 采样）。
- [ ] P3（配合 04）：实现带 USE_MAP / USE_SKINNING 两个宏开关的 uber shader，验证同一份源码产出 4 个 program 变体且缓存命中。
- [ ] P4（配合 05）：完成 Raycaster 拾取，鼠标悬停高亮 + 点击沿场景图冒泡派发事件。
- [ ] P5（配合 06）：加载一个带骨骼动画的模型，实现 idle 与 walk 两动作的 0.5 秒 crossfade。
- [ ] P6（配合 07）：跑通简版 glTF 加载器，加载一个含层级、贴图、蒙皮的 .gltf 模型并无报错渲染。
- [ ] P7（配合 08）：数学库与场景图核心流程的 vitest 单测全部通过，覆盖率报告输出。
- [ ] P8（最终）：框架定名、npm 发布、示例站上线，三项完成后勾掉大纲实践任务。

## 阶段自测

答不上就回对应分册，答案能落在自己框架的代码上才算过：

1. 你的框架分几层？相邻两层之间的依赖方向是什么？举一个"放错层的功能"并说明放错会怎样。（对应 02）
2. 状态缓存为什么能提速？如果用户代码直接调了 `gl.enable()` 绕过你的 StateCache，会发生什么，如何兜底？（对应 02）
3. 从场景里移除一个 Mesh 后显存里还剩什么？写出你的 dispose 清理清单。（对应 02）
4. worldMatrix 的更新为什么必须"自上而下"？脏标记剪枝在哪种父子结构下收益最大，哪种下几乎没有收益？（对应 03）
5. 不透明物体为什么按"材质分组 + 由近到远"排序，透明物体却按"由远到近"？两个排序目标冲突时（同一材质内深度交错）你保证什么、放弃什么？（对应 03）
6. uniform 反射在什么时机做、为什么只做一次？数组 uniform 的 name 为什么要去掉 `[0]` 后缀？（对应 04）
7. uber shader 的变体数量为什么会组合爆炸？你会怎样约束 defines 的组合空间？（对应 04）
8. 默写屏幕坐标到 NDC 的两行公式，说明 y 为什么要翻转；devicePixelRatio 会在哪一步引入 bug？（对应 05）
9. Möller–Trumbore 里 det 接近 0 意味着什么？背面剔除版与非剔除版的判断差异在哪一行？（对应 05）
10. 位置、旋转、缩放三种轨道分别用什么插值？旋转用欧拉角线性插值会出什么问题？（对应 06）
11. inverseBindMatrix 存的是什么时刻的什么矩阵？顶点坐标经过哪两步矩阵从"绑定姿势"搬到"当前姿势"？（对应 06）
12. 同一 URL 的资源被两个模型引用，你的加载器会发几次请求？加载失败的依赖如何传播？（对应 07）
13. glTF 的 node.matrix 与 TRS 两个字段都存在时以谁为准？accessor 的 byteStride 什么时候必须处理？（对应 07）
14. `noUncheckedIndexedAccess` 开启后 `children[0]` 的类型是什么？你的代码里哪三处需要因此补防御？（对应 08）
15. 你的包在 exports 里声明了几个入口？`sideEffects: false` 对使用你库的 webpack 项目意味着什么？（对应 08）
