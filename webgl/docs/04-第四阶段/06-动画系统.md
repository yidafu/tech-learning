# 5. 动画系统

先立一个全局观：动画系统在渲染管线里站哪。每帧的更新顺序是——

```text
输入（时间 dt）
  -> 动画系统：采样关键帧 -> 混合姿势（pose） -> 写到骨骼/节点的 TRS
  -> 场景图：updateMatrixWorld（03 册脏标记接力）
  -> 渲染队列收集 -> draw
```

动画系统**只写变换、不碰 GL**：它是场景层的一部分，蒙皮矩阵算好后交给渲染层上传。这个位置决定了它可以脱离 canvas 做单元测试。

## 5.1 关键帧插值

### 5.1.1 设计动机：动画 = 按时间查表 + 插值

一段动画数据就是"若干关键帧"：每帧一个时间点和一组值。播放时给定当前时间 t，找到**包住 t 的两个关键帧**，按比例插值。三个子问题：数据怎么组织（轨道，track）、区间怎么找（查找）、值怎么插（不同类型不同算法）。

**为什么位置/缩放用线性插值（lerp）、旋转必须用球面插值（slerp）**：

- 位置、缩放是普通标量/向量空间，lerp 就是正确答案：`v = v0 + (v1 - v0) * α`。
- 旋转用四元数存（03 册 2.1.4 坑 4），四元数是单位四元数时对应旋转。两个单位四元数直接 lerp，结果长度不保 1，要再归一化——这叫 nlerp，速度快但**角速度不均匀**（中间快两头慢）；slerp 沿四维球面走大圆，角速度恒定。视觉差异在 90 度以上转角明显，动画里选 slerp。
- 千万不要把旋转存欧拉角然后分量 lerp：三个分量各自插值，合成路径不经过任何"自然的中间旋转"，还会在万向节锁（gimbal lock）附近抖动。第三阶段的痛在这里兑现为一条铁律。

### 5.1.2 方案对比：轨道数据怎么组织

| 方案 | 结构 | 查找 | 适用 |
|---|---|---|---|
| 每帧存对象数组 `[{t, value}]` | 直观 | 逐帧扫 | 帧数少无所谓 |
| 时间数组 + 值平铺数组（本方案） | `times: number[]`、`values: Float32Array` | 二分/游标 | 与 glTF/二进制格式天然对齐（07 册） |
| 采样烘焙（每 1/60 秒一格） | 查表即得 | O(1) | 内存换查找，采样精度受烘焙间隔限制 |

第二方案是被 glTF"选中"的结构：动画数据来自二进制缓冲，typed array 视图直接指进去，零拷贝。播放中查找用**游标（cursor）缓存**：动画总是向前走（或循环回绕），记住上次命中的区间索引，下次从它开始向后找，平均 O(1)。

### 5.1.3 完整核心代码：轨道采样

```typescript
// animation/AnimationClip.ts
import { Vec3 } from "../math/Vec3";
import { Quaternion } from "../math/Quaternion";

export type TrackName = "position" | "quaternion" | "scale";

/** 一条轨道：作用于一个目标节点的某条 TRS 通道 */
export class KeyframeTrack {
  /** 游标：上次采样命中的区间起点索引，加速下一次查找 */
  private cursor = 0;

  constructor(
    readonly target: Node3D,
    readonly name: TrackName,
    readonly times: number[],        // 严格递增
    readonly values: Float32Array,   // N 帧 × 分量数（position 3，quaternion 4，scale 3）
  ) {}

  get duration(): number { return this.times[this.times.length - 1] ?? 0; }

  /** 采样到 time，把插值结果写到 out（分量布局同 values 单帧） */
  sample(time: number, out: Float32Array): void {
    const times = this.times;
    const last = times.length - 1;

    // 钳制边界：循环外的时间给端点值
    if (time <= times[0]!) { this.copyFrame(0, out); return; }
    if (time >= times[last]!) { this.copyFrame(last, out); return; }

    // 游标查找：从上次区间向后找（time 回绕时游标重置在 play 层做）
    let i = this.cursor;
    if (times[i]! > time) i = 0;             // 时间跳变（seek），从头找
    while (i < last && times[i + 1]! < time) i++;
    this.cursor = i;

    // 区间内插值比例 alpha
    const t0 = times[i]!;
    const t1 = times[i + 1]!;
    const alpha = (time - t0) / (t1 - t0);

    this.interpolate(i, alpha, out);
  }

  /** 按 5.1.1 的铁律分派插值算法 */
  private interpolate(frame: number, alpha: number, out: Float32Array): void {
    const stride = this.name === "quaternion" ? 4 : 3;
    const o0 = frame * stride;
    const o1 = o0 + stride;

    if (this.name === "quaternion") {
      // 旋转：slerp（minmath 提供，第三阶段已实现并测试）
      Quaternion.slerpToBuffer(this.values, o0, o1, alpha, out);
    } else {
      // 位置/缩放：lerp
      for (let k = 0; k < stride; k++) {
        const v0 = this.values[o0 + k]!;
        const v1 = this.values[o1 + k]!;
        out[k] = v0 + (v1 - v0) * alpha;
      }
    }
  }

  private copyFrame(frame: number, out: Float32Array): void {
    const stride = this.name === "quaternion" ? 4 : 3;
    for (let k = 0; k < stride; k++) out[k] = this.values[frame * stride + k]!;
  }
}

export class AnimationClip {
  constructor(readonly name: string, readonly tracks: KeyframeTrack[]) {}
  get duration(): number {
    return Math.max(...this.tracks.map((t) => t.duration));
  }
}
```

## 5.2 动画混合（mix / blend）

### 5.2.1 设计动机：一个角色同时是"走路的"和"变矮的"

单一动作播放很简单，真实需求全是组合：走与跑按速度线性混合、急停时上半身 play attack 下半身 play idle、切换动作要 crossfade（交叉淡化，旧动作淡出同时新动作淡入）。混合的单位不是"动画"而是**姿势（pose）**：某时刻所有骨骼/节点 TRS 的快照。混合 = 两个姿势按权重逐分量插值，再写回场景图。

### 5.2.2 方案对比：在哪一层混合

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 直接写节点：每个 action 采样即写 TRS | 顺序执行，后写的赢（硬切） | 实现十行 | 没有混合，只有覆盖 |
| 采样到独立 pose，混合后一次写回（本方案） | pose 是纯数据，权重归一化后统一插值 | 支持任意权重组合，同 three.js AnimationMixer | 多一层 pose 数据结构 |
| 着色器层混合（骨骼矩阵插在 GPU） | CPU 只传两组 jointMatrices | CPU 省了插值 | 变体多、灵活性差，调试难 |

第二方案是 CPU 蒙皮前的标准中间层：即便将来骨骼上传 GPU（5.3.4），pose 混合也保留在 CPU——它处理的常常不只是骨骼（还有位移轨道、表情轨道）。

### 5.2.3 完整核心代码：AnimationAction 与 Mixer

```typescript
// animation/AnimationMixer.ts
interface PoseValue {
  position: Float32Array;
  quaternion: Float32Array;
  scale: Float32Array;
}
type Pose = Map<Node3D, PoseValue>;

function emptyPose(): Float32Array { return new Float32Array(3); }
function emptyQuatPose(): Float32Array { return new Float32Array(4); }

export class AnimationAction {
  time = 0;
  timeScale = 1;
  loop = true;
  /** 当前权重，crossfade 由 mixer 调整它 */
  weight = 1;

  private readonly pose: Pose = new Map();
  private readonly buffer = new Float32Array(4); // 复用的采样缓冲

  constructor(readonly clip: AnimationClip) {}

  /** 采样：时间推进 + 逐轨道写独立 pose */
  protected samplePose(dt: number): void {
    this.time += dt * this.timeScale;
    const dur = this.clip.duration;
    if (this.loop && dur > 0) this.time %= dur; // 回绕：游标在 5.1.3 内部处理

    for (const track of this.clip.tracks) {
      let entry = this.pose.get(track.target);
      if (!entry) {
        entry = { position: emptyPose(), quaternion: emptyQuatPose(), scale: emptyPose() };
        this.pose.set(track.target, entry);
      }
      track.sample(this.time, entry[track.name] as Float32Array);
    }
  }

  getPose(): Pose { return this.pose; }
}

export class AnimationMixer {
  readonly actions: AnimationAction[] = [];

  play(action: AnimationAction): void {
    action.weight = 1;
    if (!this.actions.includes(action)) this.actions.push(action);
  }

  stop(action: AnimationAction): void {
    const i = this.actions.indexOf(action);
    if (i >= 0) this.actions.splice(i, 1);
  }

  /** crossfade：dur 秒内 from 权重降到 0、to 升到 1 */
  crossfade(from: AnimationAction, to: AnimationAction, duration: number): void {
    const start = performance.now();
    const tick = () => {
      const t = Math.min(1, (performance.now() - start) / (duration * 1000));
      from.weight = 1 - t;
      to.weight = t;
      if (t < 1) requestAnimationFrame(tick);
      else this.stop(from);
    };
    this.play(to);
    tick();
  }

  private readonly result: Pose = new Map();

  update(dt: number): void {
    if (this.actions.length === 0) return;

    // 1. 全部动作先采样（各自推进时间）
    for (const action of this.actions) action.samplePose(dt);

    // 2. 权重归一化：总权重 sum，各动作实际贡献 = w / sum
    let sum = 0;
    for (const action of this.actions) sum += action.weight;
    if (sum <= 0) return;

    // 3. 逐节点混合：dst 归零后做加权累加（首动作与其他动作走同一条路径，
    //    因为权重已归一化，首动作的贡献同样是 w 而不是 1）
    this.result.clear();
    for (const action of this.actions) {
      const w = action.weight / sum;
      for (const [node, src] of action.getPose()) {
        let dst = this.result.get(node);
        if (!dst) {
          dst = { position: emptyPose(), quaternion: emptyQuatPose(), scale: emptyPose() };
          this.result.set(node, dst);
        }
        accumulate(dst, src, w);
      }
    }

    // 4. 写回场景图：quaternion 先整体归一化（加权和不再是单位四元数），
    //    再写 TRS 触发 03 册的脏标记，updateMatrixWorld 接力
    for (const [node, pose] of this.result) {
      normalize4InPlace(pose.quaternion);
      node.position.fromArray(pose.position);
      node.quaternion.fromArray(pose.quaternion);
      node.scale.fromArray(pose.scale);
    }
  }
}

/**
 * 加权累加。quaternion 处先做符号对齐：q 与 -q 表示同一旋转，
 * 两个来源的动画数据符号可能不一致，直接累加会混合出"绕远路"的中间旋转，
 * 所以 dot(dst, src) < 0 时给本次累加翻符号（three.js 的 slerpFlat 同款处理）
 */
function accumulate(dst: PoseValue, src: PoseValue, w: number): void {
  for (let k = 0; k < 3; k++) {
    dst.position[k] += src.position[k] * w;
    dst.scale[k] += src.scale[k] * w;
  }
  const dot =
    dst.quaternion[0]! * src.quaternion[0]! +
    dst.quaternion[1]! * src.quaternion[1]! +
    dst.quaternion[2]! * src.quaternion[2]! +
    dst.quaternion[3]! * src.quaternion[3]!;
  const signedW = dot < 0 ? -w : w;
  for (let k = 0; k < 4; k++) dst.quaternion[k] += src.quaternion[k] * signedW;
}

function normalize4InPlace(q: Float32Array): void {
  const len = Math.hypot(q[0]!, q[1]!, q[2]!, q[3]!) || 1;
  for (let k = 0; k < 4; k++) q[k] = q[k]! / len;
}
```

加权混合四元数为什么"加权和再归一化"可行，前提是上面 `accumulate` 里的**符号对齐**：两个四元数 q、-q 表示同一旋转，来源不同的动画数据符号可能不一致，不先对齐直接累加，混合结果会绕远路。工业实现（three.js）在 `Quaternion.slerpFlat` 里做同款处理，这是四元数插值/混合绕不开的细节。

### 5.2.4 常见坑

1. **权重不归一化**：walk 权重 1 + run 权重 1 混出"两倍位移"。方案对比里的"归一化后插值"就是为了这个；代价是加一个动作会把其他动作"挤掉"——这正是期望的行为（权重是份额不是叠加系数）。
2. **crossfade 期间动作被 stop**：淡出中的动作必须继续采样，只是权重在降。提前 stop 会让姿势瞬间跳变。上面代码 `crossfade` 在 t=1 才 stop，就是这条纪律。
3. **根位移轨道与控制器打架**：动画自带的位移（root motion）每帧写 `node.position`，OrbitControls 又锁定目标，物体"漂走"。要么烘焙掉根位移（导出时移除位移轨道），要么把根位移转交给游戏逻辑层消费。
4. **回绕后游标错位**：时间取模回绕到 0，5.1.3 的游标还停在末尾。代码里 `times[i] > time` 时游标归零已覆盖此情形，但 seek（跳转播放）场景要记得也依赖同一条分支。

## 5.3 骨骼蒙皮入门

### 5.3.1 设计动机：网格顶点跟着骨骼走

刚体动画（5.1）让"整个节点"动，角色关节处会断裂。蒙皮（skinning）让**每个顶点受多根骨骼影响**，权重和为 1，关节处的顶点一半跟着上臂一半跟着下臂，形成连续弯折。三要素：

- **骨架（skeleton）**：一堆按父子链组织的骨骼节点（本质就是场景图节点）；
- **绑定姿势（bind pose）**：蒙皮数据绑定的那一刻，每根骨骼的世界矩阵快照的**逆**，称为逆绑定矩阵（inverse bind matrix）；
- **顶点权重**：每个顶点存 4 个 `(骨骼索引, 权重)` 对。

### 5.3.2 数学：顶点从绑定姿势到当前姿势的两步

顶点缓冲里存的是**绑定姿势下模型空间**的坐标 `v_bind`。要把它搬到"当前姿势"，理论路径是三步矩阵：

```text
v_world = Σ_j  w_j × ( jointWorld_j × inverseBind_j × v_bind )
```

读法（以第 j 根骨骼为例）：

1. `inverseBind_j × v_bind`：把顶点从"绑定时的模型空间"搬进"绑定时的第 j 根骨骼局部空间"——**问绑定时顶点长在这根骨头的什么位置**；
2. `jointWorld_j × ...`：再按第 j 根骨骼**当前**的世界矩阵搬到当前世界——骨头动到哪，这个"长在骨头上的点"跟到哪；
3. 多根骨骼的结果按权重 `w_j` 加权求和（Σw = 1），关节平滑过渡。

第 1、2 步之间的差就是"姿势变化"；两步合起来等价于"**顶点相对骨骼不动，骨骼带着顶点走**"。`inverseBind_j = inverse(jointWorld_j at bind time)`，在加载时算好一次（glTF 直接存了这个矩阵，07 册 6.3 第 8 步）。

### 5.3.3 完整核心代码：Skeleton 与 SkinnedMesh

```typescript
// scene/Skeleton.ts
import { Mat4 } from "../math/Mat4";
import { Node3D } from "./Node3D";

export const MAX_JOINTS = 64; // 与 GLSL 里数组长度一致

export class Skeleton {
  /** jointMatrices：拍平的 4x4 矩阵数组，每帧一次 uniformMatrix4fv 上传 */
  readonly jointMatrices = new Float32Array(MAX_JOINTS * 16);
  private readonly tmp = new Mat4();

  constructor(
    readonly joints: Node3D[],             // 骨骼节点（引用场景图）
    readonly inverseBindMatrices: Mat4[],  // 加载时从 glTF 读入
  ) {}

  /** 前提：场景图 updateMatrixWorld 之后调用（骨骼世界矩阵已是新值） */
  update(meshWorldInverse: Mat4): void {
    for (let j = 0; j < this.joints.length && j < MAX_JOINTS; j++) {
      // 第 1+2 步合并：jointWorld × inverseBind
      Mat4.multiply(this.tmp, this.joints[j]!.matrixWorld, this.inverseBindMatrices[j]!);
      // 左乘 mesh 世界逆：把结果从"世界空间"折算回"网格模型空间"，
      // 这样顶点着色器里只需 u_jointMatrix × v_position，无需再乘 u_model
      Mat4.multiply(this.tmp, meshWorldInverse, this.tmp);
      this.tmp.toArray(this.jointMatrices, j * 16);
    }
  }
}

// scene/SkinnedMesh.ts —— Mesh 子类：多两个 attribute + 一个 skeleton
export class SkinnedMesh extends Mesh {
  skeleton: Skeleton | null = null;

  /** 几何上多两个 attribute：
   *  a_joints: vec4（每顶点 4 个骨骼索引）
   *  a_weights: vec4（对应权重，加载器保证 Σ=1） */
  uploadSkinningState(): void { /* geometry 增加 attribute，走 04 册正常路径 */ }

  override beforeRender(): void {
    // 蒙皮矩阵依赖骨骼世界矩阵：必须在 updateMatrixWorld 之后、draw 之前
    const meshWorldInverse = Mat4.invert(new Mat4(), this.matrixWorld);
    this.skeleton!.update(meshWorldInverse);
    this.uniforms["u_jointMatrix"] = this.skeleton!.jointMatrices;
    this.defines["USE_SKINNING"] = true; // 04 册宏开关
  }
}
```

顶点着色器里的蒙皮（GLSL，配合 04 册宏开关）：

```glsl
#version 300 es
#ifdef USE_SKINNING
  uniform mat4 u_jointMatrix[64]; // 与 MAX_JOINTS 一致
  in vec4 a_joints;
  in vec4 a_weights;
#endif

vec4 skinnedPosition(vec4 position) {
#ifdef USE_SKINNING
  vec4 p = vec4(0.0);
  // 固定 4 次展开：循环上限必须编译期常量，且避免动态索引开销
  p += a_weights[0] * (u_jointMatrix[int(a_joints[0])] * position);
  p += a_weights[1] * (u_jointMatrix[int(a_joints[1])] * position);
  p += a_weights[2] * (u_jointMatrix[int(a_joints[2])] * position);
  p += a_weights[3] * (u_jointMatrix[int(a_joints[3])] * position);
  return p;
#else
  return position;
#endif
}

void main() {
  vec4 world = skinnedPosition(vec4(a_position, 1.0));
  gl_Position = u_projection * u_view * world; // 注意：蒙皮后不再乘 u_model（见 5.3.3 注释）
}
```

### 5.3.4 uniform 数组 vs 纹理：jointMatrices 怎么上 GPU

| 方案 | 上传 | 限制 | 适用 |
|---|---|---|---|
| uniform 数组（本方案） | 一次 `uniformMatrix4fv(loc, false, jointMatrices)` | uniform 上限（通常 1024 vec4）约 64 根骨骼 | 迷你框架、小骨架 |
| 矩阵纹理（matrix palette texture） | 每矩阵 4 像素（RGBA32F 每通道存一行），`texelFetch` 取 | 无骨骼数上限 | 大骨架（面部 200+ 骨骼） |

换算：64 根骨骼 × 16 分量 = 1024 个 vec4，刚好顶到典型上限；超过 64 根（或同场景多骨架）必须走纹理。纹理方案每根骨骼占 4 个相邻像素，`texelFetch(palette, ivec2(jointIndex * 4 + row, 0), 0)` 取第 jointIndex 根骨骼第 row 行。迷你框架实现 uniform 数组版，纹理版知道布局即可。

### 5.3.5 常见坑

1. **先 draw 后 update 骨骼矩阵**：骨骼动了一帧之后网格才跟上，关节"拖影"。铁律顺序：`mixer.update` -> `scene.updateMatrixWorld` -> `skeleton.update` -> draw。`skeleton.update` 依赖两步，必须夹在中间。
2. **忘了左乘 meshWorldInverse**：网格与骨骼根不共享同一父节点时（比如 mesh 挂在 scene、骨骼挂在 character 组），蒙皮结果整体偏移/加倍变换。glTF 规范明确要求相对网格节点计算，5.3.3 代码的第三行乘法就是这条规范。
3. **权重和不为 1**：建模软件导出时常见 Σw = 0.9997，顶点轻微缩水。加载器统一归一化（除以和）。
4. **inverseBindMatrices 用了"当前姿势"**：绑定姿势是蒙皮数据生成时刻的快照，运行时重算它等于"每次都以当前姿势为绑定"——模型塌缩成姿势交叠的鬼影。必须用资产里存的矩阵。
5. **骨骼节点误被视锥剔除**：骨骼是"看不见的节点"，剔除逻辑若按节点遍历会把它们跳过——但它们**必须参与 updateMatrixWorld**。骨骼挂在 SkinnedMesh 下并标 `visible=false` 时，注意你的剔除与更新遍历是否共用 visible 判断（03 册 collect 只收集 Mesh，天然安全；若改成"visible 才 traverse"就踩雷）。
