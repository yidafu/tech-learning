# 4. 交互系统

## 4.1 Raycaster 完整推导：屏幕坐标 → NDC → 世界射线

### 4.1.1 设计动机：拾取是渲染管线的逆问题

渲染把顶点经 model → view → projection 变换、齐次除法、视口映射，最终落到屏幕像素；拾取（picking）要反过来：**从被点击的屏幕像素，反推一条穿过场景的世界空间射线（ray）**，再找出它与哪些物体相交。反推之所以可行，是因为整条变换链每一步都可逆（透视投影的逆在齐次除法之前做）。

选"射线求交"而不是"读回像素颜色 ID"（GPU picking）作为入门方案，理由：CPU 射线法无 RTT（render to texture）依赖、结果带精确交点与法线、可在无渲染的测试环境跑——它与 02 册"渲染层之外不碰 gl"的边界天然兼容。

### 4.1.2 每一步的公式

**第一步：屏幕坐标（CSS 像素）。** canvas 在页面里的位置要用 `getBoundingClientRect()` 换算，鼠标事件给的是视口坐标：

```text
px = event.clientX - rect.left
py = event.clientY - rect.top
```

注意 `rect.width/height` 是 **CSS 尺寸**。canvas 的绘图缓冲（`canvas.width`，物理像素）通常是 CSS 尺寸乘 devicePixelRatio。NDC 换算必须用 CSS 尺寸——鼠标事件的坐标天生就是 CSS 像素，两边一致；混用了物理像素，高 DPI 屏上拾取点会整体偏移甚至飞出画面。

**第二步：归一化设备坐标（NDC，Normalized Device Coordinates）。** NDC 空间 x/y ∈ [-1, 1]，y 轴**向上**；屏幕坐标系 y 向下。所以 x 线性映射，y 要翻转：

```text
ndcX = (px / rect.width)  * 2 - 1        // 左 0 -> -1，右 -> +1
ndcY = 1 - (py / rect.height) * 2        // 上 0 -> +1（翻转！），下 -> -1
```

**第三步：齐次逆投影（inverse projection）。** 直接取 NDC 平面上两点——近平面对应 `ndcZ = -1`、远平面对应 `ndcZ = +1`（WebGL 的 z ∈ [-1, 1]，与 Direct3D 的 [0, 1] 不同）——拼成齐次坐标（clip coordinate）再左乘 `viewProjection` 的逆：

```text
clipNear = (ndcX, ndcY, -1, 1)
clipFar  = (ndcX, ndcY, +1, 1)

worldNear_h = inverse(viewProjection) · clipNear
worldFar_h  = inverse(viewProjection) · clipFar
```

`viewProjection = projection × view`，用一次合并的矩阵求逆比"分别逆乘"少一次矩阵乘，且精度更好。

**第四步：齐次除法（perspective divide）。** 逆变换后的 w 分量一般不是 1，必须除回去才得到仿射坐标：

```text
worldNear = worldNear_h.xyz / worldNear_h.w
worldFar  = worldFar_h.xyz  / worldFar_h.w
```

跳过这一步是本节最高频错误：正交相机下 w 恒为 1 无事发生，一切换透视相机射线方向就歪——错误被相机类型掩盖。

**第五步：组装射线。** 起点（origin）取近点（或相机世界位置，两者在同一直线上），方向（direction）归一化：

```text
origin    = worldNear
direction = normalize(worldFar - worldNear)
```

### 4.1.3 完整核心代码：Raycaster

```typescript
// interaction/Raycaster.ts
import { Vec3 } from "../math/Vec3";
import { Mat4 } from "../math/Mat4";
import { Camera } from "../scene/Camera";
import { Node3D, Mesh } from "../scene";

export class Ray {
  readonly origin = new Vec3();
  readonly direction = new Vec3(0, 0, -1);

  /** 由相机与 NDC 点设置射线：4.1.2 五步公式的落地 */
  setFromCameraNDC(camera: Camera, ndcX: number, ndcY: number): void {
    const invVP = Mat4.invert(
      new Mat4(),
      Mat4.multiply(new Mat4(), camera.projectionMatrix, camera.viewMatrix),
    );

    // 第三步：NDC -> 齐次坐标 -> 逆变换（先近后远两个点）
    const nearH = Vec3.transformMat4Homogeneous(
      new Vec3(), new Vec3(ndcX, ndcY, -1), invVP);
    const farH = Vec3.transformMat4Homogeneous(
      new Vec3(), new Vec3(ndcX, ndcY, +1), invVP);

    // 第四步：齐次除法
    this.origin.copy(nearH);
    // 第五步：方向 = far - near，归一化
    Vec3.subtract(this.direction, farH, nearH);
    Vec3.normalize(this.direction, this.direction);
  }
}

/** 屏幕事件坐标 -> NDC（第一步 + 第二步） */
export function pointerToNDC(
  event: { clientX: number; clientY: number },
  canvas: HTMLCanvasElement,
): { x: number; y: number } {
  const rect = canvas.getBoundingClientRect();
  return {
    x: ((event.clientX - rect.left) / rect.width) * 2 - 1,
    y: 1 - ((event.clientY - rect.top) / rect.height) * 2,
  };
}

export interface RaycastHit {
  distance: number;   // 沿方向的距离 t
  point: Vec3;        // 世界空间交点
  node: Node3D;       // 命中的节点
  uv?: { u: number; v: number }; // 三角形求交顺带产出（重心坐标换算）
}

export class Raycaster {
  readonly ray = new Ray();
  /** 超出此距离的命中忽略 */
  far = Infinity;

  setFromEvent(camera: Camera, event: PointerEvent, canvas: HTMLCanvasElement): void {
    const ndc = pointerToNDC(event, canvas);
    this.ray.setFromCameraNDC(camera, ndc.x, ndc.y);
  }

  intersectObject(root: Node3D): RaycastHit[] {
    const hits: RaycastHit[] = [];
    root.traverse((node) => {
      const mesh = node as Mesh;
      if (!(mesh instanceof Mesh)) return;
      // 4.3：先包围体粗测，再三角形精测
      const hit = raycastMesh(this.ray, mesh);
      if (hit) hits.push(hit);
    });
    hits.sort((a, b) => a.distance - b.distance); // 近者优先
    return hits;
  }
}
```

（`transformMat4Homogeneous` 是 minmath 里"乘 4×4 后做 w 除法"的辅助函数；若第三阶段没写，现在补上，它是齐次坐标操作的基本件。）

## 4.2 射线与三角形相交：Möller–Trumbore

### 4.2.1 推导：从方程组到克莱姆法则

三角形内一点可以用重心坐标（barycentric coordinates）表示为 `V0 + u·E1 + v·E2`，其中 `E1 = V1 - V0`、`E2 = V2 - V0`、u ≥ 0、v ≥ 0、u + v ≤ 1（三角形内部/边界）。射线上的点是 `O + t·D`。相交即两个表示相等：

```text
O + t·D = V0 + u·E1 + v·E2
移项：  -t·D + u·E1 + v·E2 = O - V0
```

这是关于 (t, u, v) 的线性方程组，按克莱姆法则（Cramer's rule）求解，系数行列式为 `det = E1 · (D × E2)`（记 `pvec = D × E2`，则 `det = E1 · pvec`）。三个解：

```text
tvec = O - V0
qvec = tvec × E1
t = (E2 · qvec) / det
u = (tvec · pvec) / det
v = (D · qvec) / det
```

这就是 Möller–Trumbore 算法：**两次叉积、三次点积**解出全部三个未知数，不需要预先算三角形平面方程，也天然给出重心坐标（交点处的插值 uv、法线插值都靠它）。两个退化情形的处理：

- `det ≈ 0`：射线与三角形平面平行，无解；
- `det < 0`：射线从三角形**背面**射入（D 叉乘方向翻转）。背面剔除版直接拒绝 `det < ε`；双面拾取版对 `|det| < ε` 拒绝、其余照算。

### 4.2.2 完整核心代码

```typescript
// interaction/intersect.ts
import { Vec3 } from "../math/Vec3";

export interface TriangleHit {
  t: number; // 射线参数：交点 = origin + t * direction
  u: number; // 重心坐标（相对 V1）
  v: number; // 重心坐标（相对 V2）
}

const EPSILON = 1e-8;
const _edge1 = new Vec3();
const _edge2 = new Vec3();
const _pvec = new Vec3();
const _tvec = new Vec3();
const _qvec = new Vec3();

/**
 * Möller–Trumbore 射线-三角形求交
 * @param cullBackface true 时背面（det < 0）直接返回 null
 */
export function intersectTriangle(
  origin: Vec3, direction: Vec3,
  v0: Vec3, v1: Vec3, v2: Vec3,
  cullBackface = false,
): TriangleHit | null {
  Vec3.subtract(_edge1, v1, v0);          // E1
  Vec3.subtract(_edge2, v2, v0);          // E2
  Vec3.cross(_pvec, direction, _edge2);   // pvec = D × E2

  const det = Vec3.dot(_edge1, _pvec);    // det = E1 · pvec
  if (cullBackface) {
    if (det < EPSILON) return null;       // 背面或平行
  } else {
    if (Math.abs(det) < EPSILON) return null; // 仅拒绝平行
  }
  const invDet = 1 / det;

  Vec3.subtract(_tvec, origin, v0);       // tvec = O - V0
  const u = Vec3.dot(_tvec, _pvec) * invDet;
  if (u < 0 || u > 1) return null;        // 快速剔除：u 出界

  Vec3.cross(_qvec, _tvec, _edge1);       // qvec = tvec × E1
  const v = Vec3.dot(direction, _qvec) * invDet;
  if (v < 0 || u + v > 1) return null;    // v 出界或 u+v 出界

  const t = Vec3.dot(_edge2, _qvec) * invDet;
  if (t < 0) return null;                 // 三角形在射线背后

  return { t, u, v };
}
```

注意代码顺序是"算一个验一个"（u 验完再算 v），大部分未命中三角形在头两次点积后就退出——比"全算完再一起验"平均快一倍以上，这是分支友好的经典写法。

三角形顶点来自几何数据，但射线是世界空间的——**必须先把顶点变换到世界空间**（乘 `mesh.matrixWorld`），或者等价地把射线逆变换到模型局部空间（乘逆矩阵，每 mesh 一次而不是每顶点一次）。后者更优：

```typescript
// 模型空间求交：只做两次矩阵变换，而不是 N 次顶点变换
const invWorld = Mat4.invert(new Mat4(), mesh.matrixWorld);
const localRay = {
  origin: Vec3.transformMat4(new Vec3(), ray.origin, invWorld),
  direction: Vec3.transformDirection(new Vec3(), ray.direction, invWorld),
  // 注意：direction 乘 4x4 后要归一化（含缩放时长度会变），
  // 且 t 需要按缩放比例换算回世界距离：t_world = t_local / length(未归一化方向)
};
```

`t` 的换算容易漏：局部空间里方向若被缩放短了，`t_local` 与世界距离不同比例。简单做法是变换后先记录长度 `len`、归一化再求交，世界距离 = `t_local * len`。

## 4.3 射线与球 / 包围盒求交：先粗后细

### 4.3.1 设计动机：不要对每个三角形做 Möller–Trumbore

一个 2 万三角形的模型，鼠标每移动一次都做 2 万次三角形求交，60fps 的交互帧预算（16ms）根本扛不住。先做**粗测（broad phase）**：射线与包围体（bounding volume）求交，包围体都不碰的模型直接跳过；命中的再做三角形级**精测（narrow phase）**。两级包围体是标配：

- **包围球（bounding sphere）**：求交最便宜（解一元二次方程），旋转不变（模型转了球不用重算）；
- **轴对齐包围盒（AABB，Axis-Aligned Bounding Box）**：通常比球贴得更紧，求交稍贵（slab method）。

更复杂的模型再加一层 **BVH（Bounding Volume Hierarchy，层次包围体）**：三角形分组成树，自顶向下先测大盒再深入，把精测从 O(n) 降到 O(log n)。迷你框架实现球 + AABB 两级即可，BVH 留给性能需要时（第六阶段对标 three.js 的 `Raycast` 加速结构）。

### 4.3.2 完整核心代码：球与 AABB

```typescript
// interaction/bounds.ts

/** 射线-球：代入 |O + tD - C|² = r² 解一元二次方程 */
export function intersectSphere(
  origin: Vec3, direction: Vec3,
  center: Vec3, radius: number,
): number | null {
  // direction 已归一化时 a = D·D = 1，方程简化为 t² + 2bt + c = 0
  const ox = origin.x - center.x;
  const oy = origin.y - center.y;
  const oz = origin.z - center.z;
  const b = ox * direction.x + oy * direction.y + oz * direction.z; // b = D·(O-C)
  const c = ox * ox + oy * oy + oz * oz - radius * radius;          // c = |O-C|²-r²
  const discriminant = b * b - c;
  if (discriminant < 0) return null;      // 判别式 < 0：射线不碰球
  const sqrtD = Math.sqrt(discriminant);
  const t0 = -b - sqrtD;                  // 近交点
  const t1 = -b + sqrtD;                  // 远交点
  if (t0 >= 0) return t0;                 // 球在射线前方
  if (t1 >= 0) return 0;                  // 起点在球内：视为命中（t=0）
  return null;                            // 球在射线背后
}

/** 射线-AABB：slab method，逐轴求射线进出区间的交集 */
export function intersectAABB(
  origin: Vec3, direction: Vec3,
  min: Vec3, max: Vec3,
): number | null {
  let tmin = -Infinity;
  let tmax = Infinity;

  for (const axis of ["x", "y", "z"] as const) {
    const d = direction[axis];
    const o = origin[axis];
    if (Math.abs(d) < 1e-10) {
      // 射线与该轴平行：起点在 slab 外则整条射线不可能进盒
      if (o < min[axis] || o > max[axis]) return null;
      continue;
    }
    let t1 = (min[axis] - o) / d;   // 进入该轴 slab 的 t
    let t2 = (max[axis] - o) / d;   // 离开该轴 slab 的 t
    if (t1 > t2) { const tmp = t1; t1 = t2; t2 = tmp; } // 反向射线交换
    tmin = Math.max(tmin, t1);      // 三轴进入时间的最大值
    tmax = Math.min(tmax, t2);      // 三轴离开时间的最小值
    if (tmin > tmax) return null;   // 三段区间无交集：不命中
  }
  return tmin >= 0 ? tmin : (tmax >= 0 ? 0 : null); // 起点在盒内返回 0
}
```

slab method 的直觉：把盒子看成三对平行平板（slab）的交集，射线与每对平板相交出一个 t 区间，三个区间有公共部分（`tmin ≤ tmax`）即穿过盒子；`tmin ≥ 0` 表示盒子在前方。它一次处理三个轴、无三角函数，是 AABB 求交的标准解。

```typescript
// interaction/raycastMesh.ts —— 先粗后细的完整拾取路径
function raycastMesh(ray: Ray, mesh: Mesh): RaycastHit | null {
  // 粗测 1：包围球（世界空间，由 mesh 上帧 matrixWorld 更新时同步刷新）
  if (intersectSphere(ray.origin, ray.direction,
                      mesh.boundingSphere.center, mesh.boundingSphere.radius) === null) {
    return null; // 球都不碰，2 万个三角形一个都不用测
  }
  // 粗测 2（可选）：局部 AABB，比球紧时再过滤一层
  // 精测：射线逆变换到模型空间，逐三角形 Möller–Trumbore，取最近 t
  let best: TriangleHit | null = null; let bestTri = -1;
  for (let i = 0; i < mesh.geometry.indexCount; i += 3) {
    const tri = readTriangleWorldOrLocal(mesh.geometry, i); // 顶点读取
    const hit = intersectTriangle(localRay.origin, localRay.direction,
                                  tri[0], tri[1], tri[2]);
    if (hit && (best === null || hit.t < best.t)) { best = hit; bestTri = i; }
  }
  if (!best) return null;
  // 组装世界空间命中信息（t 按缩放换算，见 4.2.2 末尾）
  return { distance: best.t, point: /* O + t·D */, node: mesh, /* uv 由重心坐标插值 */ };
}
```

## 4.4 事件系统与控制器抽象

### 4.4.1 设计动机：拾取结果要变成"谁收到了点击"

`raycaster.intersectObject()` 返回命中列表只是半成品，用户想要的是 `mesh.on("click", ...)`。交互系统三件事：**事件语义**（click 与 pointerdown/pointerup 的关系、enter/leave 的界定）、**传播路径**（命中节点及其祖先谁先收到——沿场景图冒泡，与 DOM 一致的心智模型）、**输入抽象**（Pointer Events 统一鼠标/触摸）。

### 4.4.2 方案对比

| 方案 | 派发路径 | 优点 | 缺点 |
|---|---|---|---|
| 只派发给命中节点 | 无传播 | 简单 | 想在父节点统一处理子物体点击做不到 |
| 沿父链冒泡（本方案，同 DOM） | 节点 → parent → … → scene | 分组处理自然，心智模型熟悉 | 需要 stopPropagation 约定 |
| 事件总线广播 | 全局订阅过滤 | 解耦 | "谁在听"不可见，调试困难 |

### 4.4.3 完整核心代码：InteractionManager

```typescript
// interaction/InteractionManager.ts
type InteractionEventName = "click" | "pointerdown" | "pointerup" | "pointerenter" | "pointerleave";

export class Emitter {
  private listeners = new Map<string, Set<(e: unknown) => void>>();
  on(name: string, fn: (e: unknown) => void): () => void {
    if (!this.listeners.has(name)) this.listeners.set(name, new Set());
    this.listeners.get(name)!.add(fn);
    return () => this.off(name, fn); // 返回解绑函数
  }
  off(name: string, fn: (e: unknown) => void): void {
    this.listeners.get(name)?.delete(fn);
  }
  emit(name: string, e: unknown): void {
    for (const fn of this.listeners.get(name) ?? []) fn(e);
  }
}

// Node3D 继承 Emitter（场景层不动渲染层，事件能力挂在节点上）

interface InteractionEvent {
  type: InteractionEventName;
  hit: RaycastHit;
  /** 冒泡控制：true 则不再传给祖先 */
  stopPropagation(): void;
  propagationStopped: boolean;
  originalEvent: PointerEvent;
}

export class InteractionManager {
  private raycaster = new Raycaster();
  private hovered: Node3D | null = null;

  constructor(private canvas: HTMLCanvasElement,
              private getCamera: () => Camera,
              private scene: Node3D) {
    canvas.addEventListener("pointerdown", this.onPointerDown);
    canvas.addEventListener("pointerup", this.onPointerUp);
    canvas.addEventListener("pointermove", this.onPointerMove);
    canvas.addEventListener("pointerleave", this.onPointerLeave);
  }

  private dispatch(hit: RaycastHit, type: InteractionEventName, raw: PointerEvent): void {
    let node: Node3D | null = hit.node;
    const e: InteractionEvent = {
      type, hit, originalEvent: raw,
      propagationStopped: false,
      stopPropagation() { this.propagationStopped = true; },
    };
    // 沿父链冒泡：命中节点 -> 祖先 -> scene 根
    while (node) {
      node.emit(type, e);
      if (e.propagationStopped) break;
      node = node.parent;
    }
  }

  private updateHover(raw: PointerEvent): RaycastHit | null {
    this.raycaster.setFromEvent(this.getCamera(), raw, this.canvas);
    const hits = this.raycaster.intersectObject(this.scene);
    const top = hits[0]?.node ?? null;

    // enter/leave 语义：悬停对象变化时，旧对象 leave、新对象 enter
    if (top !== this.hovered) {
      this.hovered?.emit("pointerleave", { originalEvent: raw });
      this.hovered = top;
      top?.emit("pointerenter", { originalEvent: raw });
    }
    return hits[0] ?? null;
  }

  private onPointerMove = (raw: PointerEvent): void => {
    const hit = this.updateHover(raw);
    if (hit) this.dispatch(hit, "pointermove", raw); // 简化：move 事件派发给命中链
  };

  private downHit: RaycastHit | null = null;
  private onPointerDown = (raw: PointerEvent): void => {
    this.downHit = this.updateHover(raw);
    if (this.downHit) this.dispatch(this.downHit, "pointerdown", raw);
  };
  private onPointerUp = (raw: PointerEvent): void => {
    const upHit = this.updateHover(raw);
    if (upHit) this.dispatch(upHit, "pointerup", raw);
    // click 语义：按下与抬起命中同一对象才触发（同 DOM）
    if (upHit && this.downHit && upHit.node === this.downHit.node) {
      this.dispatch(upHit, "click", raw);
    }
    this.downHit = null;
  };

  private onPointerLeave = (): void => {
    this.hovered?.emit("pointerleave", {});
    this.hovered = null;
  };

  dispose(): void {
    // 移除全部监听（防止 canvas 移除后仍持有场景引用）
  }
}
```

### 4.4.4 控制器抽象：OrbitControls 的骨架

控制器（controls）与事件系统的分工：事件系统回答"点了哪个物体"，控制器回答"相机怎么动"。两者都消费 pointer 事件但互不感知——控制器监听 canvas、自己维护相机，不参与冒泡。OrbitControls 的状态只有一个球坐标（spherical coordinates）加目标点：

```typescript
// interaction/OrbitControls.ts —— 骨架（完整版第三阶段已搭，此处补抽象边界）
export class OrbitControls {
  private theta = 0.6;      // 水平角
  private phi = 1.0;        // 垂直角（clamp 在 (0.01, PI-0.01) 防万向节翻转）
  private radius = 5;
  readonly target = new Vec3();

  constructor(private canvas: HTMLCanvasElement, private camera: PerspectiveCamera) {
    canvas.addEventListener("pointerdown", this.onDown);
    canvas.addEventListener("wheel", this.onWheel, { passive: false });
  }

  private onDrag = (dx: number, dy: number): void => {
    this.theta -= dx * 0.005;   // 拖拽 -> 角度
    this.phi   -= dy * 0.005;
    this.phi = Math.min(Math.PI - 0.01, Math.max(0.01, this.phi));
    this.apply();
  };

  private onWheel = (e: WheelEvent): void => {
    e.preventDefault();
    this.radius *= e.deltaY > 0 ? 1.1 : 0.9; // 滚轮 -> 半径（指数缩放手感均匀）
    this.apply();
  };

  /** 球坐标 -> 相机位置 -> lookAt，相机参数只在这里写 */
  private apply(): void {
    const { theta, phi, radius } = this;
    this.camera.position.set(
      this.target.x + radius * Math.sin(phi) * Math.sin(theta),
      this.target.y + radius * Math.cos(phi),
      this.target.z + radius * Math.sin(phi) * Math.cos(theta),
    );
    this.camera.lookAt(this.target);
  }
}
```

抽象边界一句话：**控制器改相机参数，不改场景、不改渲染状态**——将来加第一人称控制器、轨迹球控制器，都只实现"pointer 输入到相机参数"这一段映射。

### 4.4.5 常见坑

1. **每 pointermove 全场景 raycast**。move 事件高频触发（高刷屏 120Hz+），而大多数帧命中结果没变。两个缓解：事件节流（16ms 内只测一次）；缓存上次命中的包围球先验测试。
2. **canvas 尺寸变化后 rect 未重取**。`getBoundingClientRect` 每次都调有 layout 成本，但缓存它会在窗口 resize 后给出错误 NDC。折中：resize 事件时失效缓存。
3. **hover 高亮改了材质 uniform 却没恢复**。enter 时改 `material.color`、leave 时忘了存旧值。正确做法：enter/leave 成对操作放在同一个状态对象里管理，或高亮用独立 technique（比如描边 pass）不动原材质。
4. **点透**：点击落在透明物体上时 `intersectObject` 命中了它，但用户想选它背后的实体。给材质加 `raycastEnabled = false` 开关，玻璃、大气壳类物体关掉。
5. **pointerup 在 canvas 外发生**。拖拽出画布松手，`pointerup` 收不到、拖拽状态卡死。用 `setPointerCapture`（指针捕获）把后续事件锁给 canvas。
