## 1. 思维切换：从「控制流劫持」到「堆元数据攻击」

[22 册](./22-ROP-返回导向编程.md) 的栈利用是**直接**控制流劫持：溢出 → 覆盖返回地址 → 立刻决定 CPU 下一步执行什么。堆利用是**间接**的，多一层「造原语」：

```text
栈溢出（ROP 思维）：  溢出 ──────────────► 控制流（rip）
堆利用（本篇思维）：  溢出/UAF/double free ─► 分配器元数据 ─► 「任意地址分配/写」原语 ─► 控制流或数据流
```

为什么需要这层中转？因为堆上**没有返回地址**——越界写踩到的是 malloc 的**账本**（size、fd/bk、next），攻击者要做的是把账本改成「malloc 会把下一个 chunk 开在我想写的地址」。堆利用的套路名（poisoning、dup、unlink、house of …）本质上都在回答同一个问题：

> **给攻击者一次「越界写」或「悬垂写」，如何让它变成一次「写任意地址」？**

三种最常见的第一步原语（回顾 [21 册 §7](./21-栈溢出与堆溢出.md)）：

| 第一原语 | 来源 | 特点 |
| --- | --- | --- |
| 堆溢出（越界写） | `strcpy/memcpy` 越界 | 只能写**相邻** chunk 的元数据，位置受限 |
| UAF（悬垂写） | free 后指针未置空 | 能写**已释放** chunk 的 fd/next 等字段，位置自由 |
| double free | 同一指针释放两次 | 让同一 chunk 在账本里出现两次 → 别名 |

本篇 §3—§5 的每个技术，都是「第一原语 × 分配器某条路径」的组合。

## 2. ptmalloc 全景：chunk、arena、bin 与 malloc/free 路径

> [20 册 §5](./20-程序内存布局.md) 已入门过 chunk 与 bin；本节补齐 arena 与路径，作为后续每个攻击的「地图」。

### 2.1 chunk 结构与 P/M/N 标志位

```text
chunk 指针指向 chunk 头；malloc 返回的是 mem = chunk + 0x10（x86-64）

        ┌─────────────────┐  ← chunk 指针（低地址）
        │ prev_size (0x08)│  仅当上一块空闲（P=0）时有意义：上一块的大小；
        │                 │  上一块在用时这里是上一块的 user data（可复用，省 8 字节）
        ├─────────────────┤
        │ size      (0x08)│  本块总大小（含头），低 3 位是标志位，参与对齐
        ├─────────────────┤  ← mem 指针 = malloc 的返回值
        │ user data ...   │  可用大小 ≈ size − 8（借用了下一块的 prev_size）
        └─────────────────┘
低三位标志位（掩码 0x7）：
  P = PREV_INUSE    (0x1)  上一块是否在用；P=0 时 free 会向低地址合并
  M = IS_MMAPPED    (0x2)  本块是否由 mmap 单独映射（free 走 munmap，不进 bin）
  N = NON_MAIN_ARENA(0x4)  本块是否属于非主线程 arena（多线程堆的关键）
```

**尺寸换算（request → chunk size）速查**：x86-64 下 `request2size` 宏的算法是「请求 + 8 字节（size 头；prev_size 可借用下一块）向上对齐到 0x10，最小 0x20」。这是堆题手算基本功（[21 册 §9.3](./21-栈溢出与堆溢出.md) 第 5 条坑的完整版）：

| `malloc(n)` | chunk 实际 size | free 后第一站（惯例值） |
| --- | --- | --- |
| 0x18 | 0x20 | tcache 0x20 桶 |
| 0x40 | 0x50 | tcache 0x50 桶 |
| 0x78 | 0x80 | tcache 0x80 桶（0x80 也是 fastbin 上限边界） |
| 0x88 | 0x90 | tcache 0x90 桶（超出 fastbin 档位） |
| 0x408 | 0x410 | tcache 最大桶 |
| 0x410 | 0x420 | **超 tcache 上限** → 合并检查 → unsorted bin |
| 0x500 | 0x510 | unsorted bin（large bin 尺寸） |

三条由结构直接导出的规则（后面所有攻击都在钻它们的空子）：

1. **`size` 是唯一被信任的账目**：free/malloc 的大量路径先信 size 再核对（或不核对）——改 size 就能「让分配器看错账」；
2. **`prev_size` 是条件字段**：P=1 时它属于上一块的 user data，**写它无害**（[21 册 §7.1](./21-栈溢出与堆溢出.md) 的堆溢出代码正是先写 0 占位）；P=0 时它被信任用于向低地址合并；
3. **user 区前 16 字节在 free 后会被链表字段复用**：tcache 的 `next/key`、fastbin 的 `fd`、普通 bin 的 `fd/bk` 都直接踩进原 user data——UAF 改的就是它们。

### 2.2 arena：账本的宿主

- **main_arena**：主线程的 `malloc_state` 结构，位于 glibc 数据段（**非 PIE libc 的已知地址之一**，unsorted bin attack/泄露 libc 基址都靠它）；主堆来自 `brk`，不足以 `mmap` 补；
- **thread arena**：非主线程首次 malloc 时由 `mmap` 单独创建的堆区；其 chunk 的 N 位（NON_MAIN_ARENA）置 1，free 时据此路由到正确的 arena——**改 N 位能把 chunk 送进错误的账本**（进阶玩法，知道即可）；
- 单线程下一切讨论都在 main_arena；多线程下每线程一个 arena、堆题里常关线程（无锁竞争）。

### 2.3 bin 家族：空闲 chunk 的分级账本

| bin | 结构与组织 | 大小范围（x86-64 惯例） | 查找顺序要点 |
| --- | --- | --- | --- |
| **tcache** | 每线程 64 个桶，每桶默认 7 个；单链 `next`（LIFO）+ `key` 防护 | 0x20—0x410 | **malloc/free 的第一站**，命中即返回，几乎无检查 |
| **fastbin** | main_arena 里 10 个（数量为惯例值）单链表 `fd`（LIFO） | < 0x80（`global_max_fast` 惯例值） | tcache 空了才看；取出时校验 size 与 bin 匹配 |
| **small bin** | 0x20—0x3f0，每尺寸一条**双链**（fd/bk，FIFO） | 精确尺寸命中 | 大 bin 数组直接索引 |
| **large bin** | ≥ 0x400，**双链 + fd_nextsize/bk_nextsize** 跳表式组织 | 0x400 以上 | 取「不小于请求的最小块」，可能切割 |
| **unsorted bin** | **一条双链**，所有非 fastbin/tcache 的 free chunk 先进这里；malloc 时遍历：精确命中直接返回，否则按 size 归位到 small/large bin | 不限 | 大小分配的**中转站**，也是「泄露 main_arena 地址」的经典泄露点 |
| **top chunk** | 堆顶的「最后一块」 | — | 所有 bin 都失败时从这里切割；不够则 `sysmalloc` 扩堆 |

记住两条流水线（下一节的路径由此展开）：**free 流水线**：tcache → fastbin →（否则）合并邻居 → unsorted bin；**malloc 流水线**：tcache → fastbin/smallbin → unsorted bin 遍历 → binmap 扫 → top。

### 2.4 malloc 关键路径（伪代码级）

```text
malloc(req)（线程安全外壳之后，tcache 快路径）
├─ ① tcache：对应桶 count>0 → tcache_get 直接弹出返回（检查极少：对齐检查见 §6.3）
├─ ② _int_malloc：
│   ├─ req ≤ fastbin 上限：对应 fastbin 链头取出（校验 chunk size 与 bin 匹配）；
│   │   顺带把该 fastbin 其余块批量转存进 tcache（stashing，§3.3 的舞台）
│   ├─ req 为 small：smallbin 精确取（同样批量转存进 tcache）
│   ├─ 遍历 unsorted bin：
│   │    ├─ 精确命中 → 返回（唯一在途切割例外：last_remainder 规则）
│   │    ├─ 否则把每块按 size 归位 small/large bin（对 victim 的 fd/bk 一致性有检查，§6.3）
│   ├─ binmap 扫描更大的 bin：取出最小够用的，切割，余料回 unsorted/small
│   └─ top chunk 切割；不够 → sysmalloc（brk/mmap）
└─ 各级取出时若 tcache 有空位，常顺手把同尺寸兄弟填充进 tcache（fill）
```

攻击视角读这张图：**①几乎不设防（tcache 系攻击的主场）、②的 fastbin 只查 size、③的双链操作是 unsorted bin attack 与 unlink 攻击的舞台、top 相关是 house of force/orange 的舞台。**

### 2.5 free 关键路径（伪代码级）

```text
free(p)
├─ 尺寸/对齐合法性检查（free(): invalid pointer / invalid size）
├─ ① tcache 未满 → tcache_put：写 e->key = tcache_key（2.29+）；
│    若发现 e->key == tcache_key → 遍历链表查 double free（§6.2）
├─ ② fastbin 尺寸 → 只查「链头 == 本块吗」（fasttop 检查）后头插 fd
├─ ③ 否则普通路径：
│    ├─ 读 prev_inuse：P=0 → 上一块空闲 → 从其 bin 摘除（unlink，含一致性检查）
│    ├─ 读 next chunk 的 size / nextnext 的 P 位：决定是否与下一块合并
│    └─ 合并结果头插进 unsorted bin（写 fd/bk = unsorted bin 头，main_arena 地址）
└─ 空闲内存累计超阈值 → malloc_consolidate（把 fastbin 也合并进 unsorted/top）
```

攻击视角：**①的 key 检查可被「顺手覆写」绕过；②的 fasttop 只看链头（fastbin dup 的生存空间）；③的 unlink 一致性检查是 unsafe unlink 的对手盘——检查加严史就是攻击淘汰史。**

> 路径中每一步的具体检查项与报错字符串，**以所用版本 `malloc/malloc.c` 源码为准**；调试时在 pwndbg 里直接 `heap`、`bins`、`tcache` 观察真实状态（[24 册](./24-二进制分析工具-gdb-pwndbg-ghidra-objdump.md)）。

## 3. tcache：现代堆题的第一战场

[21 册 §7.2](./21-栈溢出与堆溢出.md) 已给出最小 tcache poisoning；本节补齐「为什么它这么好打」与三个进阶变体。

### 3.1 tcache poisoning：任意地址分配

**结构**：tcache 每桶是 `entries[i]` 链头 + 计数；free 进桶时 `e->next = entries[i]; e->key = tcache_key; entries[i] = e`；malloc 取出时只做 `entries[i] = e->next` 就返回——**取出的值完全来自链上节点的 next 字段**。

**攻击**：任何能写到「已 free 的 tcache 块」的前 8 字节的第一原语（UAF/堆溢出/double free 造别名），把 `next` 改成目标地址：

```text
改 next 前的链：entries → B → A → NULL        （free B 再 free A 得到）
改 B->next 后：entries → B → TARGET
malloc 第 1 次：返回 B，entries 指向 TARGET（next 已是伪造值）
malloc 第 2 次：返回 TARGET                    ← 任意地址「分配」，随后写即任意写
```

**一次典型 grooming（顺序编排）全记录**（UAF 场景，glibc 2.31 惯例参数，示意）：

```text
① malloc A(0x40); malloc B(0x40); malloc C(0x40)   C 防 top 合并
② free A; free B          tcache[0x50]: B → A（count=2）
③ UAF edit B: B->next = TARGET               链变 B → TARGET
④ malloc → B        （count=1，entries=TARGET）
⑤ malloc → TARGET   （count=0）任意地址到手，edit 即写
—— 若 ③ 之前没有 ② 的两次 free（count<2），第 ⑤ 步根本走不到 tcache 路径：
   「让账本上有货可取」与「把货指向目标」同样重要，这就是 grooming 的含义
```

三个工程细节（承接 [21 册 §7.2](./21-栈溢出与堆溢出.md)，此处只列增量）：

1. **桶内 count ≥ 2 才取得出两连**——分配/释放的**顺序编排**（grooming）是堆题的「内功」；
2. **2.32+ Safe-Linking**：写入值必须是 `(B地址 >> 12) ^ TARGET`（§6.1）；同时取出时校验 `TARGET` 按 0x10 对齐（`malloc(): unaligned tcache chunk detected`）——**目标地址必须对齐**，且通常还需要目标处能通过后续使用；
3. **打到哪去（目标选择随时代变化）**：`__free_hook/__malloc_hook`（≤ 2.33，[37 册 §6.3](../07-ctf/37-CTF-Pwn-方向.md) 的经典两步）→ 2.34 后 hook 删除，改打 `exit_funcs`、`_IO_list_all`/FILE 结构、栈上返回地址（需先泄露栈地址）、TLS/`ld.so` 相关结构——**poisoning 原语本身不变，变的只是目的地**。

### 3.2 tcache dup：double free 的 tcache 变体

**glibc 2.26—2.28（无 key 的黄金期）**：tcache 完全没有 double free 检测——同一块 free 两次，链变成 `entries → A → A → A …`（第二次 free 时 `A->next = entries` 即 `A->next = A`，自环）。malloc 两次取回同一块，第二次分配后 edit 就是在改「还在链上的链头 next」——**一个 double free 直接等于一次 poisoning**。

**glibc 2.29+（key 检测上岗）**：tcache_put 写 `e->key = tcache_key`；再次 free 同一块时先比对 key，命中再遍历链表确认，确认即 `abort`。绕过思路（理解检测原理后自然得出）：

- **改 key**：第一原语顺手把 `key` 覆写成别的值（堆溢出/UAF 的常规动作）；
- **换路径**：先让块离开 tcache（被 malloc 取走）再 free 第二次——此时它走 fastbin/普通路径，两次进入**不同账本**，配合 §4.1 fastbin dup；
- **house of botcake**：让同一块同时存在于 tcache 与 unsorted bin 两条账本（先填满 tcache 再 free 触发合并路径），名字来自「烘焙蛋糕般把两条链路叠起来」——how2heap 有完整 demo，本篇不展开。

### 3.3 tcache stashing unlink（概念级）

**舞台**：`_int_malloc` 从 smallbin（或 fastbin 转存）取出命中块时，会把同 bin 的**其余块批量搬进 tcache**（stashing，填充缓存）——搬运动作内部含一次「从 smallbin 双链摘除」（unlink）。

**攻击**（需要 calloc 或 tcache 已满等「绕过 tcache 直接打 smallbin」的条件）：堆溢出改 smallbin 中某块 `b->bk` 指向 `FAKE − 0x10`，搬家时分配器把 `FAKE` 当作链上的下一块**链进 tcache**。效果：一次攻击同时获得「smallbin 摘除时的指针写」与「伪造块进入 tcache（随后可被 malloc 取出）」两重收益——典型用途是把 `FAKE` 设在栈/目标结构附近实现「把任意地址链入分配账本」。

理解到「**它攻击的是『取出时顺带填充 tcache』这条自动化流水线**」即可；复现走 CTF Wiki/how2heap。

## 4. 经典 bin 攻击：fastbin dup、unsorted bin attack、unsafe unlink

### 4.1 fastbin dup（A-B-A 三明治）

fastbin 的 free 侧只有 fasttop 检查：`if (old == p) abort`（只比链头）。于是：

```text
free(A); free(B); free(A)      ← A 不在链头时第二次 free 不会被拦
fastbin[idx]：A → B → A → B → …（A、B 交替成环）
malloc×4：拿到 A, B, A, B      ← 第 1 次拿到 A 时它还在链上！
此时用 edit/write 填 A->fd = FAKE（fastbin 的 fd 指向 chunk 头）
再 malloc：返回 B，链头变 FAKE；再 malloc：返回 FAKE+0x10
```

**FAKE 的门槛**：从 fastbin 取出时校验「chunk 的 size 与该 fastbin 档位匹配」——伪造地址处必须有一个合法 size。著名目标 `__malloc_hook - 0x23` 的玄机：该偏移处恰好有 libc 里的字节序列凑出合法 size（`0x7f`），错位排布使「hook 之前的无用字节」被当成 size——这是**「在不可写区域找合法 size 指纹」**的通用技巧。hook 已在 2.34 删除，此打法退场，但「size 指纹」思想仍在（[37 册 §6.2](../07-ctf/37-CTF-Pwn-方向.md) 有完整串讲）。

### 4.2 unsorted bin attack（概念级）

**机制**：malloc 从 unsorted bin 取走 victim 时执行双链摘除，其中一步是 `bck->fd = unsorted_chunks(av)`——把 **unsorted bin 头（main_arena 内的地址）写入 `victim->bk->fd`**。

**攻击**：堆溢出改 `victim->bk = TARGET - 0x10`，使 `TARGET` 处被写入 main_arena 地址。**效果是「向目标写一个大且半固定的值」**，不是任意值——经典用途是覆写 `global_max_fast`（把 fastbin 上限改大，解锁更多 fastbin 档位以衔接后续攻击）。

**现状**：现代 glibc 在 unsorted 取出路径加了 `bck->fd == victim` 一致性检查，直接版已死；它的现代转世是 **large bin attack**（利用 fd_nextsize 搬运时的写，同样「写半固定值」）。理解价值在于：**凡「双链摘除」，必有「bk/fd 的间接写」**——这是 unlink 类攻击的共同内核。

### 4.3 unsafe unlink 与堆溢出：老而弥坚

**unlink 宏**（把空闲块 P 从双链摘除）的骨架与检查：

```c
// 检查（现代 glibc）：FD = P->fd; BK = P->bk;
//   if (FD->bk != P || BK->fd != P) → "corrupted double-linked list"
//   （2.26+ 另有 prev_size/size 一致性检查）
FD->bk = BK;
BK->fd = FD;      // 两次间接写
```

**经典利用（unsafe unlink）**：用堆溢出改一个**已空闲块**的 `fd/bk`，使两次间接写落在攻击者想要的位置。绕过 `FD->bk == P && BK->fd == P` 检查的姿势是「自己指向自己」：设程序里有全局指针 `ptr` 指向该堆块，取

```text
P->fd = &ptr - 0x18      （使 FD->bk 即 *(&ptr-0x18+0x18) == ptr == P ✓）
P->bk = &ptr - 0x10      （使 BK->fd 即 *(&ptr-0x10+0x10) == ptr == P ✓）
```

合并触发 unlink 后，`ptr` 被改写为 `&ptr - 0x18`——**全局指针从此指向自己附近**，后续 `ptr->field = X` 类写就变成「改 ptr 本身再改任意地址」的两级跳板。防御视角：这套姿势依赖「存在指向堆块的可寻址指针」（全局变量/结构体成员），也依赖检查不严的旧版本；但**「制造一个通过了完整性检查的假双链」这一内核思想**贯穿 largebin attack、tcache stashing 等一切现代变体。

## 5. house of 系列一瞥（点名思想，不展开流程）

「house of X」谱系源自《The Malloc Maleficarum》对 ptmalloc 攻击面的系统枚举——**每幢「房子」= 绕过当时某组检查的一条完整建造流水线**。思想谱系（细节以 how2heap 对应 demo 与注释为准）：

| 名号 | 一句话思想 | 舞台 |
| --- | --- | --- |
| **house of spirit** | free 一个**根本不在堆上的伪造 chunk**（栈/BSS 上排好 size 与「下一块」的假象），让后续 malloc 把它取出来——「free 的输入可控」即是原语 | free 路径的边界检查 |
| **house of orange** | 全程 free 不了也能造空闲块：改小 top 的 size 迫使 sysmalloc 换堆，**旧 top 摇身变成 unsorted bin 里的空闲块**；再接 unsorted bin attack 打 `_IO_list_all`，伪造 FILE 结构走 `_IO_flush_all_lockp` 拿控制权（FSOP 思想的开山） | top/sysmalloc 与 IO 子系统 |
| house of force（已故） | 覆盖 top 的 size 为 -1，让下一次超大 malloc 直接「走到」目标地址附近 | 老 glibc 的 top 检查缺失 |
| house of botcake | §3.2 所述：同一块同时挂 tcache 与 unsorted 两条账本，绕 2.29 key 检测 | 2.29+ |
| house of einherjar / poison-null-byte | off-by-one（清零 P 位/size 低位）触发错误合并 | off-by-one 场景 |

看点不是背名字，而是**每幢房子都精确对应一组「当时缺失的检查」**：读 how2heap 时先问「这个 demo 依赖哪个检查不存在/可被满足」，再对照 [21 册 §9.2](./21-栈溢出与堆溢出.md) 的版本时间线——攻击的兴衰史就是分配器的加固史。

两个点名对象展开半步（仍不展开完整利用流程）：

**house of spirit 要骗过 free 的哪几道检查**（对照 §6.3 矩阵读，这同时是自测第 10 题的答案框架）：

```text
伪造块 FAKE（栈/BSS 上）需要：
① 指针对齐（free(): invalid pointer 的对齐分支）
② FAKE 的 size 合法且落在 tcache/fastbin 档位（invalid size 分支）
③ 「下一块」的 size 在合理区间（invalid next size 分支——所以要在 FAKE+size 处再布置一个像样的 size）
④ fastbin 路径还要过 fasttop；tcache 路径则连 ③ 都宽松——2.26 后首选 tcache 档位
随后 malloc 同尺寸 → tcache/fastbin 把栈上地址当货发出 → 栈上拿到「堆分配」
```

**house of orange 的四步骨架**（理解「没有 free 也能入账」这一反直觉点即可）：

```text
① 堆溢出改小 top->size（保留页对齐与标志位合法性——sysmalloc 有自己的完整性检查）
② 请求一个大于残存 top 的块 → sysmalloc 弃用旧 top 换新堆（mmap/扩展）
③ 旧 top 进入 unsorted bin —— 攻击者凭空获得了一个「已入账」的空闲块
④ 后续：用它泄露 main_arena（unsorted 双链指向）→ unsorted bin attack / largebin 路线 → 打 _IO_list_all 走 FSOP
```

其余各幢房子建议按此模板自学：**先列它必须骗过的检查，再看 demo 如何布置数据**。

## 6. 现代缓解与绕过思路

### 6.1 Safe-Linking（glibc 2.32+）：指针异或保护

```c
// 存（tcache_put / fastbin 头插）：
e->next = PROTECT_PTR(&e->next, entries[i]);   // PROTECT_PTR(pos, ptr) = ((size_t)pos >> 12) ^ (size_t)ptr
// 取（tcache_get / fastbin 弹出）：
entries[i] = REVEAL_PTR(e->next);              // 同一公式再异或一次还原
```

- **保护逻辑**：指针在静止存储态不再是明文。不知道 chunk 自身地址（堆地址）就无法伪造出正确的 next——**它把「任意写 next」升级成「先泄露堆地址」**；
- **绕过思路**（均为靶场常识）：①任何一次堆地址泄露（unsorted bin 泄 libc 是不够的，需要**堆上指针**或 tcache 链残留）即可计算 `pos>>12`；②部分场景下 next 所在页对齐的高位可预测，剩余位暴力（条件苛刻）；③干脆不打链表，转向改 size/counts 或 §6.4 的其他结构；
- 注意 `pos` 是**存储位置**的地址（&e->next），不是 chunk 本身——手算时用错地址是新手第一大坑（详见 §9 常见坑）。

**手算示例（示意值，理解公式用）**：

```text
设 B 的 mem 地址 = 0x5555555592a0（堆上），想把 next 指向 TARGET = 0x55555555b000：
  e->next 的存储位置 pos = &e->next = B 的 mem 地址 = 0x5555555592a0
  pos >> 12          = 0x555555559
  应写入值           = 0x555555559 ^ 0x55555555b000
  （分配器取出时用同一公式异或还原出 TARGET）
反过来：从泄露的明文 next（静止存储态）与已知 pos 也能还原出真实指针——
safe-linking 同时是「堆地址泄露点」：任何一次能读到链表残留的输出，都等于送出一个堆地址
```

### 6.2 tcache key：double free 检测

- 2.29 起 free 进 tcache 时写 `e->key = tcache`（结构体地址）；2.34 起改为**随机生成的 `tcache_key`**（不再是可预测的结构体地址——防止攻击者「顺手把 key 恢复成合法值」的模板化绕过）；
- 检测在 free 侧：key 命中 → 遍历链表二次确认 → abort。**绕过 = 让检测前置条件失效**（改 key、换账本、botcake，见 §3.2）——检测提高的是「顺手利用」的成本，不是理论不可利用。

### 6.3 `_int_free` / `_int_malloc` 检查矩阵（读法）

| 检查点（报错关键词） | 挡住什么 | 主要对应攻击 |
| --- | --- | --- |
| `free(): invalid pointer / invalid size`（对齐、最小尺寸） | 野指针 free、错位 chunk | house of spirit 的入场检查 |
| `free(): invalid next size (fast/normal)` | 伪造块的「下一块 size」离谱 | house of spirit、fastbin dup 伪造 |
| `double free detected in tcache 2`（2.29+） | 同块重复进 tcache | tcache dup |
| `double free or corruption (fasttop)` | 连续两次 free 同一块进同一 fastbin | fastbin dup（A-B-A 正是绕它） |
| `malloc(): memory corruption (fast)` | fastbin 取出时 size 不匹配 | fastbin 伪造（size 指纹技巧的对手） |
| `malloc(): unaligned tcache chunk detected`（2.32+） | 毒化 next 指向未对齐地址 | tcache poisoning 的对齐要求 |
| `corrupted double-linked list` / `corrupted size vs. prev_size`（unlink 一致性） | 伪造双链 | unsafe unlink、合并类攻击 |
| unsorted 取出一致性（`unsorted_chunks(av)->fd` 相关检查，随版本收紧） | 伪造 unsorted bk | unsorted bin attack 的直接版 |

**矩阵的正确用法**：不是背报错字符串，而是**把每一条映射到「它在哪个路径的哪一步、攻击者需要让什么条件为真」**。具体某版本有哪些检查，以该版本源码为准；pwndbg 报错时先 `bt` 回到 `_int_free/_int_malloc` 现场读源码，是最快的学法。

### 6.4 glibc 2.34+：hook 删除与攻击面迁移

[37 册 §6.4](../07-ctf/37-CTF-Pwn-方向.md) 已给结论：`__malloc_hook/__free_hook/__realloc_hook` 被移除，「poisoning → hook → getshell」的一代标准答案退场。迁移方向（按学习优先级）：

1. **IO/FSOP 系**：伪造 FILE 结构（`_IO_list_all`、`vtable` 相关检查的绕过）——house of orange 思想的现代延续，堆题主流；
2. **exit 系**：`__exit_funcs`/`atexit` 处理链上的函数指针（配合 PTR_MANGLE 的密钥泄露需求）；
3. **回到栈**：poisoning 分配到栈上返回地址附近（需要栈地址泄露）——用堆原语复刻 ROP 结局，思路闭环回 [22 册](./22-ROP-返回导向编程.md)；
4. **TLS/ld.so 系**：打 `TLS` 里的 `tcache` 结构本身（直接改每桶 counts/entries，跳过链表毒化）与动态链接器结构——较新的对抗面。

## 8. 防御视角（本篇的落点）

### 8.1 缓解措施矩阵：各项缓解对堆利用的真实影响

| 缓解 | 对堆利用的作用 | 残余风险 / 绕过 |
| --- | --- | --- |
| ASLR + PIE | 堆/libc 地址随机化——**所有 poisoning 都前置一次信息泄露** | 任何泄露原语（unsorted bin 泄 libc、格式化字符串 [23 册](./23-格式化字符串漏洞.md)、IO 泄露）即解锁 |
| NX/DEP | 堆页不可执行——shellcode 落堆必死 | 攻击本来就转向数据面/控制流（ROP/FSOP），对堆元数据攻击几乎无感 |
| Full RELRO | GOT 只读——经典落点消失 | 落点迁移到 hooks（旧版）、IO/exit/TLS（新版），**堆攻击不依赖 GOT** |
| Canary | 只保栈线性溢出 | 对堆溢出/UAF **无效**（不保护堆元数据） |
| Safe-Linking（glibc 2.32+） | 明文改 next 失效 | 堆地址泄露后可逆；转向改 size/counts/结构体 |
| tcache key（2.29/2.34） | 模板化 double free 失效 | 改 key / 换账本 / botcake |
| CET/Shadow Stack（新硬件） | 挡 ret 劫持（ROP 结局） | 堆原语可以不打返回地址（打函数指针/IO/数据）；IBT 对 JOP 的覆盖仍在演进 |
| 替代分配器（hardened malloc / scudo / PartitionAlloc 等） | 结构级重构，本篇多数针对 ptmalloc 的攻击不直接适用 | 代价是生态/性能兼容；其自身也有独立的攻击研究面（以各自项目文档为准） |

读法：**通用缓解（NX/RELRO/Canary）对堆攻击的针对性很弱；堆的「专属缓解」是分配器自身的检查与加固**——这正是防御投入最划算的位置。

### 8.2 真实世界堆漏洞的防御面

从「第一原语」倒推，防御是四层漏斗：

1. **别让原语出生（语言/代码层）**：新代码优先内存安全语言（Rust）或带边界检查的抽象（C++ 智能指针/容器）；C 代码的铁律——`free(p); p = NULL;`（同时管住所有别名，[21 册 §7.6](./21-栈溢出与堆溢出.md)）、长度入参统一 `memcpy` 家族、对象生命周期与所有权注释化评审；
2. **让原语难变成任意写（分配器层）**：跟进发行版的 glibc（每次检查加固都在淘汰一类模板攻击）；对高价值服务评估 hardened 分配器；必要时用 tunables 调整 tcache 行为（选项名与默认值以版本文档为准）；
3. **让任意写难变成控制流（运行时层）**：全开 PIE/NX/Full RELRO/Canary；新硬件跟进 CET；关键进程可评估 CFI 类方案；
4. **让漏洞在上线前死掉（工程层）**：Fuzzing 是堆漏洞第一杀手——AFL++/libFuzzer 常态化跑解析器与输入处理面，配合 **ASan/MSan**（把越界/UAF 从「沉默腐坏」变成「当场报错」；性能代价决定其跑在 CI 与灰度，而非全量生产）；线上用分配器报错（`abort` 信息进告警）与崩溃聚合兜底。供应链侧：依赖的 C 库版本与发行版补丁节奏纳入 [31 册](../06-security-engineering/31-依赖与供应链安全.md) 的 SBOM 视野。

### 8.3 防御检查清单

- [ ] 存量 C/C++ 组件清单化：是否有堆敏感面（解析外部输入的 C/C++ 库）
- [ ] 代码规约入 CI：free 后置空、禁裸 `memcpy` 长度入参、双 free/UAF 静态扫描（Clang 静态分析/CodeQL 规则）
- [ ] 关键解析面接入 fuzzing + ASan，崩溃样本有闭环处理流程
- [ ] 编译基线：PIE/NX/Full RELRO/Canary 全开（对照 [21 册 §2](./21-栈溢出与堆溢出.md) checksec）
- [ ] glibc/分配器跟随发行版补丁节奏，SBOM 里可见；评估高价值服务的 hardened 分配器
- [ ] 监控：分配器 abort 类崩溃（`SIGABRT` + malloc 报错串）纳入告警与自动重启策略
- [ ] 应急预演：堆类 1-day 披露时，先回答「输入能否触达该路径、缓解矩阵挡住哪几步」

## 9. 常见坑（本篇高能区）

1. **环境错位**：macOS 没有 glibc——本篇一切实验必须在 Linux + 指定版本 glibc 下做（§0）；`ldd --version` 不核对就动手，注定对着错误版本的检查调试。
2. **Safe-Linking 用错 pos**：`PROTECT_PTR` 的第一个参数是**存储位置** `&e->next`，不是「chunk 头」也不是「mem」；差 0x10 的偏移算出来就是错的。
3. **tcache 桶深想当然**：每桶 7 个是默认值不是定理（tunables 可调、版本可变）；编排 grooming 前先在 pwndbg 里 `tcache` 看真实 counts。
4. **fastbin 的 fd 与 tcache 的 next 混用**：fastbin fd 指向 **chunk 头**（malloc 返回 fd+0x10），tcache next 存的是 **mem 指针**（原样返回）——[21 册 §7.2](./21-栈溢出与堆溢出.md) 踩过的坑在 safe-linking 时代变体更多。
5. **忘了取出时的 stashing/填充副作用**：以为只 malloc 了一次，tcache 却被 smallbin/fastbin 批量填充改变了后续序列（§3.3 的机制反咬调试者）。
6. **对着报错字符串猜**：malloc 的 abort 信息只指明「哪个检查炸了」；正确姿势是 `bt` 进 `_int_free/_int_malloc` 对照该版本源码读条件（§6.3 的用法）。
7. **把 2.31 的 exp 硬搬到 2.35**：hook 没了、key 随机了、safe-linking 在了——三个前提全变；先按 [37 册 §6.4](../07-ctf/37-CTF-Pwn-方向.md) 换目标结构。
8. **UAF 块前 16 字节假设可写**：next/key/fd 就住在这 16 字节里，free 后它们必然「面目全非」；利用残留数据先确认这 16 字节的现状（[21 册 §9.3](./21-栈溢出与堆溢出.md) 第 6 条同源）。

## 11. 小结

- 堆利用 = **两级跳**：第一原语（溢出/UAF/double free）→ 分配器元数据 → 任意地址分配/写 → 控制流或数据面落点；套路名都在回答「如何过账本检查」；
- ptmalloc 三件套（chunk 标志位 / bin 家族 / malloc-free 路径）是一切技术的地图——**报错字符串是路标，源码是终点**；
- tcache 系（poisoning/dup/stashing）是现代第一战场，但它的兴衰完全由 2.26/2.29/2.32/2.34 四个版本节点决定——**版本管理即实验方法论**（37 册 §2.3）；
- 防御的性价比排序：**别让第一原语出生（语言与代码纪律 + fuzzing/ASan）> 分配器加固跟进 > 通用缓解全开 > 监控兜底**；通用缓解挡不住堆攻击的内核路径。
