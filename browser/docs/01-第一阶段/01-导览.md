## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 画出 17 步主时间线（输入 URL → 导航决策 → DNS → TCP → TLS → 请求 → 服务端 → 响应回程 → 接收 → commit → DOM → CSSOM → JS → Style → 渲染管线 → 首帧 → 交互），说清每一段发生在哪个进程。
2. 说出本地与 4G 弱网下各段耗时的量级（比如 DNS 典型几十毫秒、TLS 握手 1~2 个 RTT），并知道哪些段受 RTT 支配、哪些段受计算支配。
3. 说清浏览器至少有哪五类进程、它们各管什么、渲染进程为什么被沙箱（没有文件系统、没有直接网络访问）。
4. 解释两个标签页为什么可能不共享渲染进程，而两个 `iframe` 又为什么可能各自独立进程（site isolation）。
5. 在 Network 面板里指认一条请求的 Queueing / Stalled / Request sent / Waiting (TTFB) / Content Download 各段，并说出每段过长分别意味着什么。
6. 用 Performance 面板录一次完整加载，认出 Main 线程轨道上的 DCL、FCP、LCP 标记。

## 知识点地图

### 1. 主时间线与账本思维（02 册）

- **为什么先建账本**：性能优化最容易犯的错是「凭感觉猜瓶颈」。账本把一次加载拆成 17 段，每段有名字、有量级、有归属进程——后面的每个阶段都是在给其中某几段「精修」，每次精修完回来核账，看整体数字怎么变。
- **两套量级表**：本地（RTT < 1ms）与 4G 弱网（RTT ~50-100ms）下的耗时结构完全不同——弱网下连接建立（③④⑤）能占首屏时间的一半以上，本地则几乎全是解析与渲染的计算时间。这就是为什么「弱网模拟」是本站的默认度量姿势。
- **各段归属**：①② 发生在 UI/Browser 进程，③~⑧ 在操作系统网络栈与服务端之间，⑨⑩ 在网络进程，⑪~⑮ 在渲染进程，⑯⑰ 是全链路结果。谁慢了找谁。

### 2. 浏览器的进程架构（03 册）

- **五类进程**：Browser（管理 chrome：地址栏、标签、存储）、Network（所有 HTTP 出入）、Renderer（每个站点的页面，可能多个）、GPU（合成与光栅）、Utility（网络存储、音视频解码等辅助服务）。
- **为什么多进程**：一个页面崩溃不拖垮浏览器、一个站点卡死主线程不影响别的标签、安全隔离（渲染进程解析不可信的网页内容，必须沙箱）。
- **site isolation**：跨站文档不放同一进程。代价是进程数暴涨（内存），收益是恶意站点即使搞崩自己的进程也读不到别的站点的数据——这是 Meltdown/Spectre 之后浏览器安全模型的基石。
- **Mojo IPC**：进程之间不是裸管道，而是带接口定义的 IPC 框架——导航、网络请求、合成帧提交都走 Mojo。

### 3. 度量基础（04 册）

- **Network 面板的一条请求**：从左到右依次看 Queueing（排队：连接数上限/优先级）、Stalled（等待：代理协商、磁盘缓存检查）、DNS/Connect/SSL、Request sent、Waiting for server response（TTFB）、Content Download。哪段长，瓶颈就在哪层。
- **Performance 面板的一条加载**：顶部时间轴 + Network 轨道 + Main 线程火焰图 + 标记线（DCL/FMP/FCP/LCP）。火焰图每一格是一次函数调用，宽度就是耗时——这是后面所有渲染阶段分析的物理载体。
- **指标全景**：TTFB（服务器多快给首字节）、FCP（第一次画出内容）、LCP（最大内容元素出现）、CLS（布局稳定性）、INP（交互响应性）。第一阶段只需要知道名字和「它们分别对应主时间线的哪几段」。

## 实践任务

1. 选定毕业项目对象站点（后面九个阶段都用它），建一个 `labs/` 目录记录所有度量数据。
2. 本地 + Fast 4G 节流各录一次完整加载，把 17 步对号入座，填出你的第一版时间线账本（02 册有表格模板）。
3. 打开任务管理器（Shift+Esc），数一数当前浏览器开了多少个进程，对照 03 册的五类进程归类。
4. 用 `chrome://process-internals/` 看一次真实的 frame tree。

## 自测题

1. 主时间线的 17 步里，哪几步发生在渲染进程之外？（提示：数一数 DNS 之前和 commit 之前各有哪些）
2. 本地回环环境下 DNS/TCP/TLS 几乎不花时间，那首屏耗时主要落在哪几段？弱网下呢？
3. 为什么渲染进程被设计成「没有文件系统、没有直接网络访问」？它需要读文件、发请求时怎么办？
4. 两个不同站点的标签页一定在不同进程吗？两个同站点的 iframe 一定在同进程吗？（提示：site isolation 的粒度是「站」还是「页面」？）
5. Queueing 和 Stalled 有什么区别？各自最常见的成因是什么？
6. TTFB 很长时，你会先怀疑哪一层？给出三个可能的原因与对应的验证方法。
7. Content Download 很长但页面看起来不慢，这可能吗？什么情况下会这样？
8. FCP 和 LCP 的区别是什么？一个页面可能 FCP 很早而 LCP 很晚吗？举一个真实场景。
9. 为什么 DevTools 的节流模拟（Fast 4G）不能完全代表真实弱网？lab 数据与 field 数据的差异在哪里？
10. 「这个页面慢」——在本阶段的能力范围内，你的第一步动作是什么？请给出一个固定的诊断开场流程。
