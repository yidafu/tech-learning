## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 说清 DOM 树、LayoutObject 树、PaintLayer 树、合成层树四棵树的对应与差异，display:none 的节点在哪几棵树上有/没有。
2. 解释 BFC 的五条创建条件与四条布局规则，用 margin 合并的三个场景说出「为什么外边距会叠在一起」。
3. 面对一段 JS 循环「读 offsetHeight → 改 style」，指出 trace 里的强制同步布局，并给出三种治理方案（批量读写、transform、contain）。
4. 列出至少五种「会把元素提升为合成层」的情况，说出层爆炸的内存代价怎么量（DevTools Layers 面板）。
5. 解释「合成器动画为什么快」：transform/opacity 动画只重合成、不重布局重绘，主线程卡死时动画照跑。
6. 画出一次完整帧的流水线（rAF → style → layout → paint → commit 到合成线程 → 栅格化 → draw → swap），标出主线程与合成线程的分工边界。

## 知识点地图

### 1. 树与布局（02、03 册）

- **四棵树**：DOM（逻辑结构）→ LayoutObject（盒与几何）→ PaintLayer（绘制顺序与叠加上下文）→ 合成层（GPU 独立纹理）。display:none 连 LayoutObject 都没有；visibility:hidden 有盒子但不上屏。
- **LayoutNG**：现代 Blink 的布局引擎，输出 fragment 树 + 布局结果不可变对象——为「增量布局」与「多线程布局」铺路。
- **格式化上下文**：BFC（块级排布的独立王国：不吃外部浮动、不含内部浮动、margin 不跨界合并）、IFC（行内布局：基线、行盒、 strut）、Flex/Grid 各自的算法骨架。
- **脏标记与局部布局**：改一个节点不是全页重排——失效沿树传播到「脏子树」，LayoutNG 尽量只算子树。但读几何信息（offsetTop 等）会把脏立即清掉（强制同步布局）。

### 2. 分层与绘制（04、05 册）

- **为什么分层**：绘制顺序问题（z-index、透明度、裁剪）需要 PaintLayer；滚动/变换性能问题需要合成层（独立纹理，可单独动）。
- **提升条件**：3D transform、will-change、video/canvas、固定定位在滚动容器内、动画 transform/opacity……每条都有代价：显存 × 尺寸。
- **display list**：主线程把「画什么」记录成指令列表（在 (x,y) 画矩形、以字体 F 画文本…），栅格化时才真正执行——指令与执行分离是局部重绘的前提。
- **瓦片化**：一层纹理被切成 256/512 瓦片，只栅格化视口附近的——滚动时「现做新瓦片、丢远瓦片」。

### 3. 合成与帧（06、07 册）

- **合成线程**：渲染进程里独立于主线程的线程。滚动、transform/opacity 动画、合成层位图的搬运都归它——主线程忙到死，滚动照常（这就是「合成器滚动」）。
- **vsync 节拍**：屏幕 60Hz，帧预算 16.6ms（120Hz 是 8.3ms）；掉帧 = 一帧的流水线没跑完就到下一个 vsync。渲染不是「改完就画」，而是「等 vsync、在节拍里算完」。
- **失效传播的粒度**：改 background-color → 只重绘；改 width → 布局+重绘；改 transform → 只合成。优化就是尽量把改动「降级」到更便宜的失效类型。

## 实践任务

1. DevTools Layers 面板打开一个长列表页，数一数合成层数量与显存占用；给列表加 `will-change: transform` 再数一次。
2. 录制一段布局抖动代码的 trace，找到「强制同步布局」的紫色 Layout 条，应用批量读写改造后重录对比。
3. 用 Performance 面板的 Frames 轨道找出一次掉帧，放大那一帧，说出主线程卡在哪一段（Script/Render）。
4. 给一个元素分别做 `top` 动画与 `transform` 动画，对比两条 trace 的主线程负载差异。
5. 滚动一个长页面时录制 trace，验证「滚动在合成线程、主线程空闲」；再故意在 scroll 事件里塞同步布局，观察差异。

## 自测题

1. `display:none` 和 `visibility:hidden` 的节点分别在四棵树（DOM/LayoutObject/PaintLayer/合成层）的哪几棵上存在？
2. 为什么「父元素 overflow:hidden + 子元素 margin-top」时 margin 会「穿透」出去？用 BFC 规则解释并给出两种修复。
3. 强制同步布局为什么「同步」？它和正常布局（在渲染阶段统一算）的区别在哪？代价差多少？
4. 一个 position:fixed 的全屏遮罩在滚动页面时需要重新布局吗？为什么它通常被提升成合成层？
5. 层爆炸是怎么发生的？「给所有列表项加 will-change」的显存代价怎么估算？
6. display list 的「指令与执行分离」给局部重绘带来什么？改一个按钮的颜色，重绘范围是整页还是它所在的 PaintLayer？
7. 主线程完全卡死（死循环）时，页面还能滚动吗？还能播放 CSS transform 动画吗？分别说明归谁管。
8. 60Hz 屏幕上 16.6ms 的预算里，主线程和合成线程各分到什么活？哪些活必须串行、哪些可以并行？
9. 改 `width` 和改 `transform: scale` 都能让元素变大，两者的失效传播链分别走到哪一站？
10. 把本阶段与 `gui/` 站第六阶段对照：浏览器的「脏标记 + 增量布局」与自绘框架的「脏控件 + 局部重绘」有哪些同构、哪些不同（比如浏览器为什么要合成线程而教学框架不需要）？
