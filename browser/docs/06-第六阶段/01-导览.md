## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 描述响应字节从 socket 到渲染进程的完整路径，说出 MIME sniffing 在哪一步发生、`nosniff` 改变了什么、CORB 会拦下什么样的跨域响应。
2. 面对任意 Cache-Control 组合（`max-age=0, must-revalidate` / `no-cache` / `no-store` / `stale-while-revalidate`），准确说出下一次请求走强缓存、协商缓存还是网络。
3. 解释启发式缓存的 10% 规则：没有显式缓存头时，浏览器怎么自己决定缓存多久。
4. 说清 Service Worker 的三层生命周期状态与「旧 SW 控制 + 新 SW waiting」的更新时序，以及 respondWith 里 promise 慢了会发生什么。
5. 给出常见资源的默认优先级排序（CSS/字体/同步 JS 高、图片 Low、prefetch Lowest），并解释 preload 与 prefetch 的本质区别（本页 vs 下一页）。
6. 画出 sync / defer / async / module 四种脚本的加载-执行-事件时序图，并说出每种对 DOMContentLoaded 的影响。

## 知识点地图

### 1. 接收流水线（02 册）

- **MIME sniffing**：Content-Type 缺失或可疑时，浏览器偷看前几个字节猜类型——这套猜测历史上造成大量 XSS，`X-Content-Type-Options: nosniff` 就是把它关掉。
- **CORB/ORB**：跨域响应若「看起来不该被当前站读」（如 HTML 被当图片加载），直接在渲染进程外被剥离 body——Spectre 时代「数据不能进攻击者进程」思想的产物。
- **乐观准备**：响应头一到（body 还没下完），渲染进程就开始解析已到的字节——第七阶段的解析在本阶段就已经开工。

### 2. HTTP 缓存（03 册）

- **判定流程**：查找（内存→磁盘）→ 新鲜度判定（max-age / Expires / 启发式）→ 新鲜：直接用，零网络 → 过期：带验证器发条件请求 → 304 用本地 + 更新元数据 / 200 换新。
- **指令速记**：`no-store`（彻底不存）＞ `no-cache`（存但每次问）＞ `max-age=0, must-revalidate`（≈no-cache）；`immutable`（连 revalidate 都省）。
- **ETag 怎么来的**：mtime+size（Nginx 默认）还是内容哈希（很多框架）——决定「内容没变但重新部署」会不会引发 ETag 失效风暴。

### 3. Service Worker（04 册）

- **生命周期**：install（预缓存）→ waiting（等旧 SW 释放）→ activate（清旧缓存）——「为什么我更新了代码页面没变」的九成答案在 waiting。
- **拦截时序**：SW 命中 → fetch 事件在 SW 进程触发 → respondWith 的 promise 决定响应来源（Cache API / 网络 / 兜底）。SW 缓存与 HTTP 缓存是两层独立体系，SW 里 fetch 时还能再命中 HTTP 缓存。

### 4. 子资源调度与脚本加载（05、06 册）

- **preload scanner**：HTML 才刚边收边解析，一个轻量扫描器已经把后面的 `<link>/<script>/<img>` 预约了下载——主解析器被 JS 阻塞时，下载照跑不误。
- **优先级与 hint**：`<link rel="preconnect">`（提前建连）、`rel="dns-prefetch"`（提前查 DNS）、`rel="preload"`（本页高优）、`rel="prefetch"`（下页空闲时低优）、`fetchpriority`（手动调优先级）、Speculation Rules（整页 prerender）。
- **脚本四形态**：sync（阻塞解析器直到执行完）＞ defer（下载不阻塞、DOMContentLoaded 前按序执行）＞ async（下载不阻塞、下载完立刻执行、乱序）＞ module（默认 defer + 依赖图先解析）。

## 实践任务

1. 同一页面强刷 / 普通刷新 / 二次访问各一次，用 Network 的 Size 列区分「from disk cache / memory cache / 304 / 200」，对照[03 册](03-HTTP缓存体系全解.md)判定流程。
2. 服务器把 `Cache-Control: no-store` 加到 HTML 上再刷新，观察 HTML 变回真实请求而静态资源依旧命中——理解「HTML 不缓存、资源哈希缓存」这套经典架构。
3. 给页面加一个 3 秒的 SW respondWith 延迟，观察首屏与 LCP 的变化；再切换 cache-first 策略对比（[04 册](04-ServiceWorker-生命周期与拦截时序.md)实验 3）。
4. 写四个 `<script>`（sync/defer/async/module）各打一行 log + 边缘一个 DOM 操作，验证执行顺序与 DOMContentLoaded 时机（[06 册](06-脚本加载模型-阻塞-defer-async与module.md)实验 1）。
5. 用 `document.createElement('script')` 动态插入脚本，对照[06 册](06-脚本加载模型-阻塞-defer-async与module.md)的时序图验证它属于哪一类。

## 自测题

1. `max-age=0, must-revalidate` 和 `no-cache` 有区别吗？和 `no-store` 呢？分别写出三次刷新下 Network Size 列的期望值。
2. 一个响应只有 `Last-Modified: 三天前`，没有任何 Cache-Control，浏览器会缓存它吗？缓存多久？
3. ETag 在「内容没变但文件 mtime 变了」时会不会变？两种生成策略下分别回答。
4. SW 的 skipWaiting 与 clients.claim 各做了什么？不调用它们的更新流程是什么样的？
5. preload 了 CSS 但没用 as="style"，会发生什么？preload 的资源没被当前页使用，控制台会警告什么？
6. preload 与 prefetch 优先级差异的本质是什么？为什么 prefetch 不该用于本页关键资源？
7. `<script>` 放在 `<head>` 里同步加载，preload scanner 还能提前下载它吗？那阻塞的到底是什么？
8. defer 脚本执行时 DOM 就绪了吗？async 脚本执行时呢？两者对 DOMContentLoaded 的推迟逻辑有何不同？
9. module 脚本的执行为什么一定在依赖图解析完之后？这和第七阶段的哪个环节（V8）有关？
10. 把本阶段放进时间线账本：哪些缓存命中能让 ③④⑤⑥⑦⑧ 全部消失？哪一层命中连 ⑨ 都能跳过？
