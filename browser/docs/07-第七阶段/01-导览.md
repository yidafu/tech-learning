## 阶段目标

学完本阶段，你应该能不查资料做到这些事：

1. 说清字符编码判定链的顺序与「meta charset 必须在前 1024 字节」的真正原因（解析器以何种编码启动、猜错怎么办）。
2. 描述 HTML 解析器的双层结构（分词状态机 + 树构建），解释 `<p>内嵌<div>` 这类容错为什么是「规范规定的行为」而非随意补救。
3. 解释同步 `<script>` 阻塞解析的完整机理（解析器停、DOM 停、但 preload scanner 照跑），以及 `document.write` 为什么是毒药。
4. 说清 CSSOM 构建的阻塞规则：哪些 CSS 阻塞渲染、哪些不阻塞（media 不匹配）、@import 为什么是串行灾难。
5. 解释选择器为什么右到左匹配、浏览器用什么数据结构避免全量匹配（规则哈希分桶、祖先 Bloom 过滤器、style 共享）。
6. 画出 V8 的四层编译流水线，说清一段代码从字节码到优化机器码的升级路径，以及什么会触发去优化。
7. 完整说出一次事件循环的步骤序列（宏任务 → 微任务队列清空 → 判断是否该渲染 → rAF → style/layout/paint → 下一轮）。

## 知识点地图

### 1. 字节 → 字符（02 册）

- **判定链**：BOM > HTTP `charset` > `<meta charset>`（前 1024 字节内）> 本地化默认。meta 之所以限 1024 字节：解析器必须先选定编码才能「正经解析」，前 1024 字节是给它的侦察窗口。
- **乱码分类**：编码声明与实际不符（meta 写 GBK 实发 UTF-8）、声明缺失猜错、双重编码——每类的修复位置不同。

### 2. HTML 解析（03 册）

- **规范即容错**：WHATWG 用状态机把「世界上所有烂 HTML」的处理方式标准化——`<b><i></b></i>` 的最终 DOM 是确定的，各浏览器一致。
- **树构建**：开放元素栈 + 插入模式切换；`<script>` 遇到时暂停解析、执行完再继续——这是第六阶段脚本阻塞语义的解析器内部视角。
- **流式**：网络字节一到就逐块喂给解析器；preload scanner 在旁边同步扫「还没真正解析到」的资源并预约下载。

### 3. CSS 与样式计算（04、05 册）

- **CSSOM 与阻塞**：head 里的 CSS 必须构建完 CSSOM 才允许渲染（无样式内容闪烁问题）；`media` 不匹配的样式表下载但不阻塞；`@import` 是「解析到才知道还有下一个请求」的串行链。
- **右到左匹配**：`div a span` 先找所有 span 再向上验证——因为「大多数选择器命中 0 个元素」，从最右端开始能用最小的候选集。
- **工程优化**：规则按最右选择器分桶（id/class/tag 哈希表）、祖先过滤器（Bloom filter 快速排除不可能的祖先）、ComputedStyle 共享（兄弟节点同上下文复用）。
- **getComputedStyle 的陷阱**：它返回「已计算」样式，若布局脏了会强制同步布局——第八阶段 layout thrashing 的第一现场在这里。

### 4. V8 与事件循环（06、07 册）

- **四层流水线**：源码 →（惰性编译）→ Ignition 字节码 → Sparkplug 基线 →（热点）→ Maglev 中层 → Turbofan 优化机器码；假设被打破 → 去优化回字节码。
- **隐藏类与内联缓存**：对象形状（shape）固定让属性访问变数组下标访问；`delete`、乱序添加属性都在给隐藏类「改名」。
- **script streaming**：大脚本边下载边在后台线程预解析，主线程拿到的已是 AST 级产物——与第六阶段的下载调度衔接。
- **事件循环**：宏任务（脚本/事件回调）跑完 → 清空全部微任务（promise/queueMicrotask）→ 「该渲染吗」（vsync 节拍）→ rAF 回调 → 渲染管线 → 下一轮。渲染不是每轮循环都发生——它是循环与 vsync 的合谋。

## 实践任务

1. 把 `<meta charset="GBK">` 写进一个 UTF-8 页面的前 10 字节与第 2000 字节处各测一次，观察乱码差异，对照判定链。
2. 用 Performance 面板放大一次页面加载的 Main 轨道：找到 Parse HTML、Recalculate Style、Layout、脚本编译各段，截图存档到 `labs/`。
3. 构造一个 5 层嵌套的 `@import` CSS 链，测量与「合并成单文件」的加载时间差。
4. 用 `%GetOptimizationStatus`（或 console 里观察）验证一个热点函数从字节码升级到 Turbofan、再被类型改变打回原形的过程。
5. 写一段「微任务插队」代码：宏任务里先同步 log、再 await、再 log，预测输出顺序并验证。

## 自测题

1. 没有 BOM、没有 HTTP charset、meta 写在第 3000 字节——浏览器用什么编码解析？解析过程中「改主意」的机制叫什么？
2. `<table><tr><td>x</td></tr></table>` 里浏览器自动插入了什么元素？为什么容错规则要为 table 单独设计？
3. 同步脚本阻塞期间，preload scanner 在干什么？「下载提前、执行仍阻塞」的收益怎么在 waterfall 里看出来？
4. CSS 放 body 末尾会阻塞渲染吗？media="print" 的样式表呢？逐条说明理由。
5. `a div span` 和 `span` 两个选择器，在「10000 个元素只有 3 个 span」的页面上，右到左匹配分别要验证多少条路径？
6. getComputedStyle 在布局脏时会不会触发强制布局？写一段「读 offsetHeight 又改 style」循环 100 次的代码，说明 trace 里会看到什么。
7. 一段代码先以数字参数调用一万次、再以字符串调用一次，V8 内部发生了什么？「类型反馈」在哪里记录了假设？
8. 为什么 microtask 一定在「下一个宏任务之前」清空？如果微任务里无限生成微任务会发生什么？
9. rAF 回调在微任务之前还是之后？「在 rAF 里改 DOM，同一帧内布局会算几次」？
10. requestIdleCallback 的回调为什么不能保证执行？它和长任务（>50ms）判定的关系是什么？
