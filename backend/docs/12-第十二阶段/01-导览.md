# 第十二阶段导览：毕业项目——从单体到微服务

> [返回：后端开发学习大纲](../后端开发学习大纲.md)
> 本文是第十二阶段的入口，也是全站收官。前十一阶段给了你零件，本阶段要求你组装一次：先写模块化单体并压出基线，再按边界拆两个服务，最后做生产化收尾与复盘。

**建议时长**：3~4 周。**没有「跑通了」这个终点，只有「有数字、有记录、能交接」这个终点。**

## 分册计划

| 分册 | 内容要点 |
|---|---|
| 02-选题与需求拆解 | 三个候选选题、接口清单、数据模型、非功能指标定义 |
| 03-模块化单体与压测基线 | 模块划分、契约先行、测试齐全、拿到基线的 P99 与容量数字 |
| 04-拆出两个服务-边界-通信与数据迁移 | 选边界、切数据、补偿与灰度、拆完的延迟变化 |
| 05-生产化收尾与故障演练 | 可观测、安全、限流降级、故障注入演练、容量与成本 |
| 06-复盘报告与验收清单 | 报告模板（前后对比/决策记录/踩坑清单）与逐条验收 |

## 选题

三个候选，选一个，**不要三个都做**：

| 选题 | 核心难点 | 适合练什么 |
|---|---|---|
| 订单系统 | 库存扣减、幂等、状态机、分布式事务 | 事务与一致性、并发控制、Saga |
| 短链服务 | 高并发读、ID 生成、缓存与预热 | 缓存三件套、限流、压测调优 |
| 预约系统 | 时段冲突、并发占座、超时释放 | 乐观锁/悲观锁、延迟任务、对账 |

选题的共同要求：有**写热点**（能练锁与并发）、有**读热点**（能练缓存）、有**跨服务流程**（能练消息与一致性）、有**可量化的非功能指标**。

## 阶段目标

1. 把需求拆成接口清单、数据模型与非功能指标（目标 QPS、P99、错误率、数据规模）。
2. 先交付一个**模块化单体**：模块间只通过接口与事件通信，测试覆盖关键路径，压出基线数字。
3. 按边界拆出两个服务，完成数据迁移与双写过渡，量化「拆分带来的延迟与复杂度成本」。
4. 补齐生产化要素：可观测、安全、限流降级、优雅停机、回滚预案。
5. 做一次故障演练（下游超时、数据库抖动、消息积压），验证系统与预案。
6. 写一份能让别人接手的复盘报告：决策记录、数字对比、踩坑清单、遗留风险。

## 交付物清单

| 类别 | 具体内容 |
|---|---|
| 代码 | 模块化单体（分模块）→ 两个服务 + 网关；关键路径有测试 |
| 数据 | Flyway 迁移脚本、索引设计说明、数据迁移与回填脚本 |
| 契约 | OpenAPI 文档 + 至少一组契约测试 |
| 观测 | 核心指标面板、结构化日志、跨服务 trace 截图 |
| 安全 | 鉴权链路、越权回归测试、密钥外置说明 |
| 压测 | 压测脚本、基线报告、调优前后对比 |
| 文档 | 架构决策记录（ADR）、复盘报告、运维手册（启动/回滚/告警处置） |

## 里程碑与验收

```mermaid
flowchart LR
  M1[M1 需求与契约<br>接口+数据模型+指标] --> M2[M2 模块化单体<br>测试齐+基线数字]
  M2 --> M3[M3 拆分两个服务<br>数据迁移+灰度]
  M3 --> M4[M4 生产化<br>可观测+安全+限流]
  M4 --> M5[M5 故障演练<br>预案验证]
  M5 --> M6[M6 复盘报告<br>可交接]
```

- **M1 验收**：接口清单覆盖全部用户故事；每个接口有错误码与幂等策略；非功能指标写成可测的数字。
- **M2 验收**：单体跑起来，压测报告里有 QPS/P99/资源曲线；关键路径测试覆盖率达标；能指出账本里最慢的三站。
- **M3 验收**：拆分后功能不回退；跨服务流程有一致性方案与对账脚本；trace 能串起两个服务；灰度与回滚演练通过。
- **M4 验收**：滚动更新零 5xx；越权测试通过；限流降级开关可用；有告警规则与处置手册。
- **M5 验收**：三类故障注入下系统「降级但不崩」，恢复后能自愈或按预案恢复。
- **M6 验收**：报告能让一个没参与过的人接手运维与继续开发。

## 常见失败模式

1. **一上来就拆微服务**：还没压出单体基线，就已经在调三个服务的联调环境——最后什么都没量化。
2. **只做功能不做数字**：所有接口都能跑，但说不出 P99、不知道拐点、没有调优记录，等于没做。
3. **没有对账**：跨服务流程只要有一次不一致，就永远查不出来。
4. **测试补齐但没跑通 CI**：测试是给人看的，不是给流水线跑的。
5. **复盘写成流水账**：没有「当时的假设 / 实际结果 / 为什么不同」的记录，下次还会踩同一个坑。

## 自测

1. 你的单体基线是 800 QPS / P99 120ms，拆分后变成 600 QPS / P99 180ms，这个结果「失败」吗？怎么判断？
2. 拆服务时为什么要求「先切读后切写」？
3. 拆分后某个流程跨两个服务，你怎么保证「不会出现一半成功」？
4. 故障演练里「数据库抖动 30 秒」，你期望系统表现出什么行为？哪些是不合格的？
5. 复盘报告里最该写的三段内容是什么？
