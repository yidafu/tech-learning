# 06. 复盘报告与验收清单：能交接才算毕业

> [← 第十二阶段导览](01-导览.md) · 全站最后一册。毕业的终点不是「系统跑起来了」，是一份能让没参与过的人接手运维与继续开发的复盘报告，加一份覆盖十二个阶段的验收清单——本册给出六段结构、ADR 格式、30 条验收项与可直接复制的骨架模板。

## 1. 复盘报告的六段结构

报告按固定的六段写，每段回答一个明确的问题，写完检查「每段能不能独立回答它的问题」：

| 段 | 回答的问题 | 原料来源 |
|---|---|---|
| ① 目标与指标回顾 | 当初承诺的数字（02 册的指标定义）做到没有？ | 02 册指标表 vs 实测 |
| ② 关键决策记录 | 拆谁、怎么拆、为什么，当时的选项与权衡是什么？ | 03 册五问、04 册边界打分，ADR 格式（第 2 节） |
| ③ 数字对比 | 基线 vs 拆分后 vs 调优后，每笔成本与收益可解释吗？ | 03 册基线表、04 册前后对照表 |
| ④ 踩坑清单 | 踩了什么坑，根因是什么，下次怎么提前发现？ | 各册「坑/取舍」+ 演练缺陷清单 |
| ⑤ 遗留风险 | 哪些已知问题没修，触发条件与应急动作是什么？ | 对账未清项、演练未过项、范围裁剪的债 |
| ⑥ 交接手册要点 | 接手的人第一天需要知道什么？ | 05 册生产化清单 + 运维操作步骤 |

六段里最容易被省略、也最值钱的是②和④：②让「当时的判断」留存下来（半年后没人记得为什么拆库存不拆支付），④把学费变成资产。①③是证据，⑤⑥是责任——报告的读者不是现在的你，是三个月后接手的人。

**为什么要有固定结构**：流水账式复盘（「第一周做了 A，第二周做了 B」）的失效原因是它按时间组织而不是按问题组织——读者无法从中提取「下次该怎么做」。六段结构强制每段产出一种可复用的内容类型，这正是导览里失败模式 5 的解法。

## 2. ADR：决策记录的写法与一个完整示例

关键决策用 ADR（Architecture Decision Record）格式写进报告第②段，五要素：背景（为什么现在要做决策）、选项（至少两个）、决定、理由（为什么选它）、后果（付出的代价与获得的好处）。示例取自本项目最重的决策：

```text
ADR-003：先拆库存服务，而不是支付服务

背景：
  模块化单体基线显示库存扣减是「最慢三站」之一（行锁等待 23ms，P99 贡献），
  且写热点集中在单行更新。需要验证拆分能力，并量化拆分税。

选项：
  A. 拆库存服务 —— 边界干净（表只被 skuId 引用）、接口窄（reserve/confirm/release）、
     收益可证（锁竞争隔离，独立伸缩）
  B. 拆支付服务 —— 拆完只有演练价值（支付是模拟的假下游），锁与热点留在单体
  C. 不拆，继续单体 —— 但「团队规模 × 变更频率」的动机暂时不成立，
     需要一次拆分练习来完成毕业项目目标

决定：选 A。

理由：窄接口把要跨进程传递的语义（幂等、超时、重试）压到最少；
  数据耦合最小使迁移与对账可行（旧库存表无跨表 join）；
  拆分收益可以用压测前后对照证明，符合「每个决策都要有数字」的项目纪律。

后果：
  - 获得：单体的行锁等待消失，库存可独立扩容；「拆分税」有了第一手数据
    （P99 +39ms，部署单元 ×3）。
  - 付出：库存与订单之间的一致性从本地事务降级为「同步 reserve + Outbox + 对账」，
    对账 SQL 与反向双写是长期维护成本。
  - 若重选：结论不变，但会先补「反向双写」再切写（切写当日曾因未就绪推迟一次）。
```

写 ADR 的三条纪律：**选项至少两个**（只有一个选项的记录不是决策记录，是既成事实说明书）；**后果必须包含代价**（只写收益的 ADR 会误导后来人）；**「若重选」一栏留给诚实**（拆分当日推迟切写这种「不完美」正是最有教学价值的部分）。

## 3. 数字对比：基线 vs 拆分后 vs 调优后

报告第③段的主体是一张三列对比表，每一行的变化都要有「为什么」（数字不可解释就不能上表）：

| 指标 | 单体基线 | 拆分后 | 调优后 | 变化解释 |
|---|---|---|---|---|
| 下单 P99 | 132ms | 171ms | 148ms | 拆分 +1 网络往返；调优把序列化换成紧凑 DTO 并预热连接 |
| 下单 P999 | 310ms | 590ms | 420ms | 尾部放大来自库存服务抖动；熔断半开自愈缩短尾部 |
| 写极限 QPS | 240 | 218 | 260 | 链路变长损耗；库存独立扩容后反超基线 |
| 读 QPS / 命中率 | 95 / 0% | 95 / 0% | 200 / 92% | 读调优加缓存（07 册三件套），DB 回到安全水位 |
| 部署单元 | 1 | 3 | 3 | 结构性成本，不随调优变化 |
| 月成本 | ≈1700 元 | ≈3050 元 | ≈3050 元 | 中间件最小规格占大头（05 册演算） |

表格的读法写在报告里：**延迟税结构性存在但可摊薄，复杂度税不可消除，收益在伸缩性与隔离性**——这三句话就是 03 册第 6 节五问的最终答案。

## 4. 踩坑清单的格式

每条踩坑四要素：现象、根因、修法、如何提前发现。示例两条（格式比内容重要，内容换成你自己的）：

| 现象 | 根因 | 修法 | 如何提前发现 |
|---|---|---|---|
| 切写当日下单 P99 冲到 800ms，409 比例飙升 | 库存服务的 HikariCP 沿用了单体的默认值，而独立服务流量模式不同，池满排队 | 按池大小公式重算并压测验证 | 拆分后每个服务的连接池参数必须重新核算，不能继承 |
| 切读阶段对账持续报少量不一致 | 双写的「在途写」被对账当成不一致；对账 SQL 没有时间界限 | 加 5 秒界限排除在途行（04 册第 4 节） | 对账工具上线前先跑「双写空跑」校准误报率 |

「如何提前发现」一列是清单的灵魂：没有它，清单只是回忆录；有了它，同类坑在下次项目里变成一条 checklist 项。

## 5. 常见失败模式与各自的预防

导览列过五个失败模式，这里给出每一条的「早期信号」与「预防动作」，形成闭环：

| 失败模式 | 早期信号 | 预防动作 |
|---|---|---|
| 一上来就拆微服务 | 第一周就在调三个服务的联调环境 | 纪律：M2 没压出基线数字之前，禁止建第二个部署单元（03 册五问把关） |
| 只做功能不做数字 | 实现清单比接口清单长；说不出自己的 P99 | 02 册指标定义先行，每周对照一次；任何功能没有支撑故事就砍 |
| 没有对账 | 跨服务流程「看起来是对的」但没有验证手段 | 04 册对账 SQL 在切读之前就绪，双写期间每天跑 |
| 测试没进 CI | 「我本地是绿的」成为口头禅 | 03 册测试清单第一条要求就是可进 CI；本地通过 ≠ 流水线通过 |
| 复盘写成流水账 | 报告按时间叙述、没有数字对比与决策记录 | 本册第 1 节六段结构 + 第 2 节 ADR 格式，写完自检每段 |

## 6. 交接手册要点

报告第⑥段（或独立文档）回答「接手的人第一天到第五天需要什么」：**第一天**——怎么把整套环境跑起来（Compose 文件、启动顺序、预置账号）；**第二天**——系统边界图与关键指标面板在哪（05 册清单）；**第三天**——回滚预案三步与告警处置表（05 册交付项）；**之后**——ADR 全集、遗留风险清单、测试怎么跑、数据模型与索引说明（02 册第 5 节）。判断交接质量的标准：让一个没参与的同学按手册把系统从零跑起来并完成一次「改一个小功能 → 测试 → 发布 → 观察指标」的闭环，卡住的每一步都是手册要补的一行。

| | 24 | 滚动更新零 5xx，优雅停机验证过 | 发布日志 |
| 11 微服务 | 25 | 拆分五问有书面回答（ADR 形式） | ADR-003 等 |
| | 26 | 双写过渡 + 切读切写按序完成，回滚矩阵演练过 | 04 册矩阵表 + 演练记录 |

## 8. 复盘报告骨架模板

可直接复制，替换方括号内容：

```text
# 毕业项目复盘报告：[项目名]（订单 / 短链 / 预约）

## 1. 目标与指标回顾
| 指标 | 02 册定义值 | 实测值 | 结论 |
|---|---|---|---|
| [目标 QPS / P99 / 错误率 / 数据规模] | | | 达成 / 未达成 / 调整为 |

## 2. 关键决策记录（每条一份 ADR）
- ADR-001：[选题与范围裁剪] 背景/选项/决定/理由/后果/若重选
- ADR-002：[模块划分与事件边界]
- ADR-003：[先拆哪个服务]
- ADR-004：[数据迁移与切流策略]

## 3. 数字对比
[基线 vs 拆分后 vs 调优后 三列表，每行附变化解释；不可解释的数字先查清再上表]

## 4. 踩坑清单
| 现象 | 根因 | 修法 | 如何提前发现 |
|---|---|---|---|

## 5. 遗留风险
| 风险 | 触发条件 | 当前缓解 | 应急动作 |
|---|---|---|---|

## 6. 交接手册要点
[跑起来 → 看监控 → 回滚 → 改功能闭环，逐步骤；ADR 与脚本索引]
```

模板与六段结构的对应关系：每一段的表头就是该段要回答的问题——填不出来的格子，就是这一段还没完成的部分。

## 9. 自测

1. 六段结构里为什么说②④最值钱而①③是证据、⑤⑥是责任？省掉⑤的报告会误导接手的人什么？
2. ADR 的「选项至少两个」「后果必须包含代价」分别防什么失效？
3. 数字对比表里「不可解释的数字不能上表」——你项目里有没有一个目前解释不了的指标？打算怎么查？
4. 踩坑清单四要素里，「如何提前发现」为什么是灵魂？把你本项目最痛的一个坑写成完整四要素。
5. 验收清单第 27 条（对账归零）为什么不允许被其余 29 条「带过」？
6. 「新人闭环」测试是什么？用它在你的交接手册上找三处缺口。
