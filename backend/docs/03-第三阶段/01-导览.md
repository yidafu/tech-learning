# 第三阶段导览：Spring 容器与启动原理

> [返回：后端开发学习大纲](../后端开发学习大纲.md)
> 本文是第三阶段的入口。这一阶段回答三个高频困惑：「为什么我的 Bean 是 null」「为什么注解在这里不生效」「启动为什么这么慢」。答案都在容器里。

**建议时长**：1.5 周。读源码不是目的，能画出「Bean 从类变成可调用对象」的完整时序才是。

## 阶段目标

1. 说清一个类从「被扫描到」到「成为可用 Bean」的完整步骤，并指出每一步能插入什么扩展点。
2. 解释构造器注入、setter 注入、字段注入的差别，以及为什么官方推荐构造器注入。
3. 解释 AOP 代理的生成时机与调用路径，能判断「哪些方法调用不会走切面」。
4. 说清 `@Transactional` 失效与「自调用」的关系（第六阶段会展开，这里只要原理）。
5. 说出自动配置的加载机制，并能在不改框架代码的前提下排除/覆盖某个自动配置。
6. 说明 `refresh()` 十二步里哪几步最耗时，并能量出自己项目的启动耗时分布。
7. 手写一个支持扫描、构造器注入、单例缓存与简单 AOP 的迷你容器。

## 知识点地图

### 1. 容器与 BeanDefinition（02 册）

- **两阶段**：先是「读元数据 → 注册 BeanDefinition」（此时还没造对象），再是「按需实例化」。理解这一点，才能明白为什么 `@Conditional` 能在实例化之前决定要不要这个 Bean。
- **构造器注入最优的原因**：字段 `final`、对象创建即完整、单构造器时无需 `@Autowired`、单测不用启动容器。
- **循环依赖**：单例 + setter/字段注入能靠三级缓存「先给引用后填充」解掉；构造器循环依赖无解，只能改设计——**报错是好事**。

### 2. 生命周期与扩展点（03 册）

- **典型顺序**：构造 → `@Autowired`/属性填充 → `BeanNameAware`/`ApplicationContextAware` → `BeanPostProcessor#postProcessBeforeInitialization` → `@PostConstruct` → `InitializingBean` → 自定义 init → `postProcessAfterInitialization`（**AOP 代理在这里生成**）→ 使用 → `@PreDestroy`。
- **AOP 代理为什么在 `postProcessAfterInitialization`**：代理要包住「已经初始化完成的对象」，所以你在 `@PostConstruct` 里拿到的是原始对象。
- 十二个扩展点的价值不在于背名字，而在于**知道该在哪个点做哪类事**：改 Bean 定义用 `BeanFactoryPostProcessor`，包装 Bean 用 `BeanPostProcessor`，容器就绪后做一次性动作优先用事件监听。

### 3. 代理（04 册）

- **JDK 动态代理 vs CGLIB**：有接口默认 JDK 代理（基于接口），无接口用 CGLIB（生成子类）。Spring Boot 2.x 起默认 `proxyTargetClass=true`，即优先 CGLIB。
- **自调用失效的根因**：`this.method()` 走的是原始对象，不经过代理对象，切面自然不生效。三种解法：拆类、注入自身代理、`AopContext.currentProxy()`（要求 `exposeProxy`）。
- **代理链顺序**：多个切面按 `@Order` 嵌套，外层先执行；排查「日志里参数为什么是原始值」时这个顺序是关键。

### 4. 自动配置（05 册）

- **机制**：`@EnableAutoConfiguration` → 读取各 jar 的 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` → 按 `@Conditional` 过滤 → 注册。Boot 4 把它拆成更细的模块，条件更精确、可排除粒度更小。
- **排查三件套**：`--debug` 看条件评估报告（`CONDITIONS EVALUATION REPORT`）、Actuator `conditions` 端点、`spring.autoconfigure.exclude` 精确排除。
- **自定义 starter 的正确姿势**：`@AutoConfiguration` + `@ConditionalOnMissingBean`，让使用者能用自己的 Bean 覆盖你的默认实现。

### 5. 启动流程（06 册）

- **`refresh()` 的十二步**里，与业务最相关的是：`invokeBeanFactoryPostProcessors`（解析配置类、注册 Bean 定义）、`registerBeanPostProcessors`、`onRefresh`（**内嵌 Tomcat 在这里创建并启动**）、`finishRefresh`（发布就绪事件）。
- **启动慢的常见元凶**：大量 `@Component` 全量扫描、启动时打远程配置/注册中心、连接池预建连接、初始化时加载大缓存、JPA 全量元数据构建。先量再改。
- **优雅停机**：`server.shutdown=graceful` + 前置的 readiness 摘流，顺序反了会把正在处理的请求打断。
