# 05 · ES2015+ 关键特性：解构、展开、迭代器、生成器、Proxy/Reflect

> 对应大纲：阶段 1.5（ES2015+ 关键特性：解构、剩余/展开、可选链、空值合并、迭代器与生成器、异步迭代、Proxy/Reflect）

规范引用说明：本文引用的 ECMA-262 章节编号（§7.4 迭代器协议、§13.15.5 解构赋值求值、§14.4.14 `yield*` 求值、§6.1.7.2 Proxy 内部方法不变量）在不同版本间可能漂移，查阅时以 tc39.es/ecma262 现行版的同名 Runtime Semantics 为准。

## 学习目标

1. 把「解构 / 展开」从 API 用法提升到规范语义：数组解构为什么走迭代器、对象展开为什么不触发目标 setter——都能落到具体的抽象操作（GetIterator / CopyDataProperties / CreateDataProperty）
2. 讲清迭代器协议与可迭代协议的分层，以及生成器对象「一身二职」的原因
3. 掌握 `yield` 双向通信与 `yield*` 委托的求值过程（这是 async/await 原理的地基，阶段 1.4 已预告）
4. 理解 Proxy 的不变量为什么存在、Reflect 的存在意义（receiver 参数），并能手写 track/trigger 雏形——这是阶段 5 手写响应式（Vue reactivity）的入场券

## 关键概念

### 1. 解构的本质是模式匹配，且有两条完全不同的求值路径

「解构 = 按模式从数据里取值」。但数组解构和对象解构走的**根本不是同一条机制**：

- **数组解构走迭代器协议**（依据 §13.15.5 迭代 DestructuringAssignmentEvaluation）：先对右侧调用 `GetIterator`，然后逐个 `IteratorStep`/`IteratorValue` 取值，按**位置顺序**绑定给模式里的变量。所以：右侧不可迭代（`const [a] = 123`）→ `TypeError`；取不够就补 `undefined`；多余的被忽略；**惰性**——`const [a] = infiniteIterable` 只取一个值。
- **对象解构走自有属性查找**：先 `RequireObjectCoercible`（null/undefined 直接 `TypeError`；原始值会被装箱成包装对象），然后按模式里出现的 key 逐个 `Get(obj, key)`。**与枚举顺序无关**（只查模式里写过的键），也**不是迭代**——所以对象解构 null 会抛错，但 `const { length } = 'abc'` 能成功（装箱后的 String 有 length）。

**默认值触发条件是「严格等于 undefined」**：取到的值 `=== undefined` 才求默认值表达式；`null` 是合法值，原样保留（`const { a = 1 } = { a: null }` 得到 `null` 不是 `1`）。默认值表达式是惰性求值的——不触发就不会执行（可能有副作用/性能成本）。

**重命名与默认值组合**：`{ key: alias = default }`。匹配发生在 key 上，绑定名是 alias；默认值同样只看 key 匹配的结果是否为 undefined。

**嵌套解构**：模式可以任意嵌套，求值递归进行——嵌套的对象模式要求对应位置「可强制为对象」，嵌套的数组模式要求对应位置「可迭代」，失败同样抛 `TypeError`。

**嵌套解构**：模式可以任意嵌套，求值递归进行——嵌套的对象模式要求对应位置「可强制为对象」，嵌套的数组模式要求对应位置「可迭代」，失败同样抛 `TypeError`：

```js
// 嵌套 + 重命名 + 默认值三合一
const {
  node: { id, meta: { tags = [] } = {} } = {},
  rest: [first, ...others] = [],
} = { node: { id: 1, meta: { tags: ['a'] } }, rest: [1, 2, 3] };
// id=1, tags=['a'], first=1, others=[2,3]
// 任何一层「形状不匹配」（比如给数组模式一个非可迭代值）→ TypeError
```

**解构失败的三种形式**（都能说出「为什么」才算过关）：

```js live noInline
const [a] = 123;        // TypeError：GetIterator(123) 失败 —— number 没有 [Symbol.iterator]
const { b } = null;     // TypeError：RequireObjectCoercible(null) 失败 —— null 无法强制为对象
const { length } = 'ab'; // 2：原始值被装箱成 String 包装对象 —— 对象解构成功
```

**函数参数解构 = 参数位置的解构模式**：`function f({ a, b } = {}) {}`，与默认参数一样在「调用时」求值（见下面的参数作用域）。

**参数默认值的作用域经典题**：一旦有参数默认值，引擎会创建两层环境——**参数环境**（默认值表达式在这里求值，其 outer 是函数**定义处**的外层作用域）与**函数体环境**（body 的 let/const/class 在这里）。两个反直觉结论：

```js live noInline
let x = 'outer';
function f(y = x) { let x = 'inner'; return y; }
f(); // 'outer'，不抛错！默认值看不到函数体环境里的 x
function g(a = b, b = 2) {} // 参数从左到右初始化：a 求值时 b 在 TDZ
g(); // ReferenceError —— 这才是真正的 TDZ 经典题
```

### 2. 剩余（rest）与展开（spread）：三种语义，一个省略号

| 语法 | 位置 | 机制 |
| --- | --- | --- |
| `[...x]` | 数组字面量 / 函数调用 | 调用 `GetIterator(x)`，消费迭代器（与数组解构同源） |
| `{...x}` | 对象字面量 | `CopyDataProperties`：复制 x 的**自有可枚举**属性（含 Symbol 键） |
| `const [a, ...rest]` | 解构模式（rest） | 迭代器取剩余值组成新数组 |
| `function f(...args)` | 参数（rest） | 收集「多余实参」为真数组 |

- **数组展开消费 `[Symbol.iterator]`**：任何自定义可迭代对象都能被展开、被 `Math.max(...)`、被 `Array.from` 消费——这是「鸭子类型」而非 `Array` 专属。
- **对象展开 = 自有可枚举属性复制**（CopyDataProperties）：
  - 源侧用 `Get(source, key)` 逐个读值 → **源对象的自有 getter 会被调用**；原型上的属性不在 `[[OwnPropertyKeys]]` 结果里，完全不触碰；
  - 目标侧用 `CreateDataPropertyOrThrow` **定义**数据属性 → 不走 `[[Set]]` 赋值，**不触发目标（及其原型）上的 setter**；
  - 覆盖顺序 = 书写顺序：`{ ...a, k: 1 }` 中后写的 `k: 1` 覆盖展开进来的值。

**对象展开的最小实验**（完整版在练习 01，这里是可以直接粘贴的核心证据）：

```js live noInline
const proto = { get inherited() { console.log('原型 getter 被调用'); return 1; } };
const child = Object.create(proto);
child.own = 'v';
const copy = { ...child };              // 不打印任何东西：原型上的访问器根本不被触碰
console.log('inherited' in copy);       // false：只复制自有可枚举属性

const src2 = { get v() { console.log('源对象自有 getter 被调用'); return 7; } };
const copy2 = { ...src2 };              // 打印：源对象自有 getter 被调用（源侧走 Get）
```

**对象展开 vs Object.assign 关键差异表**：

| 维度 | `{ ...src }` 对象展开 | `Object.assign(target, src)` |
| --- | --- | --- |
| 目标对象 | 总是新建（字面量的一部分） | 第一个参数，**会被修改** |
| 写入语义 | `CreateDataProperty`（定义） | `[[Set]]`（赋值） |
| 触发目标自有/继承 setter | 否 | **是**（这正是它触发 setter / 原型链 setter 的原因） |
| 读取源属性 | `Get`（触发源 getter） | `Get`（同样触发源 getter） |
| 复制范围 | 源的自有可枚举属性（含 Symbol 键） | 同左 |
| 中途异常 | 整个字面量求值失败，不留半成品 | target 可能已被**部分修改** |
| 典型用途 | 不可变更新（Redux 风格） | 就地合并 / 需要走 setter 的场景 |

### 3. 可选链 `?.` 与空值合并 `??`：短路语义是核心

- `?.` 的「短路」是**整段跳过**：`a?.b.c()` 中若 `a` 是 null/undefined，后面的 `.b.c()` 整体不求值，表达式直接得 `undefined`——不是只跳过 `.b`。
- 只对 null/undefined 短路：`0?.toFixed`、`''?.length`、`false?.x` 都会继续求值（0、''、false 是合法的接收者）。`||` 的 falsy 陷阱在这里不存在。
- **不能用于赋值左侧**：`a?.b = 1` 是语法错误（SyntaxError）。原因：短路时左侧没有接收者，赋值无处安放——规范干脆禁止。
- 变体：`a?.[k]`（属性访问）、`a?.(...)`（可选调用，a 为空则不调用整体得 undefined）、`delete a?.b`（合法，a 为空时删除被跳过）。
- `??` 只把 null/undefined 当「空」：`0 ?? 42` 是 `0`，而 `0 || 42` 是 `42`——处理「合法的 0/false/空串」时必须用 `??`。
- **优先级与混用**：`a ?? b || c`、`a || b ?? c` 都是 **SyntaxError**——规范强制要求显式括号 `(a ?? b) || c`，因为两者的短路语义组合容易被误读。

```js live noInline
const conf = { retries: 0, timeout: null };
const retries = conf.retries ?? 3;   // 0：?? 只把 null/undefined 当空
const timeout = conf.timeout ?? 30;  // 30
const bad = conf.retries || 3;       // 3：|| 把 0 也吞了 —— 经典 bug 源
const label = conf.name?.trim() ?? 'default'; // 可选链 + 空值合并的标准组合
```

### 4. 迭代器协议：两层协议，职责分离（依据 §7.4）

- **iterator protocol（迭代器协议）**：一个对象有 `next()` 方法，调用返回 `{ value, done }`。迭代器是**一次性的**——走完即废弃。
- **iterable protocol（可迭代协议）**：一个对象有 `[Symbol.iterator]()` 方法，**返回一个迭代器**。可迭代对象可以反复开启新迭代。
- 分层的意义：同一个可迭代对象可以被多次消费（每次 for...of 都重新调用 `[Symbol.iterator]()` 拿全新迭代器——练习 02 用日志验证过）。

**手写最小可迭代对象**（协议的全部要求就这么多）：

```js live noInline
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {          // iterable：提供「生产迭代器」的入口
    let cur = this.from;
    return {
      next: () =>                 // iterator：提供「逐步取值」的游标
        cur <= this.to
          ? { value: cur++, done: false }
          : { value: undefined, done: true },
    };
  },
};
[...range];      // [1, 2, 3]：数组展开消费迭代器
Array.from(range); // 同样走迭代器（非数组则尝试迭代协议，其次类数组）
```
- 内置可迭代对象：Array、String、Map、Set、TypedArray、`arguments`（类数组但可迭代）、NodeList 等。普通对象**不可迭代**（没有 `[Symbol.iterator]`）——所以 `[...obj]` 报错而 `{...obj}` 可以（后者走属性复制，不是迭代）。
- 可迭代对象的消费位置：`for...of`、数组/对象字面里的展开、数组解构、`Array.from()`、`yield*`、`Promise.all/race/allSettled/any`（接受可迭代的 promise）、`new Map(iterable)` / `new Set(iterable)`、解构函数参数。

### 5. 生成器：function* 生成「可暂停的惰性状态机」

- 调用生成器函数**不执行函数体**，返回一个生成器对象；生成器对象**同时实现 iterator + iterable** 两个协议（它的 `[Symbol.iterator]()` 返回自身）——所以既能手动 `next()`，也能直接进 `for...of`。
- **双向通信**：`yield` 是表达式，它的值 = 恢复执行的那次 `next(arg)` 的 `arg`。第一次 `next()` 的参数**必然被丢弃**（还没有 yield 在等它）。这是 async/await 中「await 表达式的值 = Promise 的 resolve 值」的同步原型。

```js live noInline
function* ask() {
  const name = yield '你叫什么？';   // name ← 第 2 次 next('小明') 的参数
  return `hi ${name}`;
}
const it = ask();
it.next();          // { value: '你叫什么？', done: false }（参数无处可去）
it.next('小明');    // { value: 'hi 小明', done: true }
```
- `return(value)`：在暂停点注入 return，函数体终止（finally 块会执行），之后 next 只得 done。
- `throw(err)`：在暂停点**抛出**异常——生成器内部的 try/catch 能接住它，接住后从该 yield 继续执行。
- `for...of` 提前 break/throw/return 时，会自动调用 `iterator.return()`（若存在）关闭生成器——finally 块因此执行。这是「协作式清理」的机制。
- **`yield*` 委托**（依据 §14.4.14 yield* 求值）：`yield* iterable` 把 next 参数、产出值、return 全部转发给内层可迭代对象；**`yield*` 整个表达式的值 = 内层的 return 值**（不是最后一个 yield 值）。它对任何可迭代对象都有效（不只是生成器）。

### 6. 异步迭代：把「等待」接进迭代协议

- `Symbol.asyncIterator` + `next()` 返回 `Promise<IteratorResult>` = 异步迭代器协议。
- `for await...of` 每步先 await next() 的 Promise，body 拿到 result.value；**同步 for...of 拿到的则是 Promise 对象本身**（不会自动等）。
- `async function*` 内部可以 `await`，且 **yield 出去的值会被隐式 await** 后再交给消费方——这是 async generator 与手写 asyncIterable 的关键差异：手写对象的 `IteratorResult.value` **不会**被自动解包（哪怕它本身是 Promise）。TS 对 for await 元素类型按 `Awaited<T>` 处理，也印证了这一约定。

```js live noInline
// 手写 asyncIterable：next 返回 Promise<IteratorResult>，仅此而已
const asyncRange = {
  [Symbol.asyncIterator]() {
    let i = 0;
    return {
      next: () =>
        Promise.resolve(i < 2 ? { value: ++i, done: false } : { value: undefined, done: true }),
    };
  },
};
for await (const v of asyncRange) console.log(v); // 1, 2 —— 每步都先等 Promise 落定

// 对照：同步迭代器产出 Promise，for...of 不会等
for (const p of [Promise.resolve(1)]) console.log(p); // Promise { 1 } —— 拿到的是 Promise 对象
```
- 典型场景：分页拉取、逐条消费消息队列——「边生产边消费」，内存里永远只有一条数据。

### 7. Proxy / Reflect：元编程的拦截层与规范操作的门面

- Proxy 拦截的是**内部方法**（`[[Get]]`/`[[Set]]`/`[[HasProperty]]`/`[[Delete]]`/`[[OwnPropertyKeys]]`/`[[Call]]`/`[[Construct]]` 等 13 个），对应 get/set/has/deleteProperty/ownKeys/apply/construct 等 trap。**属性访问 `p.x` 只是 `[[Get]]` 的语法糖**——理解这点，trap 触发时机就全部可推导。

常用 trap 速查（完整 13 个见规范 [[Proxy]] 一节）：

| trap | 拦截的内部方法 | 典型触发语法 |
| --- | --- | --- |
| get | `[[Get]]` | `p.x`、`p[k]`、解构读取 |
| set | `[[Set]]` | `p.x = 1`、`Object.assign(p, ...)` 写入侧 |
| has | `[[HasProperty]]` | `'x' in p`、`with (p)` 查找 |
| deleteProperty | `[[Delete]]` | `delete p.x` |
| ownKeys | `[[OwnPropertyKeys]]` | `Object.keys/entries`、`JSON.stringify`、for...in |
| apply | `[[Call]]` | `p(...)`（目标必须是函数） |
| construct | `[[Construct]]` | `new p()`（目标必须是构造器） |
| getPrototypeOf / setPrototypeOf | `[[GetPrototypeOf]]` / `[[SetPrototypeOf]]` | `Object.getPrototypeOf(p)`、`p.__proto__` |
| defineProperty / getOwnPropertyDescriptor | `[[DefineOwnProperty]]` / `[[GetOwnProperty]]` | `Object.defineProperty` / `Object.getOwnPropertyDescriptor` |
| isExtensible / preventExtensions | `[[IsExtensible]]` / `[[PreventExtensions]]` | `Object.isExtensible` / `Object.preventExtensions` |
- **代理不变量**（依据 §6.1.7.2 内部方法不变量）：proxy 不能「比 target 更会撒谎」。违反即 TypeError。两个最常考的例子：
  - target 有**不可写且不可配置**的数据属性（如 `Object.freeze` 之后）→ get trap **必须返回原值**，返回别的值抛 TypeError；
  - set trap 返回 false → 在严格模式（ESM 模块都是严格模式）下赋值表达式抛 TypeError；`Reflect.set` 则返回 false 不抛。不变量存在的意义：**保证「通过 proxy 观察/修改 target」与「直接操作 target」语义一致**，否则代理可以凭空伪造一个与目标矛盾的视图。

其他高频不变量（知道两条以上即超出平均水准）：

- 对 target 上**不可配置**的属性，deleteProperty trap 若返回 true（谎报删除成功）→ TypeError；
- target 不可扩展（`Object.preventExtensions`）时，ownKeys 返回的键集合必须与 target 的自有键**完全一致**（不能多也不能少）；
- target 上**不可配置**的自有属性必须出现在 ownKeys 的结果里（不能把它藏起来）；
- apply/construct trap 只有目标本身是函数/构造器时才可设置（new Proxy 时即校验）。
- **Reflect 的意义**：
  1. 与 Proxy trap 一一对应的函数集合——在 trap 里转发默认行为的标准写法（`return Reflect.get(target, key, receiver)`）；
  2. **receiver 参数保住 this**：getter 里的 this 不是「属性所在对象」，而是 `[[Get]]` 的 receiver。转发时传 receiver（= proxy）→ getter 内部的 `this.x` 会**再次经过 proxy** 被拦截（响应式依赖收集的正确性基础）；不传则 this 落到原对象上，嵌套访问绕过代理；
  3. 把「内部操作」以函数形式暴露：`Reflect.set` 返回布尔而非抛错、`Reflect.defineProperty` 返回布尔——在 trap 内「表达默认行为并检查结果」变得自然。
- **迷你响应式（track/trigger 雏形）**：get trap 里登记「谁在读这个 key」（track），set trap 里通知「这个 key 变了」（trigger）。加上 effect 栈、嵌套代理、cleanup 与调度就是 Vue reactivity 的骨架（阶段 5 展开）。

最小骨架（响应式雏形，完整版见练习 04）：

```ts live noInline
const targetMap = new Map<object, Map<string, Set<() => void>>>(); // target → key → 依赖集合
let activeEffect: (() => void) | null = null;

function track(target: object, key: string): void {
  if (activeEffect === null) return;
  // 把 activeEffect 放进 targetMap 对应的集合（练习 04 有完整代码）
}
function trigger(target: object, key: string): void {
  // 取出依赖集合并逐个执行
}

function reactive<T extends object>(obj: T): T {
  return new Proxy(obj, {
    get(t, key, receiver) {
      track(t, String(key));                        // 谁在读
      return Reflect.get(t, key, receiver);         // 传 receiver：getter 的 this = proxy
    },
    set(t, key, value, receiver) {
      const old = Reflect.get(t, key, receiver);
      const ok = Reflect.set(t, key, value, receiver);
      if (ok && old !== value) trigger(t, String(key)); // 变了才通知
      return ok;
    },
  });
}
```

验证 receiver 的作用（getter 里 this 的归宿，30 秒实验）：

```js live noInline
const seen = [];
const base = { first: 'F', second: 'S', get combined() { return `${this.first}-${this.second}`; } };
const p = new Proxy(base, {
  get(t, key, receiver) { seen.push(String(key)); return Reflect.get(t, key, receiver); },
});
p.combined;               // 'F-S'
seen.join(' → ');         // 'combined → first → second'：getter 内 this = proxy，嵌套读取继续被拦截
// 若改成 return t[key]（不传 receiver）：seen 只剩 'combined' —— 嵌套读取逃过了代理
```

## 易错点与面试高频

1. **「解构默认值对 null 生效」**——错。只有 undefined 触发；`{ a = 1 } = { a: null }` 得 null。高频笔试题。
2. **「对象展开不触发 getter」**——半错。目标侧不触发 setter（CreateDataProperty 定义新属性）；**源侧的自有 getter 会被 Get 调用**；原型上的访问器完全不触碰。面试时能分清源/目标两侧就是加分项。
3. **`??` 与 `||` 混用不写括号**——SyntaxError，不是优先级问题，是语法直接禁止。
4. **`a?.b = 1`**——SyntaxError；可选链只能出现在读取/调用/删除位置。
5. **普通对象不可迭代**：`[...{}]` 报错不是 bug，是「展开数组走迭代器、展开对象走属性复制」的分流；`for...in` 遍历键（含原型链可枚举）、`for...of` 消费迭代器——两者名字像，机制无关。
6. **第一次 `next(arg)` 的参数被丢弃**——双向通信从第二次 next 开始。
7. **`yield*` 的值是内层的 return 值**，不是最后一个 yield 值；且 next 参数会穿透 `yield*` 直接交给内层。
8. **冻结对象的代理 get trap 返回别的值 / set trap 返回 false 后赋值**——都抛 TypeError（不变量）；能说出「为什么必须有不变量」才算懂 Proxy。
9. **trap 里 `target[key]` 与 `Reflect.get(target, key, receiver)` 的差异**——getter 中 this 的归宿；响应式系统里用错会导致嵌套属性逃过依赖收集（练习 04 Part 2 有对照实验）。
10. **参数默认值经典题的两个真相**：函数体内 let 同名变量**不会**让默认值进 TDZ（默认值在参数环境求值）；默认值引用**后面的参数**才会 TDZ（参数从左到右初始化）。

## 输出预测题

先闭卷写出输出，再看文末答案（建议直接在 `npx tsx` 里验证）。

### 题 1

```js live noInline
const log = [];
const rec = (v) => { log.push(v); return v; };

const { a = rec('a'), b = rec('b'), c: alias = rec('c') } = { a: undefined, b: null };
console.log(a, b, alias);
console.log(log.join(','));

const merged = { ...{ x: 1, get y() { log.push('getter-y'); return 2; } }, x: 99 };
console.log(merged.x, merged.y);
console.log(log.join(','));
```

### 题 2

```js live noInline
function* inner() {
  const got = yield 'i';
  console.log('inner got', got);
  return 'R';
}
function* outer() {
  const v = yield* inner();
  console.log('outer got', v);
  yield 'o';
}
const it = outer();
console.log(it.next().value);
console.log(it.next('X').value);

const frozen = Object.freeze({ v: 1 });
const p = new Proxy(frozen, { get() { return 999; } });
try { console.log(p.v); } catch (e) { console.log('TypeError:', e instanceof TypeError); }
```

## 预测题答案

### 题 1 答案

```
a null c
a,c
99 2
a,c,getter-y
```

推理：

1. `a` 是 undefined → 默认值 `rec('a')` 求值 → a = `'a'`；`b` 是 null → **默认值不求值**，b = `null`；`c` 在源对象上不存在（取到 undefined）→ 默认值 `rec('c')` 求值 → alias = `'c'`
2. `log` 此时是 `a,c`（b 的默认值从未求值）
3. `merged`：展开时源侧 `Get(source, 'y')` **调用了自有 getter** → log 追加 `getter-y`；后书写的 `x: 99` 覆盖展开进来的 `x: 1` → 打印 `99 2`
4. 最终 log 为 `a,c,getter-y`

### 题 2 答案

```
i
inner got X
outer got R
o
TypeError: true
```

推理：第 1 次 `next()` 执行到 inner 的第一个 yield，产出 `'i'`；第 2 次 `next('X')` 的参数成为 inner 中 `got` 的值（打印 `inner got X`），inner `return 'R'` 使 `yield*` 表达式得 `'R'`（打印 `outer got R`），outer 继续到 `yield 'o'` 产出 `'o'`。最后：`v` 是**不可写不可配置**数据属性（freeze），get trap 返回 999 违反代理不变量 → TypeError（练习 04 Part 4 的实测行为）。
